REPORT 074

Forum post performance

Summarizes forum post volumes and calculated monthly, weekly, and daily averages since the module was added, highlighting the most frequent posting periods.

Report purpose

Summarizes forum post volumes and calculated monthly, weekly, and daily averages since the module was added, highlighting the most frequent posting periods.

Why use this report?

Helps teachers and administrators track posting volume and identify weekday and time-of-day patterns using forum records.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic filter is Course, identified by :courseid. MySQL uses the parameter four times (three frequency subqueries and the main filter), whereas PostgreSQL uses it once (the main filter), since frequencies are calculated using forum-correlated LATERAL subqueries.

The SQL requires visible = 1 for the course and considers posts from discussions belonging to each forum. There are no dynamic filters for date, author, or module visibility.

Visualization and full original SQL

One table visualization includes two complete SQL queries, cache and refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL appear in separate panels within the same visualization.

1. Forum post performance · Table

The per-forum table shows its name, course, total distinct posts, average posts per month, week, and day since the module was added, most frequent weekday, most frequent hour, and most frequent week-of-month band.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_f.id                                                                                                as fid,
       kbi_f.name,
       kbi_c.fullname,
       COUNT(DISTINCT kbi_fp.id)                                                                               AS all_posts,
       COUNT(DISTINCT kbi_fp.id) /
       GREATEST(PERIOD_DIFF(DATE_FORMAT(NOW(), '%Y%m'), DATE_FORMAT(FROM_UNIXTIME(kbi_cm.added), '%Y%m')), 1)  as avg_month,
       COUNT(DISTINCT kbi_fp.id) /
       GREATEST(CEILING(DATEDIFF(DATE_FORMAT(NOW(), '%Y%m%d'), DATE_FORMAT(FROM_UNIXTIME(kbi_cm.added), '%Y%m%d')) / 7),
                1)                                                                                         as avg_week,
       COUNT(DISTINCT kbi_fp.id) /
       GREATEST(DATEDIFF(DATE_FORMAT(NOW(), '%Y%m%d'), DATE_FORMAT(FROM_UNIXTIME(kbi_cm.added), '%Y%m%d')), 1) as avg_day,
       popular_day.day                                                                                     AS popular_day,
       popular_hour.hour                                                                                   AS popular_hour,
       popular_week.week                                                                                   AS popular_week
FROM mdl_forum kbi_f
       JOIN mdl_modules kbi_m ON kbi_m.name = 'forum'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_f.course AND kbi_cm.instance = kbi_f.id AND kbi_cm.module = kbi_m.id
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_f.course
       LEFT JOIN mdl_forum_discussions kbi_fd ON kbi_fd.forum = kbi_f.id
       LEFT JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id
       LEFT JOIN (SELECT a.posts, a.day, a.id
                  FROM (SELECT COUNT(DISTINCT kbi_fp2.id)                             as posts,
                               WEEKDAY(FROM_UNIXTIME(kbi_fp2.created, '%Y-%m-%d %T')) AS day,
                               kbi_f2.id
                        FROM mdl_forum kbi_f2
                               LEFT JOIN mdl_forum_discussions kbi_fd2 ON kbi_fd2.forum = kbi_f2.id
                               LEFT JOIN mdl_forum_posts kbi_fp2 ON kbi_fp2.discussion = kbi_fd2.id
                        WHERE kbi_f2.course = :courseid
                        GROUP BY day, kbi_f2.id
                        ORDER BY posts DESC) AS a
                  GROUP BY a.id) as popular_day ON popular_day.id = kbi_f.id
       LEFT JOIN (SELECT a.posts, a.hour, a.id
                  FROM (SELECT COUNT(DISTINCT kbi_fp2.id) as posts, FROM_UNIXTIME(kbi_fp2.created, '%H') AS hour, kbi_f2.id
                        FROM mdl_forum kbi_f2
                               LEFT JOIN mdl_forum_discussions kbi_fd2 ON kbi_fd2.forum = kbi_f2.id
                               LEFT JOIN mdl_forum_posts kbi_fp2 ON kbi_fp2.discussion = kbi_fd2.id
                        WHERE kbi_f2.course = :courseid
                        GROUP BY hour, kbi_f2.id
                        ORDER BY posts DESC) AS a
                  GROUP BY a.id) as popular_hour ON popular_hour.id = kbi_f.id
       LEFT JOIN (SELECT a.posts, a.week, a.id
                  FROM (SELECT COUNT(DISTINCT kbi_fp2.id)                                             as posts,
                               CEILING(DAYOFMONTH(FROM_UNIXTIME(kbi_fp2.created, '%Y-%m-%d %T')) / 7) AS week,
                               kbi_f2.id
                        FROM mdl_forum kbi_f2
                               LEFT JOIN mdl_forum_discussions kbi_fd2 ON kbi_fd2.forum = kbi_f2.id
                               LEFT JOIN mdl_forum_posts kbi_fp2 ON kbi_fp2.discussion = kbi_fd2.id
                        WHERE kbi_f2.course = :courseid
                        GROUP BY week, kbi_f2.id
                        ORDER BY posts DESC) AS a
                  GROUP BY a.id) as popular_week ON popular_week.id = kbi_f.id
WHERE kbi_f.course = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_f.id
ORDER BY all_posts DESC, kbi_f.name

Full original PostgreSQL SQL

SELECT f.id AS fid,
       f.name,
       c.fullname,
       COUNT(DISTINCT fp.id) AS all_posts,
       COUNT(DISTINCT fp.id)::numeric / GREATEST(
           (EXTRACT(YEAR FROM AGE(CURRENT_DATE, TO_TIMESTAMP(cm.added)::date)) * 12
            + EXTRACT(MONTH FROM AGE(CURRENT_DATE, TO_TIMESTAMP(cm.added)::date))), 1
       ) AS avg_month,
       COUNT(DISTINCT fp.id)::numeric / GREATEST(
           CEIL(GREATEST(CURRENT_DATE - TO_TIMESTAMP(cm.added)::date, 0)::numeric / 7), 1
       ) AS avg_week,
       COUNT(DISTINCT fp.id)::numeric / GREATEST(
           CURRENT_DATE - TO_TIMESTAMP(cm.added)::date, 1
       ) AS avg_day,
       pd.day AS popular_day,
       ph.hour AS popular_hour,
       pw.week AS popular_week
FROM mdl_forum f
JOIN mdl_modules m ON m.name = 'forum'
LEFT JOIN mdl_course_modules cm ON cm.course = f.course AND cm.instance = f.id AND cm.module = m.id
LEFT JOIN mdl_course c ON c.id = f.course
LEFT JOIN mdl_forum_discussions d ON d.forum = f.id
LEFT JOIN mdl_forum_posts fp ON fp.discussion = d.id
LEFT JOIN LATERAL (
    SELECT (EXTRACT(ISODOW FROM TO_TIMESTAMP(p.created))::integer - 1) AS day
      FROM mdl_forum_discussions d2
      JOIN mdl_forum_posts p ON p.discussion = d2.id
     WHERE d2.forum = f.id
     GROUP BY 1
     ORDER BY COUNT(DISTINCT p.id) DESC, 1
     LIMIT 1
) pd ON TRUE
LEFT JOIN LATERAL (
    SELECT EXTRACT(HOUR FROM TO_TIMESTAMP(p.created))::integer AS hour
      FROM mdl_forum_discussions d2
      JOIN mdl_forum_posts p ON p.discussion = d2.id
     WHERE d2.forum = f.id
     GROUP BY 1
     ORDER BY COUNT(DISTINCT p.id) DESC, 1
     LIMIT 1
) ph ON TRUE
LEFT JOIN LATERAL (
    SELECT CEIL(EXTRACT(DAY FROM TO_TIMESTAMP(p.created)) / 7.0)::integer AS week
      FROM mdl_forum_discussions d2
      JOIN mdl_forum_posts p ON p.discussion = d2.id
     WHERE d2.forum = f.id
     GROUP BY 1
     ORDER BY COUNT(DISTINCT p.id) DESC, 1
     LIMIT 1
) pw ON TRUE
WHERE f.course = :courseid AND c.visible = 1
GROUP BY f.id, c.id, cm.added, pd.day, ph.hour, pw.week
ORDER BY all_posts DESC, f.name

Limitations and cautions

  • The avg_month, avg_week, and avg_day indicators are posting averages since the module was added, not averages for the previous month, week, or day.
  • MySQL calculates months using PERIOD_DIFF and day intervals using DATEDIFF; PostgreSQL uses AGE, CURRENT_DATE, and calendar intervals. Results can differ because of reference dates and rounding rules.
  • Both variants protect minimum denominators using GREATEST, but depend on the availability and meaning of the course_modules.added date.
  • In MySQL, subqueries order their counts before grouping solely by forum ID. That ordering does not guarantee that the selected weekday, hour, or week is the most frequent.
  • In PostgreSQL, LATERAL subqueries explicitly order by distinct post count, using the period as a tiebreaker, resulting in a more clearly defined selection.
  • The popular week calculation uses ranges of days within a month, not ISO weeks of the year. Hours and days depend on the database time zone.
  • Counts do not distinguish initial posts from replies and do not require active participant status or module visibility.
  • Post counts reflect volume, not participation quality or learning. The SQL does not provide a selectable reporting period.
