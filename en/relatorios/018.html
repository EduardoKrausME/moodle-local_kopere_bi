REPORT 018

User engagement

Lists students with course-context role assignments, the number of associated courses, and time recorded by Kopere BI for the site, courses, and activities.

Report purpose

Lists students with course-context role assignments, the number of associated courses, and time recorded by Kopere BI for the site, courses, and activities.

Why use this report?

Provides an administrative overview of recorded tracking data for each student, helping identify overall participation patterns and cases that may need further educational investigation.

Actual filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for user, course, cohort, or date range. The SQL includes users assigned role ID 5 in a course context (contextlevel = 50).

Users must also have an ID greater than 0, be neither deleted nor suspended, and not be guest. The query aggregates available tracking records without a time window.

Visualization and full original SQL

The report contains one table and one SQL query, with cache, refresh settings, and Prism.js syntax highlighting. The original catalog does not provide a separate PostgreSQL variant.

1. User engagement · Table

Table showing user identification and account creation data, the number of distinct courses with a role ID 5 assignment, and three time measures: total site time, course-related tracking records, and activity-related tracking records.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_u.timecreated,
       COUNT(DISTINCT kbi_ctx.instanceid) as courses,
       MAX(lit.timesite)              AS timesite,
       MAX(lit.timecourses)           AS timecourses,
       MAX(lit.timeactivities)        AS timeactivities
FROM mdl_role_assignments kbi_ra
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       LEFT JOIN (SELECT userid,
                         SUM(timespend)                                              as timesite,
                         SUM(CASE WHEN courseid > 0 THEN timespend ELSE null END)    as timecourses,
                         SUM(CASE WHEN page = 'module' THEN timespend ELSE null END) as timeactivities
                  FROM mdl_local_kopere_bi_tracking
                  GROUP BY userid) as lit ON lit.userid = kbi_u.id
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_ra.roleid = 5
GROUP BY kbi_u.id

Limitations and cautions

  • The definition of a student depends on role ID 5. On sites with customized roles, the selected population may differ from expectations.
  • The course count represents distinct course contexts where this role is assigned, not necessarily all of the user's active enrolments.
  • Site, course, and activity time values come from potentially overlapping totals. Do not add the three columns to calculate total time without reviewing how the records are collected.
  • Recorded time does not demonstrate continuous attention, learning, activity completion, or course completion.
  • There is no selectable date range. The values depend on the historical coverage and updates of mdl_local_kopere_bi_tracking.
  • The file does not provide a separate PostgreSQL variant. Review the SQL and permissions for personal information in the target environment.
