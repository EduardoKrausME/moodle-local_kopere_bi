REPORT 039

Course content usage

Detailed tracking of visible modules in the selected course, including visits, time spent, access dates, and browser and platform information.

Report purpose

Detailed tracking of visible modules in the selected course, including visits, time spent, access dates, and browser and platform information.

Why use this report?

Helps investigate the recorded usage of specific activities and resources in a course, examining the distribution of visits, usage time, and technical characteristics of access.

Available filters Visualization and SQL Limitations

Available filters

The dynamic filter is Course, implemented by :courseid once in the tracking table condition.

Fixed criteria select kbi_l.page = 'module', a visible module (kbi_cm.visible = 1), a visible course, and users who are neither deleted nor suspended and are not guest. There are no dynamic user, activity, or date-range filters.

Visualization and full original SQL

One table visualization contains one SQL query, cache settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided for this report.

1. Course content usage · Table

Each module tracking record identifies the user, course, category, CMID, module type, date added, visits, time spent, first and last access, browser, operating system, language, and recorded IP address.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_l.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.fullname,
       kbi_c.shortname,
       kbi_ca.name  AS category,
       kbi_l.param,
       kbi_l.visits,
       kbi_l.timespend,
       kbi_l.firstaccess,
       kbi_l.lastaccess,
       kbi_l.useragent,
       kbi_l.useros,
       kbi_l.userlang,
       kbi_l.userip,
       kbi_l.userid,
       kbi_l.courseid,
       kbi_cm.added as created,
       kbi_m.name   as module
FROM mdl_local_kopere_bi_tracking kbi_l
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_l.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_l.courseid
       LEFT JOIN mdl_course_categories kbi_ca ON kbi_ca.id = kbi_c.category
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.id = kbi_l.param
       LEFT JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
WHERE kbi_l.page = 'module'
  AND kbi_l.courseid = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • Visit counts, time spent, and access dates come from mdl_local_kopere_bi_tracking and depend on the plugin's data collection. They do not necessarily represent individual sessions, continuous attention, or activity completion.
  • Filtering for visible modules excludes hidden modules but does not guarantee an activity is available to a user under availability restrictions or other access conditions.
  • The SQL performs no additional grouping or aggregation. A user can appear in multiple rows when there are different tracking records, modules, or access characteristics.
  • The created field comes from mdl_course_modules.added, meaning the date a module was added, not the first visit.
  • The useragent, useros, userlang, and userip fields reflect data recorded during tracking and can be absent, inaccurate, or outdated.
  • The table includes user identifiers, email addresses, and IP addresses. Respect access controls, retention policies, and privacy requirements.
  • There is no separate PostgreSQL variant in the catalog for this report.
