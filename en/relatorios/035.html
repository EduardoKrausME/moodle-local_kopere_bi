REPORT 035

Course access

Summary of the selected course with enrolled participants, tracked users, course and activity completions, visits, recorded time, and assigned teachers.

Report purpose

Summary of the selected course with enrolled participants, tracked users, course and activity completions, visits, recorded time, and assigned teachers.

Why use this report?

Helps administrators and managers examine a specific course, compare enrolments against tracking records, and review completions, visits, and usage captured by Kopere BI.

Available filters Visualization and SQL Limitations

Available filters

The available dynamic filter is Course, associated with :courseid, which occurs five times in each SQL variant: in course completion, activity completion, enrolment, and tracking subqueries and in the main course selection.

Fixed conditions require a course with an ID greater than 1 that is visible (kbi_c.visible = 1), enrolments and enrolment methods with status 0, course completion with timecompleted > 0, and activities in completion states 1 or 2. Teachers are identified by role ID 3 in the course context. There is no dynamic time filter.

Visualization and full original SQL

One table visualization contains two complete SQL queries, cache settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL variants appear in separate panels of the same visualization.

1. Course access · Table

The table displays the course name, category, and start date; users with tracking data; enrolments classified as active by their recorded status; a calculated inactive-user difference; formal course and activity completions; total time and visits; latest recorded access; and assigned teachers' names.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       kbi_c.shortname,
       kbi_ca.name                             AS category,
       kbi_c.startdate,
       x.users,
       (ue.enrolled - x.users)             AS inactiveusers,
       ue.enrolled,
       cc.completed,
       x.timespend,
       x.visits,
       x.lastaccess,
       completed_activities,
       (SELECT GROUP_CONCAT(DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) SEPARATOR ', ')
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3) AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_course_categories kbi_ca ON kbi_ca.id = kbi_c.category
       LEFT JOIN (SELECT course, COUNT(*) AS completed
                  FROM mdl_course_completions
                  WHERE timecompleted > 0
                    AND course = :courseid
                  GROUP BY course) cc ON cc.course = kbi_c.id
       LEFT JOIN (SELECT kbi_cc.course, COUNT(*) as completed_activities
                  FROM mdl_course_modules_completion kbi_cmc
                         JOIN mdl_course_modules kbi_cc ON kbi_cc.id = kbi_cmc.coursemoduleid
                  WHERE 1 = 1
                    AND kbi_cmc.completionstate IN (1, 2)
                    AND kbi_cc.course = :courseid
                  GROUP BY kbi_cc.course) compl ON compl.course = kbi_c.id
       LEFT JOIN (SELECT kbi_e.courseid, COUNT(DISTINCT kbi_ue.userid) AS enrolled
                  FROM mdl_enrol kbi_e
                         JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
                  WHERE 1 = 1
                    AND kbi_ue.status = 0
                    AND kbi_e.status = 0
                    AND kbi_e.courseid = :courseid
                  GROUP BY kbi_e.courseid) ue ON ue.courseid = kbi_c.id
       LEFT JOIN (SELECT kbi_t.courseid,
                         COUNT(DISTINCT kbi_t.userid) as users,
                         MAX(lastaccess)          AS lastaccess,
                         SUM(kbi_l.timespend)         AS timespend,
                         SUM(kbi_l.visits)            AS visits
                  FROM mdl_local_kopere_bi_tracking kbi_t
                         JOIN mdl_local_kopere_bi_track_log kbi_l ON kbi_l.trackid = kbi_t.id
                  WHERE 1 = 1
                    AND kbi_t.courseid = :courseid
                  GROUP BY kbi_t.courseid) x ON x.courseid = kbi_c.id
WHERE kbi_c.id > 1
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1

Limitations and cautions

  • The inactiveusers column calculates ue.enrolled - x.users, the difference between enrolled users and users appearing in tracking records. It applies no inactivity threshold and does not necessarily identify inactive users.
  • The x.users count includes distinct users with tracking records linked to logs, even when those users no longer have active enrolments. The inactiveusers difference may therefore be negative.
  • If a subquery has no records, LEFT JOIN operations may produce NULL values. Missing data should not automatically be interpreted as zero.
  • The completed_activities field counts module completion records, not the number of distinct completed modules or the number of students who completed them.
  • The completed field counts formal course completions with a recorded date, without directly restricting them to users with active enrolments in the corresponding subquery.
  • Visit, time, and last-access values depend on Kopere BI logs and tracking data. There is no selectable date range, and the last activity is taken from the tracking source.
  • Teacher names are aggregated with GROUP_CONCAT in MySQL and STRING_AGG in PostgreSQL. Each query variant must be used with the compatible database.
