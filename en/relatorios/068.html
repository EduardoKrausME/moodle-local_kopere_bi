REPORT 068

Quiz progress by cohort

Summarizes distinct quizzes and recorded attempts by cohort membership among users who attempted quizzes in the selected course.

Report purpose

Summarizes distinct quizzes and recorded attempts by cohort membership among users who attempted quizzes in the selected course.

Why use this report?

Helps educational teams identify cohorts with quiz attempts in the course and compare quiz participation volumes between groups.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic filter is Course, represented by :courseid and used once in the SQL.

The fixed condition requires kbi_c.visible = 1. Cohorts are linked through mdl_cohort_members, associating each user who attempted a quiz with any cohort they belong to. There are no parameters for cohort, date range, student, or quiz.

Visualization and full original SQL

One table visualization contains one complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL definition is provided.

1. Quiz progress by cohort · Table

The table lists each cohort's ID and name, the number of distinct quizzes with attempts (submitted), and the number of distinct attempts (attempted), sorted by cohort name.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_co.id,
       kbi_co.name,
       COUNT(DISTINCT kbi_qa.quiz) AS submitted,
       COUNT(DISTINCT kbi_qa.id)   AS attempted
FROM mdl_quiz_attempts kbi_qa
       JOIN mdl_quiz kbi_q ON kbi_q.id = kbi_qa.quiz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_q.course
       JOIN mdl_cohort_members kbi_cm ON kbi_cm.userid = kbi_qa.userid
       JOIN mdl_cohort kbi_co ON kbi_co.id = kbi_cm.cohortid
WHERE kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_co.id, kbi_co.name
ORDER BY kbi_co.name

Limitations and cautions

  • Despite the title, there is no percentage of progress or completion. The submitted field counts distinct quiz IDs with attempts, while attempted counts distinct attempt IDs.
  • The submitted label does not mean attempts were submitted or finished: the query does not filter state = 'finished' or exclude preview records.
  • Cohort membership comes from mdl_cohort_members and does not prove that the cohort is specifically associated with the course or that the user is enrolled in it.
  • A user may belong to multiple cohorts. Their attempts may contribute to several group totals; do not add rows to obtain platform-wide distinct totals.
  • Only cohorts with at least one associated attempt are included; cohorts without attempts are not listed.
  • The query does not filter deleted or suspended users, enrolment status, quiz module visibility, or attempt dates.
  • There is no separate PostgreSQL SQL file for this report. These values are event counts, not conclusive measures of learning.
