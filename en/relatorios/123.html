REPORT 123

Quiz performance by question tag

Fully correct question results grouped by question tag, considering finished quiz attempts.

Report purpose

Table by course and tag, showing the tag name, number of distinct questions found, evaluated response occurrences, fully correct occurrences, and percentage of responses with a fraction of at least 1. Results are sorted by descending occurrence count and course, with a limit of 500 rows.

Why use this report?

Analyze which question tags are associated with the most evaluated responses and what proportion earned full credit, helping investigate performance patterns by topic.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for course, quiz, tag, student, or reporting period. The query requires finished quiz attempts (a.state = 'finished') and final question-attempt steps with st.fraction IS NOT NULL.

Tag matching uses fixed criteria ti.itemtype = 'question' and ti.itemid = q.id. The query does not explicitly filter preview attempts (a.preview), deleted accounts, or hidden courses. Results are limited to 500 groups.

Visualization and full original SQL

The report contains one table visualization with the complete original SQL, caching, and refresh settings. Prism.js provides syntax highlighting. No separate PostgreSQL variant was found in master, so no nonexistent query has been added.

1. Quiz performance by question tag · Table

Table by course and tag, with tag name, number of distinct questions, evaluated occurrences, fully correct occurrences, and percentage of responses earning full credit. Rows are sorted by descending occurrence volume and course, with a 500-row limit.

Cache: 1h · Refresh: none.

Full original SQL

SELECT CONCAT(c.id, '-', tag.id) AS id, c.id AS courseid, c.fullname AS course,
       tag.rawname AS tag, COUNT(DISTINCT q.id) AS questions, COUNT(*) AS attempts,
       SUM(CASE WHEN st.fraction >= 1 THEN 1 ELSE 0 END) AS fully_correct,
       ROUND(100.0 * SUM(CASE WHEN st.fraction >= 1 THEN 1 ELSE 0 END) / COUNT(*), 2) AS fully_correct_percent
  FROM mdl_quiz_attempts a
  JOIN mdl_quiz quiz ON quiz.id = a.quiz
  JOIN mdl_course c ON c.id = quiz.course
  JOIN mdl_question_attempts att ON att.questionusageid = a.uniqueid
  JOIN mdl_question q ON q.id = att.questionid
  JOIN mdl_tag_instance ti ON ti.itemtype = 'question' AND ti.itemid = q.id
  JOIN mdl_tag tag ON tag.id = ti.tagid
  JOIN mdl_question_attempt_steps st ON st.questionattemptid = att.id
       AND st.sequencenumber = (SELECT MAX(st2.sequencenumber)
                                 FROM mdl_question_attempt_steps st2
                                WHERE st2.questionattemptid = att.id)
 WHERE a.state = 'finished' AND st.fraction IS NOT NULL
 GROUP BY c.id, c.fullname, tag.id, tag.rawname
 ORDER BY attempts DESC, c.fullname
 LIMIT 500

Calculation criteria and behavior

The SQL joins quizzes, questions, and their tags and selects the last step through MAX(st2.sequencenumber) to obtain the response fraction. Results are grouped by course and tag. COUNT(DISTINCT q.id) counts different questions, while COUNT(*) counts evaluated occurrences for that tag.

fully_correct counts occurrences where st.fraction >= 1. fully_correct_percent divides that count by the group's occurrence count. Questions bearing multiple tags may contribute separately to multiple groups; the metric is not a percentage of distinct students.

Limitations and cautions

  • Preview attempts are not explicitly excluded: there is no a.preview = 0 condition. Depending on the stored records, previews may affect totals.
  • COUNT(*) counts question-and-tag occurrences, not distinct users. Repeated attempts can give the same participant greater weight.
  • A question with multiple tags appears in multiple groups. Tag totals must not be summed as though the categories were mutually exclusive.
  • Tag-to-question matching depends on the database schema and how a Moodle installation stores question tags. Verify compatibility of ti.itemtype = 'question' and ti.itemid = q.id with the Moodle version.
  • The fraction >= 1 threshold represents full credit in the selected grading step, not necessarily passing or demonstrating mastery of the topic.
  • There is no reporting-period, account-status, or course-visibility filter. The 500 most frequent groups may hide less frequently used tags.
  • Comparisons between tags may be affected by differences in question counts, difficulty, question types, and attempt policies.

The SQL was reproduced verbatim from the original JSON in master and was not executed on Moodle during this documentation work. Before institutional use, verify database compatibility, interpretation of the results, and access permissions.
