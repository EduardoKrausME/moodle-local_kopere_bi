REPORT 104

Student registrations by month

Counts accounts identified as students by the month the accounts were created, split into current active, suspended, and deleted statuses.

Report purpose

Counts accounts identified as students by the month the accounts were created, split into current active, suspended, and deleted statuses.

Why use this report?

Helps track changes in the number of accounts assigned the student role and examine their current administrative statuses by registration month.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for course, user, cohort, or reporting period, and no predefined range of months. The query groups the complete available account-creation history.

The only explicit condition in the outer query's WHERE clause is username <> 'guest'. The subquery requires an assignment of the student role in a course context. Suspended and deleted accounts are not excluded because they are needed for the status breakdown.

Visualization and full original SQL

One table visualization contains two equivalent complete original SQL queries, MySQL and PostgreSQL, grouped in the same block. Prism.js highlights the syntax without changing the SQL.

1. Student registrations by month · Table

One row per month in YYYY-MM format, with a total of distinct student accounts and counts of accounts currently active, suspended, or deleted, ordered by month descending.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT DATE_FORMAT(FROM_UNIXTIME(kbi_u.timecreated), '%Y-%m') AS id,
       DATE_FORMAT(FROM_UNIXTIME(kbi_u.timecreated), '%Y-%m') AS period_month,
       COUNT(DISTINCT kbi_u.id) AS student_count,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 0 THEN 1 ELSE 0 END) AS active_students,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 1 THEN 1 ELSE 0 END) AS suspended_students,
       SUM(CASE WHEN kbi_u.deleted = 1 THEN 1 ELSE 0 END) AS deleted_students
FROM mdl_user kbi_u
       JOIN (
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
             WHERE kbi_r.shortname = 'student'
       ) kbi_students ON kbi_students.userid = kbi_u.id
WHERE kbi_u.username <> 'guest'
GROUP BY period_month
ORDER BY period_month DESC

Full original PostgreSQL SQL

SELECT TO_CHAR(TO_TIMESTAMP(kbi_u.timecreated), 'YYYY-MM') AS id,
       TO_CHAR(TO_TIMESTAMP(kbi_u.timecreated), 'YYYY-MM') AS period_month,
       COUNT(DISTINCT kbi_u.id) AS student_count,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 0 THEN 1 ELSE 0 END) AS active_students,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 1 THEN 1 ELSE 0 END) AS suspended_students,
       SUM(CASE WHEN kbi_u.deleted = 1 THEN 1 ELSE 0 END) AS deleted_students
FROM mdl_user kbi_u
       JOIN(
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
             WHERE kbi_r.shortname = 'student'
       ) kbi_students ON kbi_students.userid = kbi_u.id
WHERE kbi_u.username <> 'guest'
GROUP BY period_month
ORDER BY period_month DESC

Calculation criteria and behavior

The reference date is mdl_user.timecreated. The query selects users assigned a role with short name student in at least one course context (contextlevel = 50). The subquery uses DISTINCT userid to avoid duplicates for users assigned the role in multiple courses.

MySQL formats months using DATE_FORMAT(FROM_UNIXTIME(...), '%Y-%m'), while PostgreSQL uses TO_CHAR(TO_TIMESTAMP(...), 'YYYY-MM'). The active_students, suspended_students, and deleted_students fields are calculated from the account's current status.

Limitations and cautions

  • The month represents when the Moodle account was created, not when the user enrolled in a course or was assigned the student role.
  • Active, suspended, and deleted categories reflect the accounts' current statuses. The report does not reconstruct their historical status in the indicated month.
  • The query includes only users who still have a student role assignment in a course context. Accounts that no longer have the role may be absent.
  • There is no dynamic breakdown by course, enrolment method, or reporting period. A person with multiple accounts may be counted as multiple registrations.
  • Timestamp-to-month conversions can depend on the database connection's time zone. Check records near a month boundary for possible differences.

The SQL is reproduced verbatim from the JSON definitions in master and has not been executed on a Moodle installation during this documentation work. Check compatibility, results, permissions, and privacy before institutional use.
