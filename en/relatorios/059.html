REPORT 059

Simplified activity status overview

Compact overview of grades, completion states, and dates for visible modules by enrolled user in the selected course.

Report purpose

Compact overview of grades, completion states, and dates for visible modules by enrolled user in the selected course.

Why use this report?

Helps monitor recorded performance and activity completion without exposing the expanded personal profile information shown in the detailed report.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, through :courseid, used once in each variant in kbi_cm.course = :courseid.

Fixed criteria include a visible course and module, and users who are neither deleted nor suspended and are not guest. The query requires a grade item of type course but does not filter enrolment status, validity dates, or user role.

Visualization and full original SQL

One table visualization includes full MySQL and PostgreSQL variants in separate panels within the same block, with Prism.js syntax highlighting.

1. Simplified activity status overview · Table

One row per enrolled participant and visible module, with name and email, course, grade-item type and name, module addition date, grade modification date, activity and course grades, maximum grade, completion configuration and state, aggregated enrolment status and end date, and activity completion record update date.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT ue.userid,
       kbi_u.email,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.fullname,
       kbi_g.timemodified                                        as graduated,
       kbi_cm.added                                              as created,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0)                   AS grade,
       ROUND((CASE
                WHEN kbi_g_c.rawgrademax > 0 THEN (kbi_g_c.finalgrade / kbi_g_c.rawgrademax) * 100
                ELSE kbi_g_c.finalgrade END), 0)                 AS grade_course,
       kbi_gi.gradepass,
       kbi_g.rawgrademax,
       kbi_g.finalgrade,
       kbi_cm.completion,
       kbi_cmc.completionstate,
       kbi_m.name                                                AS module_name,
       kbi_gi.itemname,
       ue.status                                             AS enrol_status,
       ue.timeend,
       CASE
         WHEN ue.id > 0 AND kbi_cmc.completionstate IN (1, 2)
                 THEN kbi_cmc.timemodified
         ELSE NULL END                                       AS completed_date
FROM (SELECT MAX(kbi_ue.id) AS id, MIN(kbi_ue.status) AS status, MAX(kbi_ue.timeend) AS timeend, kbi_ue.userid, kbi_e.courseid
      FROM mdl_user_enrolments kbi_ue
             JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
      GROUP BY kbi_e.courseid, kbi_ue.userid) ue
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = ue.courseid
       JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       JOIN mdl_user kbi_u ON kbi_u.id = ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = ue.courseid
       JOIN mdl_grade_items kbi_gi_c ON kbi_gi_c.itemtype = 'course' AND kbi_gi_c.courseid = ue.courseid
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemtype = 'mod' AND kbi_gi.iteminstance = kbi_cm.instance AND kbi_gi.itemmodule = kbi_m.name
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = ue.userid
       LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.userid = ue.userid
       LEFT JOIN mdl_grade_grades kbi_g_c ON kbi_g_c.itemid = kbi_gi_c.id AND kbi_g_c.userid = ue.userid
WHERE ue.id > 0
  AND kbi_cm.course = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • The query includes users with course enrolment records even if some enrolments are inactive. The enrol_status and timeend values come from independent aggregates (MIN(status) and MAX(timeend)), which need not describe the same enrolment.
  • Because the query uses JOIN mdl_grade_items for a course-type grade item, courses without such an item may be excluded.
  • The completed_date field returns mdl_course_modules_completion.timemodified when the state is 1 or 2. This is the record's modification date, not necessarily the first date the activity was completed.
  • The graduated column means the last grade modification, not issuance of a diploma or formal course completion.
  • The grade and grade_course calculations may represent percentages when the maximum grade is positive or raw grade values otherwise; interpret the figures according to the grading scale.
  • Visible modules appear even without an activity grade, because joining the module grade item is optional.
  • The SQL does not filter for the student role or a date range. Displaying identifiable data and grades requires appropriate permissions.
  • MySQL and PostgreSQL variants serve the same purpose but use different rounding expressions.
