REPORT 105

Student profile distribution

Groups accounts assigned the student role by country, city, institution, and department recorded in their profiles, including totals and account statuses.

Report purpose

Groups accounts assigned the student role by country, city, institution, and department recorded in their profiles, including totals and account statuses.

Why use this report?

Helps examine students' self-reported geographic and institutional distribution, identify missing profile information, and estimate the numbers of active and suspended accounts.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for course, user, cohort, country, city, institution, department, or reporting period. The only fixed restriction in the WHERE clause excludes the account with username = 'guest'.

Active and suspended statuses are counted in separate columns. Deleted accounts are still included in student_count, but not in either status count.

Visualization and full original SQL

One table visualization includes two equivalent complete original SQL queries, MySQL and PostgreSQL, grouped in the same block. Prism.js highlights the syntax without modifying the SQL.

1. Student profile distribution · Table

The table groups profiles by country, city, institution, and department, with the total number of distinct accounts and separate counts for active and suspended accounts. Groups are ordered from largest to smallest.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT CONCAT(COALESCE(NULLIF(TRIM(kbi_u.country), ''), 'not-informed'), '-',
              COALESCE(NULLIF(TRIM(kbi_u.city), ''), 'not-informed'), '-',
              COALESCE(NULLIF(TRIM(kbi_u.institution), ''), 'not-informed'), '-',
              COALESCE(NULLIF(TRIM(kbi_u.department), ''), 'not-informed')) AS id,
       COALESCE(NULLIF(TRIM(kbi_u.country), ''), 'Not informed') AS country,
       COALESCE(NULLIF(TRIM(kbi_u.city), ''), 'Not informed') AS city,
       COALESCE(NULLIF(TRIM(kbi_u.institution), ''), 'Not informed') AS institution,
       COALESCE(NULLIF(TRIM(kbi_u.department), ''), 'Not informed') AS department,
       COUNT(DISTINCT kbi_u.id) AS student_count,
       SUM(CASE WHEN kbi_u.suspended = 0 AND kbi_u.deleted = 0 THEN 1 ELSE 0 END) AS active_students,
       SUM(CASE WHEN kbi_u.suspended = 1 AND kbi_u.deleted = 0 THEN 1 ELSE 0 END) AS suspended_students
FROM mdl_user kbi_u
       JOIN (
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
             WHERE kbi_r.shortname = 'student'
       ) kbi_students ON kbi_students.userid = kbi_u.id
WHERE kbi_u.username <> 'guest'
GROUP BY country, city, institution, department
ORDER BY student_count DESC, country, city, institution, department

              COALESCE(NULLIF(TRIM(kbi_u.city), ''), 'not-informed'), '-',
              COALESCE(NULLIF(TRIM(kbi_u.institution), ''), 'not-informed'), '-',
              COALESCE(NULLIF(TRIM(kbi_u.department), ''), 'not-informed')) AS id,

       COALESCE(NULLIF(TRIM(kbi_u.institution), ''), 'Not informed') AS institution,

       JOIN(
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid

Calculation criteria and behavior

The report includes users assigned the student role in any course context and excludes only the guest account. The student list is deduplicated by user before aggregation.

Country, city, institution, and department values are normalized using TRIM, NULLIF, and COALESCE. Empty or NULL values appear as Not informed. Totals use COUNT(DISTINCT id), while active and suspended counts use SUM(CASE ...).

Limitations and cautions

  • Country, city, institution, and department are values provided in user profiles, not IP-based geolocation or verified addresses.
  • Missing values appear as Not informed. Different spellings of city or institution names may create separate groups.
  • The student total includes deleted accounts that still have the relevant role assignment, so it may exceed the sum of active and suspended accounts.
  • The student role may be assigned in any course. The report does not identify the courses in which each group is enrolled or offer course selection.
  • Publishing small groups can expose information about individuals in specific contexts. Consider minimum group sizes and access restrictions before sharing or exporting.

The SQL is reproduced verbatim from JSON definitions in master and has not been executed on a Moodle installation during this documentation work. Verify compatibility, results, permissions, and privacy before institutional use.
