REPORT 069

Quiz progress by course

Summarizes how many distinct quizzes have recorded attempts and how many distinct attempts exist in the selected course.

Report purpose

Summarizes how many distinct quizzes have recorded attempts and how many distinct attempts exist in the selected course.

Why use this report?

Provides a concise overview of attempt volumes by course as a starting point for comparing quiz coverage and investigating assessment activity.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, implemented by :courseid and used once in the WHERE clause.

The fixed condition requires kbi_c.visible = 1. The query starts from recorded attempts and joins quizzes and courses. There are no filters for student, status, module visibility, cohort, or time period.

Visualization and full original SQL

One table visualization contains the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL definition for this report.

1. Quiz progress by course · Table

The table shows the course ID and full name, the total number of distinct quizzes with attempts in submitted, and the total number of distinct attempts in attempted.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       COUNT(DISTINCT kbi_qa.quiz) AS submitted,
       COUNT(DISTINCT kbi_qa.id)   AS attempted
FROM mdl_quiz_attempts kbi_qa
       JOIN mdl_quiz kbi_q ON kbi_q.id = kbi_qa.quiz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_q.course
WHERE kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id, kbi_c.fullname
ORDER BY kbi_c.fullname

Limitations and cautions

  • Despite the word 'progress' in the title, these metrics do not measure completion, achievement, scores, or curricular progress. They only count quizzes and attempts.
  • The submitted field counts distinct quizzes with at least one attempt, not attempts that were formally submitted or completed.
  • The attempted count includes all distinct attempt IDs without distinguishing previews, completion states, teachers, and students.
  • The query starts from mdl_quiz_attempts. Courses without attempts do not produce a row even if quizzes are configured.
  • There is no verification of active enrolments, suspended or deleted users, or visibility of the individual quiz module.
  • There is no time window, normalization by student count, or comparison with the total number of configured quizzes. Consider these differences when comparing courses.
  • No separate PostgreSQL variant is provided in the original catalog.
