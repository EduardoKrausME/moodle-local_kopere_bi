REPORT 029

Teacher engagement ratio

Operational indicators by teacher and course, including enrolments, assignments, grading, forums, events, and module counts.

Report purpose

Operational indicators by teacher and course, including enrolments, assignments, grading, forums, events, and module counts.

Why use this report?

Combines different signals of platform usage in one view to identify courses that may need attention and indicators warranting administrative or educational investigation.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, user, teacher, cohort, or date range. The query includes teachers assigned role ID 3 in level 50 course contexts, visible courses, and valid accounts.

The needs_grading indicator uses a fixed 30-day window (2592000 seconds) for recent submitted submissions with latest = 1 and no valid grade. Other indicators do not necessarily share that time window.

Visualization and full original SQL

The report contains one table visualization and two SQL queries, with cache, refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL variants appear in separate panels within the same visualization block.

1. Teacher engagement ratio · Table

The table shows teacher and course data, users assigned the student role, assignment counts, recently ungraded submissions, average time between submission and grading, Kopere BI tracking measures, forum discussions and posts, event counts, and course module counts. MySQL and PostgreSQL use different expressions for the submission time window.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ra.id,
       kbi_c.id                                                               AS courseid,
       kbi_c.fullname                                                         AS course_name,
       kbi_c.timecreated                                                      AS course_created,
       kbi_u.id                                                               AS teacher_id,
       kbi_u.lastname,
       kbi_u.firstname,
       kbi_u.email,
       kbi_u.picture                                                          AS teacher_picture,
       kbi_u.firstnamephonetic                                                AS teacher_firstnamephonetic,
       kbi_u.lastnamephonetic                                                 AS teacher_lastnamephonetic,
       kbi_u.middlename                                                       AS teacher_middlename,
       kbi_u.alternatename                                                    AS teacher_alternatename,
       kbi_u.imagealt                                                         AS teacher_imagealt,
       (SELECT COUNT(distinct kbi_ras.userid)
        FROM mdl_role_assignments kbi_ras, mdl_context kbi_con
        WHERE kbi_con.id = kbi_ras.contextid
          AND kbi_con.contextlevel = 50
          AND kbi_ras.roleid = 5
          AND kbi_con.instanceid = kbi_c.id)                                      AS enrolled_students,
       (SELECT COUNT(kbi_ass.id) FROM mdl_assign kbi_ass WHERE kbi_ass.course = kbi_c.id) AS assignments,
       (SELECT COUNT(DISTINCT kbi_sub.id)
        FROM mdl_assign_submission kbi_sub
               LEFT JOIN mdl_assign_grades kbi_as_grade
                 ON kbi_as_grade.userid = kbi_sub.userid AND kbi_as_grade.assignment = kbi_sub.assignment AND
                    kbi_as_grade.attemptnumber = kbi_sub.attemptnumber
               JOIN mdl_assign kbi_ass ON kbi_ass.id = kbi_sub.assignment
        WHERE kbi_sub.status = 'submitted'
          AND kbi_sub.latest = 1
          AND kbi_sub.timecreated > (UNIX_TIMESTAMP() - 2592000)
          AND (kbi_as_grade.grade IS NULL OR kbi_as_grade.grade < 0)
          AND kbi_ass.course = kbi_c.id)                                          AS needs_grading,
       (SELECT AVG(kbi_as_grade.timecreated - kbi_sub.timecreated)
        FROM mdl_assign_submission kbi_sub
               LEFT JOIN mdl_assign_grades kbi_as_grade
                 ON kbi_as_grade.userid = kbi_sub.userid AND kbi_as_grade.assignment = kbi_sub.assignment AND
                    kbi_as_grade.attemptnumber = kbi_sub.attemptnumber
               JOIN mdl_assign kbi_ass ON kbi_ass.id = kbi_sub.assignment
        WHERE kbi_sub.status = 'submitted'
          AND kbi_sub.latest = 1
          AND kbi_as_grade.grade IS NOT NULL
          AND kbi_as_grade.grade >= 0
          AND kbi_ass.course = kbi_c.id)                                          AS avg_time_to_grade,
       (SELECT SUM(kbi_lil.visits) / COUNT(DISTINCT timepoint)
        FROM mdl_local_kopere_bi_tracking kbi_lit, mdl_local_kopere_bi_track_log kbi_lil
        WHERE kbi_lil.trackid = kbi_lit.id
          AND kbi_lit.courseid = kbi_c.id)                                        AS logins_by_teacher,
       (SELECT COUNT(DISTINCT kbi_fd.id)
        FROM mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
        WHERE kbi_fp.discussion = kbi_fd.id
          AND kbi_fd.course = kbi_c.id)                                           AS teacher_discussions,
       (SELECT COUNT(DISTINCT kbi_fp.id)
        FROM mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
        WHERE kbi_fp.discussion = kbi_fd.id
          AND kbi_fd.course = kbi_c.id)                                           AS teacher_posts,
       (SELECT COUNT(DISTINCT kbi_fp.id)
        FROM mdl_role_assignments kbi_ras, mdl_context kbi_con, mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
        WHERE kbi_con.id = kbi_ras.contextid
          AND kbi_ras.roleid = 5
          AND kbi_con.contextlevel = 50
          AND kbi_fp.discussion = kbi_fd.id
          AND kbi_fd.course = kbi_con.instanceid
          AND kbi_con.instanceid = kbi_c.id)                                      AS students_posts,
       (SELECT COUNT(distinct id) FROM mdl_event WHERE userid = kbi_u.id)     AS teacher_events,
       (SELECT COUNT(distinct kbi_e.id)
        FROM mdl_event kbi_e, mdl_role_assignments kbi_ras, mdl_context kbi_con
        WHERE kbi_ras.userid = kbi_e.userid
          AND kbi_ras.roleid = 5
          AND kbi_con.id = kbi_ras.contextid
          AND kbi_con.contextlevel = 50
          AND kbi_e.courseid = kbi_con.instanceid
          AND kbi_con.instanceid = kbi_c.id)                                      AS students_events,
       (SELECT COUNT(id) FROM mdl_course_modules WHERE course = kbi_c.id)     AS added_course_module
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
WHERE kbi_ra.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 3

Limitations and cautions

  • Despite its title, the report does not calculate a single engagement index or percentage. It shows different indicators without a shared ratio formula.
  • The teacher_discussions and teacher_posts fields count discussions and posts by all participants in course forums. The SQL does not match the author to the teacher's ID.
  • The students_posts field does not link individual post authors to students. Its join tests for role ID 5 assignments in the course, so the count may not exclusively represent student posts.
  • The logins_by_teacher expression sums course visits and divides by COUNT(DISTINCT timepoint), but does not restrict the subquery to that teacher's ID. It therefore does not necessarily measure that teacher's logins. A zero denominator may produce NULL or an error depending on the database.
  • The 30-day window applies only to needs_grading. Average grading time is the difference between timestamps, with neither the same time limit nor an explicit exclusion of negative values.
  • The teacher_events and students_events fields query mdl_event rather than the usual recorded event log mdl_logstore_standard_log; their interpretation and usefulness depend on the Moodle installation and available data.
  • The enrolled-student indicator counts users assigned role ID 5 in the course context without directly checking enrolment or enrolment-method status.
  • MySQL and PostgreSQL versions use database-specific time operations. Interpret results with attention to differences between queries and compatibility with the installation.
