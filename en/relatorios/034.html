REPORT 034

Teacher and student engagement by course

Table of teachers and courses with student, event, forum post, module, and activity counts, plus a ratio calculated from recorded visits.

Report purpose

Table of teachers and courses with student, event, forum post, module, and activity counts, plus a ratio calculated from recorded visits.

Why use this report?

Combines course configuration and student participation indicators to help coordinators identify follow-up needs, review activity provision, and inform preliminary educational assessments.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, teacher, student, cohort, or date range. The report includes visible courses with teachers assigned role ID 3 in the course context (contextlevel = 50) and accounts that are neither deleted nor suspended and are not guest.

Students are identified through role ID 5 assignments in course contexts, while visible modules are counted using kbi_cm.visible = 1. The posts-per-day ratio uses the number of days since kbi_c.timecreated, without a configurable date filter.

Visualization and full original SQL

One table visualization contains two complete SQL queries, cache settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL variants appear in separate panels of the same visualization.

1. Teacher and student engagement by course · Table

The table has a row for each teacher role assignment within a course, showing the teacher, course name and dates, student role count, event count, calculated posts per day, visit ratio, visible modules, module completion records, and numbers of assignments, quizzes, and workshops.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ra.id,
       kbi_c.id                                                                           AS courseid,
       kbi_c.fullname                                                                     AS course_name,
       kbi_c.timecreated                                                                  AS course_created,
       kbi_c.startdate,
       kbi_u.id                                                                           AS teacher_id,
       kbi_u.lastname,
       kbi_u.firstname,
       (SELECT COUNT(distinct kbi_ras.userid)
        FROM mdl_role_assignments kbi_ras, mdl_context kbi_con
        WHERE kbi_con.id = kbi_ras.contextid
          AND kbi_con.contextlevel = 50
          AND kbi_ras.roleid = 5
          AND kbi_con.instanceid = kbi_c.id)                                                  AS learners,
       (SELECT COUNT(distinct kbi_e.id)
        FROM mdl_event kbi_e, mdl_role_assignments kbi_ras, mdl_context kbi_con
        WHERE kbi_ras.userid = kbi_e.userid
          AND kbi_ras.roleid = 5
          AND kbi_con.id = kbi_ras.contextid
          AND kbi_con.contextlevel = 50
          AND kbi_e.courseid = kbi_con.instanceid
          AND kbi_con.instanceid = kbi_c.id)                                                  AS events,
       (SELECT CASE
                 WHEN (TO_DAYS(NOW()) - TO_DAYS(FROM_UNIXTIME(kbi_c.timecreated))) > 0 THEN (COUNT(DISTINCT kbi_fp.id) /
                                                                                         (TO_DAYS(NOW()) - TO_DAYS(FROM_UNIXTIME(kbi_c.timecreated))))
                 ELSE 0 END
        FROM mdl_role_assignments kbi_ras, mdl_context kbi_con, mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
        WHERE kbi_con.id = kbi_ras.contextid
          AND kbi_ras.roleid = 5
          AND kbi_con.contextlevel = 50
          AND kbi_fd.course = kbi_con.instanceid
          AND kbi_fp.userid = kbi_ras.userid
          AND kbi_fp.discussion = kbi_fd.id
          AND kbi_con.instanceid = kbi_c.id)                                                  AS post_per_day,
       (SELECT CASE
                 WHEN COUNT(DISTINCT timepoint) > 0 THEN (SUM(kbi_lil.visits) / COUNT(DISTINCT timepoint))
                 ELSE 0 END
        FROM mdl_role_assignments kbi_ras, mdl_context kbi_con, mdl_local_kopere_bi_tracking kbi_lit, mdl_local_kopere_bi_track_log kbi_lil
        WHERE kbi_con.id = kbi_ras.contextid
          AND kbi_ras.roleid = 5
          AND kbi_con.contextlevel = 50
          AND kbi_con.instanceid = kbi_lit.courseid
          AND kbi_ras.userid = kbi_lit.userid
          AND kbi_lil.trackid = kbi_lit.id
          AND kbi_con.instanceid = kbi_c.id)                                                  AS visits,
       (SELECT COUNT(DISTINCT kbi_cm.id) FROM mdl_course_modules kbi_cm WHERE kbi_cm.course = kbi_c.id
                                                                  AND kbi_cm.visible = 1) AS modules,
       (SELECT COUNT(DISTINCT kbi_cmc.id)
        FROM mdl_course_modules kbi_cm
               LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id AND
                                                              kbi_cmc.completionstate IN
                                                              (1, 2) AND
                                                              kbi_cm.visible = 1
        WHERE kbi_cm.course = kbi_c.id)                                                       AS completed_modules,
       (SELECT COUNT(id) FROM mdl_assign WHERE course = kbi_c.id)                         AS assignment,
       (SELECT COUNT(id) FROM mdl_quiz WHERE course = kbi_c.id)                           AS quiz,
       (SELECT COUNT(id) FROM mdl_workshop WHERE course = kbi_c.id)                       AS workshop
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
WHERE kbi_ra.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 3
ORDER BY kbi_c.fullname asc

Limitations and cautions

  • The table is displayed by teacher assignment, but student, post, visit, and module metrics are calculated for the entire course. Teachers in the same course may therefore show identical values.
  • The events field queries mdl_event for users assigned the student role; these are not necessarily events from Moodle's standard event log. Verify the presence and meaning of this data in the installation.
  • The post_per_day indicator divides posts attributed to students by days since the course was created, not since its start date. It does not represent a daily average over a defined teaching period.
  • The visits column uses SUM(visits) / COUNT(DISTINCT timepoint) in Kopere BI logs. This is a technical ratio rather than a raw access count or a teacher-specific measure.
  • The completed_modules field counts activity completion records in states 1 and 2, not distinct completed modules. The same activity may contribute multiple student completion records.
  • Assignment, quiz, and workshop totals are counted from their activity tables without explicitly filtering the visibility of each individual instance.
  • Teacher and student identification depends on fixed role IDs 3 and 5, which may differ on sites with customized institutional roles. MySQL and PostgreSQL use database-specific date functions.
