REPORT 121

Grade change history

Grade history showing previous grades, calculated changes, and the user recorded as making a change where records have been retained.

Report purpose

Historical table by grade-change event, showing course, student, grade item, action, grade in the current history record, previous recorded grade, difference, normalized item percentage, recorded editor, and modification date. Results prioritize the 500 most recent events.

Why use this report?

Support academic audits and enquiries about grade changes by examining earlier values, calculated differences, and the recorded editor when that information is available.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for course, student, grade item, editor, or reporting period. The only fixed scope condition is c.id > 1, excluding Moodle's special course with ID 1. There is no date window or explicit restriction for course visibility or account status.

Records are ordered by h.timemodified DESC, h.id DESC with LIMIT 500. This selects the 500 most recent history entries overall, not changes within a chosen course.

Visualization and full original SQL

This report contains one table visualization with full original SQL, cache, and refresh settings. Prism.js provides syntax highlighting. No separate PostgreSQL variant was found in master, so none has been invented.

1. Grade change history · Table

The historical table displays each grade-change event, including course, student, grade item, action, current and previous history values, delta, normalized percentage, recorded editor, and change date. It prioritizes the 500 latest records.

Cache: 1h · Refresh: none.

Full original SQL

SELECT h.id, c.id AS courseid, c.fullname AS course, h.userid, u.firstname, u.lastname,
       gi.itemname, h.action, h.finalgrade, previous.finalgrade AS previous_grade,
       CASE WHEN h.finalgrade IS NOT NULL AND previous.finalgrade IS NOT NULL
            THEN ROUND(h.finalgrade - previous.finalgrade, 2) ELSE NULL END AS grade_delta,
       h.loggeduser AS changed_by_userid, editor.firstname AS editor_firstname, editor.lastname AS editor_lastname,
       CASE WHEN gi.grademax > gi.grademin AND h.finalgrade IS NOT NULL
            THEN ROUND(100.0 * (h.finalgrade - gi.grademin) / (gi.grademax - gi.grademin), 2)
            ELSE NULL END AS grade_percent,
       h.timemodified AS changed_at
  FROM mdl_grade_grades_history h
  JOIN mdl_grade_items gi ON gi.id = h.itemid
  JOIN mdl_course c ON c.id = gi.courseid
  JOIN mdl_user u ON u.id = h.userid
  LEFT JOIN mdl_grade_grades_history previous ON previous.id = (
       SELECT MAX(ph.id) FROM mdl_grade_grades_history ph
        WHERE ph.oldid = h.oldid AND ph.id < h.id
          AND ph.itemid = h.itemid AND ph.userid = h.userid)
  LEFT JOIN mdl_user editor ON editor.id = h.loggeduser
 WHERE c.id > 1
 ORDER BY h.timemodified DESC, h.id DESC
 LIMIT 500

Calculation criteria and behavior

The query reads mdl_grade_grades_history, joining the grade item (mdl_grade_items), course, and student account. It finds an earlier grade in the same history table using the greatest preceding MAX(ph.id) for the same oldid, grade item, and user.

grade_delta is calculated as ROUND(h.finalgrade - previous.finalgrade, 2) when both values exist; otherwise it is NULL. grade_percent scales the value to the item's range, using (finalgrade - grademin) / (grademax - grademin) multiplied by 100 only for a positive range. The editor is looked up through an optional join using h.loggeduser.

Limitations and cautions

  • The history includes only records actually preserved in mdl_grade_grades_history; missing or deleted history entries cannot be reconstructed.
  • The previous grade is selected by the greatest earlier history ID with matching identifiers. This assumes ID ordering correctly represents the sequence of relevant events.
  • History events can represent insertions, updates, or deletions. Changing another field does not necessarily mean the numerical grade changed.
  • The grade difference and normalized percentage may be NULL if the previous grade, current grade, or a valid minimum-to-maximum range is missing.
  • The recorded editor in loggeduser may be absent; this field alone is not sufficient to attribute responsibility conclusively for an academic change.
  • The query does not restrict deleted users, periods, categories, or items, and returns only 500 records. It is not a complete historical audit.
  • Grades and related fields are personal academic data. Restrict access, exports, and disclosure to authorized users.

The SQL is reproduced verbatim from the original JSON in master and was not executed on Moodle during this documentation work. Before institutional use, check database compatibility, accuracy of interpretation, and access permissions.
