REPORT 010

Cohort success and progress

Table of students enrolled in the selected course, including grades, completion data, completed modules, associated teachers, and access tracking information.

Report purpose

Table of students enrolled in the selected course, including grades, completion data, completed modules, associated teachers, and access tracking information.

Why use this report?

Helps academic managers track students' progress within a course, comparing grades, completion, and tracking data. Although the title mentions cohorts, this version of the query does not perform an actual cohort-based analysis.

Actual filters Visualizations and SQL Limitations

Available filters

The only dynamic SQL filter is :courseid, used twice in each query variant: in the subquery on the mdl_local_kopere_bi_tracking tracking table and when selecting course enrolments. The parameter is linked to course selection in Kopere BI, subject to the filters available in the installation.

Fixed criteria require active enrolments and enrolment methods (kbi_ue.status = 0 and kbi_e.status = 0), visible courses, users who are neither deleted nor suspended, and exclusion of the guest account. There are no user, cohort, or date-range SQL parameters.

Visualizations and full SQL

This report provides one table visualization and two equivalent SQL queries, with cache and refresh settings. Full MySQL and PostgreSQL SQL statements are shown in separate panels within the same block, with Prism.js syntax highlighting.

1. Cohort success and progress · Table

Detailed table showing enrolment, start date, percentage grade, passing status, completion, course, student, teacher, and Kopere BI visit and tracked-time data.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ue.id                             AS id,
       kbi_cri.gradepass                     AS gradepass,
       kbi_ue.timecreated                    as started,
       ROUND((CASE
                WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                        THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                ELSE kbi_g.finalgrade END),
             0)                          AS grade,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END),
             0)                          AS grade_real,
       kbi_cc.timecompleted                  as complete,
       kbi_c.id                              as cid,
       kbi_c.fullname,
       kbi_e.enrol,
       kbi_u.email,
       kbi_u.id                              AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.enablecompletion,
       (SELECT COUNT(DISTINCT kbi_cmc.id)
        FROM mdl_course_modules_completion kbi_cmc, mdl_course_modules kbi_cm
        WHERE kbi_cm.visible = 1
          AND kbi_cmc.coursemoduleid = kbi_cm.id
          AND kbi_cmc.completionstate IN (1, 2)
          AND kbi_cm.completion > 0
          AND kbi_cm.course = kbi_c.id
          AND kbi_cmc.userid = kbi_u.id)         AS completed,
       (SELECT ROUND((CASE
                        WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                                THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                        ELSE kbi_g.finalgrade END), 0)
        FROM mdl_grade_items kbi_gi, mdl_grade_grades kbi_g
        WHERE kbi_gi.itemtype = 'course'
          AND kbi_g.itemid = kbi_gi.id
          AND kbi_g.finalgrade IS NOT NULL
          AND kbi_gi.courseid = kbi_c.id
        LIMIT 1)                         AS average,
       (SELECT GROUP_CONCAT(DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) SEPARATOR ', ')
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3) AS teacher,
       ''                                as cohortname,
       lit.timespend                     AS timespend,
       lit.visits                        AS visits
FROM mdl_user_enrolments kbi_ue
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       LEFT JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_ue.userid
       LEFT JOIN mdl_course_completion_criteria kbi_cri ON kbi_cri.course = kbi_e.courseid AND kbi_cri.criteriatype = 6
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_c.id AND kbi_gi.itemtype = 'course'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = kbi_u.id
       LEFT JOIN (SELECT userid, courseid, SUM(timespend) as timespend, SUM(visits) as visits
                  FROM mdl_local_kopere_bi_tracking
                  WHERE id > 0
                    AND courseid = :courseid
                  GROUP BY userid, courseid) lit ON lit.courseid = kbi_c.id AND lit.userid = kbi_u.id
WHERE kbi_ue.id > 0
  AND kbi_e.courseid = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0

Limitations and cautions

  • Despite the phrase 'by cohort' in the title, the query defines '' AS cohortname and does not join the cohort membership table. Thus the results contain neither a real cohort name nor a cohort filter.
  • Visit and tracked-time data depend on records from mdl_local_kopere_bi_tracking; missing values do not prove that no learning took place.
  • The reported average comes from a course-grade subquery with LIMIT 1, not from a statistical average calculated across all students. Interpret this field carefully.
  • A user's enrolment can appear in multiple rows depending on the grade items and completion criteria associated with the course. Do not equate row counts with distinct students.
  • The query exposes email addresses, grades, and individual performance. Ensure appropriate permissions and a privacy policy before sharing.
