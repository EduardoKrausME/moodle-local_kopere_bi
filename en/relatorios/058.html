REPORT 058

Activity status details

Detailed status of enrolled participants and visible course modules, including activity completion, grades, enrolment status, and user profile information.

Report purpose

Detailed status of enrolled participants and visible course modules, including activity completion, grades, enrolment status, and user profile information.

Why use this report?

Allows academic teams to review module completion and grade records, enrolment status, and identifying and contact information for users associated with the course in one table.

Available filters Visualization and SQL Limitations

Available filters

The dynamic filter is Course, bound to :courseid and used three times in each SQL statement: in the quiz attempt and assignment submission subqueries and in the main module selection.

Fixed criteria require a visible course and visible modules, users who are neither deleted nor suspended and are not guest. Users must have an enrolment record in the course, but the query does not explicitly restrict enrolment-method or enrolment status, user role, or enrolment validity. There are no dynamic participant, activity, or date filters.

Visualization and full original SQL

One table visualization includes full MySQL and PostgreSQL variants, displayed in separate panels within the same block. Prism.js provides syntax highlighting.

1. Activity status details · Table

One row per enrolled participant and visible module, including name, email, phone numbers, institution, department, address, location, course, module type and date added, grade modification date, activity and course grades, passing grade, completion configuration and state, activity tags, and aggregated enrolment status and end-date fields.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT ue.userid,
       kbi_u.email,
       kbi_u.phone1,
       kbi_u.phone2,
       kbi_u.institution,
       kbi_u.department,
       kbi_u.address,
       kbi_u.city,
       kbi_u.country,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.fullname,
       kbi_g.timemodified                        as graduated,
       kbi_cm.added                              as created,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0)   AS grade,
       ROUND((CASE
                WHEN kbi_g_c.rawgrademax > 0 THEN (kbi_g_c.finalgrade / kbi_g_c.rawgrademax) * 100
                ELSE kbi_g_c.finalgrade END), 0) AS grade_course,
       kbi_gi.gradepass,
       kbi_g.rawgrademax,
       kbi_g.finalgrade,
       kbi_cm.completion,
       kbi_cmc.completionstate,
       kbi_m.name                                AS module_name,
       ta.tags,
       ue.enrol_status,
       ue.timeend
FROM (SELECT MIN(kbi_ue1.id) AS id, kbi_ue1.userid, kbi_e1.courseid, MIN(kbi_ue1.status) AS enrol_status, MIN(kbi_ue1.timeend) AS timeend
      FROM mdl_user_enrolments kbi_ue1
             JOIN mdl_enrol kbi_e1 ON kbi_e1.id = kbi_ue1.enrolid
      GROUP BY kbi_ue1.userid, kbi_e1.courseid) ue
       JOIN mdl_user kbi_u ON kbi_u.id = ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = ue.courseid
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.instance > 0
       JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       LEFT JOIN mdl_grade_items kbi_gi
         ON kbi_gi.itemtype = 'mod' AND kbi_gi.iteminstance = kbi_cm.instance AND kbi_gi.itemmodule = kbi_m.name AND kbi_gi.gradetype = 1
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_qa.quiz,
                         kbi_qa.userid,
                         MAX(kbi_qa.attempt)      AS num_of_attempts,
                         MIN(kbi_qa.timemodified) AS first_completed_date
                  FROM mdl_quiz_attempts kbi_qa
                         JOIN mdl_quiz kbi_q ON kbi_q.id = kbi_qa.quiz AND kbi_q.course = :courseid
                  GROUP BY kbi_qa.quiz, kbi_qa.userid) qat ON qat.userid = kbi_u.id AND kbi_m.name = 'quiz' AND qat.quiz = kbi_cm.instance
       LEFT JOIN (SELECT kbi_asbm1.assignment,
                         kbi_asbm1.userid,
                         COUNT(*)                AS num_of_attempts,
                         MIN(kbi_asbm1.timemodified) AS first_completed_date
                  FROM mdl_assign_submission kbi_asbm1
                         JOIN mdl_assign kbi_a ON kbi_a.id = kbi_asbm1.assignment AND kbi_a.course = :courseid
                  GROUP BY kbi_asbm1.assignment, kbi_asbm1.userid) asbm
         ON asbm.userid = kbi_u.id AND kbi_m.name = 'assign' AND asbm.assignment = kbi_cm.instance
       LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_i.itemid, GROUP_CONCAT(DISTINCT kbi_t.rawname) AS tags
                  FROM mdl_tag_instance kbi_i, mdl_tag kbi_t
                  WHERE kbi_t.id = kbi_i.tagid
                    AND kbi_i.itemtype = 'course_modules'
                  GROUP BY kbi_i.itemid) ta ON ta.itemid = kbi_cm.id
       LEFT JOIN mdl_grade_items kbi_gi_c ON kbi_gi_c.itemtype = 'course' AND kbi_gi_c.courseid = kbi_c.id
       LEFT JOIN mdl_grade_grades kbi_g_c ON kbi_g_c.itemid = kbi_gi_c.id AND kbi_g_c.userid = kbi_u.id
WHERE ue.id > 0
  AND kbi_cm.course = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • The table includes users with an enrolment record, not only students with active enrolments. The SQL aggregates MIN(status) and MIN(timeend) across a user's enrolments in the same course; these fields do not necessarily describe one particular enrolment.
  • Personal information includes telephone numbers, addresses, institution, department, city, and country, as well as names and email addresses. Require appropriate permissions and protect exports.
  • The graduated field is the modification date of the activity grade record, while created is when the module was added to the course, not when the activity was completed.
  • The grade and grade_course values divide the final grade by rawgrademax when positive; otherwise, they use the raw final value. They are not always comparable percentages.
  • The quiz attempt and assignment submission subqueries compute attempt details and start dates, but those fields are not projected in the final SELECT. They therefore do not appear as table columns.
  • The completion setting and completionstate represent the module and user, not formal course completion.
  • Grade-item and tag joins are optional; missing values do not automatically imply failure or absence of access.
  • MySQL and PostgreSQL use different tag-concatenation and rounding functions. The query does not restrict history to a date range.
