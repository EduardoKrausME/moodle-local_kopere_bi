REPORT 094

File usage by teacher

Summarizes file resources in the selected course, linked filenames and technical references, and one teacher name obtained from course role assignments.

Report purpose

Summarizes file resources in the selected course, linked filenames and technical references, and one teacher name obtained from course role assignments.

Why use this report?

Helps locate File resources within a course, inspect their associated filenames and technical references, and identify one user assigned the conventional teacher role.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in each variant in kbi_c.id = :courseid.

Fixed conditions require a positive course ID and a visible course (kbi_c.visible = 1). The file join uses component = 'mod_resource', filearea = 'content', itemid = 0, and filesize > 0 in a module context (contextlevel = 70). The teacher lookup uses role ID 3 in the course context (contextlevel = 50).

Visualization and full original SQL

One table visualization contains two complete original SQL queries, cache and refresh settings, and Prism.js syntax highlighting. Equivalent MySQL and PostgreSQL variants are shown in separate panels.

1. File usage by teacher · Table

The course-level table shows course ID and name, a resource count field, concatenated technical file paths and names, and the name of one user assigned role ID 3. Both SQL variants return the same columns.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_r.id)                                     as resources,
       GROUP_CONCAT(CASE
                      WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath,
                                                        kbi_f.filename)
                      ELSE NULL END SEPARATOR '[[,]]') AS files,
       GROUP_CONCAT(kbi_f.filename)                        AS files_sorting,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)                                       AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       LEFT JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

Full original PostgreSQL SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_r.id)                                     as resources,
       STRING_AGG((CASE
                      WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath,
                                                        kbi_f.filename)
                      ELSE NULL END)::text, '[[,]]') AS files,
       STRING_AGG((kbi_f.filename)::text, ',')                        AS files_sorting,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)                                       AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       LEFT JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

Limitations and cautions

  • The resources column uses COUNT(kbi_r.id), without DISTINCT. A resource with multiple files may be duplicated by the joins, inflating the count above the actual number of resources in the course.
  • Although its title suggests file usage by teacher, the SQL does not establish who uploaded, created, or accessed each file. The teacher is selected independently of the resource's origin, and there are no visit, download, or time-tracking metrics.
  • The teacher subquery uses SELECT DISTINCT ... LIMIT 1 without ORDER BY. When several people have role ID 3, the choice may be arbitrary; custom teacher roles with other IDs are not considered.
  • The files and files_sorting fields concatenate file paths and names as text, not evidence that files were read or downloaded. Joins may produce duplicate values.
  • MySQL uses GROUP_CONCAT while PostgreSQL uses STRING_AGG. Neither variant specifies an internal file ordering, and [[,]] is a technical separator in the path list.
  • File paths include the context, revision, filepath, and filename, but do not constitute public URLs or proof of permission to access content.
  • The query checks course visibility but does not require file modules to be visible. Hidden resources may affect results.
  • A row may exist even when a course has no file resources because of optional joins. No date or participant filters are available.
