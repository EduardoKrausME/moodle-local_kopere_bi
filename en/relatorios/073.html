REPORT 073

Replies to forum posts

Lists forum discussion posts across the platform, including direct reply counts and the date and author of the latest matching direct reply.

Report purpose

Lists forum discussion posts across the platform, including direct reply counts and the date and author of the latest matching direct reply.

Why use this report?

Helps monitoring and moderation teams review posts with interactions, their authors, and the latest reply associated with an original or intermediate post.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, forum, user, or date range. The query contains no :courseid and covers forums throughout the installation.

The only final fixed condition is kbi_u.id IS NOT NULL, requiring an existing user associated with the post. Direct reply counts use parent = kbi_fp.id; the latest-reply query finds the greatest created timestamp for each parent post.

Visualization and full original SQL

One table visualization includes one complete SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the source.

1. Replies to forum posts · Table

The table lists each forum post's course, forum, discussion, subject, author, and creation date, its number of direct replies, and the available latest direct reply's identifier, author name, and date.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.fullname                                                   AS course,
       kbi_f.name                                                       AS forum,
       kbi_fd.name                                                      AS discussion,
       kbi_fp.subject                                                   AS post,
       kbi_u.id                                                         AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_fp.created,
       (SELECT COUNT(id) FROM mdl_forum_posts WHERE parent = kbi_fp.id) as count_reply,
       last_reply.time                                              AS last_reply_time,
       last_reply.firstname                                         AS last_reply_firstname,
       last_reply.lastname                                          AS last_reply_lastname,
       last_reply.id                                                AS last_reply_userid
FROM mdl_forum kbi_f
       LEFT JOIN mdl_forum_discussions kbi_fd ON kbi_fd.forum = kbi_f.id
       LEFT JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_f.course
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_fp.userid
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = 'forum'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.course = kbi_c.id AND kbi_cm.instance = kbi_f.id
       LEFT JOIN (SELECT *
                  FROM (SELECT kbi_post.parent, kbi_post.created AS time, kbi_ur.firstname, kbi_ur.lastname, kbi_ur.id
                        FROM mdl_forum_posts kbi_post
                               JOIN mdl_user kbi_ur ON kbi_ur.id = kbi_post.userid
                               JOIN mdl_forum_discussions kbi_d ON kbi_d.id = kbi_post.discussion
                               JOIN mdl_forum kbi_f ON kbi_d.forum = kbi_f.id
                        WHERE kbi_ur.id > 0
                          AND CONCAT(kbi_post.parent, '-', kbi_post.created) IN(SELECT CONCAT(parent, '-', MAX(created))
                                                                        FROM mdl_forum_posts
                                                                        GROUP BY parent)
                        ORDER BY kbi_post.created DESC) p
                  GROUP BY p.parent, p.time, p.firstname, p.lastname, p.id) last_reply ON last_reply.parent = kbi_fp.id
WHERE kbi_u.id IS NOT NULL

Limitations and cautions

  • The report does not require the course, forum, or module to be visible and does not check the author's account status. Forums in hidden courses may be included; access control must be enforced in the interface.
  • The count_reply value counts only direct replies to a post, not the entire tree of descendant replies.
  • The latest-reply query uses the greatest Unix creation timestamp per parent without a stable ID tiebreaker. Tied timestamps may produce multiple rows for the same post.
  • Matching the latest reply concatenates the parent post ID and timestamp into a string. This strategy depends on the data representation and is not equivalent to joining by post identifiers.
  • Latest-reply details are NULL when no matching reply exists. Posts without a valid author are excluded by the final condition.
  • There are no date-range filters or metrics for reading, educational quality, grades, or time spent.
  • The report exposes names and interactions across different courses. Respect permissions and privacy requirements. No separate PostgreSQL definition is provided.
