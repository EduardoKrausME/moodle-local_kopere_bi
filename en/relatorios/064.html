REPORT 064

Quiz activity by student

Detailed quiz attempts by users with enrolment records in the selected course, including scores, calculated duration, attempt states, and completion indicators.

Report purpose

Detailed quiz attempts by users with enrolment records in the selected course, including scores, calculated duration, attempt states, and completion indicators.

Why use this report?

Helps teachers and coordinators investigate individual quiz attempts, compare each user's minimum and maximum calculated scores, and review associated dates and assessment states.

Available filters Visualization and SQL Limitations

Available filters

The dynamic filter is Course, linked to :courseid and used once in the main condition WHERE kbi_c.id = :courseid.

The query requires a non-deleted, non-suspended participant other than guest with an enrolment record for the course. It includes every attempt state, without preview = 0 or state = 'finished' restrictions, and does not require an active enrolment, visible course, visible module, or specific student role.

Visualization and full original SQL

One table visualization contains the complete original SQL, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL definition file is provided in the catalog.

1. Quiz activity by student · Table

The table has one row per recorded attempt, including attempt ID, course, quiz, user, attempt number, highest and lowest percentage scores aggregated by user and quiz, duration in seconds, enrolment status and end date, attempt state, latest finished attempt, calculated earliest completion date, raw attempt score, maximum mark, passing grade, and module completion record modification date.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_qa.id                        as quiz_attempt_id,
       kbi_c.fullname                   AS course_name,
       kbi_q.name                       AS quiz_name,
       kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_qa.attempt                   AS all_att,
       attm.highest_grade,
       attm.lowest_grade,
       kbi_qa.timefinish - kbi_qa.timestart AS timespend,
       ue.enrol_status              AS enrol_status,
       ue.timeend,
       kbi_qa.state                     AS completion_state,
       attm.latest_submission,
       kbi_q.sumgrades                  AS marksmax,
       kbi_q.grade                      AS grademax,
       kbi_qa.sumgrades                 AS finalgrade,
       attm.first_completed_date,
       kbi_gi.gradepass                 AS gradepass,
       kbi_cmc.timemodified             AS timemodified,
       kbi_u.deleted,
       kbi_u.suspended,
       kbi_u.username
FROM mdl_quiz_attempts kbi_qa
       JOIN (SELECT kbi_qa1.quiz,
                    kbi_qa1.userid,
                    COUNT(kbi_qa1.id)                                                        AS at_cont,
                    (MAX(kbi_qa1.sumgrades) / kbi_q1.sumgrades) * 100                            AS highest_grade,
                    (MIN(kbi_qa1.sumgrades) / kbi_q1.sumgrades) * 100                            AS lowest_grade,
                    MAX(CASE WHEN kbi_qa1.state = 'finished' THEN kbi_qa1.timefinish ELSE 0 END) AS latest_submission,
                    MIN(kbi_qa1.timefinish)                                                  AS first_completed_date
             FROM mdl_quiz_attempts kbi_qa1
                    JOIN mdl_quiz kbi_q1 ON kbi_q1.id = kbi_qa1.quiz
             GROUP BY kbi_qa1.quiz, kbi_qa1.userid, kbi_q1.sumgrades) attm ON attm.quiz = kbi_qa.quiz AND attm.userid = kbi_qa.userid
       JOIN mdl_quiz kbi_q ON kbi_q.id = kbi_qa.quiz
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_qa.userid
       JOIN (SELECT kbi_e.courseid, kbi_ue.userid, MIN(kbi_ue.status) AS enrol_status, MIN(kbi_ue.timeend) AS timeend
             FROM mdl_enrol kbi_e
                    JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
             GROUP BY kbi_e.courseid, kbi_ue.userid) ue ON ue.courseid = kbi_q.course AND ue.userid = kbi_u.id
       JOIN mdl_modules kbi_m ON kbi_m.name = 'quiz'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_q.course AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_q.id
       JOIN mdl_grade_items kbi_gi ON kbi_gi.itemmodule = 'quiz' AND kbi_gi.iteminstance = kbi_q.id
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_cm.course
       LEFT JOIN mdl_course_modules_completion kbi_cmc
         ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.completionstate IN (1, 2) AND
            kbi_cmc.userid = kbi_qa.userid
WHERE kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'

Limitations and cautions

  • The result has one row per quiz attempt, but highest_grade and lowest_grade aggregate all attempts by that user in the quiz and are repeated on every corresponding row.
  • Maximum and minimum percentage scores divide attempt points by kbi_q1.sumgrades, with no protection for a zero maximum grade (no NULLIF).
  • The timespend duration equals timefinish - timestart. In-progress attempts may have invalid or negative values because no completed-attempt filter applies.
  • The first_completed_date column uses MIN(kbi_qa1.timefinish) across all attempts, including records with a zero finish time. It therefore does not necessarily represent the earliest truly completed attempt.
  • The latest_submission field considers only attempts in the finished state, but the highest- and lowest-score aggregation does not apply that restriction.
  • Enrolment status and end date use MIN(status) and MIN(timeend) across all of a user's course enrolments and may not describe the same enrolment.
  • The SQL does not check kbi_c.visible or kbi_cm.visible and does not restrict user roles. Hidden courses or activities may appear, depending on report permissions.
  • The finalgrade field is kbi_qa.sumgrades, the attempt's raw score, not necessarily the consolidated final grade in the gradebook. No separate PostgreSQL variant is provided.
