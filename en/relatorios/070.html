REPORT 070

Quiz progress by user

Shows distinct quizzes with recorded attempts and the total number of attempts for each user who attempted quizzes in the selected course.

Report purpose

Shows distinct quizzes with recorded attempts and the total number of attempts for each user who attempted quizzes in the selected course.

Why use this report?

Helps teachers and administrators identify users appearing in the attempt history and how many different quizzes and attempts each has in the course before reviewing assessment details.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic SQL filter is Course, represented by :courseid and used once in kbi_c.id = :courseid.

The SQL requires a visible course and a user who is neither deleted nor suspended and is not guest. Results originate in mdl_quiz_attempts, without restricting completion state, previews, student role, active enrolment, specific quiz, or time period.

Visualization and full original SQL

One table visualization includes the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL variant in the source.

1. Quiz progress by user · Table

The per-user table displays ID, first name, surname, email, phone numbers, institution, department, address, city, country, the number of distinct quizzes with attempts (submitted), and the total number of distinct attempts (attempted).

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_u.phone1,
       kbi_u.phone2,
       kbi_u.institution,
       kbi_u.department,
       kbi_u.address,
       kbi_u.city,
       kbi_u.country,
       COUNT(DISTINCT kbi_qa.quiz) AS submitted,
       COUNT(DISTINCT kbi_qa.id)   AS attempted
FROM mdl_quiz_attempts kbi_qa
       JOIN mdl_quiz kbi_q ON kbi_q.id = kbi_qa.quiz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_q.course
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_qa.userid
WHERE kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
GROUP BY kbi_u.id,
         kbi_u.firstname,
         kbi_u.lastname,
         kbi_u.email,
         kbi_u.phone1,
         kbi_u.phone2,
         kbi_u.institution,
         kbi_u.department,
         kbi_u.address,
         kbi_u.city,
         kbi_u.country
ORDER BY kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • Despite the title, the report does not calculate progress, completion percentages, or performance; it only presents distinct counts of quizzes with attempts and recorded attempts.
  • The submitted column corresponds to COUNT(DISTINCT kbi_qa.quiz). It does not mean that the quizzes were submitted or completed.
  • The attempted column corresponds to COUNT(DISTINCT kbi_qa.id) and may include unfinished attempts and preview records because there are no filters for state or preview.
  • Users without attempts do not appear, even when enrolled in the course. Conversely, there is no verification of current enrolment or student role.
  • Course visibility is checked, but the query does not check visibility of each quiz module.
  • There is no time filter or normalization against the total number of quizzes. These counts do not show what proportion of the assessment content was covered.
  • Results include email addresses, phone numbers, and address, institution, and department information. Restrict access and exports in accordance with privacy policies.
  • The catalog does not include a separate PostgreSQL variant for this report.
