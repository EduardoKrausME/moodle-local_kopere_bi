REPORT 003

Courses

Four tables for a selected course: completion progress, grades, activity access history, and classification of activity participation or completion.

What this report shows

Four tables for a selected course: completion progress, grades, activity access history, and classification of activity participation or completion.

Why and when to use it

Useful for course coordinators and tutors comparing student participation, enrolments, and performance within a specific course and investigating differences between access, grades, and completion.

Available filters Visualizations and SQL Limitations

Course

The Available filters filter is linked to the SQL parameter :courseid. The course is selected through the corresponding control, when that filter subplugin is enabled, and applied to every query. No user, cohort, or date-range SQL filters were found.

Visualizations and SQL

This report contains 4 SQL queries. Each item provides its visualization type, purpose, cache settings, and full SQL. Expand an item to inspect its code.

1. Completion progress by student · Table

Table showing the student profile, enrolment, and percentage of eligible modules with recorded completion.

Cache: 6h. Refresh: 30m.

Full original SQL

SELECT u.id AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       u.institution,
       u.department,
       u.phone1,
       u.phone2,
       u.address,
       u.city,
       u.country,
       u.timezone,
       u.firstaccess,
       u.lastaccess,
       ue.timecreated,
       MAX(cc.timecompleted) AS timecompleted,
       ROUND(((MAX(cmc.completed) / MAX(m.modules)) * 100), 0) AS course_completed
  FROM {user_enrolments} ue
  JOIN {user} u ON u.id = ue.userid
  JOIN {enrol} e ON e.id = ue.enrolid
  JOIN {course} c ON c.id = e.courseid
  LEFT JOIN {course_completions} cc ON cc.timecompleted > 0
                                   AND cc.course = e.courseid
                                   AND cc.userid = ue.userid
  LEFT JOIN (
        SELECT course,
               COUNT(id) AS modules
          FROM {course_modules}
         WHERE visible = 1
           AND completion > 0
           AND deletioninprogress = 0
      GROUP BY course
      ) AS m ON m.course = c.id
  LEFT JOIN (
        SELECT cm_i.course,
               cmc_i.userid,
               COUNT(DISTINCT cmc_i.id) AS completed
          FROM {course_modules} cm_i,
               {course_modules_completion} cmc_i
         WHERE cmc_i.coursemoduleid = cm_i.id
           AND cm_i.visible = 1
           AND cmc_i.completionstate IN (1, 2)
           AND cm_i.deletioninprogress = 0
      GROUP BY cm_i.course,
               cmc_i.userid
      ) AS cmc ON cmc.course = c.id
              AND cmc.userid = ue.userid
 WHERE ue.id > 0
   AND u.id > 1
   AND u.deleted = 0
   AND u.suspended = 0
   AND ue.status = 0
   AND e.status = 0
   AND c.id = :courseid
GROUP BY u.id, ue.timecreated
2. Course grade indicators · Table

Table showing the course grade item score and student information.

Cache: none. Refresh: none.

Full original SQL

SELECT u.id AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       MIN(gc.grade) AS grade
  FROM mdl_user_enrolments ue
  LEFT JOIN mdl_user u ON u.id = ue.userid
  LEFT JOIN mdl_enrol e ON e.id = ue.enrolid
  LEFT JOIN mdl_course c ON c.id = e.courseid
  LEFT JOIN (
             SELECT course, COUNT(id) AS cmnums
               FROM mdl_course_modules
              WHERE visible = 1
           GROUP BY course
            ) AS cm ON cm.course = c.id
  LEFT JOIN (
             SELECT course, COUNT(id) AS cmnumx
               FROM mdl_course_modules
              WHERE visible = 1
                AND completion > 0
           GROUP BY course
            ) cmx ON cmx.course = c.id
  LEFT JOIN (
             SELECT cm.course, cmc.userid, COUNT(cmc.id) AS cmcnums
               FROM mdl_course_modules cm,
                    mdl_course_modules_completion cmc
              WHERE cmc.coursemoduleid = cm.id
                AND cm.visible = 1
                AND cmc.completionstate IN (1, 2)
           GROUP BY cm.course, cmc.userid
            ) cmc ON cmc.course = c.id
                AND cmc.userid = u.id
  LEFT JOIN (
             SELECT cm.course, cmc.userid, COUNT(cmc.id) AS cmcnuma
               FROM mdl_course_modules cm,
                    mdl_course_modules_completion cmc
              WHERE cmc.coursemoduleid = cm.id
                AND cm.module = 1
                AND cm.visible = 1
                AND cmc.completionstate IN (1, 2)
           GROUP BY cm.course, cmc.userid
            ) AS cmca ON cmca.course = c.id
                   AND cmca.userid = u.id
  LEFT JOIN (
             SELECT gi.courseid,
                    g.userid,
                    ROUND((CASE WHEN g.rawgrademax > 0 THEN (g.finalgrade / g.rawgrademax) * 100 ELSE g.finalgrade END), 0) AS grade
               FROM mdl_grade_items gi,
                    mdl_grade_grades g
              WHERE gi.itemtype = 'course'
                AND g.itemid = gi.id
                AND g.finalgrade IS NOT NULL
           GROUP BY gi.courseid, g.userid, g.finalgrade, g.rawgrademax
            ) AS gc ON gc.courseid = c.id
                AND gc.userid = u.id
 WHERE ue.id > 0
   AND e.courseid = :courseid
   AND u.deleted = 0
   AND u.suspended = 0
   AND c.visible = 1
GROUP BY u.id, c.id
3. Activity access records · Table

Table of recorded events, including module, source, IP address, and access date and time.

Cache: 6h. Refresh: 30m.

Full original SQL

SELECT u.id                    AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       l.contextinstanceid     AS cm_cmid,
       CONCAT('lang::modulename::', l.objecttable) AS module_name,
       l.origin                AS l_origin,
       l.ip                    AS l_ip,
       l.timecreated           AS l_timecreated,
       l.objecttable
       
     FROM mdl_local_kopere_bi_log_tmp l
LEFT JOIN mdl_course       c  ON c.id = l.courseid
LEFT JOIN mdl_user         u  ON u.id = l.userid
LEFT JOIN mdl_modules      m  ON m.name = SUBSTRING(l.component, 5)
LEFT JOIN mdl_course_modules cm ON cm.id = l.contextinstanceid

WHERE u.id > 1
  AND l.component LIKE '%mod_%'
  AND l.courseid = :courseid
  AND u.deleted = 0
  AND u.suspended = 0
  AND c.visible = 1
  AND cm.visible = 1
4. Participation and completion analysis · Table

Table with a status calculated from last access and the presence of activity completion records.

Cache: 6h. Refresh: 30m.

Full original SQL

SELECT u.id        AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       CASE 
           WHEN ul.id IS NULL THEN 'lang::case_never_accessed::local_kopere_bi'
           WHEN comp.userid IS NOT NULL THEN 'lang::case_complete::local_kopere_bi'
           ELSE 'lang::case_incomplete::local_kopere_bi'
       END AS status
       
FROM mdl_role_assignments ra
       JOIN mdl_context ctx                                   ON ctx.id = ra.contextid 
                                                            AND ctx.contextlevel = 50
       JOIN mdl_course c                                     ON c.id = ctx.instanceid
       JOIN mdl_user u                                      ON u.id = ra.userid
       
       LEFT JOIN (SELECT cm.course, cmc.userid
                  FROM   mdl_course_modules cm
                         JOIN mdl_course_modules_completion cmc ON cmc.coursemoduleid = cm.id 
                                                              AND cmc.completionstate = 1
                  WHERE  cmc.id > 0
                  GROUP BY cm.course, cmc.userid
                 ) comp ON comp.userid = u.id 
                         AND comp.course = c.id
       
       LEFT JOIN mdl_user_lastaccess ul                         ON ul.courseid = c.id 
                                                            AND ul.userid = ra.userid
       
WHERE  c.id = :courseid 
  AND  u.deleted = 0 
  AND  u.suspended = 0  
  AND  c.visible = 1 
  AND  ra.roleid = 5
GROUP BY u.id

Limitations and interpretation

  • The :courseid filter is used in all four queries and restricts the tables to the selected course.
  • The 'Completo' (complete) classification in the participation table depends on activity completion records and does not prove formal course completion.
  • One query uses a fixed role ID 5, and its grouping expressions need compatibility checks against the installed database.
  • This report contains personal information, IP addresses, and grades; strictly control access permissions and page visibility.
