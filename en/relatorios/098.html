REPORT 098

Student progress overview

Summarizes course-level access, tracked activity completion, calculated progress, grades, and formal course completion for users assigned the student role in visible courses.

Report purpose

Summarizes course-level access, tracked activity completion, calculated progress, grades, and formal course completion for users assigned the student role in visible courses.

Why use this report?

Helps teachers and managers identify students with no recorded activity, completed activities, available grades, or formal course completion, supporting prioritization of follow-up.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, student, date range, enrolment status, or progress state.

Fixed conditions require a role assignment with shortname = 'student' in the course context (contextlevel = 50), a user who is neither deleted nor suspended and is not guest, and a visible course. Activity totals include modules with deletioninprogress = 0, visible = 1, and completion > 0. Completed modules are counted when completionstate IN (1, 2). The enrolment subquery includes active user enrolments and methods, with no recorded end date or a future timeend.

Visualization and full original SQL

One table visualization includes the two complete original SQL queries, MySQL and PostgreSQL, shown separately within the same visualization. Prism.js provides syntax highlighting.

1. Student progress overview · Table

Each student-course row displays student details and email, enrolment date when available, last course access, total visible modules with completion tracking, modules completed, calculated progress percentage, final grade, percentage course grade, formal course completion date, and a status derived from completion, activity, or access.

Full original MySQL SQL

SELECT CONCAT(kbi_students.userid, '-', kbi_students.courseid) AS id,
       kbi_students.userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_enrol.enrolled_at,
       COALESCE(kbi_la.timeaccess, 0) AS course_lastaccess,
       COALESCE(kbi_total.total_activities, 0) AS total_activities,
       COALESCE(kbi_done.completed_activities, 0) AS completed_activities,
       CASE
         WHEN COALESCE(kbi_total.total_activities, 0) > 0 THEN ROUND((COALESCE(kbi_done.completed_activities, 0) / kbi_total.total_activities) * 100, 2)
         ELSE 0
       END AS progress_percent,
       ROUND(kbi_grade.finalgrade, 2) AS finalgrade,
       ROUND(kbi_grade.grade_percent, 2) AS grade_percent,
       kbi_cc.timecompleted,
       CASE
         WHEN kbi_cc.timecompleted IS NOT NULL THEN 'Completed'
         WHEN COALESCE(kbi_done.completed_activities, 0) > 0 THEN 'In progress'
         WHEN COALESCE(kbi_la.timeaccess, 0) > 0 THEN 'Accessed'
         ELSE 'Not started'
       END AS student_status
FROM (SELECT DISTINCT kbi_ra.userid,
                kbi_ctx.instanceid AS courseid
FROM mdl_role_assignments kbi_ra
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
WHERE kbi_r.shortname = 'student') kbi_students
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_students.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_students.courseid
       LEFT JOIN (SELECT kbi_ue.userid,
       kbi_e.courseid,
       MIN(kbi_ue.id) AS enrolmentid,
       COALESCE(MIN(NULLIF(kbi_ue.timestart, 0)), MIN(kbi_ue.timecreated)) AS enrolled_at,
       MAX(kbi_ue.timeend) AS enrol_timeend
FROM mdl_enrol kbi_e
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.status = 0
  AND kbi_ue.status = 0
  AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP())
GROUP BY kbi_ue.userid, kbi_e.courseid) kbi_enrol ON kbi_enrol.userid = kbi_students.userid AND kbi_enrol.courseid = kbi_students.courseid
       LEFT JOIN mdl_user_lastaccess kbi_la ON kbi_la.userid = kbi_students.userid AND kbi_la.courseid = kbi_students.courseid
       LEFT JOIN (SELECT kbi_cm.course,
       COUNT(DISTINCT kbi_cm.id) AS total_activities
FROM mdl_course_modules kbi_cm
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
GROUP BY kbi_cm.course) kbi_total ON kbi_total.course = kbi_students.courseid
       LEFT JOIN (SELECT kbi_cm.course,
       kbi_cmc.userid,
       COUNT(DISTINCT kbi_cmc.coursemoduleid) AS completed_activities
FROM mdl_course_modules kbi_cm
       JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
  AND kbi_cmc.completionstate IN (1, 2)
GROUP BY kbi_cm.course, kbi_cmc.userid) kbi_done ON kbi_done.course = kbi_students.courseid AND kbi_done.userid = kbi_students.userid
       LEFT JOIN (SELECT kbi_gi.courseid,
       kbi_gg.userid,
       kbi_gi.gradepass,
       kbi_gi.grademax,
       kbi_gg.finalgrade,
       CASE
         WHEN kbi_gi.grademax > 0 AND kbi_gg.finalgrade IS NOT NULL THEN ROUND((kbi_gg.finalgrade / kbi_gi.grademax) * 100, 2)
         ELSE NULL
       END AS grade_percent
FROM mdl_grade_items kbi_gi
       JOIN mdl_grade_grades kbi_gg ON kbi_gg.itemid = kbi_gi.id
WHERE kbi_gi.itemtype = 'course') kbi_grade ON kbi_grade.courseid = kbi_students.courseid AND kbi_grade.userid = kbi_students.userid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_students.courseid AND kbi_cc.userid = kbi_students.userid
WHERE kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • Results start from assignments of the student role, not enrolment records. Because the enrolment subquery uses a LEFT JOIN, a student with an assigned role may appear without an active enrolment record; enrolled_at can therefore be NULL.
  • The enrolment subquery considers records active when e.status = 0, ue.status = 0, and timeend is zero or in the future. It does not explicitly verify whether timestart has been reached.
  • The progress_percent field measures the proportion of visible completion-tracked modules marked complete. It is not necessarily formal course completion, which is tracked separately in mdl_course_completions.timecompleted.
  • In PostgreSQL, completed_activities / total_activities divides integers before casting to numeric. Fractional results may be truncated, yielding 0% for partially completed courses below 100%. Rounding afterward does not restore the lost fraction.
  • MySQL handles the division operator differently, allowing fractional results. The calculated progress percentages may therefore diverge between databases with identical records.
  • The SQL returns progress_percent = 0 when no activities have completion tracking configured. This does not mean a course was started and left unfinished.
  • The student_status field is a derived classification based on formal completion, completed activities, or last access, in that order. It does not directly capture the actual enrolment status or every activity's state.
  • The SQL returns status labels as literal English values (Completed, In progress, Accessed, and Not started).
  • The finalgrade field comes from the course grade item, and grade_percent divides by the configured maximum when positive. Grades, activity completion percentage, and formal course completion are separate indicators.
  • The course_lastaccess field uses mdl_user_lastaccess. A missing or zero value alone does not establish that the user has never triggered any course-related event. Personal and academic information is included.
