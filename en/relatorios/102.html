REPORT 102

Student enrolments ending soon

Lists student enrolments with a specified end date that has already passed or falls within the next 30 days, including the calculated expiry status.

Report purpose

Lists student enrolments with a specified end date that has already passed or falls within the next 30 days, including the calculated expiry status.

Why use this report?

Helps identify enrolments approaching their end dates, as well as those already expired, to support notifications, renewals, and administrative checks.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, student, enrolment, date, or time window. The 30-day horizon is fixed in both MySQL and PostgreSQL.

Filters require an account that is not deleted and is not guest, a visible course, an enabled enrolment method (kbi_e.status = 0), a positive end date (kbi_ue.timeend > 0), and a role with shortname = 'student' in the course context. The end date must be in the past or within the next 30 days.

Visualization and full original SQL

One table visualization contains the complete original MySQL and PostgreSQL queries in separate panels within the same block, with Prism.js syntax highlighting.

1. Student enrolments ending soon · Table

One row per eligible enrolment record, including enrolment ID, student and contact details, course, enrolment method, start and end dates, days remaining, and a textual status of Expired, Ends in 7 days, or Ends in 30 days.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT CONCAT(kbi_ue.id, '-', kbi_c.id) AS id,
       kbi_ue.id AS enrolid,
       kbi_u.id AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_e.enrol AS enrol_method,
       COALESCE(NULLIF(kbi_ue.timestart, 0), kbi_ue.timecreated) AS enrolled_at,
       kbi_ue.timeend AS enrol_timeend,
       DATEDIFF(FROM_UNIXTIME(kbi_ue.timeend), NOW()) AS days_to_end,
       CASE
         WHEN kbi_ue.timeend < UNIX_TIMESTAMP() THEN 'Expired'
         WHEN kbi_ue.timeend <= (UNIX_TIMESTAMP() + (7 * 24 * 60 * 60)) THEN 'Ends in 7 days'
         WHEN kbi_ue.timeend <= (UNIX_TIMESTAMP() + (30 * 24 * 60 * 60)) THEN 'Ends in 30 days'
         ELSE 'Scheduled'
       END AS expiry_status
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_context kbi_ctx ON kbi_ctx.instanceid = kbi_c.id AND kbi_ctx.contextlevel = 50
       JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_ctx.id AND kbi_ra.userid = kbi_u.id
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid AND kbi_r.shortname = 'student'
WHERE kbi_u.deleted = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
  AND kbi_e.status = 0
  AND kbi_ue.timeend > 0
  AND (kbi_ue.timeend < UNIX_TIMESTAMP() OR kbi_ue.timeend <= (UNIX_TIMESTAMP() + (30 * 24 * 60 * 60)))
ORDER BY kbi_ue.timeend, kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Full original PostgreSQL SQL

SELECT CONCAT(kbi_ue.id, '-', kbi_c.id) AS id,
       kbi_ue.id AS enrolid,
       kbi_u.id AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_e.enrol AS enrol_method,
       COALESCE(NULLIF(kbi_ue.timestart, 0), kbi_ue.timecreated) AS enrolled_at,
       kbi_ue.timeend AS enrol_timeend,
       ((TO_TIMESTAMP(kbi_ue.timeend))::date - (CURRENT_TIMESTAMP)::date) AS days_to_end,
       CASE
         WHEN kbi_ue.timeend < (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) THEN 'Expired'
         WHEN kbi_ue.timeend <= ((EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) + (7 * 24 * 60 * 60)) THEN 'Ends in 7 days'
         WHEN kbi_ue.timeend <= ((EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) + (30 * 24 * 60 * 60)) THEN 'Ends in 30 days'
         ELSE 'Scheduled'
       END AS expiry_status
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_context kbi_ctx ON kbi_ctx.instanceid = kbi_c.id AND kbi_ctx.contextlevel = 50
       JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_ctx.id AND kbi_ra.userid = kbi_u.id
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid AND kbi_r.shortname = 'student'
WHERE kbi_u.deleted = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
  AND kbi_e.status = 0
  AND kbi_ue.timeend > 0
  AND(kbi_ue.timeend < (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) OR kbi_ue.timeend <= ((EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) + (30 * 24 * 60 * 60)))
ORDER BY kbi_ue.timeend, kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The query also includes enrolments that have already expired, even though the title emphasizes upcoming end dates. Older enrolment records may still be returned.
  • Only enrolments with timeend > 0 are listed. Enrolments without an end date are omitted.
  • The condition does not check kbi_ue.status = 0, so an enrolment record itself may be suspended. It also does not check kbi_u.suspended = 0.
  • The student role is identified by the student short name in the course context. Custom roles with a different short name may be excluded.
  • Status groups compare Unix timestamps in seconds, but days_to_end measures the difference between calendar dates. Rounding differences may occur around the 7-day and 30-day boundaries.
  • The CASE expression includes a fallback Scheduled status, but the filter for past or next-30-day end dates normally excludes later future enrolments.
  • Date values depend on time-zone settings and database-specific MySQL or PostgreSQL conversions. Results near midnight may differ.
  • Multiple matching role assignments may produce more than one row for an enrolment. Use the enrolment ID when reviewing the results.
  • The list includes participant names and email addresses. Apply appropriate permissions and export controls before using it for notifications.
