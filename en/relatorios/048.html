REPORT 048

Enrolments and completion by course

Per-visible-course summary of users enrolled through active methods, formal course completions, and the completion ratio between those totals.

Report purpose

Per-visible-course summary of users enrolled through active methods, formal course completions, and the completion ratio between those totals.

Why use this report?

Supports administrative monitoring of enrolments and formal course completions by providing an initial proportion of enrolled users who completed the course.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters to select a course, period, cohort, or participant. The report lists visible courses with positive IDs and enrolments and enrolment methods with status 0, excluding deleted, suspended, and guest accounts.

A completion record requires mdl_course_completions.timecompleted > 0. There is no student-role filter or date restriction on completion.

Visualization and full original SQL

One table visualization includes the full original SQL query, cache and refresh settings, and Prism.js syntax highlighting. The catalog has no separate PostgreSQL variant for this report.

1. Enrolments and completion by course · Table

The table lists the course ID and name, distinct number of enrolled users, distinct number of users with a formal course completion record, and the progress ratio calculated by dividing those totals and rounding to two decimal places.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       COUNT(DISTINCT kbi_ue.userid)                                          users,
       COUNT(DISTINCT kbi_cc.userid)                                       as completed,
       ROUND(COUNT(DISTINCT kbi_cc.userid) / COUNT(DISTINCT kbi_ue.userid), 2) as progress
FROM mdl_user_enrolments kbi_ue
       INNER JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       LEFT JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_ue.userid AND kbi_cc.timecompleted > 0
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
GROUP BY kbi_c.id, kbi_c.fullname
ORDER BY kbi_c.fullname

Limitations and cautions

  • The progress column is a rounded ratio from 0 to 1, not a percentage from 0 to 100. For example, 0.75 represents 75%.
  • The calculation uses distinct users whose enrolment and enrolment method both have status zero. The SQL does not explicitly verify whether enrolment start and end dates are currently valid.
  • There is no role filter: the count may include teachers or other users enrolled in the course, not just students.
  • The completed total depends on dated formal course completion records, not completion of individual activities.
  • The query starts from mdl_user_enrolments. Courses without users enrolled under the specified conditions are excluded.
  • The SQL has no date-range filter and does not calculate time to completion, average grades, or usage time.
  • There is no separate PostgreSQL variant. Interpret the ratios in the context of the institution's completion rules and enrolment settings.
