REPORT 103

Course completion status by student

Shows the calculated course completion status for each student identified by the student role, including formal completion date, last access, and number of completed activities.

Report purpose

Shows the calculated course completion status for each student identified by the student role, including formal completion date, last access, and number of completed activities.

Why use this report?

Helps coordinators and tutors distinguish students who have completed a course, started activities, or have no recorded access, while keeping formal course completion separate from activity progress.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, user, cohort, or period. The query includes visible courses and student accounts that are neither deleted nor suspended and are not guest, identified by assignment of a role with short name student.

The enrolment subquery requires enrolment methods and records with status 0 and an unexpired end date, but is linked to the main query with LEFT JOIN. An enrolment record's absence therefore does not exclude the student identified through a role assignment.

Visualization and full original SQL

One table visualization includes two equivalent complete original SQL queries, MySQL and PostgreSQL, within the same block. Prism.js provides syntax highlighting without changing the SQL.

1. Course completion status by student · Table

Each student-course row includes the name, email, course, whether completion tracking is enabled, enrolment date if available, last access, formal completion date, calculated status, number of tracked activities, number completed, and progress percentage.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT CONCAT(kbi_students.userid, '-', kbi_students.courseid) AS id,
       kbi_students.userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_c.enablecompletion,
       kbi_enrol.enrolled_at,
       COALESCE(kbi_la.timeaccess, 0) AS course_lastaccess,
       kbi_cc.timecompleted,
       CASE
         WHEN kbi_c.enablecompletion = 0 THEN 'Completion disabled'
         WHEN kbi_cc.timecompleted IS NOT NULL THEN 'Completed'
         WHEN COALESCE(kbi_la.timeaccess, 0) > 0 OR COALESCE(kbi_done.completed_activities, 0) > 0 THEN 'In progress'
         ELSE 'Not started'
       END AS completion_status,
       COALESCE(kbi_total.total_activities, 0) AS total_activities,
       COALESCE(kbi_done.completed_activities, 0) AS completed_activities,
       CASE
         WHEN COALESCE(kbi_total.total_activities, 0) > 0 THEN ROUND((COALESCE(kbi_done.completed_activities, 0) / kbi_total.total_activities) * 100, 2)
         ELSE 0
       END AS progress_percent
FROM (SELECT DISTINCT kbi_ra.userid,
                kbi_ctx.instanceid AS courseid
FROM mdl_role_assignments kbi_ra
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
WHERE kbi_r.shortname = 'student') kbi_students
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_students.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_students.courseid
       LEFT JOIN (SELECT kbi_ue.userid,
       kbi_e.courseid,
       MIN(kbi_ue.id) AS enrolmentid,
       COALESCE(MIN(NULLIF(kbi_ue.timestart, 0)), MIN(kbi_ue.timecreated)) AS enrolled_at,
       MAX(kbi_ue.timeend) AS enrol_timeend
FROM mdl_enrol kbi_e
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.status = 0
  AND kbi_ue.status = 0
  AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP())
GROUP BY kbi_ue.userid, kbi_e.courseid) kbi_enrol ON kbi_enrol.userid = kbi_students.userid AND kbi_enrol.courseid = kbi_students.courseid
       LEFT JOIN mdl_user_lastaccess kbi_la ON kbi_la.userid = kbi_students.userid AND kbi_la.courseid = kbi_students.courseid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_students.courseid AND kbi_cc.userid = kbi_students.userid
       LEFT JOIN (SELECT kbi_cm.course,
       COUNT(DISTINCT kbi_cm.id) AS total_activities
FROM mdl_course_modules kbi_cm
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
GROUP BY kbi_cm.course) kbi_total ON kbi_total.course = kbi_students.courseid
       LEFT JOIN (SELECT kbi_cm.course,
       kbi_cmc.userid,
       COUNT(DISTINCT kbi_cmc.coursemoduleid) AS completed_activities
FROM mdl_course_modules kbi_cm
       JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
  AND kbi_cmc.completionstate IN (1, 2)
GROUP BY kbi_cm.course, kbi_cmc.userid) kbi_done ON kbi_done.course = kbi_students.courseid AND kbi_done.userid = kbi_students.userid
WHERE kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
ORDER BY completion_status, kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Calculation criteria and behavior

The query starts from course-context assignments of the role with short name student (contextlevel = 50) and joins the account, course, last visit, formal course completion, and activity progress. It considers visible activities with completion > 0 that are not being deleted; a module counts as completed when completionstate IN (1, 2).

A CASE expression calculates status in this order: Completion disabled if the course disables completion tracking; Completed if timecompleted is present; In progress if there is a last access or completed activity; otherwise Not started. This should not be interpreted as a broader measure of academic standing.

Limitations and cautions

  • Inclusion is based on an assigned student role in the course, not solely on an active enrolment. The enrolment subquery is optional.
  • When the course disables completion tracking, the 'Completion disabled' status takes priority even when other completion data exists.
  • Progress percentage includes only visible activities with completion tracking and completion states 1 or 2. It neither replaces formal course completion nor measures learning directly.
  • In the PostgreSQL variant, integer counts are divided before the result is cast to numeric within ROUND. This can truncate partial percentages and incorrectly yield 0% or 100%. The original SQL is preserved without modification.
  • Last course access and activity counts may be missing. A missing record does not prove a lack of interest, and the exposed data include email addresses and individual progress.

The SQL is reproduced verbatim from the JSON definitions in master and has not been executed on a Moodle installation during this documentation work. Check compatibility, results, permissions, and privacy before institutional use.
