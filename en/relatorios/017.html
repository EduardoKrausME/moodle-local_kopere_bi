REPORT 017

Overdue users

Lists students enrolled in the selected course, with enrolment dates, formal course completion dates, and calculated grades.

Report purpose

Lists students enrolled in the selected course, with enrolment dates, formal course completion dates, and calculated grades.

Why use this report?

Can support individual enrolment follow-up and administrative review of students without recorded completion, provided that overdue status is determined using additional criteria.

Actual filters Visualization and SQL Limitations

Available filters

The available dynamic filter is Course, linked to the :courseid parameter. The SQL restricts rows to the selected course.

Other criteria are fixed: accounts that are neither deleted nor suspended and are not guest, visible courses, and enrolments and enrolment methods with status 0. There is no SQL filter for student, cohort, or time period.

Visualization and full original SQL

The report contains one table and one SQL query, with cache, refresh settings, and Prism.js syntax highlighting. The original catalog does not provide a separate PostgreSQL variant.

1. Overdue users · Table

Table listing students, enrolment date, course completion date, percentage grade when assessed, technical course identifiers used for navigation, completion settings, and course name. The cohort field is empty in the definition.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_ue.id,
       kbi_ue.timecreated                      as enrolled,
       kbi_cc.timecompleted                    as complete,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0) AS grade,
       kbi_u.id                                as uid,
       kbi_u.email,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.id                                as cid,
       kbi_c.enablecompletion,
       kbi_c.fullname                          as course,
       ''                                  as cohortname
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_u.id
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_e.courseid AND kbi_gi.itemtype = 'course'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = kbi_u.id
WHERE kbi_ue.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The SQL does not actually identify overdue students. There is no comparison against a deadline, timeend, submission due date, or similar criterion. It lists course enrolments, including completed ones.
  • The cohortname field is an empty string and does not indicate actual cohort membership.
  • The grade uses finalgrade and rawgrademax; a missing grade must not be interpreted as failure or overdue status.
  • The formal course completion date may be empty even when the student has completed some activities; activity completion and course completion are different concepts.
  • The query uses an optional join to course grade items, which may affect the number of rows depending on grade configuration.
  • The original file has no independent PostgreSQL variant and contains SQL whose compatibility needs validation against the installed database.
