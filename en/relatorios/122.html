REPORT 122

Most frequent answers without full credit

Frequent responses receiving less than full credit in finished quiz attempts, excluding previews and reporting each response's share among selected answers.

Report purpose

Table by course, question, and response summary, showing occurrence counts, distinct learners, and the percentage represented by each response summary among selected records for that question. It sorts by descending frequency and returns up to 500 rows.

Why use this report?

Help teachers and instructional designers identify recurring response patterns that did not earn full credit, for reviewing answer choices, question wording, and potential learning difficulties.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, quiz, question, student, reporting period, or response. The query requires attempts with a.state = 'finished', excludes previews (a.preview = 0), and accepts accounts that are not deleted and are not guest.

For the last step of the question attempt, the conditions are st.fraction IS NOT NULL and st.fraction < 1; responsesummary must also be non-NULL and nonempty. Results are limited to 500 groups, ordered by descending frequency.

Visualization and full original SQL

One table visualization contains the complete original SQL and cache and refresh settings, with Prism.js syntax highlighting. No separate PostgreSQL variant was found in master, so a nonexistent version has not been added.

1. Most frequent answers without full credit · Table

Table by course, question, and response summary, showing occurrences, distinct learners, and each summary's percentage among the selected responses to that question. It sorts by highest occurrence count and returns at most 500 rows.

Cache: 1h · Refresh: none.

Full original SQL

SELECT MD5(CONCAT(c.id, '-', q.id, '-', att.responsesummary)) AS id,
       c.id AS courseid, c.fullname AS course, q.id AS questionid, q.name AS question,
       att.responsesummary AS answer, COUNT(*) AS occurrences,
       COUNT(DISTINCT a.userid) AS learners,
       ROUND(100.0 * COUNT(*) /
             NULLIF(SUM(COUNT(*)) OVER (PARTITION BY c.id, q.id), 0), 2)
             AS incorrect_answer_share
  FROM mdl_quiz_attempts a
  JOIN mdl_quiz quiz ON quiz.id = a.quiz
  JOIN mdl_course c ON c.id = quiz.course
  JOIN mdl_user u ON u.id = a.userid AND u.deleted = 0 AND u.username <> 'guest'
  JOIN mdl_question_attempts att ON att.questionusageid = a.uniqueid
  JOIN mdl_question q ON q.id = att.questionid
  JOIN mdl_question_attempt_steps st ON st.questionattemptid = att.id
       AND st.sequencenumber = (SELECT MAX(st2.sequencenumber)
                                 FROM mdl_question_attempt_steps st2
                                WHERE st2.questionattemptid = att.id)
 WHERE a.state = 'finished' AND a.preview = 0 AND st.fraction IS NOT NULL AND st.fraction < 1
   AND att.responsesummary IS NOT NULL AND att.responsesummary <> ''
 GROUP BY c.id, c.fullname, q.id, q.name, att.responsesummary
 ORDER BY occurrences DESC, c.fullname
 LIMIT 500

Calculation criteria and behavior

The SQL joins quiz attempts to question attempts using questionusageid. It selects the step with the greatest sequencenumber in each question attempt and retains steps graded with a fraction below one.

Responses are grouped by course, question, and att.responsesummary. COUNT(*) counts occurrences, and COUNT(DISTINCT a.userid) counts distinct users. incorrect_answer_share uses a window function: occurrences for one answer divided by all occurrences among the no-full-credit response groups for that course and question, multiplied by 100. It measures the share among selected responses, not the overall error rate of all participants.

Limitations and cautions

  • The fraction-below-one rule includes partially correct answers (earning partial credit), not just entirely wrong answers. It does not exclusively describe zero-mark answers.
  • Responses are identified using responsesummary. Semantically identical answers represented differently may appear in separate groups.
  • The occurrence count refers to attempts, while learners counts distinct users. A participant with repeated attempts can contribute several occurrences.
  • The percentage is calculated within the no-full-credit responses for each question, not among all finished submissions, including fully correct answers.
  • The query depends on the matching final question-attempt step and its grade. Some question types or grading states may be excluded unexpectedly.
  • The SQL orders all groups globally by occurrence count and returns at most 500 groups. Less frequent answers are omitted, and no date filter is provided.
  • Response summaries may contain student-provided text. Check privacy safeguards and risks of exposing personal content before exporting.

The SQL was reproduced verbatim from the original JSON in master and was not executed on Moodle during this documentation work. Before institutional use, check database compatibility, accuracy of interpretation, and access permissions.
