REPORT 051

Enrolment method summary

Summarizes enrolments associated with enabled enrolment methods, showing course counts, enrolment records, and distinct users for each method type.

Report purpose

Summarizes enrolments associated with enabled enrolment methods, showing course counts, enrolment records, and distinct users for each method type.

Why use this report?

Helps explain how enrolment methods are distributed across the platform and compare the volume of enrolment records, course coverage, and unique participants by method.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, method, user, cohort, or time period. The query includes enrolment method instances with kbi_e.id > 0 and kbi_e.status = 0, as well as user enrolments with kbi_ue.status = 0.

Results are grouped by kbi_e.enrol, the enrolment method type code, and ordered by the number of enrolment records in descending order, followed by method name.

Visualization and full original SQL

One table visualization includes one complete SQL query, cache settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the original catalog.

1. Enrolment method summary · Table

One row per enrolment method code, displaying an aggregate method instance identifier, the number of distinct courses, the number of user enrolment records, and the number of distinct users.

Cache: 1h · Refresh: none.

Full original SQL

SELECT MAX(kbi_e.id)                  AS id,
       kbi_e.enrol                    as enrol,
       COUNT(DISTINCT kbi_e.courseid) as courses,
       COUNT(kbi_ue.userid)           as users,
       COUNT(DISTINCT kbi_ue.userid)  as uniusers
FROM mdl_enrol kbi_e
       LEFT JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.id > 0
  AND kbi_e.status = 0
  AND kbi_ue.status = 0
GROUP BY kbi_e.enrol
ORDER BY users DESC, kbi_e.enrol

Limitations and cautions

  • The users field uses COUNT(kbi_ue.userid), which counts enrolment records rather than distinct people. A person enrolled in multiple courses or methods may be counted several times.
  • The uniusers field uses COUNT(DISTINCT kbi_ue.userid) to count distinct people within each method type, not a platform-wide deduplicated total.
  • The courses column counts distinct courses associated with enrolments using the method, not necessarily every course where that method is configured.
  • Although enrolments are joined using LEFT JOIN, the kbi_ue.status = 0 condition in the WHERE clause excludes methods without matching enrolments, effectively making that join mandatory.
  • The query does not filter course visibility or status, deleted or suspended users, enrolment start and end dates, or time periods.
  • The displayed ID is MAX(kbi_e.id), an aggregate identifier of one method instance, not a unique identifier for the method type throughout the platform.
  • There is no separate PostgreSQL variant in the catalog; these totals do not represent payments, revenue, or course completions.
