REPORT 086

Learning plan progress

Calculates an estimated proficiency percentage for each template-based learning plan, alongside its owner, status, and a calculated date when the estimate reaches 100%.

Report purpose

Calculates an estimated proficiency percentage for each template-based learning plan, alongside its owner, status, and a calculated date when the estimate reaches 100%.

Why use this report?

Helps administrators and educators review template-based learning plans and provisionally monitor the proportion of competencies with proficiency records.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, person, plan, competency, template, or reporting period.

The query considers templates in mdl_competency_template and plans with kbi_cp.id IS NOT NULL. It joins competencies through their template and proficiency records through the user and competency. Results are grouped by plan and user, then sorted by surname, first name, and plan name.

Visualization and full original SQL

One table visualization contains the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. The definitions catalog does not provide a separate PostgreSQL variant.

1. Learning plan progress · Table

The per-plan table shows the user ID, first name and surname, plan title, creation date, and status, together with a calculated progress percentage, calculated completion date, and plan template ID.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_cp.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.id                                                  AS userid,
       kbi_cp.name,
       kbi_cp.timecreated,
       kbi_cp.status,
       CASE
         WHEN ROUND((SUM(kbi_cu.proficiency) / COUNT(kbi_ctc.id)) * 100, 2) >= 100 THEN MAX(kbi_cu.timecreated)
         ELSE 0 END                                          AS completion_date,
       ROUND((SUM(kbi_cu.proficiency) / COUNT(kbi_ctc.id)) * 100, 2) AS progress,
       kbi_cp.templateid
FROM mdl_competency_template kbi_ct
       LEFT JOIN mdl_competency_templatecomp kbi_ctc ON kbi_ctc.templateid = kbi_ct.id
       LEFT JOIN mdl_competency_plan kbi_cp ON kbi_cp.templateid = kbi_ct.id
       LEFT JOIN mdl_competency_usercomp kbi_cu ON kbi_cu.competencyid = kbi_ctc.competencyid AND kbi_cu.userid = kbi_cp.userid
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_cp.userid
WHERE kbi_cp.id IS NOT NULL
GROUP BY kbi_cp.id, kbi_u.id
ORDER BY kbi_u.lastname, kbi_u.firstname, kbi_cp.name

Limitations and cautions

  • The progress field uses SUM(kbi_cu.proficiency) / COUNT(kbi_ctc.id) * 100. This assumes proficiency values can serve as numeric indicators, but does not necessarily match the official learning plan completion percentage.
  • The query does not use COALESCE to convert missing proficiency records to zero. Plans without proficiency values may therefore have a NULL progress result.
  • If the template has no competencies, the denominator COUNT(kbi_ctc.id) may be zero. The SQL contains no NULLIF to guard against division by zero.
  • Duplicate records or multiple proficiency relationships for a single competency can alter the numerator and intermediate row counts. The query does not explicitly count distinct proficient competencies.
  • The completion_date column returns the greatest mdl_competency_usercomp.timecreated value when the calculated percentage reaches at least 100%. This is the creation date of a user competency record, not necessarily the official plan completion date.
  • A 0 in completion_date means the calculated value has not reached the 100% threshold; it is not a valid date.
  • The query does not require a specific kbi_cp.status, check for deleted or suspended users, or filter by course or individual learning plan.
  • Interpret names and indicators in light of how proficiency is configured and updated. No separate PostgreSQL file is provided.
