REPORT 019

User profiles and demographics

Table of Moodle profiles with identity, contact details, declared location, authentication method, account status, and dates relating to platform use.

Report purpose

Table of Moodle profiles with identity, contact details, declared location, authentication method, account status, and dates relating to platform use.

Why use this report?

Allows administrators to review accounts, contact fields, institution, department, authentication methods, and basic access indicators to support profile maintenance and user support.

Filtros disponíveis Visualization and SQL Limitations

Available filters

This report has no dynamic course, user, cohort, or date-range filters in its SQL. It lists accounts meeting the fixed conditions kbi_u.id > 0, kbi_u.deleted = 0, kbi_u.suspended = 0, and kbi_u.username != 'guest'.

Users are ordered by last name, first name, and ID. The SQL does not restrict results to a particular course or to an account creation or access period.

Visualization and full original SQL

The report contains one table and one SQL query, with Prism.js syntax highlighting. The original catalog provides a single SQL definition without a separate PostgreSQL variant.

1. User profiles and demographics · Table

Per-account table containing first name, middle name, email, username, telephone numbers, address, city, country, institution, department, authentication method, account confirmation, creation and modification dates, first and last access, login date, and last recorded IP address.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.middlename,
       kbi_u.email,
       kbi_u.idnumber,
       kbi_u.username,
       kbi_u.phone1,
       kbi_u.phone2,
       kbi_u.institution,
       kbi_u.department,
       kbi_u.address,
       kbi_u.city,
       kbi_u.country,
       kbi_u.auth,
       kbi_u.confirmed,
       kbi_u.suspended,
       kbi_u.deleted,
       kbi_u.timecreated,
       kbi_u.timemodified,
       kbi_u.firstaccess,
       kbi_u.lastaccess,
       kbi_u.lastlogin,
       kbi_u.currentlogin,
       kbi_u.lastip
FROM mdl_user kbi_u
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
ORDER BY kbi_u.lastname, kbi_u.firstname, kbi_u.id

Limitations and cautions

  • The table contains personal and potentially sensitive administrative information, including telephone numbers, addresses, email, usernames, and last IP addresses. Apply strict permissions and comply with Brazil's LGPD data protection requirements.
  • City, country, institution, and department fields reflect profile information, which may be outdated, empty, or supplied by users themselves.
  • Although the suspended and deleted fields are selected, the query filters their values to zero. This is not a complete inventory of suspended or deleted accounts.
  • Access and login dates are profile fields, not a history of authentication events or sessions. The report applies no date filter.
  • There is no separate PostgreSQL variant for this definition; the displayed SQL is the original catalog query.
