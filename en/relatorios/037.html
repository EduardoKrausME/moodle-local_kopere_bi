REPORT 037

Course activities overview

Lists users enrolled with the student role in the selected course, including enrolment status and dates, assigned role, and last access recorded by Kopere BI.

Report purpose

Lists users enrolled with the student role in the selected course, including enrolment status and dates, assigned role, and last access recorded by Kopere BI.

Why use this report?

Helps check which students appear in course enrolment records, inspect enrolment status, and determine whether Kopere BI has recorded a last access to the course page.

Available filters Visualization and SQL Limitations

Available filters

The dynamic Course filter is represented by :courseid, used once in the role-assignment subquery. Its joins to enrolments and courses indirectly restrict the list to the selected course in both MySQL and PostgreSQL.

Fixed criteria include a course context (contextlevel = 50), role ID 5, an account that is neither deleted nor suspended and is not guest. Tracking considers kbi_lit.page = 'course' and kbi_lit.param = kbi_c.id. There are no dynamic user or date-range filters.

Visualization and full original SQL

One table visualization includes two SQL queries, cache settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL variants appear in separate panels within the same visualization.

1. Course activities overview · Table

The table lists each enrolment record with student name, email, identification number, course ID, status, enrolment start and end dates, role, and last tracked access. Both SQL variants produce the same table, differing mainly in the function used to concatenate role names.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ue.id,
       kbi_u.email,
       kbi_u.idnumber,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.id         AS course_id,
       kbi_c.shortname,
       kbi_ue.status    AS enroll_status,
       kbi_ue.timestart AS enroll_started,
       kbi_ue.timeend,
       kbi_lit.lastaccess,
       ra.roles     AS role_name
FROM mdl_course kbi_c
       JOIN mdl_enrol kbi_e ON kbi_e.courseid = kbi_c.id
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
       JOIN (SELECT kbi_ra.userid,
                    kbi_ctx.instanceid     AS course_id,
                    GROUP_CONCAT(DISTINCT(CASE WHEN kbi_r.name = '' THEN kbi_r.shortname ELSE kbi_r.name END) SEPARATOR
                                 ', ') AS roles
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
             WHERE kbi_ra.id > 0
               AND kbi_ra.roleid = 5
               AND kbi_ctx.instanceid = :courseid
             GROUP BY kbi_ra.userid, kbi_ctx.instanceid) ra ON ra.userid = kbi_ue.userid AND ra.course_id = kbi_e.courseid
       JOIN mdl_user kbi_u ON kbi_u.id = ra.userid AND kbi_ue.userid = kbi_u.id
       LEFT JOIN mdl_local_kopere_bi_tracking kbi_lit ON kbi_lit.userid = kbi_u.id AND kbi_lit.page = 'course' AND kbi_lit.param = kbi_c.id
WHERE kbi_u.id IS NOT NULL
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'

Full original PostgreSQL SQL

SELECT kbi_ue.id,
       kbi_u.email,
       kbi_u.idnumber,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.id         AS course_id,
       kbi_c.shortname,
       kbi_ue.status    AS enroll_status,
       kbi_ue.timestart AS enroll_started,
       kbi_ue.timeend,
       kbi_lit.lastaccess,
       ra.roles     AS role_name
FROM mdl_course kbi_c
       JOIN mdl_enrol kbi_e ON kbi_e.courseid = kbi_c.id
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
       JOIN(SELECT kbi_ra.userid,
                    kbi_ctx.instanceid     AS course_id,
                    STRING_AGG(DISTINCT ((CASE WHEN kbi_r.name = '' THEN kbi_r.shortname ELSE kbi_r.name END))::text, ', ') AS roles
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
             WHERE kbi_ra.id > 0
               AND kbi_ra.roleid = 5
               AND kbi_ctx.instanceid = :courseid
             GROUP BY kbi_ra.userid, kbi_ctx.instanceid) ra ON ra.userid = kbi_ue.userid AND ra.course_id = kbi_e.courseid
       JOIN mdl_user kbi_u ON kbi_u.id = ra.userid AND kbi_ue.userid = kbi_u.id
       LEFT JOIN mdl_local_kopere_bi_tracking kbi_lit ON kbi_lit.userid = kbi_u.id AND kbi_lit.page = 'course' AND kbi_lit.param = kbi_c.id
WHERE kbi_u.id IS NOT NULL
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'

Limitations and cautions

  • Despite its title, the query does not enumerate course activities or modules. It displays student enrolments and the most recent access available from tracking records.
  • The query does not enforce kbi_ue.status = 0, kbi_e.status = 0, or course visibility. It may therefore include inactive enrolments and hidden courses.
  • The role_name aggregation is restricted to role ID 5, not every role assigned to that user in the course.
  • The lastaccess field comes from an optional join to tracking data, without aggregation by user and course. Multiple matching records may produce repeated rows for the same enrolment.
  • Missing tracking data may yield NULL for last access and does not prove that a student has never accessed Moodle.
  • Results include names, email addresses, and identification numbers. Restrict access and exports; MySQL and PostgreSQL use database-specific role-concatenation functions.
