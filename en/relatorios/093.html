REPORT 093

File usage by course

Lists file resources in the selected course, stored file names and technical references, resource revision, and Kopere BI visit and time-tracking indicators.

Report purpose

Lists file resources in the selected course, stored file names and technical references, resource revision, and Kopere BI visit and time-tracking indicators.

Why use this report?

Helps locate file resources provided within a course and review usage indicators for their modules when maintaining and organizing learning materials.

Available filters Visualization and SQL Limitations

Available filters

The dynamic filter is Course, represented by :courseid and used twice in each variant: in the module-file subquery and the main condition kbi_c.id = :courseid.

Fixed criteria require a visible course, a file resource with a positive ID, and files with component = 'mod_resource', filearea = 'content', itemid = 0, and filesize > 0. Visit tracking requires page = 'module' and modules of type resource. There are no dynamic filters for date, participant, or module visibility.

Visualization and full original SQL

One table visualization contains both complete original SQL queries, MySQL and PostgreSQL, in separate panels within the same block. Prism.js provides syntax highlighting.

1. File usage by course · Table

The table shows each file resource's ID and name, course name, modification date, configured revision, tracked module visits and time, a list of technical file references, and a list of filenames for sorting or display.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_r.id,
       kbi_c.fullname,
       kbi_r.name,
       kbi_r.timemodified,
       kbi_r.revision,
       MAX(sl.visits)        AS visits,
       MAX(sl.timespend)     AS timespend,
       MAX(fs.files)         AS files,
       MAX(fs.files_sorting) AS files_sorting
FROM mdl_resource kbi_r
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_r.course
       LEFT JOIN (SELECT kbi_cm.instance,
                         GROUP_CONCAT(CASE
                                        WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id,
                                                                          '/mod_resource/content/[[revision]]',
                                                                          kbi_f.filepath, kbi_f.filename)
                                        ELSE NULL END SEPARATOR '[[,]]') AS files,
                         GROUP_CONCAT(kbi_f.filename)                        AS files_sorting
                  FROM mdl_files kbi_f
                         JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_f.contextid
                         JOIN mdl_course_modules kbi_cm ON kbi_cm.id = kbi_ctx.instanceid
                  WHERE kbi_f.component = 'mod_resource'
                    AND kbi_f.filearea = 'content'
                    AND kbi_f.itemid = 0
                    AND kbi_f.filesize > 0
                    AND kbi_cm.course = :courseid
                  GROUP BY kbi_cm.instance) fs ON fs.instance = kbi_r.id
       LEFT JOIN (SELECT kbi_cm.instance, SUM(kbi_lit.timespend) as timespend, SUM(kbi_lit.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_lit, mdl_course_modules kbi_cm, mdl_modules kbi_m
                  WHERE kbi_lit.page = 'module'
                    and kbi_cm.id = kbi_lit.param
                    and kbi_m.id = kbi_cm.module
                    and kbi_m.name = 'resource'
                  GROUP BY kbi_cm.instance) sl ON sl.instance = kbi_r.id
WHERE kbi_r.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_r.id, kbi_c.id

Full original PostgreSQL SQL

SELECT kbi_r.id,
       kbi_c.fullname,
       kbi_r.name,
       kbi_r.timemodified,
       kbi_r.revision,
       MAX(sl.visits)        AS visits,
       MAX(sl.timespend)     AS timespend,
       MAX(fs.files)         AS files,
       MAX(fs.files_sorting) AS files_sorting
FROM mdl_resource kbi_r
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_r.course
       LEFT JOIN(SELECT kbi_cm.instance,
                         STRING_AGG((CASE
                                        WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id,
                                                                          '/mod_resource/content/[[revision]]',
                                                                          kbi_f.filepath, kbi_f.filename)
                                        ELSE NULL END)::text, '[[,]]') AS files,
                         STRING_AGG((kbi_f.filename)::text, ',')                        AS files_sorting
                  FROM mdl_files kbi_f
                         JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_f.contextid
                         JOIN mdl_course_modules kbi_cm ON kbi_cm.id = kbi_ctx.instanceid
                  WHERE kbi_f.component = 'mod_resource'
                    AND kbi_f.filearea = 'content'
                    AND kbi_f.itemid = 0
                    AND kbi_f.filesize > 0
                    AND kbi_cm.course = :courseid
                  GROUP BY kbi_cm.instance) fs ON fs.instance = kbi_r.id
       LEFT JOIN(SELECT kbi_cm.instance, SUM(kbi_lit.timespend) as timespend, SUM(kbi_lit.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_lit, mdl_course_modules kbi_cm, mdl_modules kbi_m
                  WHERE kbi_lit.page = 'module'
                    and kbi_cm.id = kbi_lit.param
                    and kbi_m.id = kbi_cm.module
                    and kbi_m.name = 'resource'
                  GROUP BY kbi_cm.instance) sl ON sl.instance = kbi_r.id
WHERE kbi_r.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_r.id, kbi_c.id

Limitations and cautions

  • The visits and timespend totals come from mdl_local_kopere_bi_tracking for the resource module. They do not prove that each file was downloaded, opened, or read; one module may contain more than one file.
  • The tracking subquery does not directly filter by course and groups by the resource instance ID, then associates it with the module. That association depends on consistent module IDs and tracking records.
  • The files and files_sorting fields aggregate file details into text; they are neither numeric counters nor download counts. The [[revision]] text remains a literal placeholder for processing by the application.
  • Paths concatenated in files are technical references assembled from context, file area, filepath, and filename; they are not necessarily publicly accessible URLs.
  • Only positive-size files in the expected component and file area are included. Empty records, other versions, or different components may be absent from the lists.
  • MySQL and PostgreSQL use GROUP_CONCAT and STRING_AGG, respectively, to concatenate filenames and paths. Element order is not guaranteed because there is no ORDER BY inside the aggregates.
  • The course must be visible, but course_modules.visible = 1 is not required, so hidden resources may be included. File path display must respect file-access permissions.
  • There is no reporting-period filter, no identification of which students viewed the resource, and no metric for actual content consumption.
