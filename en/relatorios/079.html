REPORT 079

SCORM occurrences by course

Shows the number of SCORM packages configured in the selected course and the name of one user assigned the teacher role.

Report purpose

Shows the number of SCORM packages configured in the selected course and the name of one user assigned the teacher role.

Why use this report?

Provides a simple overview of SCORM activities available in the course and a quick package count for administrative review.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in kbi_c.id = :courseid.

Fixed filters require kbi_c.category > 0 and a visible course (kbi_c.visible = 1). The teacher subquery uses contextlevel = 50 and role ID 3. There are no filters for date, participant, attempt, or SCORM module visibility.

Visualization and full original SQL

One table visualization contains one complete SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the original source.

1. SCORM occurrences by course · Table

One row displays the course ID and name, the number of SCORM package records associated with the course (scorms), and one user name found with role ID 3 (teacher).

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_s.id) as scorms,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)   AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_scorm kbi_s ON kbi_s.course = kbi_c.id
WHERE kbi_c.category > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

Limitations and cautions

  • The scorms column counts records in mdl_scorm, not attempts, participants, completed packages, or viewed SCORM resources.
  • The query uses LEFT JOIN with the SCORM table, so a course with no configured packages may still appear with a count of zero.
  • The SQL does not check SCORM module visibility. Hidden packages may contribute to the total.
  • The teacher field returns at most one user assigned role ID 3. Because LIMIT 1 has no ORDER BY, the selection is not deterministic and does not guarantee that this person is responsible for the activities.
  • Custom roles or role IDs other than 3 are not considered for the teacher field. The selected user's deleted or suspended status is not checked.
  • The category > 0 condition restricts the result to courses with a positive category ID; it is not a user-selectable category filter.
  • The report has no metrics for grades, study time, SCORM progress, or completion. No separate PostgreSQL variant is available in the source.
