REPORT 075

Forum replies overview

Shows original posts in forum discussions in the selected course, their replies, and parent-post details when a reply is itself a reply to another post.

Report purpose

Shows original posts in forum discussions in the selected course, their replies, and parent-post details when a reply is itself a reply to another post.

Why use this report?

Helps review forum discussions and their reply chains, linking messages, authors, and publication dates.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in both the MySQL and PostgreSQL variants.

The SQL requires a course with a positive ID, an initial post with parent = 0, replies with parent <> 0, and, for the preceding reply fields, a parent post that also has parent <> 0. No date, visibility, or user filters are applied.

Visualization and full original SQL

One table visualization contains two complete original SQL queries, cache and refresh settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL versions appear in separate panels within the same visualization.

1. Forum replies overview · Table

The table shows each discussion reply (or a discussion without replies), including course and forum names, subject, author and date of the initial post, reply text and author, and the text, author, and date of the parent post when that parent is also a reply.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_c.fullname            AS course,
       kbi_f.name                AS forum,
       kbi_fp.subject            AS discussion_post,
       kbi_u1.firstname          AS forum_started_by_first_name,
       kbi_u1.lastname           AS forum_started_by_last_name,
       kbi_fp.created            AS date_started,
       kbi_fp2.message           AS response,
       kbi_fp2.created           AS response_date,
       kbi_u2.firstname          AS response_first_name,
       kbi_u2.lastname           AS response_laste_name,
       kbi_fp3.message           AS response_immediatey_prior,
       kbi_fp3.created           AS response_immediatey_prior_date,
       kbi_u3.firstname          AS response_immediatey_prior_first_name,
       kbi_u3.lastname           AS response_immediatey_prior_last_name
FROM mdl_forum kbi_f
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_f.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'forum'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_f.id
       JOIN mdl_forum_discussions kbi_fd ON kbi_fd.forum = kbi_f.id AND kbi_fd.course = kbi_c.id
       JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id AND kbi_fp.parent = 0
       JOIN mdl_user kbi_u1 ON kbi_u1.id = kbi_fp.userid
       LEFT JOIN mdl_forum_posts kbi_fp2 ON kbi_fp2.discussion = kbi_fd.id AND kbi_fp2.parent <> 0
       LEFT JOIN mdl_user kbi_u2 ON kbi_u2.id = kbi_fp2.userid
       LEFT JOIN mdl_forum_posts kbi_fp3 ON kbi_fp3.discussion = kbi_fd.id AND kbi_fp3.id = kbi_fp2.parent AND kbi_fp3.parent <> 0
       LEFT JOIN mdl_user kbi_u3 ON kbi_u3.id = kbi_fp3.userid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid

Limitations and cautions

  • The response_immediatey_prior field identifies a reply's parent post in the reply tree, when that parent is also a reply. It is not necessarily the previous message in chronological order.
  • For direct replies to the initial post, the preceding-reply fields are NULL because the SQL excludes the initial post from that relationship.
  • Using LEFT JOIN on reply posts allows discussions without replies to appear with NULL fields.
  • The query does not require course.visible = 1 or course_modules.visible = 1 and does not check authors' account statuses. Data from hidden discussions may be returned.
  • Messages come directly from mdl_forum_posts.message and may contain HTML or private content. Display and export must follow security and permission requirements.
  • The query does not calculate volume, performance, response-time, or participation statistics. It presents relationships between posts.
  • There is a discrepancy between the metadata and SQL: the definition lists an id column in info.column, but the query does not return it. The original SQL has been preserved.
  • MySQL and PostgreSQL implement the same post-relationship logic, each with its own complete SQL statement.
