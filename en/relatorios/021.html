REPORT 021

Detailed platform usage summary by user

Per-user summary table with calculated average course grade, number of enrolled courses, formal course completions, and tracked time and visits recorded by Kopere BI.

Report purpose

Per-user summary table with calculated average course grade, number of enrolled courses, formal course completions, and tracked time and visits recorded by Kopere BI.

Why use this report?

Provides an aggregated view of platform usage, combining academic enrolment and completion indicators with user-level tracking records for initial administrative analysis.

Filtros disponíveis Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, user, cohort, or date range. Results include users with id > 0 who are neither deleted nor suspended and are not guest.

The academic aggregate considers only enrolments and enrolment methods with status 0. Tracking statistics use the available records in mdl_local_kopere_bi_tracking and mdl_local_kopere_bi_track_log, with no time-window restriction.

Visualization and full original SQL

The report contains one table and one SQL query, with Prism.js syntax highlighting. The original catalog provides a single SQL definition and no separate PostgreSQL variant.

1. Detailed platform usage summary by user · Table

Per-user table displaying name, email, account creation, calculated average grade, course count, formally completed courses, total recorded time, and visits aggregated from tracking logs.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) as user,
       kbi_u.email,
       kbi_u.timecreated,
       sub.grade,
       sub.courses,
       sub.completed_courses,
       lit.timespend                        AS timespend,
       lit.visits                           AS visits
FROM mdl_user kbi_u
       LEFT JOIN (SELECT kbi_ue.userid,
                         ROUND(AVG(CASE
                                     WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                                     ELSE kbi_g.finalgrade END), 0) AS grade,
                         COUNT(DISTINCT kbi_e.courseid)             as courses,
                         COUNT(DISTINCT kbi_cc.course)              as completed_courses
                  FROM mdl_user_enrolments kbi_ue
                         LEFT JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
                         LEFT JOIN mdl_course_completions kbi_cc
                           ON kbi_cc.timecompleted > 0 AND kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_ue.userid
                         LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemtype = 'course' AND kbi_gi.courseid = kbi_e.courseid
                         LEFT JOIN mdl_grade_grades kbi_g
                           ON kbi_g.userid = kbi_ue.userid AND kbi_g.itemid = kbi_gi.id AND kbi_g.finalgrade IS NOT NULL
                  WHERE kbi_ue.userid > 0
                    AND kbi_ue.status = 0
                    AND kbi_e.status = 0
                  GROUP BY kbi_ue.userid) sub ON sub.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_lit.userid, SUM(kbi_lil.timespend) as timespend, SUM(kbi_lil.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_lit
                         JOIN mdl_local_kopere_bi_track_log kbi_lil ON kbi_lil.trackid = kbi_lit.id
                  WHERE kbi_lil.id > 0
                  GROUP BY kbi_lit.userid) lit ON lit.userid = kbi_u.id
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'

Limitations and cautions

  • The average grade is calculated from available grading records. It is not necessarily weighted by course, contact hours, or credits; users without grades may have an empty field.
  • The distinct course count considers enrolment methods and enrolments with status zero but does not explicitly check expiry dates or course visibility.
  • Completed courses are identified by records in mdl_course_completions with timecompleted > 0. Formal course completion differs from completing individual activities.
  • Time and visits are aggregated from logs associated with the tracking table. Completeness depends on Kopere BI collection and retention; recorded time does not prove educational engagement.
  • Joins between enrolments and grade items may result in different record counts, affecting the interpretation of the average. Validate indicators before making institutional decisions.
  • Indicators may be missing for users without enrolments, grades, or tracking records. Do not confuse missing data with zero.
  • There is no separate PostgreSQL variant for this report; the SQL is preserved exactly as defined.
