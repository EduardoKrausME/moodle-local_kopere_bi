REPORT 110

Progress and grade analysis

Compares progress and grades and highlights students with the strongest results.

Report purpose

Two complementary visualizations: a course-average column chart limited to the 25 courses with the lowest health scores, and a table of up to 100 student records with no flagged risk and either high progress, a high grade, or recorded completion.

Why use this report?

Compare aggregated course progress and average grades while separately identifying students with strong results under fixed progress, grade, or completion criteria.

Available filters Visualizations and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, student, cohort, or period in either query. The chart reads the latest aggregate from mdl_local_kopere_bi_courseag, orders by healthscore ASC, and limits the results to 25 courses.

The table uses the latest batch in mdl_local_kopere_bi_engage, the fixed filter risklevel = 'none', and the condition progress >= 75 OR gradepercent >= 75 OR timecompleted IS NOT NULL. The query returns at most 100 rows. The actions30 field represents a previously calculated 30-day window, not an editable filter.

Visualizations and full original SQL

The report has two visualizations, each with full SQL, description, cache, and refresh frequency. Prism.js provides syntax highlighting. No separate PostgreSQL file exists for this definition in master, so none has been invented.

1. Progress and grade by course · Column chart

Column chart showing each course's name, average progress, and average grade from the aggregates table. It sorts by healthscore ascending and course name, with LIMIT 25. The selection comprises the 25 lowest health scores, not necessarily the highest grades.

Cache: none · Refresh: none.

Full original SQL

SELECT c.fullname AS course, ca.avgprogress AS average_progress, ca.avggrade AS average_grade
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, c.fullname
LIMIT 25
2. Students with the strongest results · Table

Table of student-course records with stored risk level none and at least one qualifying criterion: progress >= 75, gradepercent >= 75, or non-NULL timecompleted. It shows progress, percentage grade, actions over 30 days, completion, and engagement, limited to the first 100 sorted records.

Cache: none · Refresh: none.

Full original SQL

SELECT e.id, e.userid, u.firstname, u.lastname, e.courseid, c.fullname AS course, e.progress, e.gradepercent, e.actions30, e.timecompleted,
       CASE e.engagement WHEN 'high' THEN 'lang::analytics_level_high::local_kopere_bi' WHEN 'medium' THEN 'lang::analytics_level_medium::local_kopere_bi' WHEN 'low' THEN 'lang::analytics_level_low::local_kopere_bi' ELSE 'lang::analytics_level_atrisk::local_kopere_bi' END AS engagement
FROM mdl_local_kopere_bi_engage e
JOIN mdl_user u ON u.id = e.userid
JOIN mdl_course c ON c.id = e.courseid
WHERE e.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
  AND e.risklevel = 'none'
  AND (e.progress >= 75 OR e.gradepercent >= 75 OR e.timecompleted IS NOT NULL)
ORDER BY COALESCE(e.gradepercent, e.progress) DESC, e.progress DESC, c.fullname, u.lastname, u.firstname
LIMIT 100

Calculation criteria and behavior

The avgprogress and avggrade averages and healthscore are precomputed by analytics processing. The first query only displays them in the chart and applies sorting and a limit.

The second query selects records by risk level and performance or completion. Sorting begins with COALESCE(gradepercent, progress) DESC, followed by progress, course, and student name. When a grade is available, it takes precedence in the first sort key even if progress is higher.

Limitations and cautions

  • The chart displays the 25 courses with the lowest healthscore; it is not necessarily a ranking of courses with the highest grades or progress.
  • The queries use the courseag and engage tables, whose latest batches may have different dates. The two visualizations are not guaranteed to be synchronized.
  • The label 'strongest results' is an editorial classification based on fixed thresholds. A student may appear solely because completion is recorded, without a grade or progress of at least 75.
  • The risk filter requires exactly none. Students who are unclassified or have another risk level are excluded even if their performance is high.
  • The 100-row limit and the use of COALESCE in sorting can omit records and prioritize grades over progress when both are available.
  • Progress, averages, and percentage grades depend on formulas previously applied by Kopere BI. The table includes individual academic data and requires access controls.

The queries are reproduced unchanged from the original JSON in master. No SQL was executed on a Moodle installation during this documentation work. Confirm permissions, results, batch freshness, and database compatibility before institutional use.
