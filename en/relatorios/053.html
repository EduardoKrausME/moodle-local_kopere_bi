REPORT 053

Gradebook by course category

Lists users assigned the student role in visible courses, displaying student identification details and their associated courses.

Report purpose

Lists users assigned the student role in visible courses, displaying student identification details and their associated courses.

Why use this report?

Helps identify students associated with visible courses and provides a starting point for checking the population expected to have gradebook records.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, course category, user, or time period. The query covers visible courses with positive IDs, student role ID 5 assignments in course contexts (contextlevel = 50), and users who are neither deleted nor suspended and are not guest.

A subquery for category-type grade items is associated with user and course through a LEFT JOIN, but no additional condition requires an existing grade or a particular category.

Visualization and full original SQL

One table visualization includes one SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant file exists for this report.

1. Gradebook by course category · Table

The table displays the student's ID, first name, surname, and institutional identification number, along with the ID and full name of the course to which their role is assigned.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.idnumber,
       kbi_c.id AS courseid,
       kbi_c.fullname
FROM mdl_course kbi_c
       JOIN mdl_context kbi_con ON kbi_con.contextlevel = 50 AND kbi_con.instanceid = kbi_c.id
       JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_con.id
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       LEFT JOIN (SELECT t.userid, t.courseid
                  FROM (SELECT kbi_gg.itemid, kbi_gg.userid, kbi_gi.courseid
                        FROM mdl_grade_grades kbi_gg
                               JOIN mdl_grade_items kbi_gi ON kbi_gi.id = kbi_gg.itemid
                        WHERE kbi_gi.itemtype = 'category') t
                  GROUP BY t.userid, t.courseid) gt ON gt.userid = kbi_u.id AND gt.courseid = kbi_c.id
WHERE kbi_c.id > 0
  AND kbi_c.visible = 1
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_ra.roleid = 5
GROUP BY kbi_u.id, kbi_c.id

Limitations and cautions

  • Despite its title, the result does not show grades or grade-category names or IDs. The SELECT returns only student and course information.
  • The gt subquery identifies user-course pairs with category-type grade items, but the SQL uses no gt fields in the SELECT or WHERE clauses. Therefore, it does not limit results to students with category grades.
  • There is no filter for course category, gradebook category, or a selected course. The report title may suggest greater specificity than the query actually implements.
  • The population is based on role ID 5 assignments, rather than a direct check of active enrolment or enrolment validity.
  • Grouping by user and course prevents duplicate pairs in the results, but does not introduce grade or completion metrics.
  • The query includes the student's institutional identifier (idnumber), requiring access and export controls.
  • There is no separate PostgreSQL variant file for this definition.
