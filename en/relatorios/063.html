REPORT 063

Quiz performance statistics

Per-quiz summary of visible quizzes showing attempt counts, distinct participants, score statistics, average duration, and calculated pass rates.

Report purpose

Per-quiz summary of visible quizzes showing attempt counts, distinct participants, score statistics, average duration, and calculated pass rates.

Why use this report?

Provides course managers with preliminary indicators of quiz usage and grade distributions, helping identify assessments that warrant pedagogical or technical investigation.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, quiz, student, or time period. The query includes quizzes associated with visible courses and modules.

Attempts are included when kbi_qa.preview = 0. Finished attempts are counted using kbi_qa.state = 'finished'; score and duration calculations use fixed conditions requiring a positive maximum grade and an end time later than the start, respectively. The calculated pass rate requires kbi_gi.gradepass > 0 and a final grade at least equal to the configured threshold.

Visualization and full original SQL

One table visualization contains two full SQL queries, cache and refresh settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL variants appear in separate panels within the same block.

1. Quiz performance statistics · Table

The table shows each quiz and course, question slot count, distinct users with attempts, total and finished attempts, mean, minimum, maximum, and population standard deviation of percentage scores, average duration in seconds, and a calculated pass rate.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_qz.id                                                           AS id,
       kbi_c.id                                                            AS courseid,
       kbi_c.fullname                                                      AS course,
       kbi_cm.id                                                           AS cmid,
       kbi_qz.id                                                           AS quizid,
       kbi_qz.name                                                         AS quiz_name,
       COUNT(DISTINCT kbi_slot.id)                                         AS question_slots,
       COUNT(DISTINCT kbi_qa.userid)                                       AS learners_attempted,
       COUNT(kbi_qa.id)                                                    AS attempts,
       SUM(CASE WHEN kbi_qa.state = 'finished' THEN 1 ELSE 0 END)          AS finished_attempts,
       ROUND(AVG(CASE WHEN kbi_qz.sumgrades > 0 THEN (kbi_qa.sumgrades * 100 / kbi_qz.sumgrades) ELSE NULL END), 2) AS average_score_percent,
       ROUND(MIN(CASE WHEN kbi_qz.sumgrades > 0 THEN (kbi_qa.sumgrades * 100 / kbi_qz.sumgrades) ELSE NULL END), 2) AS minimum_score_percent,
       ROUND(MAX(CASE WHEN kbi_qz.sumgrades > 0 THEN (kbi_qa.sumgrades * 100 / kbi_qz.sumgrades) ELSE NULL END), 2) AS maximum_score_percent,
       ROUND(STDDEV_POP(CASE WHEN kbi_qz.sumgrades > 0 THEN (kbi_qa.sumgrades * 100 / kbi_qz.sumgrades) ELSE NULL END), 2) AS standard_deviation_percent,
       ROUND(AVG(CASE WHEN kbi_qa.timefinish > kbi_qa.timestart THEN kbi_qa.timefinish - kbi_qa.timestart ELSE NULL END), 0) AS average_duration,
       ROUND(SUM(CASE WHEN kbi_gi.gradepass > 0 AND kbi_gg.finalgrade >= kbi_gi.gradepass THEN 1 ELSE 0 END) * 100 / NULLIF(COUNT(kbi_qa.id), 0), 2) AS pass_rate_percent
FROM mdl_quiz kbi_qz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_qz.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'quiz'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_qz.id
       LEFT JOIN mdl_quiz_slots kbi_slot ON kbi_slot.quizid = kbi_qz.id
       LEFT JOIN mdl_quiz_attempts kbi_qa ON kbi_qa.quiz = kbi_qz.id AND kbi_qa.preview = 0
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemmodule = 'quiz' AND kbi_gi.iteminstance = kbi_qz.id AND kbi_gi.courseid = kbi_c.id
       LEFT JOIN mdl_grade_grades kbi_gg ON kbi_gg.itemid = kbi_gi.id AND kbi_gg.userid = kbi_qa.userid
WHERE kbi_c.visible = 1
  AND kbi_cm.visible = 1
GROUP BY kbi_qz.id, kbi_c.id, kbi_cm.id, kbi_gi.gradepass
ORDER BY kbi_c.fullname, kbi_qz.name

       ROUND((AVG(CASE WHEN kbi_qa.timefinish > kbi_qa.timestart THEN kbi_qa.timefinish - kbi_qa.timestart ELSE NULL END))::numeric, 0) AS average_duration,

FROM mdl_quiz kbi_qz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_qz.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'quiz'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_qz.id
       LEFT JOIN mdl_quiz_slots kbi_slot ON kbi_slot.quizid = kbi_qz.id
       LEFT JOIN mdl_quiz_attempts kbi_qa ON kbi_qa.quiz = kbi_qz.id AND kbi_qa.preview = 0
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemmodule = 'quiz' AND kbi_gi.iteminstance = kbi_qz.id AND kbi_gi.courseid = kbi_c.id

Limitations and cautions

  • Beware of multiplied rows. The SQL joins question slots and attempts to the same quiz without first aggregating them. In quizzes with multiple slots, each attempt may be repeated, inflating attempts and finished_attempts.
  • The question_slots column uses COUNT(DISTINCT kbi_slot.id), while learners_attempted counts distinct users. These measures are not affected by the same multiplication as simple attempt counts.
  • The pass_rate_percent value is calculated from attempt rows produced by the joins, not unique users. A final grade record may cause multiple attempts by the same user to be classified as passed; this is not an official student pass rate.
  • Percentage scores use kbi_qa.sumgrades / kbi_qz.sumgrades, requiring a positive maximum grade. Except for the specific finished_attempts count, scores are not restricted to completed attempts.
  • Average duration includes attempts with timefinish > timestart and calculates elapsed seconds. It does not account for pauses or study time outside the attempt.
  • The standard deviation uses STDDEV_POP and can return NULL when sufficient valid scoring data are unavailable.
  • For quizzes without attempts, some aggregates may be zero or NULL. The pass-rate calculation uses NULLIF to protect against division by zero.
  • The MySQL and PostgreSQL variants use database-specific rounding and type conversions. Validate results before making assessment decisions.
