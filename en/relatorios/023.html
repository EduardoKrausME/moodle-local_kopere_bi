REPORT 023

User status

Per-active-enrolment table for the selected course, including student profile, enrolment type and status, grades, formal completion, course access, tracked time, and visits.

Report purpose

Per-active-enrolment table for the selected course, including student profile, enrolment type and status, grades, formal completion, course access, tracked time, and visits.

Why use this report?

Helps academic teams review student status in a course, inspect enrolment records, and identify needs for individual contact and follow-up.

Actual filters Visualization and SQL Limitations

Available filters

The available dynamic SQL filter is Course, represented by :courseid. It restricts enrolments to the selected course.

Fixed criteria also require users who are neither deleted nor suspended and are not guest, a visible course, and enrolments and enrolment methods with status 0. There are no user, cohort, or date-range SQL parameters.

Visualization and full original SQL

The report contains one table visualization and one SQL query, with cache, refresh settings, and Prism.js syntax highlighting. The catalog does not provide a separate PostgreSQL variant.

1. User status · Table

The table combines students and courses with enrolment date, expected enrolment end, status, last course access, calculated grade, course completion, enrolment method, profile details, and Kopere BI tracked time and visits.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_ue.id,
       kbi_ue.timecreated                      AS enrolled,
       kbi_ue.timeend,
       kbi_ue.status                           AS enroll_status,
       kbi_ul.timeaccess,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0) AS grade,
       kbi_c.enablecompletion,
       kbi_cc.timecompleted                    AS complete,
       kbi_u.id                                AS uid,
       kbi_u.email,
       kbi_u.idnumber,
       kbi_u.phone1,
       kbi_u.phone2,
       kbi_u.institution,
       kbi_u.department,
       kbi_u.address,
       kbi_u.city,
       kbi_u.country,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.username,
       kbi_e.enrol                             AS enrols,
       kbi_c.id                                AS cid,
       kbi_c.fullname                          AS course,
       kbi_c.shortname,
       kbi_c.timemodified                      AS start_date,
       ''                                  as cohortname,
       l.timespend,
       l.visits
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_u.id
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_ue.userid
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemtype = 'course' AND kbi_gi.courseid = kbi_e.courseid
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.userid = kbi_u.id AND kbi_g.itemid = kbi_gi.id AND kbi_g.finalgrade IS NOT NULL
       LEFT JOIN (SELECT courseid,
                         userid,
                         SUM(timespend) AS timespend,
                         SUM(visits)    AS visits
                  FROM mdl_local_kopere_bi_tracking
                  GROUP BY courseid, userid) l ON l.courseid = kbi_c.id AND l.userid = kbi_u.id
WHERE kbi_ue.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The enrolment status field (enroll_status) will be zero in selected rows because the SQL already requires kbi_ue.status = 0; it therefore does not represent every possible status.
  • The date shown as start_date comes from kbi_c.timemodified, which is the course's last modification time, not necessarily its start date.
  • The cohortname field is explicitly set to an empty string and does not identify the student's actual cohort.
  • Missing timeaccess or tracking data may indicate missing records rather than conclusively demonstrating no activity.
  • The grade indicator uses available course grade item records; a missing grade must not be interpreted as zero.
  • The report includes personal data such as phone numbers and addresses. Review access and privacy controls; no separate PostgreSQL variant is provided.
