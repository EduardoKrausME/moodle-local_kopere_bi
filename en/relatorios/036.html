REPORT 036

Course access details

Per-user table for the selected course based on Kopere BI access and tracking records, including recorded time, visits, and formal course completion.

Report purpose

Per-user table for the selected course based on Kopere BI access and tracking records, including recorded time, visits, and formal course completion.

Why use this report?

Helps investigate how users with tracking records used a specific course, comparing recorded time, visits, and any formal course completion.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, linked to :courseid, which occurs once in the condition kbi_c.id = :courseid.

The only other main criterion is kbi_l.id > 0, requiring an associated log record. The SQL does not restrict results by active user, deleted or suspended account, course visibility, current enrolment, student role, or time period.

Visualization and full original SQL

One table visualization includes one full SQL query, cache settings, and Prism.js syntax highlighting. No separate PostgreSQL variant file is available.

1. Course access details · Table

The per-user, per-course table includes name, email, course category, formal completion date where recorded, and time and visits summed from logs associated with Kopere BI tracking records.

Cache: 1h · Refresh: none.

Full original SQL

SELECT max(kbi_t.id)             AS tid,
       kbi_u.id                  AS id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.fullname,
       kbi_c.shortname,
       kbi_ca.name               AS category,
       MAX(kbi_cc.timecompleted) AS timecompleted,
       SUM(kbi_l.timespend)      AS timespend,
       SUM(kbi_l.visits)         AS visits
FROM mdl_local_kopere_bi_track_log kbi_l
       JOIN mdl_local_kopere_bi_tracking kbi_t ON kbi_t.id = kbi_l.trackid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_t.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_t.courseid
       JOIN mdl_course_categories kbi_ca ON kbi_ca.id = kbi_c.category
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.userid = kbi_u.id AND kbi_cc.course = kbi_c.id
WHERE kbi_l.id > 0
  AND kbi_c.id = :courseid
GROUP BY kbi_u.id, kbi_c.id, kbi_ca.id

Limitations and cautions

  • Because the query starts from tracking logs, users without records in mdl_local_kopere_bi_track_log do not appear, even if they are enrolled and accessed Moodle through other routes.
  • The SQL does not require an active enrolment or a specific course role. Teachers, students, and other users with tracking records may appear.
  • Unlike other reports, this query does not filter deleted or suspended accounts or course visibility. Review institutional permissions before exposing these rows.
  • Time and visits are summed from records collected by Kopere BI, without an explicit time window. They do not prove sustained attention or effective learning.
  • The timecompleted date comes from mdl_course_completions, indicating formal course completion where recorded, not the completion of individual modules.
  • The aggregation uses MAX(kbi_t.id) for the tracking identifier and groups by user, course, and category. A single tracking identifier does not necessarily summarize every recorded occurrence.
  • This report has no separate PostgreSQL variant file. Because it displays identifiable user and access information, restrict use and exports to authorized roles.
