REPORT 076

Student participation in forums

Summarizes, by discussion author and forum in the selected course, the number of discussions started and posts by that same author within those discussions.

Report purpose

Summarizes, by discussion author and forum in the selected course, the number of discussions started and posts by that same author within those discussions.

Why use this report?

Helps teachers identify who started discussions in each forum and how many posts those authors made in their own discussions, supporting a more detailed review of participation.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic SQL filter is Course, represented by :courseid and used once in kbi_c.id = :courseid.

Fixed conditions require a visible course, a discussion author who is neither deleted nor suspended and is not guest, and a discussion with a positive ID. There are no filters for period, role, active enrolment, or forum visibility.

Visualization and full original SQL

One table visualization contains one complete SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the original catalog.

1. Student participation in forums · Table

The per-user, per-forum table lists the course name, author's first name and surname, forum name, number of discussions started, distinct posts by the same author within those discussions, and the highest discussion ID in the group.

Cache: 1h · Refresh: none.

Full original SQL

SELECT MAX(kbi_fd.id)            AS id,
       kbi_c.fullname            as course,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_f.name,
       COUNT(DISTINCT kbi_fp.id) AS posts,
       COUNT(DISTINCT kbi_fd.id) AS discussions
FROM mdl_forum_discussions kbi_fd
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_fd.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_fd.course
       LEFT JOIN mdl_forum kbi_f ON kbi_f.id = kbi_fd.forum
       LEFT JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id AND kbi_fp.userid = kbi_u.id
WHERE kbi_fd.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
GROUP BY kbi_u.id, kbi_c.id, kbi_f.id
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname, kbi_f.name

Limitations and cautions

  • The title mentions students, but the SQL does not filter for the student role. Any eligible user who started a discussion may appear, including teachers and other participants.
  • The discussions column counts discussions started by the user, not all discussions in which that user participated.
  • The posts column counts only posts by the author within discussions they started. Replies they made to discussions started by others are excluded.
  • Post counts may include both the initial post and replies by the same user because there is no parent > 0 filter.
  • Discussions without a valid author record are excluded. The query does not verify each forum's or module's status or visibility.
  • The id column uses MAX(kbi_fd.id), the highest discussion identifier in the group, not an identifier of the user or forum.
  • There is no participation percentage, response rate, reporting period, or qualitative evaluation of messages. No separate PostgreSQL variant is provided for this report.
