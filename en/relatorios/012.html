REPORT 012

Inactive users on the platform

Table of users whose last recorded activity in Moodle was more than 30 days ago, based on the global last-access field in their account profile.

Report purpose

Table of users whose last recorded activity in Moodle was more than 30 days ago, based on the global last-access field in their account profile.

Why use this report?

Helps identify accounts that may require contact or follow-up because of a lack of recent platform access, without limiting the results to a particular course.

Actual filters Visualizations and SQL Limitations

Available filters

There are no dynamic course, user, cohort, or date-range SQL parameters. The time condition is fixed: kbi_u.lastaccess < (agora - 2592000 segundos), corresponding to 30 days.

The SQL considers only accounts that are neither deleted nor suspended, excludes the username guest, and requires kbi_u.id > 0.

Visualizations and full SQL

This report provides one table visualization and two equivalent SQL queries, including cache and refresh settings. The complete MySQL and PostgreSQL queries are shown in separate panels within the same block, with Prism.js syntax highlighting.

1. Inactive users on the platform · Table

Table of users with name, email address, account creation date, first access, last access, and last login, ordered according to the table's display settings.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT DISTINCT kbi_u.id,
                kbi_u.firstname,
                kbi_u.lastname,
                kbi_u.email,
                kbi_u.timecreated,
                kbi_u.firstaccess,
                kbi_u.lastaccess,
                kbi_u.lastlogin
FROM mdl_user kbi_u
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_u.lastaccess < (UNIX_TIMESTAMP() - 2592000)

Full original PostgreSQL SQL

SELECT DISTINCT kbi_u.id,
                kbi_u.firstname,
                kbi_u.lastname,
                kbi_u.email,
                kbi_u.timecreated,
                kbi_u.firstaccess,
                kbi_u.lastaccess,
                kbi_u.lastlogin
FROM mdl_user kbi_u
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_u.lastaccess < ((EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) - 2592000)

Limitations and cautions

  • The query uses the user's global lastaccess field, not the last access to a particular course or activity.
  • Accounts with lastaccess = 0 are also included by the 30-day condition; this may include people who have never accessed the platform.
  • The 30-day period is fixed; another time window requires changing the SQL.
  • The query does not check for an active enrolment, student role, or course participation, so it must not be interpreted as a student-only list.
  • The results contain personal information; restrict access and exports in accordance with institutional policy.
