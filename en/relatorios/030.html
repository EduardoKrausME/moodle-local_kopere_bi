REPORT 030

Teacher engagement by course

Table of teachers in the selected course with student and formal completion counts, recorded time and visits, and last course access date.

Report purpose

Table of teachers in the selected course with student and formal completion counts, recorded time and visits, and last course access date.

Why use this report?

Helps coordinators review teachers' recorded activity alongside course-level student and completion totals, supporting academic organization and follow-up.

Available filters Visualization and SQL Limitations

Available filters

The SQL uses the dynamic :courseid parameter four times: to select the main course, aggregate teacher tracking, count students with role ID 5, and count formal course completions.

Fixed filters require teacher role ID 3, course context 50, a visible course, and an account that is neither deleted nor suspended and is not guest. There are no dynamic filters for teacher, cohort, or date range.

Visualization and full original SQL

The report has one table visualization and one SQL query, with cache and refresh settings and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the catalog.

1. Teacher engagement by course · Table

The table shows teacher, course, number of users assigned the student role, formal course completion records, teacher time and visits, and last course access. Where available, the last-access value comes from Kopere BI tracking; otherwise, the query falls back to Moodle's last course access field.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_ra.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.fullname,
       kbi_c.shortname,
       e.enrolled                                                AS enrolled,
       cc.completed                                              AS completed,
       CASE WHEN l.timespend IS NULL THEN 0 ELSE l.timespend END AS timespend,
       CASE WHEN l.visits IS NULL THEN 0 ELSE l.visits END       AS visits,
       CASE
         WHEN l.last_access IS NULL THEN kbi_mla.timeaccess
         ELSE l.last_access END                                  AS last_access
FROM mdl_user kbi_u
       JOIN mdl_role_assignments kbi_ra ON kbi_ra.userid = kbi_u.id AND kbi_ra.roleid = 3
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid AND kbi_c.id = :courseid
       LEFT JOIN (SELECT userid,
                         courseid,
                         SUM(kbi_t1.timespend)  AS timespend,
                         SUM(kbi_t1.visits)     AS visits,
                         MAX(kbi_t1.lastaccess) AS last_access
                  FROM mdl_local_kopere_bi_tracking kbi_t1
                  WHERE kbi_t1.id > 0
                    AND kbi_t1.courseid = :courseid
                  GROUP BY kbi_t1.courseid, kbi_t1.userid) l ON l.userid = kbi_u.id AND l.courseid = kbi_c.id
       JOIN mdl_user_lastaccess kbi_mla ON kbi_mla.userid = kbi_u.id AND kbi_mla.courseid = kbi_c.id
       LEFT JOIN (SELECT kbi_ctx1.instanceid, COUNT(DISTINCT kbi_ra1.userid) AS enrolled
                  FROM mdl_role_assignments kbi_ra1
                         JOIN mdl_context kbi_ctx1 ON kbi_ctx1.id = kbi_ra1.contextid AND kbi_ctx1.contextlevel = 50
                  WHERE kbi_ra1.roleid = 5
                    AND kbi_ctx1.instanceid = :courseid
                  GROUP BY kbi_ctx1.instanceid) e ON e.instanceid = kbi_c.id
       LEFT JOIN (SELECT course, COUNT(id) AS completed
                  FROM mdl_course_completions kbi_cc1
                  WHERE timecompleted > 0
                    AND kbi_cc1.course = :courseid
                  GROUP BY course) cc ON cc.course = kbi_c.id
WHERE kbi_ra.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
GROUP BY kbi_ra.id, kbi_u.id, kbi_c.id, e.enrolled, cc.completed, kbi_u.firstname, kbi_u.lastname, kbi_u.email, kbi_c.fullname, kbi_c.shortname,
         l.timespend, l.visits, l.last_access, kbi_mla.timeaccess

Limitations and cautions

  • The query requires a JOIN mdl_user_lastaccess record for the teacher in that course. Teachers with no record in this table are excluded even if they have the required role assignment.
  • The enrolled and completed totals are calculated at course level and repeated across teachers' rows; they are not individual teacher totals.
  • The enrolled count uses role ID 5 assignments without explicitly checking enrolment status.
  • The completed total counts mdl_course_completions records with a completion date greater than zero; it excludes partial activity completions.
  • The timespend and visits columns replace missing tracking data with zero, which does not necessarily establish that the course was never used.
  • There is no tracking time window: the totals reflect the history retained by Kopere BI. Last access may come from different sources depending on tracking availability.
  • There is no dedicated PostgreSQL file for this definition, and the personal information requires appropriate access permissions.
