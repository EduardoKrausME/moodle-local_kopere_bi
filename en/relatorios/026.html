REPORT 026

Forum statistics by teacher

Summary of forums in the selected course, including tracked visits and time, discussion and post counts, calculated forum count, and assigned teachers' names.

Report purpose

Summary of forums in the selected course, including tracked visits and time, discussion and post counts, calculated forum count, and assigned teachers' names.

Why use this report?

Helps analyze aggregate forum usage in a course, including discussion volume, posts, and recorded tracking data, to inform moderation and facilitation.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is :courseid, applied to the course being summarized.

Fixed criteria include a visible course (kbi_c.visible = 1), a positive course ID, activity tracking records with page = 'module' linked to forum modules, and teachers identified by role ID 3 in a course context (contextlevel = 50). There is no dynamic filter for teacher, individual forum, or date range.

Visualization and full original SQL

The report contains one table visualization and two SQL queries, with cache and refresh settings and Prism.js syntax highlighting. MySQL and PostgreSQL variants appear in separate panels within the same visualization block.

1. Forum statistics by teacher · Table

The per-course summary shows visits and time spent in forum modules recorded by Kopere BI, discussion counts, post counts, aggregate forum record counts, and teachers assigned role ID 3.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       MAX(v.visits)      AS visits,
       MAX(v.timespend)   AS timespend,
       MAX(d.discussions) AS discussions,
       MAX(p.posts)       AS posts,
       COUNT(*)           AS total,
       tchr.teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_forum kbi_f ON kbi_f.course = kbi_c.id
       LEFT JOIN (SELECT kbi_lit.courseid, SUM(kbi_lit.timespend) as timespend, SUM(kbi_lit.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_lit, mdl_course_modules kbi_cm, mdl_modules kbi_m
                  WHERE kbi_lit.page = 'module'
                    and kbi_cm.id = kbi_lit.param
                    and kbi_m.id = kbi_cm.module
                    and kbi_m.name = 'forum'
                  GROUP BY kbi_lit.courseid) v ON v.courseid = kbi_c.id
       LEFT JOIN (SELECT course, count(*) discussions FROM mdl_forum_discussions group by course) d ON d.course = kbi_c.id
       LEFT JOIN (SELECT kbi_fd.course, count(*) posts
                  FROM mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
                  WHERE kbi_fp.discussion = kbi_fd.id
                  group by kbi_fd.course) p ON p.course = kbi_c.id
       LEFT JOIN (SELECT GROUP_CONCAT(DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) SEPARATOR ', ') AS teacher,
                         kbi_ctx.instanceid
                  FROM mdl_role_assignments kbi_ra
                         JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
                         JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
                  WHERE kbi_ctx.contextlevel = 50
                    AND kbi_ra.roleid = 3
                  GROUP BY kbi_ctx.instanceid) tchr ON tchr.instanceid = kbi_c.id
WHERE kbi_c.id > 0
  AND kbi_c.visible = 1
  AND kbi_c.id = :courseid
GROUP BY kbi_c.id, tchr.teacher

Full original PostgreSQL SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       MAX(v.visits)      AS visits,
       MAX(v.timespend)   AS timespend,
       MAX(d.discussions) AS discussions,
       MAX(p.posts)       AS posts,
       COUNT(*)           AS total,
       tchr.teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_forum kbi_f ON kbi_f.course = kbi_c.id
       LEFT JOIN(SELECT kbi_lit.courseid, SUM(kbi_lit.timespend) as timespend, SUM(kbi_lit.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_lit, mdl_course_modules kbi_cm, mdl_modules kbi_m
                  WHERE kbi_lit.page = 'module'
                    and kbi_cm.id = kbi_lit.param
                    and kbi_m.id = kbi_cm.module
                    and kbi_m.name = 'forum'
                  GROUP BY kbi_lit.courseid) v ON v.courseid = kbi_c.id
       LEFT JOIN(SELECT course, count(*) discussions FROM mdl_forum_discussions group by course) d ON d.course = kbi_c.id
       LEFT JOIN(SELECT kbi_fd.course, count(*) posts
                  FROM mdl_forum_discussions kbi_fd, mdl_forum_posts kbi_fp
                  WHERE kbi_fp.discussion = kbi_fd.id
                  group by kbi_fd.course) p ON p.course = kbi_c.id
       LEFT JOIN(SELECT STRING_AGG(DISTINCT (CONCAT(kbi_u.firstname, ' ', kbi_u.lastname))::text, ', ') AS teacher,
                         kbi_ctx.instanceid
                  FROM mdl_role_assignments kbi_ra
                         JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
                         JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
                  WHERE kbi_ctx.contextlevel = 50
                    AND kbi_ra.roleid = 3
                  GROUP BY kbi_ctx.instanceid) tchr ON tchr.instanceid = kbi_c.id
WHERE kbi_c.id > 0
  AND kbi_c.visible = 1
  AND kbi_c.id = :courseid
GROUP BY kbi_c.id, tchr.teacher

Limitations and cautions

  • Despite its 'by teacher' title, the query groups results by course and lists assigned teachers. Visits, discussions, and posts are not attributed to individual teachers.
  • The total field uses COUNT(*) over a forum LEFT JOIN. Even if no forum records exist, the count may be 1 because the course row is retained. This does not guarantee an accurate forum count.
  • Discussion and post counts aggregate activity across all forums in the course without distinguishing authorship, teacher participation, or time period.
  • Time and visits come from forum-module tracking records and depend on the installation and data collection and retention.
  • The teacher list uses role ID 3, which may be customized in the installation. MySQL and PostgreSQL variants use different aggregators to concatenate names.
  • There are no date selectors in this definition. Analysis of a particular period requires different SQL or a compatible filtering mechanism.
  • The query includes teachers' names and course-related data; respect administrative access permissions.
