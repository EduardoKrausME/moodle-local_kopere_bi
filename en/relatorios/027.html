REPORT 027

Teacher activity engagement details

Table of teachers associated with the selected course and its visible activities, including visits, tracked time, and access dates recorded by Kopere BI.

Report purpose

Table of teachers associated with the selected course and its visible activities, including visits, tracked time, and access dates recorded by Kopere BI.

Why use this report?

Helps course coordinators and support teams review teachers' tracking records for course activities and locate modules with little recorded usage.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is :courseid, which selects the course to analyze.

The SQL requires teacher role ID 3 in a course context (contextlevel = 50), users who are neither deleted nor suspended and are not guest, a visible course, and visible modules (kbi_cm.visible = 1). The tracking join uses kbi_lit.page = 'module' and kbi_lit.param = kbi_cm.id. There is no teacher, module-type, or date SQL filter.

Visualization and full original SQL

The report contains one table visualization and one SQL query, with cache, refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant file is provided.

1. Teacher activity engagement details · Table

Table combining teachers, courses, modules, and activity instances with visits, tracked time, and first and last access dates. Teachers are paired with visible modules before the optional join to Kopere BI tracking data.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_lit.id                                                        AS lid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.fullname,
       kbi_c.shortname,
       CASE WHEN kbi_lit.visits IS NULL THEN 0 ELSE kbi_lit.visits END       AS visits,
       CASE WHEN kbi_lit.timespend IS NULL THEN 0 ELSE kbi_lit.timespend END AS timespend,
       kbi_lit.firstaccess,
       kbi_lit.lastaccess,
       kbi_cm.instance,
       kbi_m.name                                                        AS module
FROM mdl_role_assignments kbi_ra
       JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id
       LEFT JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       LEFT JOIN mdl_local_kopere_bi_tracking kbi_lit ON kbi_lit.userid = kbi_u.id AND kbi_lit.param = kbi_cm.id AND kbi_lit.page = 'module'
WHERE kbi_ctx.contextlevel = 50
  AND kbi_c.id = :courseid
  AND kbi_ra.roleid = 3
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • The table matches assigned teachers with visible modules even where no tracking records exist. SQL converts missing visits and time to zero; this does not necessarily prove that the activity was never accessed.
  • First and last access dates are empty where there is no corresponding tracking record. Data collection depends on Kopere BI.
  • The teacher filter relies on fixed role ID 3 in the course context. Customized roles or assignments outside that context may be omitted.
  • There is no date-range restriction: the indicators reflect the tracking records available, and retention may vary.
  • The row identifies the module instance and type but does not provide the activity name directly. The user represented in the table is the teacher, not the student.
  • The report measures technical usage traces, not learning or the quality of educational facilitation.
  • There is no dedicated PostgreSQL variant file for this report.
