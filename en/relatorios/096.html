REPORT 096

Lesson response details

Details responses recorded on Lesson activity pages in visible courses, including participants, page content, question types, stored answers, and one associated teacher.

Report purpose

Details responses recorded on Lesson activity pages in visible courses, including participants, page content, question types, stored answers, and one associated teacher.

Why use this report?

Helps investigate answers recorded in Lesson activities, linking pages and participants to their courses and identifying a user assigned the conventional teacher role.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, lesson, user, teacher, date, or question type. The report queries Lesson attempts across all visible courses.

Fixed criteria require an existing Lesson, a participant who is neither deleted nor suspended and is not guest, and kbi_c.visible = 1. A subquery selects the user with the lowest ID assigned role ID 3 in the course context (contextlevel = 50) as the teacher.

Visualization and full original SQL

One table visualization includes the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL file is available for this definition.

1. Lesson response details · Table

Each row represents a recorded Lesson answer attempt, including its ID and timestamp; course; participant ID, email, and username; one teacher's ID, first name, surname, email, and username; Lesson name; page content as the question; question type; and stored answer.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_la.id       AS id,
       kbi_la.timeseen,
       kbi_c.id        AS courseid,
       kbi_c.fullname,
       kbi_c.shortname,
       kbi_u.id        AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_u.username,
       t.id        AS teacher_userid,
       t.firstname AS teacher_firstname,
       t.lastname  As teacher_lastname,
       t.email     AS teacher_email,
       t.username  AS teacher_username,
       kbi_l.name      AS lesson_name,
       kbi_lp.contents AS question_name,
       kbi_lp.qtype,
       kbi_la.useranswer
FROM mdl_lesson kbi_l
       JOIN mdl_lesson_attempts kbi_la ON kbi_la.lessonid = kbi_l.id
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_l.course
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_la.userid
       JOIN mdl_lesson_pages kbi_lp ON kbi_lp.id = kbi_la.pageid
       LEFT JOIN (SELECT a.courseid, kbi_u.firstname, kbi_u.lastname, kbi_u.email, kbi_u.username, kbi_u.id
                  FROM (SELECT kbi_ctx.instanceid AS courseid, MIN(kbi_ra.userid) AS userid
                        FROM mdl_role_assignments kbi_ra
                               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
                        WHERE kbi_ctx.contextlevel = 50
                          AND kbi_ra.roleid = 3
                        GROUP BY kbi_ctx.instanceid) a
                         JOIN mdl_user kbi_u ON kbi_u.id = a.userid) t ON t.courseid = kbi_c.id
WHERE kbi_l.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1

Limitations and cautions

  • The query does not restrict the course using :courseid. It can return participants' answers from many visible courses, with implications for privacy and result volume.
  • The question_name field comes from mdl_lesson_pages.contents, which may contain HTML and page content rather than a short title or question prompt alone.
  • The useranswer field contains the value stored in the attempt. Depending on the question type, it may be an identifier, an option, or encoded data rather than a directly readable answer.
  • The timeseen field is the timestamp stored with the Lesson attempt; it does not independently indicate activity duration or Lesson completion.
  • The teacher shown is the user with the lowest ID assigned fixed role ID 3, not necessarily the person responsible for the content, grading, or participant. Teacher fields are NULL when no user has that role.
  • The query does not check active enrolment, student role, attempt completion status, grade, or visibility of the specific Lesson module.
  • Email addresses, usernames, questions, and responses can be sensitive. Display and export must follow applicable access permissions and the purpose of educational monitoring.
  • The original source provides no separate PostgreSQL variant.
