REPORT 060

Activity submission progress

Shows visible modules and users in the selected course with participation dates for assignments, forums, quizzes, glossaries, and choices, plus grades and associated teachers.

Report purpose

Shows visible modules and users in the selected course with participation dates for assignments, forums, quizzes, glossaries, and choices, plus grades and associated teachers.

Why use this report?

Helps academic teams inspect technical evidence of activity participation, submission or interaction dates, and grade records by module type.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL parameter Course, :courseid, occurs six times in each variant: in the assignment, forum, quiz, glossary, and choice subqueries and the main selection.

Fixed criteria include visible courses and modules, accounts that are neither deleted nor suspended and are not guest. The teacher list uses course-context assignments with role ID 3. Assignment submissions must have status = 'submitted', but there is no general filter for active enrolment, time period, or student role.

Visualization and full original SQL

One table visualization contains full MySQL and PostgreSQL variants in separate panels within the same block. Prism.js provides SQL syntax highlighting.

1. Activity submission progress · Table

The table lists each enrolment and visible module with user and course identifiers, module type and ID, last course access, enrolment status and end date, teacher names, and three indicators calculated with GREATEST: submission or interaction date, grading date, and highest grade between assignments and quizzes.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_u.username,
       kbi_u.idnumber,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.shortname,
       kbi_c.fullname,
       kbi_m.name                               AS mod_name,
       kbi_cm.id                                AS instance_id,
       kbi_ul.timeaccess,
       kbi_ue.status,
       kbi_ue.timeend,
       GREATEST(
         COALESCE(ass.submitted, 0), COALESCE(f.posted, 0), COALESCE(q.started, 0), COALESCE(gl.submitted, 0),
         COALESCE(ch.submitted, 0)
           )                                AS overal_submission_date,
       GREATEST(
         COALESCE(ass.graded, 0), COALESCE(q.graded, 0)
           )                                AS overal_submission_graded,
       GREATEST(
         COALESCE(ass.grade, 0), COALESCE(q.grade, 0)
           )                                AS overal_submission_grade,
       teachers.teacher
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id
       JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.userid = kbi_u.id AND kbi_ul.courseid = kbi_c.id
       LEFT JOIN (SELECT kbi_ctx.instanceid,
                         GROUP_CONCAT(DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) SEPARATOR ', ') AS teacher
                  FROM mdl_role_assignments kbi_ra
                         JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
                         JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
                  WHERE kbi_ctx.contextlevel = 50
                    AND kbi_ra.roleid = 3
                  GROUP BY kbi_ctx.instanceid) AS teachers ON teachers.instanceid = kbi_c.id
       LEFT JOIN (SELECT kbi_ass.userid,
                         kbi_ass.assignment,
                         MAX(kbi_ass.timemodified) AS submitted,
                         MAX(kbi_ag.grade)         AS grade,
                         MAX(kbi_ag.timemodified)  AS graded
                  FROM mdl_assign_submission kbi_ass
                         JOIN mdl_assign kbi_m ON kbi_m.id = kbi_ass.assignment AND kbi_m.course = :courseid
                         LEFT JOIN mdl_assign_grades kbi_ag ON kbi_ag.assignment = kbi_ass.assignment AND kbi_ag.userid = kbi_ass.userid
                  WHERE kbi_ass.status = 'submitted'
                  GROUP BY kbi_ass.userid, kbi_ass.assignment) ass
         ON ass.userid = kbi_u.id AND ass.assignment = kbi_cm.instance AND kbi_m.name = 'assign'
       LEFT JOIN (SELECT kbi_fd.forum, kbi_fp.userid, MAX(kbi_fp.modified) AS posted, NULL AS grade, NULL AS graded
                  FROM mdl_forum_discussions kbi_fd
                         JOIN mdl_forum kbi_m ON kbi_m.id = kbi_fd.forum AND kbi_m.course = :courseid
                         LEFT JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id
                  GROUP BY kbi_fd.forum, kbi_fp.userid) f ON f.userid = kbi_u.id AND f.forum = kbi_cm.instance AND kbi_m.name = 'forum'
       LEFT JOIN (SELECT kbi_qa.quiz,
                         kbi_qa.userid,
                         MIN(kbi_qa.timestart)     AS started,
                         MAX(kbi_qgr.grade)        AS grade,
                         MAX(kbi_qgr.timemodified) AS graded
                  FROM mdl_quiz_attempts kbi_qa
                         JOIN mdl_quiz kbi_m ON kbi_m.id = kbi_qa.quiz AND kbi_m.course = :courseid
                         LEFT JOIN mdl_quiz_grades kbi_qgr ON kbi_qgr.quiz = kbi_m.id AND kbi_qgr.userid = kbi_qa.userid
                  GROUP BY kbi_qa.quiz, kbi_qa.userid) q ON q.userid = kbi_u.id AND q.quiz = kbi_cm.instance AND kbi_m.name = 'quiz'
       LEFT JOIN (SELECT kbi_ge.glossaryid, kbi_ge.userid, MAX(kbi_ge.timecreated) AS submitted, NULL AS grade, NULL AS graded
                  FROM mdl_glossary_entries kbi_ge
                         JOIN mdl_glossary kbi_m ON kbi_m.id = kbi_ge.glossaryid AND kbi_m.course = :courseid
                  GROUP BY kbi_ge.glossaryid, kbi_ge.userid) gl
         ON gl.userid = kbi_u.id AND gl.glossaryid = kbi_cm.instance AND kbi_m.name = 'glossary'
       LEFT JOIN (SELECT kbi_ca.choiceid, kbi_ca.userid, MAX(kbi_ca.timemodified) AS submitted, NULL AS grade, NULL AS graded
                  FROM mdl_choice_answers kbi_ca
                         JOIN mdl_choice kbi_m ON kbi_m.id = kbi_ca.choiceid AND kbi_m.course = :courseid
                  GROUP BY kbi_ca.choiceid, kbi_ca.userid) ch
         ON ch.userid = kbi_u.id AND ch.choiceid = kbi_cm.instance AND kbi_m.name = 'choice'
WHERE kbi_ue.id > 0
  AND kbi_c.visible = 1
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_cm.visible = 1
  AND kbi_c.id = :courseid

Limitations and cautions

  • Despite its title, the query does not calculate a completion percentage, curricular progress, or submission rate. It presents aggregated event and grade fields.
  • The overal_submission_date column uses GREATEST across dates from different sources: assignment submission, forum post, quiz attempt start, glossary entry, and choice response. For quizzes it uses MIN(timestart), not the attempt completion or submission date.
  • The overal_submission_graded field chooses the latest available grade modification date across assignments and quizzes. It does not include grading from every activity type.
  • The overal_submission_grade column uses GREATEST for assignment and quiz grades, replacing missing values with zero. It is not an average grade and may conceal negative grades.
  • The query does not restrict enrolments to active status or check their validity periods. Multiple enrolments for the same user can produce repeated rows for the same module.
  • The teacher list relies on fixed role ID 3 and does not necessarily identify the grader or facilitator responsible for the activity shown.
  • Missing events may result in zero values for aggregated dates or grades without proving that no participation occurred outside the sources considered.
  • Email addresses, usernames, and institutional identifiers are displayed. Restrict access and treat the indicators as technical records, not direct measures of learning.
