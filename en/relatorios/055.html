REPORT 055

Activity completion statistics

Per-participant summary of active enrolments, completion-enabled modules, activity completion records, course grades, and calculated progress in the selected course.

Report purpose

Per-participant summary of active enrolments, completion-enabled modules, activity completion records, course grades, and calculated progress in the selected course.

Why use this report?

Supports an initial review of each participant's progress by comparing grades, activities with completion requirements, and formal course completion.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic SQL parameter is Course, corresponding to :courseid and used once in kbi_c.id = :courseid.

Fixed criteria require accounts that are neither deleted nor suspended and are not guest, a visible course, and enrolments and methods with status 0. The percentage denominator counts visible modules with completion > 0 and instance > 0; the numerator counts completion records in states 1 or 2 for visible modules. There are no dynamic filters for user, period, or cohort.

Visualization and full original SQL

One table visualization contains one SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided in the catalog.

1. Activity completion statistics · Table

The per-user, per-course table includes identifiers, enrolment date, average course-item grade, visible completion-enabled module count, completed activity records, calculated progress percentage, and formal course completion date when available.

Cache: 1h · Refresh: none.

Full original SQL

SELECT max(kbi_ue.id)                                              AS id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       MAX(kbi_ue.timecreated)                                     as enrolled,
       kbi_c.id                                                    AS courseid,
       kbi_u.id                                                    AS userid,
       kbi_c.fullname,
       ROUND(AVG(CASE
                   WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                   ELSE kbi_g.finalgrade END), 0)                  AS grade,
       MAX(m.modules)                                          AS modules,
       MAX(kbi_cc.timecompleted)                                   AS timecompleted,
       MAX(cmc.completed)                                      as modules_completed,
       round(((MAX(cmc.completed) / MAX(m.modules)) * 100), 0) as progress
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_cohort_members kbi_cm ON kbi_cm.userid = kbi_u.id
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_c.id AND kbi_gi.itemtype = 'course'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_gi.id = kbi_g.itemid AND kbi_g.userid = kbi_u.id
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.timecompleted > 0 AND kbi_cc.course = kbi_e.courseid and kbi_cc.userid = kbi_ue.userid
       LEFT JOIN (SELECT course, count(id) as modules
                  FROM mdl_course_modules
                  WHERE visible = 1
                    AND completion > 0
                    AND instance > 0
                  GROUP BY course) as m ON m.course = kbi_c.id
       LEFT JOIN (SELECT kbi_cm.course, kbi_x.userid, COUNT(DISTINCT kbi_x.id) as completed
                  FROM mdl_course_modules kbi_cm, mdl_course_modules_completion kbi_x
                  WHERE kbi_x.coursemoduleid = kbi_cm.id
                    AND kbi_cm.visible = 1
                    AND kbi_x.completionstate IN (1, 2)
                  GROUP BY kbi_cm.course, kbi_x.userid) as cmc ON cmc.course = kbi_c.id AND cmc.userid = kbi_ue.userid
WHERE kbi_ue.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
GROUP BY kbi_u.id, kbi_c.id

Limitations and cautions

  • The progress percentage divides module completion records by the number of visible modules with completion enabled. Its numerator is not explicitly restricted to modules with completion > 0, potentially yielding discrepancies or percentages above 100% for atypical data.
  • If no module has completion enabled, MAX(m.modules) may be NULL and the percentage may also be NULL. The SQL does not provide explicit NULLIF protection against a zero denominator.
  • The modules_completed column does not mean formal course completion. The timecompleted date comes from mdl_course_completions and reflects a different process.
  • The grade field averages available grade items of type course; missing grades do not establish zero performance.
  • The query uses LEFT JOIN mdl_cohort_members without filtering by cohort or showing cohort data. Users in multiple cohorts may multiply intermediate rows, even though final results are grouped by user and course.
  • Enrolment status must be zero, but the query does not explicitly check enrolment start and end dates or filter for the student role.
  • Because personal information and academic results are included, control access and exports. There is no separate PostgreSQL variant in the source.
