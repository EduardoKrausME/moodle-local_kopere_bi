REPORT 061

File uploads

Summary of Moodle file records grouped by component, including the number of files with positive sizes and the total recorded file sizes.

Report purpose

Summary of Moodle file records grouped by component, including the number of files with positive sizes and the total recorded file sizes.

Why use this report?

Helps administrators identify which components account for the most file records and recorded storage volume, providing a starting point for assessing space consumption and data growth.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, component, user, file type, or date range.

The only condition is kbi_f.filesize > 0, applied to mdl_files. The SQL groups records by kbi_f.component and sorts the results by summed file sizes in descending order.

Visualization and full original SQL

One table visualization contains one SQL query, cache and refresh settings, and Prism.js syntax highlighting. The catalog does not provide a separate PostgreSQL variant for this definition.

1. File uploads · Table

The table lists each component code, its file record count, the sum of file sizes in bytes, and the largest file ID in that component group. Results are sorted from the largest to the smallest byte total.

Cache: 1h · Refresh: none.

Full original SQL

SELECT MAX(kbi_f.id)             AS id,
       kbi_f.component,
       COUNT(kbi_f.id)           AS files,
       COALESCE(SUM(kbi_f.filesize), 0) AS filesize
FROM mdl_files kbi_f
WHERE kbi_f.filesize > 0
GROUP BY kbi_f.component
ORDER BY filesize DESC, component

Limitations and cautions

  • Despite the title 'File uploads', the results do not necessarily represent user uploads: mdl_files includes files maintained by different components, including files generated or managed by Moodle.
  • The files count represents table records with positive sizes, not necessarily unique physical files. Storage may deduplicate content or retain multiple versions.
  • The filesize value is the sum of logical file sizes in bytes. It does not necessarily equal actual disk usage because of shared content, metadata, and storage infrastructure.
  • Empty files and records with a size of zero are excluded by the filter.
  • The id field is MAX(kbi_f.id), merely the highest identifier in the group. It is not a unique identifier of the component.
  • There is no filtering by course, period, user, or upload source; do not treat the results as an auditable upload history.
  • No separate PostgreSQL file is provided for this report. Access to administrative storage data should be restricted.
