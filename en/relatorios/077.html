REPORT 077

SCORM activity details

Details users with recorded attempts in SCORM packages in the selected course, including tracking, completion, grades, statuses, and duration.

Report purpose

Details users with recorded attempts in SCORM packages in the selected course, including tracking, completion, grades, statuses, and duration.

Why use this report?

Helps administrators and teachers review SCORM object attempts, inspect completion states, compare assessment results, and investigate technical time and visit records.

Available filters Visualization and SQL Limitations

Available filters

The dynamic filter is Course, represented by :courseid and used three times in each variant: in the enrolment subquery, selection of packages with attempts, and main course condition.

The SQL requires a visible course and module, users who are neither deleted nor suspended and are not guest, at least one enrolment, and at least one SCORM attempt. It does not require currently active enrolment, a particular role, or a date window.

Visualization and full original SQL

One table visualization includes two complete original SQL queries, cache and refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL appear in separate panels within the same visualization.

1. SCORM activity details · Table

The per-participant, per-SCORM-package table includes user identification, email, institutional ID, package and course names, attempt count, last SCORM record modification, start time, accumulated duration from cmi.core.total_time records, first and latest attempt completion statuses, enrolment status, grade, module completion settings, and course-level tracking time and visits.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT t.*,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_u.idnumber,
       kbi_u.id               AS user_id,
       kbi_s.name,
       kbi_c.fullname,
       kbi_cmc.completionstate,
       kbi_cmc.timemodified   AS completiondate,
       round(sg.score, 0) AS score,
       l.timespend        AS timespend_on_course,
       ue.status          AS enrol_status,
       kbi_s.completionscorerequired,
       kbi_s.completionstatusrequired,
       kbi_s.completionstatusallscos,
       kbi_s.id               AS scorm_id,
       sg.finalgrade,
       sg.rawgrademax,
       kbi_cm.completionexpected,
       kbi_cm.completiongradeitemnumber,
       kbi_cm.completionview,
       kbi_cm.completion,
       kbi_s.grademethod      AS scorm_grade_method,
       l.visits           AS visits_on_course,
       ue.timeend,
       ''                 as cohortname
FROM mdl_scorm kbi_s
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_s.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'scorm'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_s.id
       JOIN (SELECT kbi_e.courseid, kbi_ue1.userid, MIN(kbi_ue1.status) AS status, MIN(kbi_ue1.timeend) AS timeend
             FROM mdl_enrol kbi_e
                    JOIN mdl_user_enrolments kbi_ue1 ON kbi_ue1.enrolid = kbi_e.id
             WHERE kbi_e.id > 0
               AND kbi_e.courseid = :courseid
             GROUP BY kbi_e.courseid, kbi_ue1.userid) ue ON ue.courseid = kbi_c.id
       JOIN mdl_user kbi_u ON kbi_u.id = ue.userid
       LEFT JOIN (SELECT courseid,
                         userid,
                         SUM(timespend) AS timespend,
                         SUM(visits)    AS visits
                  FROM mdl_local_kopere_bi_tracking
                  GROUP BY courseid, userid) l ON l.courseid = kbi_c.id AND l.userid = kbi_u.id
       JOIN (
             SELECT a.userid, a.scormid,
                    MIN(a.id) AS id,
                    COUNT(DISTINCT a.attempt) AS attempts,
                    MAX(v.timemodified) AS timemodified,
                    MIN(CASE WHEN e.element = 'x.start.time' THEN v.value END) AS starttime,
                    SUM(CASE WHEN e.element = 'cmi.core.total_time'
                             THEN TIME_TO_SEC(v.value) END) AS duration,
                    MAX(CASE WHEN a.attempt = 1
                              AND e.element IN ('cmi.completion_status', 'cmi.core.lesson_status')
                              AND v.value IN ('completed', 'passed')
                             THEN 'lang::report_sql_status_completed::local_kopere_bi' ELSE '' END) AS first_completion_status,
                    MAX(CASE WHEN a.attempt = la.last_attempt_number
                              AND e.element IN ('cmi.completion_status', 'cmi.core.lesson_status')
                              AND v.value IN ('completed', 'passed')
                             THEN 'lang::report_sql_status_completed::local_kopere_bi' ELSE '' END) AS current_completion_status
               FROM mdl_scorm_attempt a
               LEFT JOIN mdl_scorm_scoes_value v ON v.attemptid = a.id
               LEFT JOIN mdl_scorm_element e ON e.id = v.elementid
               JOIN (SELECT userid, scormid, MAX(attempt) AS last_attempt_number
                       FROM mdl_scorm_attempt
                   GROUP BY userid, scormid) la ON la.userid = a.userid AND la.scormid = a.scormid
              WHERE a.scormid IN (SELECT id FROM mdl_scorm WHERE course = :courseid)
           GROUP BY a.userid, a.scormid
       ) t ON t.scormid = kbi_s.id AND t.userid = kbi_u.id
       LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_gi.iteminstance,
                         ROUND((CASE
                                  WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                                  ELSE kbi_g.finalgrade END), 0) AS score,
                         kbi_g.userid,
                         kbi_g.finalgrade,
                         kbi_g.rawgrademax
                  FROM mdl_grade_items kbi_gi, mdl_grade_grades kbi_g
                  WHERE kbi_gi.itemmodule = 'scorm'
                    and kbi_g.itemid = kbi_gi.id
                    AND kbi_g.finalgrade IS NOT NULL
                    AND kbi_gi.outcomeid IS NULL
                  GROUP BY kbi_gi.iteminstance, kbi_g.userid, kbi_g.rawgrademax, kbi_g.finalgrade, kbi_gi.scaleid, kbi_g.feedback, kbi_gi.gradetype,
                           kbi_g.rawgrademin, kbi_gi.courseid) sg ON sg.iteminstance = t.scormid and sg.userid = t.userid
WHERE ue.userid > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1
ORDER BY kbi_c.fullname, kbi_s.name, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The report uses a JOIN to the SCORM attempt aggregate. Enrolled users who have not started the package therefore do not appear.
  • The enrol_status and timeend values are calculated using independent MIN aggregates across a user's enrolments in the course; they do not necessarily describe a specific enrolment.
  • The duration column sums SCORM cmi.core.total_time values converted to seconds. The availability and accuracy of these values depend on the package; absent data or incompatible formats may produce incomplete results.
  • The MySQL and PostgreSQL variants use different time conversions: TIME_TO_SEC and interval conversion with EXTRACT(EPOCH ...), respectively. Behavior may differ depending on SCORM time formatting.
  • The first_completion_status and current_completion_status fields derive from completed or passed states in the first and latest attempts, respectively. They are not automatically equivalent to Moodle module completion.
  • The SCORM status expressions return a language key as the SQL value; rendering a readable label may require the application to resolve that key.
  • The completionstate field comes from Moodle module completion. completiondate is that record's last modification time, not necessarily the initial completion date.
  • Kopere BI time and visits are summed by user and course, without restricting them to the SCORM module. Do not interpret timespend_on_course and visits_on_course as time or visits exclusively associated with the package.
  • The score value may be a percentage when rawgrademax > 0 or a raw grade otherwise. cohortname is a fixed empty string and does not indicate cohort membership.
  • The report includes personal and assessment data, including email addresses and institutional identifiers. Access and exports must comply with educational and administrative permissions.
