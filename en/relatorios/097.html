REPORT 097

Moodle messaging usage

Lists Moodle messages, their senders and other conversation members, with user details, creation dates, and role names assigned in user contexts.

Report purpose

Lists Moodle messages, their senders and other conversation members, with user details, creation dates, and role names assigned in user contexts.

Why use this report?

Helps review the volume and chronology of message records by sender and conversation participant, identifying involved users and available role information without exposing message bodies.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for course, message, sender, recipient, user, date range, or account status.

The only fixed condition is kbi_m.timecreated > 0. The conversation membership join requires kbi_mcm.userid <> kbi_m.useridfrom; role assignments are sought in contexts with contextlevel = 10. Newer messages appear first.

Visualization and full original SQL

One table visualization includes two complete original SQL queries, MySQL and PostgreSQL, shown in separate panels within the same visualization. Prism.js provides syntax highlighting.

1. Moodle messaging usage · Table

Each row represents a message and another associated conversation member, showing message ID, sender ID, first name, surname, email and aggregated roles, creation date, and the associated member's ID, name, email, and aggregated roles.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_m.id,
       kbi_uf.id                                         AS userid_from,
       kbi_uf.firstname                                  AS firstname_from,
       kbi_uf.lastname                                   AS lastname_from,
       kbi_uf.email                                      AS email_from,
       GROUP_CONCAT(DISTINCT kbi_rf.name SEPARATOR ', ') AS role_from,
       kbi_m.timecreated,
       kbi_ut.id                                         AS userid_to,
       kbi_ut.firstname                                  AS firstname_to,
       kbi_ut.lastname                                   AS lastname_to,
       kbi_ut.email                                      AS email_to,
       GROUP_CONCAT(DISTINCT kbi_rt.name SEPARATOR ', ') AS role_to
FROM mdl_messages kbi_m
       JOIN mdl_user kbi_uf ON kbi_uf.id = kbi_m.useridfrom
       JOIN mdl_message_conversation_members kbi_mcm ON kbi_mcm.conversationid = kbi_m.conversationid AND kbi_mcm.userid <> kbi_m.useridfrom
       JOIN mdl_user kbi_ut ON kbi_ut.id = kbi_mcm.userid
       JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 10
       LEFT JOIN mdl_role_assignments kbi_raf ON kbi_raf.contextid = kbi_ctx.id AND kbi_raf.userid = kbi_uf.id
       LEFT JOIN mdl_role kbi_rf ON kbi_rf.id = kbi_raf.roleid
       LEFT JOIN mdl_role_assignments kbi_rat ON kbi_rat.contextid = kbi_ctx.id AND kbi_rat.userid = kbi_ut.id
       LEFT JOIN mdl_role kbi_rt ON kbi_rt.id = kbi_rat.roleid
WHERE kbi_m.timecreated > 0
GROUP BY kbi_m.id, kbi_uf.id, kbi_ut.id
ORDER BY kbi_m.timecreated DESC, kbi_uf.lastname, kbi_ut.lastname

Full original PostgreSQL SQL

SELECT kbi_m.id,
       kbi_uf.id                                         AS userid_from,
       kbi_uf.firstname                                  AS firstname_from,
       kbi_uf.lastname                                   AS lastname_from,
       kbi_uf.email                                      AS email_from,
       STRING_AGG(DISTINCT (kbi_rf.name)::text, ', ') AS role_from,
       kbi_m.timecreated,
       kbi_ut.id                                         AS userid_to,
       kbi_ut.firstname                                  AS firstname_to,
       kbi_ut.lastname                                   AS lastname_to,
       kbi_ut.email                                      AS email_to,
       STRING_AGG(DISTINCT (kbi_rt.name)::text, ', ') AS role_to
FROM mdl_messages kbi_m
       JOIN mdl_user kbi_uf ON kbi_uf.id = kbi_m.useridfrom
       JOIN mdl_message_conversation_members kbi_mcm ON kbi_mcm.conversationid = kbi_m.conversationid AND kbi_mcm.userid <> kbi_m.useridfrom
       JOIN mdl_user kbi_ut ON kbi_ut.id = kbi_mcm.userid
       JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 10
       LEFT JOIN mdl_role_assignments kbi_raf ON kbi_raf.contextid = kbi_ctx.id AND kbi_raf.userid = kbi_uf.id
       LEFT JOIN mdl_role kbi_rf ON kbi_rf.id = kbi_raf.roleid
       LEFT JOIN mdl_role_assignments kbi_rat ON kbi_rat.contextid = kbi_ctx.id AND kbi_rat.userid = kbi_ut.id
       LEFT JOIN mdl_role kbi_rt ON kbi_rt.id = kbi_rat.roleid
WHERE kbi_m.timecreated > 0
GROUP BY kbi_m.id, kbi_uf.id, kbi_ut.id
ORDER BY kbi_m.timecreated DESC, kbi_uf.lastname, kbi_ut.lastname

Limitations and cautions

  • The SQL associates each message with all other conversation members, rather than a table that necessarily identifies its sole recipient. Conversations with multiple members can produce several rows per message.
  • The join JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 10 does not restrict the context to a specific user before joining role assignments; this can substantially increase intermediate rows and query cost.
  • The role_from and role_to fields are derived from roles assigned in user contexts, not course roles. They may be NULL even when a participant has a teaching or student role in a course.
  • Role aggregation uses GROUP_CONCAT(DISTINCT ...) in MySQL and STRING_AGG(DISTINCT ...) in PostgreSQL; no explicit ordering is applied to the aggregated names.
  • The query does not select message bodies, attachments, read status, or delivery confirmations. It cannot measure reading, responses, or communication effectiveness.
  • There are no filters for deleted or suspended accounts or for a selectable period. The report may cover historical messages from the entire installation.
  • JSON column metadata lists only id and userid_, although the SQL also returns sender and participant information. The interface may omit some columns without additional configuration.
  • Names, email addresses, and conversation relationships are personal data and require appropriate access and export controls.
