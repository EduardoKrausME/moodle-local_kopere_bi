REPORT 054

Gradebook overview

Displays grade items associated with visible modules in the selected course, including student details, final grades, percentages, and grade modification dates.

Report purpose

Displays grade items associated with visible modules in the selected course, including student details, final grades, percentages, and grade modification dates.

Why use this report?

Helps teachers and academic administrators review course activity grades, identify students without recorded grades, and inspect when grades were last updated.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in the main selection.

Fixed criteria require a visible course and module, a positive course ID, a user who is neither deleted nor suspended and is not guest, and student role ID 5 assigned in a course context (contextlevel = 50). Grade items have type mod and are matched to modules using itemmodule and iteminstance.

Visualization and full original SQL

One table visualization contains one SQL query, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL definition for this report.

1. Gradebook overview · Table

The table lists student and module grade-item information: course, student, activity type and name, module ID, grade values, calculated grade percentage, modification date, and course start and end dates.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id                                AS courseid,
       kbi_c.fullname,
       kbi_u.id                                AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_m.name,
       kbi_gi.itemname                         AS activity,
       kbi_cm.id                               as cmid,
       0                                   AS slot,
       0                                   AS attempt,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0) AS grade,
       kbi_g.finalgrade                        AS finalgrade,
       kbi_g.timemodified                      AS graded,
       kbi_c.startdate                         AS startdate,
       kbi_c.enddate                           AS enddate
FROM mdl_course kbi_c
       JOIN (SELECT kbi_con.instanceid, kbi_ra.userid
             FROM mdl_context kbi_con
                    JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_con.id
             WHERE kbi_con.contextlevel = 50
               AND kbi_ra.roleid = 5
             GROUP BY kbi_con.instanceid, kbi_ra.userid) student ON student.instanceid = kbi_c.id
       JOIN mdl_user kbi_u ON kbi_u.id = student.userid
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id
       JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       JOIN mdl_grade_items kbi_gi ON kbi_gi.itemtype = 'mod' AND kbi_gi.itemmodule = kbi_m.name AND kbi_gi.iteminstance = kbi_cm.instance
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.userid = kbi_u.id AND kbi_g.itemid = kbi_gi.id
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • The grade column calculates a final-grade percentage when rawgrademax > 0, but uses finalgrade directly otherwise. It is not a percentage in every situation.
  • The slot and attempt fields are fixed to 0 in SQL and do not indicate actual question slots or assessment attempts.
  • The query matches mod-type grade items to modules but does not directly display overall course grades or all gradebook categories.
  • The grade join is optional (LEFT JOIN); students without an item grade may appear with NULL finalgrade, grade, and assessment-date fields.
  • Student selection uses role ID 5 assignments without directly verifying enrolment status or validity dates.
  • The SQL includes only visible modules and courses, but does not check individual availability restrictions or the visibility of each grade item.
  • Academic performance data require institutional access controls. No separate PostgreSQL variant is provided.
