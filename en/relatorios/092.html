REPORT 092

Student access by weekday and time slot

Shows student visits and tracked time for each course by weekday and time slot, including each slot's share of that student's total course time.

Report purpose

Shows student visits and tracked time for each course by weekday and time slot, including each slot's share of that student's total course time.

Why use this report?

Helps teachers and administrators examine individual access patterns, requiring a student role and an active enrolment record in the query.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for user, course, role, period, or time slot. The SQL reads available records from mdl_local_kopere_bi_period and aggregates them by student, course, weekday, and time slot.

Fixed conditions require a course ID greater than 1, a visible course, and an account that is neither deleted nor suspended and is not guest. They also require an active enrolment record (ue.status = 0 and e.status = 0) and a student role in the course context, identified by r.archetype = 'student' or r.shortname = 'student'.

Visualization and full original SQL

One table visualization contains two complete original SQL queries, MySQL and PostgreSQL, in separate panels within the same block, with Prism.js syntax highlighting.

1. Student access by weekday and time slot · Table

Each row describes a student, course, weekday, and time slot, including student identification, email, institutional ID, course and category, weekday and time slot, total visits, recorded seconds and hours, and the slot's percentage of that student's own recorded course time.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT CONCAT(p.courseid, '-', p.userid, '-', p.weekdaynum, '-', p.slot) AS id,
       u.id AS userid,
       u.firstname,
       u.lastname,
       u.email,
       u.idnumber,
       c.id AS courseid,
       c.fullname AS course,
       cc.name AS category_name,
       p.weekdaynum AS weekday_number,
       CASE p.weekdaynum
         WHEN 0 THEN 'Monday'
         WHEN 1 THEN 'Tuesday'
         WHEN 2 THEN 'Wednesday'
         WHEN 3 THEN 'Thursday'
         WHEN 4 THEN 'Friday'
         WHEN 5 THEN 'Saturday'
         ELSE 'Sunday'
       END AS weekday_name,
       CASE p.slot
         WHEN 1 THEN '00:00 - 05:59'
         WHEN 2 THEN '06:00 - 08:59'
         WHEN 3 THEN '09:00 - 11:59'
         WHEN 4 THEN '12:00 - 14:59'
         WHEN 5 THEN '15:00 - 17:59'
         WHEN 6 THEN '18:00 - 20:59'
         ELSE '21:00 - 23:59'
       END AS active_period,
       SUM(p.visits) AS visits,
       SUM(p.timespend) AS timespend,
       ROUND(SUM(p.timespend) / 3600.0, 2) AS hours_spent,
       ROUND(SUM(p.timespend) * 100.0 / NULLIF(t.total_timespend, 0), 2) AS percent_of_user_course_time
  FROM mdl_local_kopere_bi_period p
  JOIN mdl_course c ON c.id = p.courseid
  LEFT JOIN mdl_course_categories cc ON cc.id = c.category
  JOIN mdl_user u ON u.id = p.userid
  JOIN (
       SELECT courseid, userid, SUM(timespend) AS total_timespend
         FROM mdl_local_kopere_bi_period
        WHERE courseid > 1
     GROUP BY courseid, userid
  ) t ON t.courseid = p.courseid AND t.userid = p.userid
 WHERE p.courseid > 1
   AND c.visible = 1
   AND u.deleted = 0
   AND u.suspended = 0
   AND u.username <> 'guest'
   AND EXISTS (
       SELECT 1
         FROM mdl_user_enrolments ue
         JOIN mdl_enrol e ON e.id = ue.enrolid
        WHERE ue.userid = u.id AND e.courseid = p.courseid
          AND ue.status = 0 AND e.status = 0
   )
   AND EXISTS (
       SELECT 1
         FROM mdl_role_assignments ra
         JOIN mdl_context cx ON cx.id = ra.contextid
         JOIN mdl_role r ON r.id = ra.roleid
        WHERE ra.userid = u.id AND cx.contextlevel = 50
          AND cx.instanceid = p.courseid
          AND (r.archetype = 'student' OR r.shortname = 'student')
   )
 GROUP BY p.courseid, p.userid, c.id, c.fullname, cc.name,
          u.id, u.firstname, u.lastname, u.email, u.idnumber,
          p.weekdaynum, p.slot, t.total_timespend
 ORDER BY c.fullname, u.lastname, u.firstname, p.weekdaynum, p.slot

Limitations and cautions

  • The percent_of_user_course_time field compares tracked time in a time slot with that user's total tracked time in the same course; it does not represent activity progress or completion.
  • Enrolment criteria check both user enrolment and enrolment method status but not the enrolment start and end dates. They do not establish that access was valid at every recorded moment.
  • The query identifies student roles by archetype or role short name in the course context, rather than a fixed numeric ID. Custom roles that fail these criteria may be excluded.
  • Tracking records may span several collection periods without date separation. Account status and role checks reflect the current records at query time, not necessarily the historical state at each visit.
  • Weekday names come from the original SQL in English, with Monday numbered 0. The seven time slots depend on the classification already stored in slot.
  • As noted in the catalog, new time-slot records use the site's configured time zone. Older daily-only aggregates cannot be retrospectively broken down by hour.
  • The percentage uses NULLIF and may be NULL when the user's total recorded time for the course is zero. It is not verified learning time.
  • The table includes names, email addresses, and institutional IDs. Individual access records must be restricted to authorized roles and protected in exports.
