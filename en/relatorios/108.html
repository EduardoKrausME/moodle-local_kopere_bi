REPORT 108

Course health

Compares course health using student engagement, progress, completion, and risk indicators.

Report purpose

The dashboard brings together four summary indicators, a column chart of the 25 courses with the lowest health scores, and a detailed table containing all records from the latest analytics batch.

Why use this report?

Compare summary indicators of course health, identify courses classified as critical or requiring attention, and support analysis of trends, risk, and performance.

Available filters Visualizations and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, student, cohort, period, or health status. Every component queries records from mdl_local_kopere_bi_courseag using the latest available MAX(batchid).

The first three indicators have fixed filters for healthlevel = 'healthy', 'attention', or 'critical'. The chart applies LIMIT 25 and sorts by health score ascending. The detailed table does not limit the number of courses in SQL.

Visualizations and full original SQL

This report contains six visualizations, each with its full original SQL, presentation description, cache, and refresh settings. Prism.js highlights SQL syntax. No separate PostgreSQL variant exists for the main definition in master, so none has been invented.

1. Healthy courses · Numeric indicator

Numeric indicator: counts course records with healthlevel = 'healthy' in the latest batch of the course-health table.

Cache: none · Refresh: none.

Full original SQL

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'healthy'
2. Courses requiring attention · Numeric indicator

Numeric indicator: counts records with healthlevel = 'attention' in the latest batch.

Cache: none · Refresh: none.

Full original SQL

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'attention'
3. Courses in critical condition · Numeric indicator

Numeric indicator: counts records with healthlevel = 'critical' in the latest batch.

Cache: none · Refresh: none.

Full original SQL

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'critical'
4. Average health score · Numeric indicator

Numeric indicator: calculates the average healthscore in the latest batch, rounded to one decimal place. It can return NULL if no records are available.

Cache: none · Refresh: none.

Full original SQL

SELECT ROUND(AVG(healthscore), 1) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
5. Course health scores · Column chart

Column chart: displays course names and healthscore, ordered from lowest to highest score, with LIMIT 25. These are not necessarily the 25 healthiest courses; the query highlights the lowest scores.

Cache: none · Refresh: none.

Full original SQL

SELECT c.fullname AS course, ca.healthscore AS health_score
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, c.fullname
LIMIT 25
6. Course health details · Table

Course table showing enrolments, active users over 7 and 30 days, users without access, completions, high- and medium-risk counts, average progress and grades, completion and engagement rates, trends, and health scores and levels.

Cache: none · Refresh: none.

Full original SQL

SELECT ca.id, c.id AS courseid, c.fullname AS course, ca.enrolments, ca.active7, ca.active30, ca.neveraccessed, ca.completions, ca.highrisk, ca.mediumrisk, ca.avgprogress, ca.avggrade, ca.completionrate, ca.engagementrate, ca.trendpercent, ca.healthscore,
       CASE ca.healthlevel
         WHEN 'healthy' THEN 'lang::analytics_health_healthy::local_kopere_bi'
         WHEN 'attention' THEN 'lang::analytics_health_attention::local_kopere_bi'
         ELSE 'lang::analytics_health_critical::local_kopere_bi'
       END AS healthlevel
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, ca.highrisk DESC, c.fullname

Calculation criteria and behavior

The healthscore, healthlevel, engagementrate, completionrate, and trendpercent values are calculated beforehand by Kopere BI. Each component's SQL reads and summarizes these fields; the report definition does not disclose how the health score is weighted.

The table resolves health levels through plugin translation keys. The chart presents no more than 25 courses with the lowest scores, sorted in ascending order.

Limitations and cautions

  • The health score is not a definitive assessment of a course's educational quality; it depends on a methodology outside the SQL definition.
  • The chart shows no more than 25 courses, selected by their lowest scores, whereas the table may display the entire batch.
  • The indicators count aggregated records and do not independently check course visibility or user account status.
  • Engagement, trend, and recent activity metrics depend on analytics processing. A cache setting of none does not guarantee that the batch is updated in real time.
  • The four summary metrics may return zero or NULL, depending on the aggregate function and the absence of records in the current batch.
  • Consider risk, enrolment, and institutional context together before comparing courses with different populations, workloads, and delivery formats.

The SQL statements are reproduced verbatim from the JSON file in master and have not been executed on a Moodle installation during this documentation work. Verify analytics table availability, compatibility, results, and permissions in the target environment.
