REPORT 040

Course inactivity

Lists users with active enrolments in the selected course who have no linked Kopere BI tracking and log records.

Report purpose

Lists users with active enrolments in the selected course who have no linked Kopere BI tracking and log records.

Why use this report?

Helps tutoring teams identify enrolments requiring further investigation, especially when no Kopere BI tracking data has been collected for a particular student and course.

Available filters Visualization and SQL Limitations

Available filters

The available dynamic filter is Course, represented by :courseid and used once to select the course.

Other criteria are fixed: no matching record in the tracking subquery (l.id IS NULL), enrolment and enrolment method status 0, a visible course, accounts that are neither deleted nor suspended, and exclusion of guest. There are no user, cohort, or date-range SQL filters.

Visualization and full original SQL

One table visualization contains one full SQL query, cache and refresh settings, and Prism.js syntax highlighting. The original definition has no separate PostgreSQL variant file.

1. Course inactivity · Table

Each enrolment row shows the user's name and email, enrolment method and date, last Moodle course access, recorded percentage grade, course identifier, and category. The central selection criterion is the absence of linked tracking and log records.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_ue.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_ue.timecreated                      as enrolled,
       kbi_ue.userid,
       kbi_e.enrol                             AS enrols,
       kbi_ul.timeaccess                       AS lastaccess,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0) AS grade,
       kbi_c.id                                as cid,
       kbi_c.shortname,
       kbi_ca.name                             AS category,
       kbi_c.fullname                          as course
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_course_categories kbi_ca ON kbi_ca.id = kbi_c.category
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_u.id
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.itemtype = 'course' AND kbi_gi.courseid = kbi_e.courseid
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.userid = kbi_u.id AND kbi_g.itemid = kbi_gi.id AND kbi_g.finalgrade IS NOT NULL
       LEFT JOIN (SELECT MAX(kbi_t.id) AS id, kbi_t.userid, kbi_t.courseid
                  FROM mdl_local_kopere_bi_tracking kbi_t, mdl_local_kopere_bi_track_log kbi_l
                  WHERE kbi_l.trackid = kbi_t.id
                  GROUP BY kbi_t.courseid, kbi_t.userid) as l ON l.courseid = kbi_e.courseid AND l.userid = kbi_ue.userid
WHERE l.id IS NULL
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0

Limitations and cautions

  • The report does not check how many days have passed since the last access. It identifies enrolments without tracking records linked to corresponding logs; these users are not automatically inactive for 30 days or any other period.
  • A user may have accessed the course in Moodle without appearing in Kopere BI tracking because of differences or failures in data collection, retention, or synchronization.
  • The lastaccess column comes from mdl_user_lastaccess, independently of the missing Kopere BI log criterion. It can show a course access even when the user appears in this list.
  • The SQL does not explicitly require assignment of the student role. It includes active enrolments that may belong to users with different roles.
  • Grades come from course grade items and can be empty. A missing grade does not demonstrate a lack of participation.
  • Status zero for both enrolment and enrolment method does not directly validate enrolment start and end dates.
  • The table contains personal information. Restrict access and exports; no separate PostgreSQL variant is supplied.
