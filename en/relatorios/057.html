REPORT 057

Activity statistics summary

Per-visible-module table for the selected course, showing activity type, date added, completion settings, completion record count, and average associated grades.

Report purpose

Per-visible-module table for the selected course, showing activity type, date added, completion settings, completion record count, and average associated grades.

Why use this report?

Provides an overview of course activities and resources, helping administrators and teachers identify modules with completion and grade records and review their configuration.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, implemented through :courseid and used once in kbi_cm.course = :courseid.

The SQL requires a positive module ID and kbi_cm.visible = 1. Completion totals include completionstate IN (1, 2); grade averages use items of type mod with finalgrade IS NOT NULL. There are no parameters for user, date, or module type.

Visualization and full original SQL

One table visualization includes one complete SQL query, cache and refresh settings, and Prism.js syntax highlighting. The catalog does not provide a separate PostgreSQL variant.

1. Activity statistics summary · Table

The per-module table shows the module ID, module type, date added, completion configuration, number of completion records in states 1 or 2, and average percentage of available final grades for grade items associated with that module.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_cm.id, kbi_m.name AS moduletype, kbi_cm.added, kbi_cm.completion, kbi_c.fullname, cmc.num_compl AS completed, grd.grade
FROM mdl_course_modules kbi_cm
       JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_cm.course
       LEFT JOIN (SELECT coursemoduleid, COUNT(id) AS num_compl
                  FROM mdl_course_modules_completion
                  WHERE id > 0
                    AND completionstate IN (1, 2)
                  GROUP BY coursemoduleid) cmc ON cmc.coursemoduleid = kbi_cm.id
       LEFT JOIN (SELECT kbi_gi.iteminstance,
                         kbi_gi.itemmodule,
                         ROUND(AVG(CASE
                                     WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                                     ELSE kbi_g.finalgrade END), 0) AS grade
                  FROM mdl_grade_items kbi_gi
                         JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.finalgrade IS NOT NULL
                  WHERE kbi_gi.itemtype = 'mod'
                  GROUP BY kbi_gi.iteminstance, kbi_gi.itemmodule) grd
         ON grd.itemmodule = kbi_m.name AND grd.iteminstance = kbi_cm.instance
WHERE kbi_cm.id > 0
  AND kbi_cm.visible = 1
  AND kbi_cm.course = :courseid

Limitations and cautions

  • The results include visible course modules but do not explicitly require kbi_c.visible = 1. Modules belonging to hidden courses may be included when their own visibility flags are enabled.
  • The completed column counts module completion records, not unique users across the platform or formal course completions.
  • The completion aggregate uses states 1 and 2 without requiring completion > 0 in the counting query.
  • The grade average uses existing final grades from items of type mod; modules that do not generate grades may produce NULL values.
  • When rawgrademax > 0, the average uses a percentage; otherwise, it uses the final grade directly. The resulting scale is not necessarily consistent across modules.
  • The SQL does not restrict the grade average to currently enrolled students or any date range; grades from users without a current enrolment may be counted.
  • The query returns module ID and type but not the activity's display name. No separate PostgreSQL definition file is available for this report.
