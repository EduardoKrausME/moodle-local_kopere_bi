REPORT 095

File usage details by teacher

Lists files associated with File resources in the selected course, including filename, technical path, creation date, and the user recorded on each file.

Report purpose

Lists files associated with File resources in the selected course, including filename, technical path, creation date, and the user recorded on each file.

Why use this report?

Helps verify files linked to File activities, their technical references, and the user account stored on each file record for administrative review and maintenance audits.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in kbi_c.id = :courseid.

Fixed criteria require a visible course and a file user who is not deleted, suspended, or named guest. Files must belong to a resource-module context (contextlevel = 70, component = 'mod_resource', filearea = 'content', itemid = 0, filesize > 0). The query has no role or reporting-period filter.

Visualization and full original SQL

One table visualization contains a complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL definition in the catalog.

1. File usage details by teacher · Table

The per-file table lists file ID, course ID and name, associated user's ID, first name, surname and username, the resource's technical filepath, filename, and record creation timestamp.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_f.id,
       kbi_c.id                                                                              AS courseid,
       kbi_c.fullname,
       kbi_u.id                                                                              AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.username,
       CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath, kbi_f.filename) AS file_path,
       kbi_f.filename,
       kbi_f.timecreated
FROM mdl_course kbi_c
       JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_f.userid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
ORDER BY kbi_c.fullname, kbi_f.filename

Limitations and cautions

  • Despite the title, the query does not filter for teachers. The user is obtained from mdl_files.userid; the SQL does not join mdl_role_assignments or require a teaching role.
  • The user ID associated with a file does not establish who read, downloaded, or used the resource. It also does not necessarily prove authorship of the learning material.
  • The query requires a valid active user record associated with the file. Files without a valid user or associated with deleted or suspended accounts are excluded.
  • Only positive-size content files of the mod_resource component are returned. Files from other activities, directories, and records without content are outside its scope.
  • Paths are built using the module context and revision number. They are technical references, and access must be authorized by the application.
  • The timecreated field records when the Moodle file record was created, not the last time the file was read, viewed, or its content modified.
  • The query does not filter by module visibility, publication period, group, or enrolment. It provides no file-visit or time-spent metrics.
  • The source catalog provides no separate PostgreSQL file.
