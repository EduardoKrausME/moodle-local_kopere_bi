REPORT 120

Comparison of two quiz results

Compares the latest finished attempts for pairs of quizzes in the same course as percentages; the order follows quiz IDs.

Report purpose

Table by participant and pair of quizzes within a course, showing both quiz titles, percentage grades from the latest finished attempts, and the difference in percentage points. It sorts by course, student, and quiz IDs, returning up to 500 rows.

Why use this report?

Compare how an individual participant's percentage scores differ between pairs of quizzes in the same course, supporting exploratory analysis and assessment review.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, student, quiz, date range, or grade. The query considers attempts with state = 'finished' for both quizzes, users who are not deleted (u.deleted = 0), and quizzes with q1.sumgrades > 0 and q2.sumgrades > 0.

The second quiz must belong to the same course and meet q2.id > q1.id. There is no explicit pre-test/post-test pairing or requirement that the quizzes be consecutive. The SQL displays up to 500 quiz pairs and participants.

Visualization and full original SQL

The report contains one table visualization with its full original SQL, caching, and refresh settings. Prism.js highlights SQL syntax. No separate PostgreSQL variant exists in master for this definition, so no nonexistent query has been introduced.

1. Comparison of two quiz results · Table

Table by participant and pair of quizzes within a course, with the two quiz titles, percentage grades from the latest finished attempts, and the difference in percentage points. Results are sorted by course, student, and quiz IDs, up to 500 rows.

Cache: 1h · Refresh: none.

Full original SQL

SELECT CONCAT(a1.id, '-', a2.id) AS id, c.id AS courseid, c.fullname AS course,
       a1.userid, u.firstname, u.lastname,
       q1.name AS first_quiz, q2.name AS second_quiz,
       ROUND(100.0 * a1.sumgrades / NULLIF(q1.sumgrades, 0), 2) AS first_percent,
       ROUND(100.0 * a2.sumgrades / NULLIF(q2.sumgrades, 0), 2) AS second_percent,
       ROUND(100.0 * a2.sumgrades / NULLIF(q2.sumgrades, 0)
           - 100.0 * a1.sumgrades / NULLIF(q1.sumgrades, 0), 2) AS delta_percent
  FROM mdl_quiz_attempts a1
  JOIN mdl_quiz q1 ON q1.id = a1.quiz
  JOIN mdl_quiz q2 ON q2.course = q1.course AND q2.id > q1.id
  JOIN mdl_quiz_attempts a2 ON a2.quiz = q2.id AND a2.userid = a1.userid
  JOIN mdl_course c ON c.id = q1.course
  JOIN mdl_user u ON u.id = a1.userid AND u.deleted = 0
 WHERE a1.state = 'finished' AND a2.state = 'finished'
   AND a1.id = (SELECT MAX(last1.id) FROM mdl_quiz_attempts last1
                 WHERE last1.quiz = a1.quiz AND last1.userid = a1.userid AND last1.state = 'finished')
   AND a2.id = (SELECT MAX(last2.id) FROM mdl_quiz_attempts last2
                 WHERE last2.quiz = a2.quiz AND last2.userid = a2.userid AND last2.state = 'finished')
   AND q1.sumgrades > 0 AND q2.sumgrades > 0
 ORDER BY c.fullname, u.lastname, q1.id, q2.id
 LIMIT 500

Calculation criteria and behavior

For each participant, the SQL selects the finished attempt with the largest id in each quiz through a MAX(id) subquery. The most recent attempt by ID is not necessarily the highest-scoring attempt.

Each quiz percentage is calculated as 100.0 * sumgrades / NULLIF(quiz.sumgrades, 0), rounded to two decimal places. delta_percent subtracts the first quiz percentage from the second and therefore represents a difference in percentage points, not relative percentage growth.

Limitations and cautions

  • The q2.id > q1.id criterion uses Moodle's internal quiz-ID ordering, not a pedagogically configured pre-test/post-test sequence. It can pair assessments with different topics and difficulty levels.
  • A participant may appear in several quiz pairs because the query includes every eligible combination with increasing quiz IDs in the same course.
  • The latest finished attempt is selected through MAX(id), rather than by highest score or the quiz's own attempt-grading policy.
  • Attempt dates are not compared. A larger quiz ID does not guarantee that the second quiz was attempted after the first.
  • Percentages from different assessments are comparable only when their topics, scales, objectives, and difficulty support that comparison; delta_percent is a difference in percentage points.
  • Suspended users, hidden courses, and hidden modules are not explicitly excluded. The 500-row limit may truncate the population.
  • The report contains identifiable individual assessment results; restrict access and exports to authorized users.

The query is reproduced verbatim from the original JSON in master. The SQL was not executed on Moodle during this documentation work. Before institutional use, validate database compatibility, data-access permissions, and interpretation of the measures.
