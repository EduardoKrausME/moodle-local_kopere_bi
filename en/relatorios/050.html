REPORT 050

Enrolment method details

Details active enrolments in the selected course, participants' assigned roles, enrolment and course dates, completion criteria, and role-assignment modifier information.

Report purpose

Details active enrolments in the selected course, participants' assigned roles, enrolment and course dates, completion criteria, and role-assignment modifier information.

Why use this report?

Helps administrative teams review how users were enrolled, verify roles associated with the course, and relate enrolment records to completion settings and dates.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, implemented through :courseid once in each original query.

Fixed criteria include a visible course, enrolment and enrolment-method status 0, accounts that are neither deleted nor suspended and are not guest. Role aggregation is restricted to course contexts (contextlevel = 50), and the completion-criterion join selects criteriatype = 2. There are no dynamic user, method, or date-range filters.

Visualization and full original SQL

One table visualization contains two original SQL queries, cache and refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL are displayed in separate panels of the same visualization.

1. Enrolment method details · Table

Each course enrolment row includes enrolment start and end dates, an associated type-2 completion criterion date if available, participant name and email, enrolment method, status, course-context roles, a possible role-assignment modifier, formal completion date, and course dates. MySQL and PostgreSQL share the visualization but use different role aggregation functions.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ue.id,
       kbi_ue.timecreated                         AS enrolstart,
       kbi_ue.timeend                             AS enrolend,
       kbi_ccc.timeend,
       kbi_c.enablecompletion,
       kbi_cc.timecompleted                       AS complete,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_ue.userid,
       kbi_e.courseid,
       kbi_e.enrol                                AS enrols,
       CONCAT(kbi_u1.firstname, ' ', kbi_u1.lastname) AS endrolled_by,
       kbi_ue.status                              AS enrol_status,
       ra.roles                               AS course_roles,
       kbi_c.fullname                             AS course,
       kbi_c.startdate                            AS startdate,
       kbi_c.enddate                              AS enddate
FROM mdl_user_enrolments kbi_ue
       JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       JOIN (SELECT kbi_ctx.instanceid,
                    kbi_ra.userid,
                    MIN(kbi_ra.modifierid)                                 AS modifierid,
                    GROUP_CONCAT(DISTINCT(kbi_r.shortname) SEPARATOR ', ') AS roles
             FROM mdl_context kbi_ctx
                    JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_ctx.id
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
             WHERE kbi_ctx.contextlevel = 50
             GROUP BY kbi_ctx.instanceid, kbi_ra.userid) ra ON ra.instanceid = kbi_e.courseid AND ra.userid = kbi_ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_e.courseid
       LEFT JOIN mdl_user kbi_u1 ON kbi_u1.id = ra.modifierid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_e.courseid AND kbi_cc.userid = kbi_ue.userid
       LEFT JOIN mdl_course_completion_criteria kbi_ccc ON kbi_ccc.course = kbi_e.courseid AND kbi_ccc.criteriatype = 2
WHERE kbi_ue.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The endrolled_by column comes from MIN(kbi_ra.modifierid), identifying a modifier of a role assignment. It does not prove who enrolled the participant, and the lowest ID does not necessarily identify the most recent modifier.
  • Because the roles subquery is attached using JOIN, enrolments without a corresponding course-context role assignment are excluded.
  • The kbi_ccc.timeend field belongs to a type-2 completion criterion, not the enrolment end date. Do not confuse it with enrolend or course.enddate.
  • A course may have multiple type-2 completion criteria. Joining them without aggregation may create duplicate rows for one enrolment.
  • Enrolment status is displayed but restricted to zero in the filter, so the table does not show every possible enrolment status.
  • The complete date comes from the formal course completion record and may be empty. The SQL does not establish completion of individual activities.
  • MySQL and PostgreSQL use different functions to concatenate role names. Names and email addresses are personal data requiring access controls.
