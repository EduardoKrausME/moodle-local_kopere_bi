REPORT 056

Activity grades and dates

Activity and course grades for the selected course, their modification dates, grade modifiers, and users' last course access.

Report purpose

Activity and course grades for the selected course, their modification dates, grade modifiers, and users' last course access.

Why use this report?

Helps review recorded grades and modification dates while comparing activities, graders, and participants in one view.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL filter is Course, represented by :courseid and used once in each MySQL and PostgreSQL variant.

Fixed criteria require a visible course with a positive ID, users who are neither deleted nor suspended and are not guest, and any role assignment in a course context (contextlevel = 50). Grade items of type mod or course are included. There are no dynamic activity, grader, or date-range filters.

Visualization and full original SQL

One table visualization contains two SQL queries, cache and refresh settings, and Prism.js syntax highlighting. Equivalent MySQL and PostgreSQL variants appear in separate panels within the same visualization.

1. Activity grades and dates · Table

The table displays each course-role user and grade item of type mod or course, activity and category, listed teachers, grades and calculated percentages, modification date and modifier name, assignment grading-related date, and last course access. Both variants produce the same table.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT DISTINCT kbi_gi.itemname                                                 AS activity_name,
                kbi_g.userid,
                kbi_u.username,
                kbi_u.firstname,
                kbi_u.lastname,
                kbi_c.fullname,
                kbi_cc1.name                                                    AS course_category,
                kbi_c.shortname,
                tcrs.teachers                                               as courseteachers,
                kbi_g.timemodified                                              AS graduated,
                ROUND((CASE
                         WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                         ELSE kbi_g.finalgrade END), 0)                         AS grade,
                ROUND((CASE
                         WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                                 THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                         ELSE kbi_g.finalgrade END), 0)                         AS grade_percent,
                kbi_wg.firstname                                                AS who_graded_first_name,
                kbi_wg.lastname                                                 AS who_graded_last_name,
                kbi_gi.itemtype,
                CASE WHEN kbi_m.name = 'assign' THEN kbi_sg.timemodified ELSE 0 END AS need_grade_assignment,
                kbi_ul.timeaccess                                               AS course_lastaccess
FROM mdl_course kbi_c
       LEFT JOIN mdl_course_categories kbi_cc1 ON kbi_cc1.id = kbi_c.category
       LEFT JOIN (SELECT kbi_cx.instanceid, GROUP_CONCAT(CONCAT(kbi_u.firstname, ' ', kbi_u.lastname) SEPARATOR ', ') as teachers
                  FROM mdl_context kbi_cx
                         JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_cx.id AND
                                                         kbi_ra.roleid IN (1, 2, 3, 4)
                         JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
                  WHERE kbi_cx.contextlevel = 50
                  GROUP BY kbi_cx.instanceid) tcrs ON tcrs.instanceid = kbi_c.id
       JOIN mdl_context kbi_ctx ON kbi_ctx.instanceid = kbi_c.id AND kbi_ctx.contextlevel = 50
       JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_ctx.id
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_c.id AND (kbi_gi.itemtype = 'mod' OR kbi_gi.itemtype = 'course')
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_gi.id = kbi_g.itemid AND kbi_g.userid = kbi_u.id
       LEFT JOIN mdl_user kbi_wg ON kbi_wg.id = kbi_g.usermodified
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = kbi_gi.itemmodule
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.instance = kbi_gi.iteminstance AND kbi_cm.module = kbi_m.id
       LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.userid = kbi_u.id
       LEFT JOIN mdl_assign_submission kbi_ass ON kbi_ass.userid = kbi_u.id AND kbi_ass.assignment = kbi_cm.instance AND
                                              kbi_ass.status = 'submitted' AND kbi_ass.latest = 1
       LEFT JOIN mdl_assign_grades kbi_sg ON kbi_ass.assignment = kbi_sg.assignment AND kbi_ass.userid = kbi_sg.userid AND
                                         kbi_sg.attemptnumber = kbi_ass.attemptnumber AND
                                         (kbi_ass.timemodified >= kbi_sg.timemodified OR kbi_sg.timemodified IS NULL OR
                                          kbi_sg.grade IS NULL)
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_u.id
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_gi.itemname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The main query does not require role ID 5 or active enrolment; any user assigned a course role, including teachers, may appear.
  • Grade items and grade records use LEFT JOIN; rows without final grades or linked activities may contain NULL fields.
  • The graduated field shows mdl_grade_grades.timemodified, when the grade record was modified, not necessarily when the original assessment occurred.
  • The grade and grade_percent columns use different formulas. The latter considers the range between rawgrademin and rawgrademax, while the former directly divides by rawgrademax when positive.
  • The need_grade_assignment column is not a Boolean pending-grading indicator. For assignments it returns kbi_sg.timemodified from the grade-record join; for other modules it returns 0. NULL values may occur.
  • The courseteachers list uses role assignments with IDs 1, 2, 3, and 4. These do not necessarily identify those responsible for grading and may include customized roles.
  • The course_lastaccess field comes from mdl_user_lastaccess and alone does not establish participation in a particular activity.
  • MySQL and PostgreSQL differ in name concatenation and rounding. Restrict access to authorized roles because the report displays grades and personal information.
