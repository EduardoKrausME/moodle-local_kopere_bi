REPORT 087

Learning plan progress details

Lists users with at least one learning plan linked to a template with a positive ID, showing only user identification and contact information.

Report purpose

Lists users with at least one learning plan linked to a template with a positive ID, showing only user identification and contact information.

Why use this report?

Helps administrators identify users associated with template-based learning plans as a starting point for further administrative queries, without implying that the results measure progress.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, user, plan, template, status, date, or competency.

Fixed criteria require kbi_cp.templateid > 0, a user who is not deleted (deleted = 0) or suspended (suspended = 0), and a username other than guest. Results are sorted by surname and first name.

Visualization and full original SQL

One table visualization includes the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. The definitions catalog does not provide a separate PostgreSQL variant.

1. Learning plan progress details · Table

The table displays user ID, first name, surname, and email address. Users are selected through learning plans that reference a template.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id, kbi_u.firstname, kbi_u.lastname, kbi_u.email
FROM mdl_competency_plan kbi_cp
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_cp.userid
WHERE kbi_cp.templateid > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
ORDER BY kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • Despite the title, the SQL does not provide progress or proficiency details. It returns no percentage, plan status, evidence, assessed competency, or completion-date columns.
  • Because the SQL uses neither DISTINCT nor GROUP BY, a user with several template-based plans may appear multiple times, once for each matching plan record.
  • The templateid > 0 condition does not verify that the template still exists or that the plan has a particular status.
  • The report does not filter by course, template, manager, role, or date range. Records come from plans throughout the installation.
  • The email column contains personal information and should only be shown to authorized users.
  • The list does not identify which plan produced each row because it does not return a plan ID or name, making duplicate rows harder to explain in the interface.
  • There is no separate PostgreSQL variant for this definition.
