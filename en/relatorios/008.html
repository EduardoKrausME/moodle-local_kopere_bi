REPORT 008

General dashboard

Dashboard with three indicators and two line charts covering users, recent access, courses, enrolment status by course, and monthly registrations.

Report purpose

Dashboard with three indicators and two line charts covering users, recent access, courses, enrolment status by course, and monthly registrations.

Why use this report?

Centralizes administrative indicators for a quick view of account registration trends and Moodle usage. It can support reviews of platform activity provided that technical criteria and SQL limitations are considered.

Actual filters Visualizations and SQL Limitations

Available filters

There are no dynamic SQL parameters for user, course, cohort, or date range in the dashboard's ten queries. Time conditions are fixed, such as 5 minutes, 1 hour, and 12 months; these are not user-selected filters.

Course and user indicators use fixed conditions for visibility, confirmation, or deletion; enrolment status is calculated when the query runs.

Visualizations and full original SQL

This report contains 5 visualizations and 10 SQL queries. Syntax highlighting preserves the original characters. MySQL and PostgreSQL variants appear in separate panels within their respective visualizations.

1. Total users and users with recorded access – Indicator

Numeric indicator showing total non-deleted users / non-deleted users with lastaccess greater than zero, excluding user ID 1.

Cache: 1h. Refresh: none.

Full original MySQL SQL

SELECT CONCAT(
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0),
    ' / ',
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0 AND lastaccess > 0)
)

Full original PostgreSQL SQL

SELECT CONCAT(
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0),
    ' / ',
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0 AND lastaccess > 0)
)
2. Recent users: five minutes and one hour – Indicator

Indicator with two counts based on lastaccess: access within the past 300 seconds and within the past 3600 seconds. The MySQL implementation includes grouping that the PostgreSQL variant does not.

Cache: 1h. Refresh: none.

Full original MySQL SQL

SELECT CONCAT(
    (
         SELECT count(id)
           FROM mdl_user
          WHERE lastaccess > UNIX_TIMESTAMP() - 300
       GROUP BY id
    ),
    ' / ',
    (
        SELECT count(id)
          FROM mdl_user
         WHERE lastaccess > UNIX_TIMESTAMP() - 3600
      GROUP BY id
    )
)

Full original PostgreSQL SQL

SELECT CONCAT(
    (
         SELECT count(id)
           FROM mdl_user
          WHERE lastaccess > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) - 300
    ),
    ' / ',
    (
        SELECT count(id)
          FROM mdl_user
         WHERE lastaccess > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) - 3600
    )
)

SELECT CONCAT(
    (
        SELECT count(*) FROM mdl_course WHERE id > 1
    ),
    ' / ',
    (
        SELECT count(*) FROM mdl_course WHERE id > 1 AND visible = 1
    )

4. Enrolments by course – Line chart

Line chart by course with three enrolment counts: active, inactive, and expired, classified by status and end date.

Cache: 1h. Refresh: none.

Full original MySQL SQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP()) THEN 1
               ELSE 0
           END) AS 'lang::active_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS 'lang::inactive_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < UNIX_TIMESTAMP() THEN 1
               ELSE 0
           END) AS 'lang::expired_enrolments::local_kopere_bi'
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname

Full original PostgreSQL SQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND(ue.timeend = 0 OR ue.timeend > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint)) THEN 1
               ELSE 0
           END) AS "lang::active_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS "lang::inactive_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) THEN 1
               ELSE 0
           END) AS "lang::expired_enrolments::local_kopere_bi"
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname
5. New users in the last 12 months – Line chart

Line chart showing the number of confirmed, non-deleted accounts created in each of the past 12 months.

Cache: none. Refresh: none.

Full original MySQL SQL

  SELECT FROM_UNIXTIME(timecreated, '%m/%Y') AS yearmonth,
         COUNT(id) AS 'lang::num_user::local_kopere_bi'
    FROM mdl_user
   WHERE deleted = 0
     AND confirmed = 1
     AND timecreated >= UNIX_TIMESTAMP(DATE_SUB(CURDATE(), INTERVAL 12 MONTH))
GROUP BY yearmonth
ORDER BY yearmonth DESC

Full original PostgreSQL SQL

  SELECT TO_CHAR(TO_TIMESTAMP(timecreated), 'MM/YYYY') AS yearmonth,
         COUNT(id) AS "lang::num_user::local_kopere_bi"
    FROM mdl_user
   WHERE deleted = 0
     AND confirmed = 1
     AND timecreated >= (EXTRACT(EPOCH FROM (CURRENT_DATE - INTERVAL '12 month'))::bigint)
GROUP BY yearmonth
ORDER BY yearmonth DESC

Limitations and cautions

  • The recent-access indicator uses lastaccess from the user account, not Kopere BI's online-presence data, and does not guarantee an open session.
  • In the MySQL variant of the online indicator, subqueries use GROUP BY id even though they are used as scalar expressions. If multiple rows are returned, a multiple-row scalar subquery error may occur. The PostgreSQL variant does not include this grouping.
  • The enrolment chart compares courses; it is not a daily time series.
  • The new-user chart orders its textual MM/YYYY label; this may produce non-chronological order across the new year.
  • Indicators cached for an hour may lag behind the most recent data. MySQL and PostgreSQL versions are documented in separate panels even when their SQL is identical.
