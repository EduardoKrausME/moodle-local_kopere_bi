REPORT 045

Engaged and non-engaged participant totals by course

Groups users with the student role in visible courses according to the presence of a last course access record and at least one activity completion record.

Report purpose

Groups users with the student role in visible courses according to the presence of a last course access record and at least one activity completion record.

Why use this report?

Provides an exploratory view of course access coverage and activity completion records, helping identify participants who may require follow-up.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, student, cohort, or date range. The query covers all visible courses with positive IDs and role ID 5 assignments in course contexts (contextlevel = 50), for users who are neither deleted nor suspended and are not guest.

Classification uses fixed criteria: whether a record exists in mdl_user_lastaccess and whether a module completion with completionstate = 1 exists for the same user and course.

Visualization and full original SQL

One table visualization contains a full original SQL query, cache settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is provided for this report.

1. Engaged and non-engaged participant totals by course · Table

The per-course table counts distinct users assigned role ID 5, students with both a recorded course access and an activity completion, students who accessed without such a completion, and students with no entry in the course last-access table.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id,
       kbi_c.fullname,
       COUNT(DISTINCT kbi_ra.userid)                                        as all_learners,
       COUNT(DISTINCT CASE
                        WHEN comp.userid IS NOT NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
                        ELSE NULL END)                                  as completed_learners,
       COUNT(DISTINCT CASE
                        WHEN comp.userid IS NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
                        ELSE NULL END)                                  as not_completed_learners,
       COUNT(DISTINCT CASE WHEN kbi_ula.id IS NULL THEN kbi_u.id ELSE NULL END) as not_accessed_learners
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       LEFT JOIN (SELECT kbi_cm.course, kbi_cmc.userid
                  FROM mdl_course_modules kbi_cm
                         JOIN mdl_course_modules_completion kbi_cmc
                           ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.completionstate = 1
                  WHERE kbi_cmc.id > 0
                  GROUP BY kbi_cm.course, kbi_cmc.userid) comp ON comp.userid = kbi_u.id AND comp.course = kbi_c.id
       LEFT JOIN mdl_user_lastaccess kbi_ula ON kbi_ula.courseid = kbi_c.id AND kbi_ula.userid = kbi_ra.userid
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 5
GROUP BY kbi_c.id

Limitations and cautions

  • This report does not directly measure educational engagement. Classification relies solely on evidence of a last course access record and completion of at least one activity.
  • The completed_learners field does not indicate formal course completion. An activity with completionstate = 1 associated with the student is sufficient.
  • Other completion states, including completionstate = 2 (completed with a passing grade), are excluded from the subquery. Students who completed activities only in these states may be classified as not having completed any.
  • The kbi_ula.id IS NOT NULL check tests whether a last-access record exists, not whether access occurred recently or lasted for a minimum period.
  • Student counts rely on role ID 5 assignments without restricting enrolment or enrolment-method status. They may therefore differ from active enrolment totals.
  • The not_accessed_learners category groups participants with no record in mdl_user_lastaccess; it does not establish that they have never used other areas of Moodle.
  • The original query has no course or date filter and no independent PostgreSQL variant.
