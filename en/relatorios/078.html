REPORT 078

SCORM activity summary by course

Summarizes SCORM packages in the selected course, including attempt records, module visits tracked by Kopere BI, and accumulated duration reported by the packages.

Report purpose

Summarizes SCORM packages in the selected course, including attempt records, module visits tracked by Kopere BI, and accumulated duration reported by the packages.

Why use this report?

Provides an operational overview of SCORM object usage, helping review attempt volumes, recorded visit frequency, and time reported by the packages themselves.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic filter is Course, represented by :courseid, which appears once in each variant in kbi_c.id = :courseid.

Fixed filters require a positive SCORM package ID and a visible course. The subqueries aggregate attempts by package, tracking records by SCORM module, and duration by package. There are no restrictions on user, role, enrolment, date, completion status, or module visibility.

Visualization and full original SQL

One table visualization contains two complete SQL queries, cache and refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL appear in separate panels within the same visualization.

1. SCORM activity summary by course · Table

The per-SCORM-package table includes its identifier, course and package names, last configuration modification date, number of attempt records, sum of visits recorded by Kopere BI for the module, and sum of SCORM durations in seconds.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_s.id,
       kbi_c.fullname,
       kbi_s.name,
       kbi_s.timemodified,
       COALESCE(kbi_attempts.attempts, 0) AS attempts,
       COALESCE(kbi_tracking.visits, 0) AS visits,
       COALESCE(kbi_duration.duration, 0) AS duration
FROM mdl_scorm kbi_s
JOIN mdl_course kbi_c ON kbi_c.id = kbi_s.course
LEFT JOIN (
    SELECT scormid, COUNT(DISTINCT id) AS attempts
      FROM mdl_scorm_attempt
     GROUP BY scormid
) kbi_attempts ON kbi_attempts.scormid = kbi_s.id
LEFT JOIN (
    SELECT kbi_cm.instance, SUM(kbi_t.visits) AS visits
      FROM mdl_course_modules kbi_cm
      JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module AND kbi_m.name = 'scorm'
      JOIN mdl_local_kopere_bi_tracking kbi_t ON kbi_t.page = 'module'
            AND kbi_t.param = kbi_cm.id
     GROUP BY kbi_cm.instance
) kbi_tracking ON kbi_tracking.instance = kbi_s.id
LEFT JOIN (
    SELECT a.scormid, SUM(CASE WHEN e.element = 'cmi.core.total_time'
                              THEN TIME_TO_SEC(v.value) ELSE NULL END) AS duration
      FROM mdl_scorm_attempt a
      JOIN mdl_scorm_scoes_value v ON v.attemptid = a.id
      JOIN mdl_scorm_element e ON e.id = v.elementid
     GROUP BY a.scormid
) kbi_duration ON kbi_duration.scormid = kbi_s.id
WHERE kbi_s.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_s.name

Full original PostgreSQL SQL

SELECT kbi_s.id,
       kbi_c.fullname,
       kbi_s.name,
       kbi_s.timemodified,
       COALESCE(kbi_attempts.attempts, 0) AS attempts,
       COALESCE(kbi_tracking.visits, 0) AS visits,
       COALESCE(kbi_duration.duration, 0) AS duration
FROM mdl_scorm kbi_s
JOIN mdl_course kbi_c ON kbi_c.id = kbi_s.course
LEFT JOIN(
    SELECT scormid, COUNT(DISTINCT id) AS attempts
      FROM mdl_scorm_attempt
     GROUP BY scormid
) kbi_attempts ON kbi_attempts.scormid = kbi_s.id
LEFT JOIN(
    SELECT kbi_cm.instance, SUM(kbi_t.visits) AS visits
      FROM mdl_course_modules kbi_cm
      JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module AND kbi_m.name = 'scorm'
      JOIN mdl_local_kopere_bi_tracking kbi_t ON kbi_t.page = 'module'
            AND kbi_t.param = kbi_cm.id
     GROUP BY kbi_cm.instance
) kbi_tracking ON kbi_tracking.instance = kbi_s.id
LEFT JOIN(
    SELECT a.scormid, SUM(CASE WHEN e.element = 'cmi.core.total_time'
                              THEN EXTRACT(EPOCH FROM NULLIF((v.value)::text, '')::interval) ELSE NULL END) AS duration
      FROM mdl_scorm_attempt a
      JOIN mdl_scorm_scoes_value v ON v.attemptid = a.id
      JOIN mdl_scorm_element e ON e.id = v.elementid
     GROUP BY a.scormid
) kbi_duration ON kbi_duration.scormid = kbi_s.id
WHERE kbi_s.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_s.name

Limitations and cautions

  • The attempts field counts distinct records in mdl_scorm_attempt, not distinct users or completed packages.
  • The visits field sums Kopere BI records with page = 'module' and param matching the course module ID. It depends on the collection and retention of tracking data.
  • The duration field sums cmi.core.total_time values stored in SCORM records and converted to seconds. This package-reported time is not the same measurement as Kopere BI visit tracking.
  • MySQL uses TIME_TO_SEC, while PostgreSQL converts intervals to seconds. Missing or malformed SCORM values may affect the totals.
  • All three metrics use COALESCE(..., 0) when records are missing. Thus, zero may indicate an absence of tracking records rather than a lack of real activity.
  • The SQL requires a visible course but does not restrict course_modules.visible. Hidden SCORM packages within the course may appear.
  • Counts and durations cover the available history without filtering by period, active enrolment, or completion status. They are not direct measures of achievement or learning.
  • The timemodified column comes from mdl_scorm, not the most recent attempt by an individual user.
