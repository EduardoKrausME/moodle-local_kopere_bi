REPORT 081

Assignment submission review

Compares each user's first submitted assignment attempt with the latest submission record, when different, including dates, grades, attached files, grading scale, and completion state.

Report purpose

Compares each user's first submitted assignment attempt with the latest submission record, when different, including dates, grades, attached files, grading scale, and completion state.

Why use this report?

Helps inspect changes between an initial and subsequent submission, identify attached files, and review grading and activity completion records.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, student, assignment, reporting period, or submission status in either the MySQL or PostgreSQL variant. The query covers courses with users assigned role ID 5 in a course context (contextlevel = 50).

Fixed conditions for the first submission require attemptnumber = 0 and status = 'submitted'. The latest submission is joined when latest = 1, with the same user as the first submission and a different ID. Attachments come from mdl_files with component = 'assignsubmission_file', filearea = 'submission_files', and filesize > 0.

Visualization and full original SQL

One table visualization includes two complete original SQL queries, cache and refresh settings, and Prism.js syntax highlighting. MySQL and PostgreSQL are shown in separate panels within a single visualization.

1. Assignment submission review · Table

The table covers combinations of course, participant with the student role, and assignment. It shows the first submitted attempt (attempt 0), attachments, grade and grading date, module completion state, the latest submission when different, its grade and attachments, attempt numbers, the user's last site-wide access, and the grading scale.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_ass_s.id,
       kbi_c.fullname                     AS course,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.idnumber,
       kbi_u.id                           AS userid,
       kbi_ass.name                       AS assignment,
       kbi_u.lastaccess,
       kbi_ass_s.timecreated              AS date_first_submission,
       kbi_ass_g.grade                    AS grade_first_submission,
       kbi_ass_g.timemodified             AS grade_time_first_submission,
       first_submission_file.filename AS first_submission_file,
       kbi_cmc.completionstate,
       kbi_ass_sl.timemodified            AS date_last_submission,
       kbi_ass_gl.grade                   AS grade_last_submission,
       kbi_ass_gl.timemodified            AS grade_time_last_submission,
       last_submission_file.filename  AS last_submission_file,
       kbi_ass_s.attemptnumber,
       kbi_ass_sl.attemptnumber           AS attemptnumber2,
       kbi_sc.scale
FROM mdl_course kbi_c
       LEFT JOIN mdl_context kbi_con ON kbi_con.contextlevel = 50 AND kbi_con.instanceid = kbi_c.id
       LEFT JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_con.id AND kbi_ra.roleid = 5
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       LEFT JOIN mdl_assign kbi_ass ON kbi_c.id = kbi_ass.course
       LEFT JOIN mdl_assign_submission kbi_ass_s
         ON kbi_ass_s.assignment = kbi_ass.id AND kbi_ass_s.attemptnumber = 0 AND kbi_ass_s.userid = kbi_u.id AND kbi_ass_s.status = 'submitted'
       LEFT JOIN mdl_assign_grades kbi_ass_g ON kbi_ass_g.userid = kbi_ass_s.userid AND kbi_ass_g.assignment = kbi_ass_s.assignment AND
                                            kbi_ass_g.attemptnumber = kbi_ass_s.attemptnumber
       LEFT JOIN (SELECT kbi_f.itemid, GROUP_CONCAT(DISTINCT CONCAT(kbi_f.filename) SEPARATOR ', ') AS filename
                  FROM mdl_files kbi_f
                  WHERE kbi_f.component = 'assignsubmission_file'
                    AND kbi_f.filearea = 'submission_files'
                    AND kbi_f.filesize > 0
                  GROUP BY kbi_f.itemid) first_submission_file ON first_submission_file.itemid = kbi_ass_s.id
       LEFT JOIN mdl_assign_submission kbi_ass_sl
         ON kbi_ass_sl.assignment = kbi_ass.id AND kbi_ass_sl.latest = 1 AND kbi_ass_sl.userid = kbi_ass_s.userid AND kbi_ass_sl.id <> kbi_ass_s.id
       LEFT JOIN mdl_assign_grades kbi_ass_gl ON kbi_ass_gl.userid = kbi_ass_sl.userid AND kbi_ass_gl.assignment = kbi_ass_sl.assignment AND
                                             kbi_ass_gl.attemptnumber = kbi_ass_sl.attemptnumber
       LEFT JOIN (SELECT kbi_f.itemid, GROUP_CONCAT(DISTINCT CONCAT(kbi_f.filename) SEPARATOR ', ') AS filename
                  FROM mdl_files kbi_f
                  WHERE kbi_f.component = 'assignsubmission_file'
                    AND kbi_f.filearea = 'submission_files'
                    AND kbi_f.filesize > 0
                  GROUP BY kbi_f.itemid) last_submission_file ON last_submission_file.itemid = kbi_ass_sl.id
       JOIN mdl_modules kbi_m ON kbi_m.name = 'assign'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_ass.course AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_ass.id
       LEFT JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.userid = kbi_ass_s.userid AND kbi_cmc.coursemoduleid = kbi_cm.id
       LEFT JOIN mdl_grade_items kbi_gi
         ON kbi_gi.courseid = kbi_ass.course AND kbi_gi.itemtype = 'mod' AND kbi_gi.itemmodule = 'assign' AND kbi_gi.iteminstance = kbi_ass.id
       LEFT JOIN mdl_scale kbi_sc ON kbi_sc.id = kbi_gi.scaleid
WHERE kbi_u.id IS NOT NULL

Limitations and cautions

  • Although the title suggests a submission review, there is no filter for course, current enrolment, visibility, deadline, or date. The query may cover many courses and users assigned the student role.
  • A user with the student role may appear even without a first submitted assignment, because the join to mdl_assign_submission is optional. Submission and grade fields are NULL in such cases.
  • The latest-submission join uses kbi_ass_sl.userid = kbi_ass_s.userid. Consequently, when there is no first submitted attempt numbered zero, the query cannot join the latest submission through that relationship.
  • date_first_submission comes from kbi_ass_s.timecreated, the record creation time, which is not necessarily the actual submission date. date_last_submission uses timemodified from the record marked as latest.
  • The latest-submission query does not explicitly require status = 'submitted'. A submission marked latest = 1 may therefore have a different status.
  • First and latest grade fields come from mdl_assign_grades.grade for the corresponding attempt numbers, not necessarily the consolidated final grade in the gradebook.
  • Attachment lists contain positive-size filenames, not download links, and do not prove that the files were assessed. MySQL uses GROUP_CONCAT and PostgreSQL uses STRING_AGG.
  • The lastaccess field is the user's last site-wide access stored in mdl_user, not necessarily access to the assignment or course.
  • Academic information and institutional identifiers are displayed. The main query does not filter deleted or suspended accounts; enforce access permissions and check account status in the application.
