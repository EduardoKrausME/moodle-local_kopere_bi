REPORT 072

Forum post ratio

Daily counts of distinct posts by users assigned the teacher role in forum discussions of the selected course, grouped by discussion modification date.

Report purpose

Daily counts of distinct posts by users assigned the teacher role in forum discussions of the selected course, grouped by discussion modification date.

Why use this report?

Helps explore the daily distribution of teacher posts and replies associated with course discussions, while distinguishing discussion modification dates from individual post dates.

Available filters Visualization and SQL Limitations

Available filters

The only dynamic SQL filter is Course, linked to :courseid and used once in kbi_c.id = :courseid.

Fixed conditions require a course context (contextlevel = 50), teacher role ID 3, and a discussion modification timestamp corresponding to a positive Unix day. Results are grouped by FLOOR(kbi_d.timemodified / 86400) * 86400 and sorted chronologically.

Visualization and full original SQL

One table visualization includes the complete original SQL, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL variant in the source.

1. Forum post ratio · Table

The table displays timepoint, the calculated start of a Unix day derived from mdl_forum_discussions.timemodified, and posts, the number of distinct records in mdl_forum_posts associated with users assigned role ID 3 in that course.

Cache: 1h · Refresh: none.

Full original SQL

SELECT floor(kbi_d.timemodified / 86400) * 86400 as timepoint, count(distinct kbi_p.id) as posts
FROM mdl_role_assignments kbi_ra
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       LEFT JOIN mdl_forum_discussions kbi_d ON kbi_d.course = kbi_c.id
       LEFT JOIN mdl_forum_posts kbi_p ON kbi_p.userid = kbi_ra.userid AND kbi_p.discussion = kbi_d.id
WHERE kbi_ctx.contextlevel = 50
  AND floor(kbi_d.timemodified / 86400) > 0
  AND kbi_c.id = :courseid
  AND kbi_ra.roleid = 3
GROUP BY timepoint
ORDER BY timepoint ASC

Limitations and cautions

  • Despite 'ratio' in the title, no ratio or percentage is calculated: posts counts distinct posts in each daily grouping.
  • The grouping uses mdl_forum_discussions.timemodified, the last discussion modification date, not when each post was created or modified. Posts from different dates can be counted on the same discussion-modification day.
  • The 86,400-second interval uses Unix timestamps to represent days since the Unix epoch. Displaying results in the institution's time zone may require conversion.
  • Filtering by role ID 3 uses course-context assignments and does not require active enrolment. Teachers assigned custom roles or other role IDs are not included.
  • The query does not require kbi_p.parent > 0, so counts can include both initial discussion posts and replies written by users assigned role ID 3.
  • The LEFT JOIN on posts allows groups with zero teacher posts when discussions with valid dates exist in the corresponding context.
  • The SQL does not check course or forum visibility, teacher account status, or a dynamic date range.
  • The absence of a separate PostgreSQL variant does not establish that the SQL is automatically portable. Validate it against the installation's database.
