REPORT 052

Items awaiting grading

Unified table of recent assignment submissions and quiz questions awaiting grading, with deadlines, waiting time, and teachers associated with the courses.

Report purpose

Unified table of recent assignment submissions and quiz questions awaiting grading, with deadlines, waiting time, and teachers associated with the courses.

Why use this report?

Helps teachers and academic teams find submitted work and questions needing assessment, prioritizing items beyond their activity deadline or awaiting grading for longer.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, teacher, student, or date range. Both variants cover all visible courses and modules, exclude deleted, suspended, and guest accounts, and require active enrolments and enrolment methods within their validity period.

For assignments, the query selects the latest submission with status = 'submitted' and a missing or negative grade, or a grade older than the last submission change. For quiz questions, it considers finished, non-preview attempts whose last step has the needsgrading state. Each SQL query has a fixed limit of 500 results.

Visualization and full original SQL

One table visualization includes two complete SQL queries, cache and refresh settings, and Prism.js syntax highlighting. The MySQL and PostgreSQL variants appear in separate panels within the same block.

1. Items awaiting grading · Table

The pending-item table combines assignment submissions with no valid grade or modified after their last grading and questions from finished quiz attempts whose latest step is needsgrading. It shows the course, activity, student, course teachers, deadline, submission date, attempt details when applicable, overdue indicator, and days waiting.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT kbi_waiting.*,
       CASE WHEN kbi_waiting.duedate > 0 AND kbi_waiting.duedate < UNIX_TIMESTAMP()
            THEN 1 ELSE 0 END AS is_overdue,
       CASE WHEN kbi_waiting.submitted_at > 0
            THEN FLOOR((UNIX_TIMESTAMP() - kbi_waiting.submitted_at) / 86400.0)
            ELSE NULL END AS waiting_days
FROM (
       SELECT CONCAT('assign-', kbi_s.id) AS id,
              kbi_c.id                   AS courseid,
              kbi_c.fullname             AS course,
              kbi_cm.id                  AS cmid,
              kbi_a.id                   AS activityid,
              kbi_a.name                 AS activity_name,
              'assign'                   AS activity_type,
              kbi_u.id                   AS userid,
              kbi_u.firstname,
              kbi_u.lastname,
              kbi_u.email,
              kbi_a.duedate,
              kbi_s.timemodified         AS submitted_at,
              kbi_g.timemodified         AS graded_at,
              NULL                       AS slot,
              NULL                       AS attemptid,
              NULL                       AS question_name,
              kbi_teachers.teacher_names AS teachers
       FROM mdl_assign_submission kbi_s
              JOIN mdl_assign kbi_a ON kbi_a.id = kbi_s.assignment
              JOIN mdl_course kbi_c ON kbi_c.id = kbi_a.course
              JOIN mdl_modules kbi_m ON kbi_m.name = 'assign'
              JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id
                    AND kbi_cm.module = kbi_m.id
                    AND kbi_cm.instance = kbi_a.id
              JOIN mdl_user kbi_u ON kbi_u.id = kbi_s.userid
              LEFT JOIN mdl_assign_grades kbi_g ON kbi_g.assignment = kbi_s.assignment
                    AND kbi_g.userid = kbi_s.userid
                    AND kbi_g.attemptnumber = kbi_s.attemptnumber
              LEFT JOIN (
                    SELECT kbi_ctx.instanceid AS courseid,
                           GROUP_CONCAT(DISTINCT CONCAT(kbi_t.firstname, ' ', kbi_t.lastname) ORDER BY kbi_t.lastname, kbi_t.firstname SEPARATOR ', ') AS teacher_names
                    FROM mdl_role_assignments kbi_ra
                           JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid AND kbi_r.shortname IN ('editingteacher', 'teacher')
                           JOIN mdl_user kbi_t ON kbi_t.id = kbi_ra.userid
                           JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
                    WHERE kbi_t.deleted = 0
                      AND kbi_t.suspended = 0
                    GROUP BY kbi_ctx.instanceid
              ) kbi_teachers ON kbi_teachers.courseid = kbi_c.id
       WHERE kbi_s.latest = 1
         AND kbi_s.status = 'submitted'
         AND (kbi_g.id IS NULL OR kbi_g.grade IS NULL OR kbi_g.grade < 0 OR kbi_s.timemodified > COALESCE(kbi_g.timemodified, 0))
         AND kbi_c.visible = 1
         AND kbi_cm.visible = 1
         AND EXISTS (
               SELECT 1 FROM mdl_user_enrolments kbi_ue
               JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
              WHERE kbi_e.courseid = kbi_c.id AND kbi_ue.userid = kbi_u.id
                AND kbi_e.status = 0 AND kbi_ue.status = 0
                AND (kbi_ue.timestart = 0 OR kbi_ue.timestart <= UNIX_TIMESTAMP())
                AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP()))
         AND kbi_u.deleted = 0
         AND kbi_u.suspended = 0
         AND kbi_u.username <> 'guest'

       UNION ALL

       SELECT CONCAT('quiz-', kbi_qa.id, '-', kbi_qatt.id) AS id,
              kbi_c.id                                    AS courseid,
              kbi_c.fullname                              AS course,
              kbi_cm.id                                   AS cmid,
              kbi_qz.id                                   AS activityid,
              kbi_qz.name                                 AS activity_name,
              'quiz'                                      AS activity_type,
              kbi_u.id                                    AS userid,
              kbi_u.firstname,
              kbi_u.lastname,
              kbi_u.email,
              kbi_qz.timeclose                            AS duedate,
              kbi_qa.timefinish                           AS submitted_at,
              NULL                                        AS graded_at,
              kbi_qatt.slot                               AS slot,
              kbi_qa.id                                   AS attemptid,
              kbi_q.name                                  AS question_name,
              kbi_teachers.teacher_names                  AS teachers
       FROM mdl_quiz_attempts kbi_qa
              JOIN mdl_quiz kbi_qz ON kbi_qz.id = kbi_qa.quiz
              JOIN mdl_course kbi_c ON kbi_c.id = kbi_qz.course
              JOIN mdl_user kbi_u ON kbi_u.id = kbi_qa.userid
              JOIN mdl_question_attempts kbi_qatt ON kbi_qatt.questionusageid = kbi_qa.uniqueid
              JOIN mdl_question kbi_q ON kbi_q.id = kbi_qatt.questionid
              JOIN mdl_question_attempt_steps kbi_qas ON kbi_qas.questionattemptid = kbi_qatt.id
                    AND kbi_qas.sequencenumber = (
                        SELECT MAX(kbi_qas2.sequencenumber)
                        FROM mdl_question_attempt_steps kbi_qas2
                        WHERE kbi_qas2.questionattemptid = kbi_qatt.id
                    )
              JOIN mdl_modules kbi_m ON kbi_m.name = 'quiz'
              JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id
                    AND kbi_cm.module = kbi_m.id
                    AND kbi_cm.instance = kbi_qz.id
              LEFT JOIN (
                    SELECT kbi_ctx.instanceid AS courseid,
                           GROUP_CONCAT(DISTINCT CONCAT(kbi_t.firstname, ' ', kbi_t.lastname) ORDER BY kbi_t.lastname, kbi_t.firstname SEPARATOR ', ') AS teacher_names
                    FROM mdl_role_assignments kbi_ra
                           JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid AND kbi_r.shortname IN ('editingteacher', 'teacher')
                           JOIN mdl_user kbi_t ON kbi_t.id = kbi_ra.userid
                           JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
                    WHERE kbi_t.deleted = 0
                      AND kbi_t.suspended = 0
                    GROUP BY kbi_ctx.instanceid
              ) kbi_teachers ON kbi_teachers.courseid = kbi_c.id
       WHERE kbi_qa.preview = 0
         AND kbi_qa.state = 'finished'
         AND kbi_qas.state = 'needsgrading'
         AND kbi_c.visible = 1
         AND kbi_cm.visible = 1
         AND EXISTS (
               SELECT 1 FROM mdl_user_enrolments kbi_ue
               JOIN mdl_enrol kbi_e ON kbi_e.id = kbi_ue.enrolid
              WHERE kbi_e.courseid = kbi_c.id AND kbi_ue.userid = kbi_u.id
                AND kbi_e.status = 0 AND kbi_ue.status = 0
                AND (kbi_ue.timestart = 0 OR kbi_ue.timestart <= UNIX_TIMESTAMP())
                AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP()))
         AND kbi_u.deleted = 0
         AND kbi_u.suspended = 0
         AND kbi_u.username <> 'guest'
) kbi_waiting
ORDER BY kbi_waiting.course, kbi_waiting.activity_name, kbi_waiting.submitted_at DESC
LIMIT 500

Limitations and cautions

  • The list is limited to 500 rows, ordered by course and activity before submission date. If more items are pending, the report may omit some, including the oldest items across the platform.
  • The query has no course or date-range parameter. Status is filtered through fixed assignment and question conditions, while the waiting-day calculation uses the database's current time.
  • The is_overdue field compares the activity's configured deadline with the current time. It does not necessarily mean the student submitted late; for quizzes it uses timeclose.
  • The waiting_days field measures time since submission or attempt completion, not time since the deadline or when grading first became necessary. The calculation does not use business days.
  • The teacher list includes users with course-context roles whose short names are editingteacher or teacher. It does not necessarily identify the teacher responsible for grading that submission.
  • The union combines different levels of detail: one row per selected assignment submission and one row per question pending manual grading in a quiz attempt. Counting rows does not equal counting distinct students or activities.
  • Results depend on grading rules, attempt steps, enrolment tables, and visibility. As student identities and email addresses are included, restrict access to authorized users.
  • MySQL and PostgreSQL use database-specific date and name-aggregation functions. Refer to the complete variant for the database in use.
