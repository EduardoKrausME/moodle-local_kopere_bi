REPORT 020

User roles and role changes

Table of role assignments in a course and information about role changes recorded in the Kopere BI temporary log history.

Report purpose

Table of role assignments in a course and information about role changes recorded in the Kopere BI temporary log history.

Why use this report?

Helps administrators review roles assigned to course participants and investigate recorded evidence of role-assignment changes, including action, actor, and related user when such records are available.

Filtros disponíveis Visualization and SQL Limitations

Available filters

The available dynamic filter is Course, linked to the SQL parameter :courseid. The query uses this value to select role assignments in the specified course.

Fixed criteria include course contexts (contextlevel = 50), existing role assignments, and, in the event subquery, assigned or unassigned actions targeting role. There are no dynamic user, cohort, or date-range SQL filters.

Visualization and full original SQL

The report contains one table and two SQL queries, highlighted using Prism.js. The MySQL and PostgreSQL variants share a visualization block, with each query in a separate panel.

1. User roles and role changes · Table

The table groups role assignments by user and course, lists assigned role short names, and summarizes the latest related event, including its action, role, date, and the person responsible. MySQL and PostgreSQL variants differ in their aggregation functions and date-to-text conversion.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT MIN(kbi_ra.id),
       kbi_c.id                                                                    AS courseid,
       kbi_c.fullname                                                              AS course_name,
       GROUP_CONCAT(DISTINCT kbi_r0.shortname)                                     AS role,
       MIN(lsl.all_count)                                                      AS all_count,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_r.shortname) ELSE '-' END     AS action_role,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_log.action) ELSE '-' END      AS action,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_log.timecreated) ELSE '-' END AS timecreated,
       CASE
         WHEN MIN(lsl.all_count) > 1 THEN MAX(CONCAT(kbi_u_action.firstname, ' ', kbi_u_action.lastname))
         ELSE '-' END                                                          AS user_action,
       MAX(kbi_u_action.id)                                                        AS user_action_id,
       MAX(kbi_u_related.firstname)                                                AS firstname,
       MAX(kbi_u_related.lastname)                                                 AS lastname,
       MAX(kbi_u_related.email)                                                    AS email,
       MAX(kbi_u_related.id)                                                       AS user_related_id
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       LEFT JOIN mdl_role kbi_r0 ON kbi_r0.id = kbi_ra.roleid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       LEFT JOIN (SELECT kbi_lsl.courseid, kbi_lsl.relateduserid, MAX(kbi_lsl.id) AS last_change, COUNT(kbi_lsl.id) AS all_count
                  FROM mdl_local_kopere_bi_log_tmp kbi_lsl
                         JOIN mdl_role_assignments kbi_ra1 ON kbi_ra1.userid = kbi_lsl.relateduserid
                         JOIN mdl_context kbi_ctx1 ON kbi_ctx1.id = kbi_ra1.contextid AND kbi_ctx1.instanceid = kbi_lsl.courseid
                  WHERE (kbi_lsl.action = 'assigned' OR kbi_lsl.action = 'unassigned')
                    AND kbi_lsl.target = 'role'
                    AND kbi_lsl.contextlevel = 50
                    AND kbi_ctx1.contextlevel = 50
                  GROUP BY kbi_lsl.courseid, kbi_lsl.relateduserid) lsl ON lsl.courseid = kbi_c.id AND lsl.relateduserid = kbi_ra.userid
       LEFT JOIN mdl_local_kopere_bi_log_tmp kbi_log ON kbi_log.id = lsl.last_change
       LEFT JOIN mdl_role kbi_r ON kbi_r.id = kbi_log.objectid
       LEFT JOIN mdl_user kbi_u_action ON kbi_u_action.id = kbi_log.userid
       LEFT JOIN mdl_user kbi_u_related ON kbi_u_related.id = kbi_log.relateduserid
WHERE kbi_ra.id > 0
  AND kbi_c.id = :courseid
GROUP BY kbi_ra.userid, kbi_c.id

Full original PostgreSQL SQL

       kbi_c.id                                                                    AS courseid,
       kbi_c.fullname                                                              AS course_name,
       STRING_AGG(DISTINCT (kbi_r0.shortname)::text, ',')                                     AS role,
       MIN(lsl.all_count)                                                      AS all_count,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_r.shortname) ELSE '-' END     AS action_role,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_log.action) ELSE '-' END      AS action,
       CASE WHEN MIN(lsl.all_count) > 1 THEN MAX(kbi_log.timecreated)::text ELSE '-' END AS timecreated,
       CASE
         WHEN MIN(lsl.all_count) > 1 THEN MAX(CONCAT(kbi_u_action.firstname, ' ', kbi_u_action.lastname))
         ELSE '-' END                                                          AS user_action,
       MAX(kbi_u_action.id)                                                        AS user_action_id,
       MAX(kbi_u_related.firstname)                                                AS firstname,
       MAX(kbi_u_related.lastname)                                                 AS lastname,
       MAX(kbi_u_related.email)                                                    AS email,
       MAX(kbi_u_related.id)                                                       AS user_related_id
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       LEFT JOIN mdl_role kbi_r0 ON kbi_r0.id = kbi_ra.roleid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       LEFT JOIN(SELECT kbi_lsl.courseid, kbi_lsl.relateduserid, MAX(kbi_lsl.id) AS last_change, COUNT(kbi_lsl.id) AS all_count
                  FROM mdl_local_kopere_bi_log_tmp kbi_lsl
                         JOIN mdl_role_assignments kbi_ra1 ON kbi_ra1.userid = kbi_lsl.relateduserid

                    AND kbi_lsl.target = 'role'
                    AND kbi_lsl.contextlevel = 50
                    AND kbi_ctx1.contextlevel = 50

Limitations and cautions

  • Role-change records come from mdl_local_kopere_bi_log_tmp, not an unlimited audit trail. Events depend on the collection and retention of this table.
  • The SQL displays change details only when MIN(lsl.all_count) > 1; a single change may therefore be omitted even when present in the log.
  • The query groups by user and course but uses aggregates such as MAX for various fields. This can combine values from different rows rather than fully describing one event.
  • The listed roles come from assignments present in the query. A record alone does not establish whether a previous assignment was later revoked.
  • MySQL and PostgreSQL variants use different functions to aggregate roles and format dates. Both require testing against actual data and permissions in the target environment.
  • The report may reveal names and email addresses of users associated with role changes. Restrict access to authorized administrative roles.
