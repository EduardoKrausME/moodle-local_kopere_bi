REPORT 024

User status summary

Per-user summary with registration and last-access dates, calculated average grades, course counts, formal course completions, completed activities, and tracking indicators.

Report purpose

Per-user summary with registration and last-access dates, calculated average grades, course counts, formal course completions, completed activities, and tracking indicators.

Why use this report?

Helps managers review each user's overall progress, combining associated courses, grades, formal completion, and platform usage records.

Actual filters Visualization and SQL Limitations

Available filters

There are no dynamic course, user, cohort, or date-range SQL parameters. The report considers accounts with id > 0 that are neither deleted nor suspended and are not guest.

Completed activities are counted using completionstate IN (1, 2). The time and visit aggregate uses tracking records associated with visible courses where courseid > 0. No dynamic course or date-range selection is available.

Visualization and full original SQL

The report contains one table visualization and one SQL query, with cache and refresh settings and Prism.js syntax highlighting. The catalog does not provide a separate PostgreSQL variant.

1. User status summary · Table

The table displays name, email, registration date, global last access, average grade, distinct courses inferred from context role assignments, formally completed courses, activity completion count, time, and visits. These indicators are aggregated by user.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_u.id,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_u.lastaccess,
       kbi_u.timecreated                          as registered,
       ROUND(AVG(CASE
                   WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                   ELSE kbi_g.finalgrade END), 0) as grade,
       COUNT(DISTINCT kbi_ctx.instanceid)         as courses,
       COUNT(DISTINCT kbi_cc.id)                  as completed_courses,
       MAX(ca.completed_activities)           AS completed_activities,
       MAX(lit.timespend)                     AS timespend,
       MAX(lit.visits)                        AS visits,
       ''                                     as cohortname
FROM mdl_user kbi_u
       LEFT JOIN mdl_role_assignments kbi_ra ON kbi_ra.userid = kbi_u.id
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       LEFT JOIN (SELECT COUNT(id) AS completed_activities, userid
                  FROM mdl_course_modules_completion
                  WHERE id > 0
                    AND completionstate IN (1, 2)
                  GROUP BY userid) ca ON ca.userid = kbi_u.id
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_ctx.instanceid AND
                                              kbi_cc.userid = kbi_u.id AND kbi_cc.timecompleted > 0
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_ctx.instanceid AND
                                       kbi_gi.itemtype = 'course'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = kbi_u.id AND
                                       kbi_g.finalgrade IS NOT NULL
       LEFT JOIN (SELECT kbi_t.userid, SUM(kbi_t.timespend) as timespend, SUM(kbi_t.visits) as visits
                  FROM mdl_local_kopere_bi_tracking kbi_t
                         JOIN mdl_course kbi_c ON kbi_t.courseid = kbi_c.id AND kbi_c.visible = 1
                  WHERE kbi_t.courseid > 0
                  GROUP BY kbi_t.userid) as lit ON lit.userid = kbi_u.id
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
GROUP BY kbi_u.id

Limitations and cautions

  • The course count comes from distinct contexts associated with the user's role assignments, without requiring a particular role or confirming enrolment status.
  • The completed activity total counts completion records associated with a user without filtering by course, module visibility, or whether completion is required. It is not limited to activities from any selected course.
  • The grade average uses values found in course grade items and may be affected by join cardinality. It is not weighted by credits or enrolments.
  • Formally completed courses are obtained from mdl_course_completions with timecompleted > 0, a different metric from activity completion.
  • The cohortname field contains an empty string; the query does not perform a genuine cohort analysis.
  • Time and visits depend on Kopere BI data recorded for visible courses; they do not prove learning. There is no separate PostgreSQL variant in the catalog.
