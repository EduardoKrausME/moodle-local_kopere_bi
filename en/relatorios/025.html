REPORT 025

Assignments graded by teacher

Course assignment table relating students, their submissions, grades, grading teachers, and last recorded course access.

Report purpose

Course assignment table relating students, their submissions, grades, grading teachers, and last recorded course access.

Why use this report?

Provides academic teams with an operational view of assignments in the selected course, identifying students with submissions, recorded grades, and assessments associated with teachers.

Available filters Visualization and SQL Limitations

Available filters

The dynamic SQL parameter is :courseid, which restricts the selection to the chosen course.

Other criteria are fixed: Moodle modules of type assign, users assigned role ID 5 in the course context, visible courses, users who are neither deleted nor suspended, and accounts other than guest. The submission subquery requires status = 'submitted' and latest = 1, while the grading association accepts grade > -1. There are no dynamic teacher, assignment, or date-range parameters.

Visualization and full original SQL

The report contains one table visualization and one SQL query, with cache and refresh settings and Prism.js syntax highlighting. No separate PostgreSQL variant file is provided.

1. Assignments graded by teacher · Table

The table shows assignment name, course and category, student details, grader name, dates associated with the grade and submission, percentage grade, and student's last course access. The SQL starts from course assignment activities and role ID 5 student assignments.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_gi.itemname                            AS activity_name,
       kbi_g.userid,
       kbi_u.username,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.fullname,
       kbi_cc1.name                               AS course_category,
       kbi_c.shortname,
       CONCAT(kbi_gu.firstname, ' ', kbi_gu.lastname) AS grader_name,
       kbi_g.timemodified                         AS graduated,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 0)    AS grade,
       ROUND((CASE
                WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                        THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                ELSE kbi_g.finalgrade END), 0)    AS grade_percent,
       kbi_gi.itemtype,
       kbi_sg.timemodified                        AS need_grade_assignment,
       kbi_ass.timemodified                       AS submission_date,
       kbi_ul.timeaccess                          AS course_lastaccess
FROM mdl_course kbi_c
       JOIN mdl_course_categories kbi_cc1 ON kbi_cc1.id = kbi_c.category
       JOIN mdl_modules kbi_m ON kbi_m.name = 'assign'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id
       JOIN (SELECT kbi_ctx.instanceid, kbi_ra.userid
             FROM mdl_context kbi_ctx
                    JOIN mdl_role_assignments kbi_ra ON kbi_ra.contextid = kbi_ctx.id AND kbi_ra.roleid = 5
             WHERE kbi_ctx.contextlevel = 50
             GROUP BY kbi_ctx.instanceid, kbi_ra.userid) ra ON ra.instanceid = kbi_c.id
       JOIN mdl_user kbi_u ON kbi_u.id = ra.userid
       JOIN mdl_grade_items kbi_gi ON kbi_gi.iteminstance = kbi_cm.instance AND kbi_gi.itemmodule = 'assign'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_gi.id = kbi_g.itemid AND kbi_g.userid = kbi_u.id
       LEFT JOIN mdl_assign_submission kbi_ass
         ON kbi_ass.userid = kbi_u.id AND kbi_ass.assignment = kbi_cm.instance AND kbi_ass.status = 'submitted' AND kbi_ass.latest = 1
       LEFT JOIN mdl_assign_grades kbi_sg
         ON kbi_ass.assignment = kbi_sg.assignment AND kbi_ass.userid = kbi_sg.userid AND kbi_sg.attemptnumber = kbi_ass.attemptnumber AND
            kbi_sg.grade > -1
       LEFT JOIN mdl_user kbi_gu ON kbi_gu.id = kbi_sg.grader
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_u.id
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1

Limitations and cautions

  • The table is not filtered by teacher: student identifiers and grades appear alongside the grader's name when a corresponding record exists. The title does not imply selecting a specific teacher.
  • The graduated field represents kbi_g.timemodified, a change to the grade record, whereas need_grade_assignment represents kbi_sg.timemodified, despite potentially confusing field names.
  • The query uses optional joins for grades, submissions, and grading, so rows without a submission or grade may appear. A missing grade alone does not imply a pending submission.
  • The SQL associates grade items by assignment instance and module type assign; for unusual grading records, verify that grades correspond to the intended assignment.
  • The query does not explicitly filter individual assignments by module visibility or deletion in progress; visibility is applied only at course level.
  • The data include students' names and identifiers, grades, and grading teachers. Restrict access and exports according to institutional privacy rules.
  • There is no separate PostgreSQL definition for this report. Validate the SQL against the database system actually in use.
