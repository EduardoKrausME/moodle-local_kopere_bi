REPORT 005

Inactive enrolments

A table lists students and courses when the join to user_lastaccess finds no access-time record.

Purpose and content

A table lists students and courses when the join to user_lastaccess finds no access-time record.

Why and when to use it

Helps identify potential first-access difficulties and review enrolled users, but does not establish whether an enrolment is actually inactive or expired.

Filters SQL and visualizations Cautions

Available filters

There are no dynamic SQL parameters for course, user, cohort, or date range. The query criterion is ul.timeaccess IS NULL, without filtering by enrolment status.

The SQL does not check ue.status, e.status, or ue.timeend; therefore, the title does not imply that only genuinely inactive enrolments appear.

Visualizations and full original SQL

This report contains 1 visualization and 1 SQL query. Where a visualization has separate MySQL and PostgreSQL queries, they are displayed in separate panels within the same item.

1. Students without recorded access time – Table

The table shows the student, course, contact details, location, first and last access, last login, and IP address. Its main condition is ul.timeaccess IS NULL.

Cache: 30m · Refresh: 30m.

Full original SQL

SELECT u.id        AS u_id,
       u.firstname,
       u.lastname,
       c.id       AS c_id,
       c.fullname AS c_fullname,
       u.email,
       u.phone1,
       u.city,
       u.country,
       u.firstaccess,
       u.lastaccess,
       u.lastlogin,
       u.lastip,
       (SELECT r.name
           FROM {user_enrolments} ue2
           JOIN {enrol} e ON e.id = ue2.enrolid
           JOIN {role}  r ON e.id = r.id
          WHERE ue2.userid = u.id
            AND e.courseid = c.id ) AS rolename
  FROM mdl_user_enrolments ue
  JOIN mdl_enrol  e ON e.id = ue.enrolid
  JOIN mdl_course c ON c.id = e.courseid
  JOIN mdl_user   u ON u.id = ue.userid
LEFT JOIN {user_lastaccess} ul ON ul.userid = u.id
 WHERE ul.timeaccess IS NULL

Limitations and interpretation

  • Missing access time is not equivalent to an inactive enrolment; active enrolments may appear.
  • The join to user_lastaccess uses only userid and does not restrict courseid. Access to another course may exclude a user from the table.
  • The role subquery links enrol.id to role.id, which is not the usual Moodle role assignment relationship; it may return incorrect information or multiple records.
  • There are no explicit exclusions for suspended users, deleted accounts, or hidden courses.
  • To audit suspended or expired enrolments, check status fields and end dates directly.

The SQL was transcribed without changes from the JSON definitions on master and was not run against Moodle at this stage. Validate permissions, performance, and results in the target environment.
