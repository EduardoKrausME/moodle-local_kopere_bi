REPORT 125

Feedback response distribution

Distribution of Feedback answer codes in completed submissions, with counts of distinct submissions and recorded answers.

Report purpose

Table by course, Feedback activity, question, and response value, showing the answer code or summary, number of stored records, distinct completed submissions, and percentage of all records for that question. Groups are sorted by course, Feedback activity, question, and response frequency, with up to 500 rows.

Why use this report?

Analyze the distribution of response values for multiple-choice questions in the Feedback module to identify the most common choices and their percentages by question.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL parameters for course, activity, question, answer, user, or reporting period. Only questions with fi.typ IN ('multichoice', 'multichoicerated') and answers in mdl_feedback_value associated with a corresponding Feedback mdl_feedback_completed record are included.

There is no filter for date, anonymous participation, user status, or visibility. Results are limited to 500 groups after sorting by course, Feedback, question, and frequency.

Visualization and full original SQL

One table visualization contains the complete original SQL, cache and refresh settings, with Prism.js syntax highlighting. No separate PostgreSQL variant was found in master, so no nonexistent query has been added.

1. Feedback response distribution · Table

Table by course, Feedback activity, question, and answer value, showing the answer code or summary, number of records, distinct completed submissions, and percentage of all records for that question. Results are sorted by course, activity, question, and answer frequency, with a 500-row limit.

Cache: 1h · Refresh: none.

Full original SQL

SELECT CONCAT(fi.id, '-', COALESCE(fv.value, '')) AS id,
       c.id AS courseid, c.fullname AS course, f.id AS feedbackid, f.name AS feedback,
       fi.id AS questionid, fi.name AS question, fi.typ AS question_type,
       CASE WHEN fv.value IS NULL OR fv.value = '' THEN 'Not selected' ELSE fv.value END AS answer,
       COUNT(fv.id) AS answers, COUNT(DISTINCT fv.completed) AS respondents,
       total.totalanswers AS total_responses,
       ROUND(100.0 * COUNT(fv.id) / NULLIF(total.totalanswers, 0), 2) AS answer_percent
  FROM mdl_feedback_value fv
  JOIN mdl_feedback_item fi ON fi.id = fv.item
  JOIN mdl_feedback f ON f.id = fi.feedback
  JOIN mdl_feedback_completed completed ON completed.id = fv.completed AND completed.feedback = f.id
  JOIN mdl_course c ON c.id = f.course
  JOIN (SELECT v2.item, COUNT(v2.id) AS totalanswers FROM mdl_feedback_value v2
          JOIN mdl_feedback_completed fc2 ON fc2.id = v2.completed
         GROUP BY v2.item) total
    ON total.item = fi.id
 WHERE fi.typ IN ('multichoice', 'multichoicerated')
 GROUP BY c.id, c.fullname, f.id, f.name, fi.id, fi.name, fi.typ, fv.value, total.totalanswers
 ORDER BY c.fullname, f.name, fi.name, answers DESC
 LIMIT 500

Calculation criteria and behavior

For each answer, the SQL uses COUNT(fv.id) to count stored records and COUNT(DISTINCT fv.completed) to count distinct completed submissions providing that value. The label Not selected is used when an existing record has an empty or NULL fv.value.

The total subquery computes COUNT(v2.id) by question. answer_percent is calculated as 100.0 * COUNT(fv.id) / total.totalanswers, rounded to two decimals. Values stored in fv.value can be internal choice codes; mapping them to the labels shown to respondents depends on the item definition.

Limitations and cautions

  • The respondents field counts distinct mdl_feedback_completed IDs, not user IDs. A completed submission may be anonymous, and a person may submit more than once if the settings allow.
  • A question without any records in mdl_feedback_value is not displayed. The label Not selected applies only to existing records with an empty or NULL value, not to everyone who skipped that question.
  • SQL groups by the original fv.value; NULL and empty-string values may be separate groups even when both display as Not selected.
  • The denominator subquery counts all stored values for a question, while the outer query has its own joins and conditions. With inconsistent data, the denominator may not exactly match the responses displayed.
  • Stored answers may be choice codes rather than readable labels. Interpreting the code requires consulting the actual Feedback item configuration.
  • The percentages describe the distribution of recorded values, not institutional satisfaction, course quality, or population representativeness without contextual analysis.
  • There is no date filter or explicit course/Feedback visibility check. The 500-group limit may exclude questions appearing later in the sort order.

The SQL was reproduced verbatim from the original JSON definition in master. No queries were executed on Moodle during this documentation work. Before institutional use, validate database compatibility, interpretation of the data, and access permissions.
