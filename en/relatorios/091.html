REPORT 091

Course access by weekday and time slot

Groups Kopere BI tracked visits and time for visible courses by weekday and time slot, showing each slot's share of the course's total recorded time.

Report purpose

Groups Kopere BI tracked visits and time for visible courses by weekday and time slot, showing each slot's share of the course's total recorded time.

Why use this report?

Helps identify the days and time slots in which courses accumulate the most recorded visits and tracked time, supporting operational analysis of access patterns and platform usage.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, user, category, calendar period, or date. Both MySQL and PostgreSQL variants query the available records in mdl_local_kopere_bi_period.

Fixed conditions are p.courseid > 1 and c.visible = 1. The reference total is computed across all time records for each course whose ID exceeds 1. Aggregation uses p.weekdaynum and p.slot, without an interactive weekday or time-slot selector.

Visualization and full original SQL

One table visualization includes both complete original SQL queries, MySQL and PostgreSQL, shown in separate panels within the same block. Prism.js highlights SQL syntax.

1. Course access by weekday and time slot · Table

One row per course, weekday, and time slot, showing the course ID, category, weekday number and name, time slot, total visits, recorded seconds, equivalent hours, and share of the course's total recorded time. Weekdays run from Monday (0) to Sunday (6), with seven predefined time slots.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT CONCAT(p.courseid, '-', p.weekdaynum, '-', p.slot) AS id,
       c.id AS courseid,
       c.fullname AS course,
       cc.name AS category_name,
       p.weekdaynum AS weekday_number,
       CASE p.weekdaynum
         WHEN 0 THEN 'Monday'
         WHEN 1 THEN 'Tuesday'
         WHEN 2 THEN 'Wednesday'
         WHEN 3 THEN 'Thursday'
         WHEN 4 THEN 'Friday'
         WHEN 5 THEN 'Saturday'
         ELSE 'Sunday'
       END AS weekday_name,
       CASE p.slot
         WHEN 1 THEN '00:00 - 05:59'
         WHEN 2 THEN '06:00 - 08:59'
         WHEN 3 THEN '09:00 - 11:59'
         WHEN 4 THEN '12:00 - 14:59'
         WHEN 5 THEN '15:00 - 17:59'
         WHEN 6 THEN '18:00 - 20:59'
         ELSE '21:00 - 23:59'
       END AS active_period,
       SUM(p.visits) AS visits,
       SUM(p.timespend) AS timespend,
       ROUND(SUM(p.timespend) / 3600.0, 2) AS hours_spent,
       ROUND(SUM(p.timespend) * 100.0 / NULLIF(t.total_timespend, 0), 2) AS percent_of_course_time
  FROM mdl_local_kopere_bi_period p
  JOIN mdl_course c ON c.id = p.courseid
  LEFT JOIN mdl_course_categories cc ON cc.id = c.category
  JOIN (
       SELECT courseid, SUM(timespend) AS total_timespend
         FROM mdl_local_kopere_bi_period
        WHERE courseid > 1
     GROUP BY courseid
  ) t ON t.courseid = p.courseid
 WHERE p.courseid > 1
   AND c.visible = 1
 GROUP BY p.courseid, c.id, c.fullname, cc.name, p.weekdaynum, p.slot, t.total_timespend
 ORDER BY c.fullname, p.weekdaynum, p.slot

Limitations and cautions

  • Records in mdl_local_kopere_bi_period are Kopere BI tracking data, not a complete raw log of every Moodle event. Missing tracking records do not prove that access did not occur.
  • The percent_of_course_time field represents the share of that course's tracked time in a particular weekday and time slot; it does not represent course completion, attendance, or academic achievement.
  • The percentage uses NULLIF(t.total_timespend, 0). When the total recorded time for a course is zero, the value is NULL to prevent division by zero.
  • The seven fixed time slots range from 00:00 - 05:59 through 21:00 - 23:59 and reflect the stored slot field. The query does not reconstruct time slots from timestamps.
  • Weekday names are returned directly in English by the original SQL CASE expression. Weekday 0 means Monday, not Sunday.
  • According to the catalog, recent time-slot records use the site's configured time zone; older records available only as daily aggregates cannot be retrospectively distributed by their original access hour.
  • There is no date-range filter, and the course must be visible when the query runs. Interpret comparisons carefully when courses have different tracking periods.
  • The visits metric counts recorded visits, not unique users. timespend is tracked time, not proof of active studying.
