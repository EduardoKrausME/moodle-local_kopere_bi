REPORT 118

Weekly course completions by category

Number of course completions and distinct courses with completions by category and UTC week.

Report purpose

Table showing category name, UTC week start, number of course-completion records, and number of distinct courses with recorded completions. Rows are ordered by newest week and category, with a 500-row limit.

Why use this report?

Analyze how formal course completions are distributed across categories and weeks, identifying their volume and how many different courses recorded at least one completion.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for category, course, student, or reporting period. The query requires cc.timecompleted IS NOT NULL and cc.timecompleted > 0, with completions in the last 31536000 seconds—a rolling window of 365 days.

There is no explicit restriction for course visibility, account status, participant role, or a selected category. The query returns up to 500 category-week combinations, prioritizing the most recent.

Visualization and full original SQL

The report has one table visualization with full original SQL, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant is available in master for this definition, so no nonexistent query has been added.

1. Weekly course completions by category · Table

Table with category name, UTC week start, number of completion records, and number of distinct courses with completions. Rows are sorted by the most recent week and category, with a limit of 500.

Cache: 1h · Refresh: none.

Full original SQL

SELECT CONCAT(cat.id, '-', (FLOOR((cc.timecompleted + 259200) / 604800.0) * 604800 - 259200)) AS id,
       cat.name AS category, (FLOOR((cc.timecompleted + 259200) / 604800.0) * 604800 - 259200) AS weekstart,
       COUNT(cc.id) AS completed, COUNT(DISTINCT cc.course) AS completed_courses
  FROM mdl_course_completions cc
  JOIN mdl_course c ON c.id = cc.course
  JOIN mdl_course_categories cat ON cat.id = c.category
 WHERE cc.timecompleted IS NOT NULL AND cc.timecompleted > 0
   AND cc.timecompleted >= UNIX_TIMESTAMP() - 31536000
 GROUP BY cat.id, cat.name, (FLOOR((cc.timecompleted + 259200) / 604800.0) * 604800 - 259200)
 ORDER BY weekstart DESC, cat.name
 LIMIT 500

Calculation criteria and behavior

The weekly period is derived from cc.timecompleted using FLOOR((timecompleted + 259200) / 604800.0) * 604800 - 259200, grouping records into weeks beginning Monday at 00:00 UTC.

COUNT(cc.id) counts course-completion records, while COUNT(DISTINCT cc.course) counts distinct courses with completions in that category and week. Grouping uses the course's current category in mdl_course_categories.

Limitations and cautions

  • Completion records do not necessarily represent distinct students: one person can complete different courses in the same category and week.
  • The number of distinct courses with completions is not the total number of existing or active courses in the category.
  • The category is the course's current category. Moving courses between categories can change how historical completions are classified.
  • The 365-day window is not exactly 12 calendar months and may include partial weeks at its beginning and end.
  • Hidden courses, deleted accounts, and other statuses are not explicitly filtered by the query.
  • The 500-row limit may omit older categories or weeks. Completion dates derived from timestamps should be interpreted in UTC.
  • The definition uses UNIX_TIMESTAMP() and has no separate PostgreSQL variant. Execution on another database requires compatibility validation.

The query is reproduced verbatim from the original JSON in master. It was not executed in Moodle during this documentation work; before institutional use, validate database compatibility, access permissions, and metric interpretation.
