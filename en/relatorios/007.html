REPORT 007

Engagement indicators

Two tables summarize teacher and course indicators: associated students, recorded completion, grades, and student access or participation status.

Report purpose

Two tables summarize teacher and course indicators: associated students, recorded completion, grades, and student access or participation status.

Why use this report?

Useful for course coordinators and tutors identifying courses with low participation, comparing support across classes, and checking teacher-related learning indicators.

Actual filters Visualizations and SQL Limitations

Available filters

There are no dynamic SQL filters for user, course, cohort, or date range. Both tables have fixed criteria: course context level 50, role IDs 3 and 5, visible courses, and users who are neither deleted nor suspended, as specified in each query.

The SQL contains a date condition on lastaccess only as a comment, so it is not applied.

Visualizations and full original SQL

This report contains 2 visualizations and 2 SQL queries. Syntax highlighting preserves the original characters. MySQL and PostgreSQL variants are shown in separate panels for each applicable visualization.

1. Teacher-related engagement – Table

Teacher-level table showing role ID 3 in a course context, number of courses, students assigned role ID 5, non-suspended accounts, formal course completions, and calculated average grades.

Cache: 30m. Refresh: 30m.

Full original SQL

SELECT
    kbi_u.id        AS u_id,
    kbi_u.firstname,
    kbi_u.lastname,
    COUNT(DISTINCT kbi_ctx.instanceid)  AS num_courses,
    SUM(l.learners)                 AS num_learners,
    SUM(l1.activelearners)          AS num_activelearners,
    SUM(cc.completed)               AS num_completedlearners,
    AVG(g.grade)                    AS grade
FROM mdl_user kbi_u
LEFT JOIN mdl_role_assignments kbi_ra ON kbi_ra.userid = kbi_u.id
LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
JOIN mdl_course kbi_c ON kbi_ctx.instanceid = kbi_c.id AND kbi_c.visible = 1
LEFT JOIN (
    SELECT 
        kbi_ctx.instanceid, 
        COUNT(DISTINCT kbi_ra.userid) AS learners
    FROM mdl_role_assignments kbi_ra, mdl_context kbi_ctx
    WHERE 
        kbi_ctx.id = kbi_ra.contextid
        AND kbi_ctx.contextlevel = 50
        AND kbi_ra.roleid = 5
    GROUP BY 
        kbi_ctx.instanceid
) AS l ON l.instanceid = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        kbi_ctx.instanceid, 
        COUNT(DISTINCT kbi_ra.userid) AS activelearners
    FROM mdl_role_assignments kbi_ra, mdl_user kbi_u, mdl_context kbi_ctx
    WHERE 
        kbi_ctx.id = kbi_ra.contextid
        AND kbi_ctx.contextlevel = 50
        AND kbi_u.id = kbi_ra.userid
        -- AND kbi_u.lastaccess BETWEEN 1707755694 AND 1710347694
        AND kbi_u.deleted = 0
        AND kbi_u.suspended = 0
        AND kbi_ra.roleid = 5
    GROUP BY 
        kbi_ctx.instanceid
) AS l1 ON l1.instanceid = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        course, 
        COUNT(id) AS completed
    FROM 
        mdl_course_completions
    WHERE 
        timecompleted > 0
    GROUP BY 
        course
) cc ON cc.course = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        kbi_gi.courseid,
        ROUND(AVG(CASE
            WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
            ELSE kbi_g.finalgrade 
        END), 0) AS grade
    FROM mdl_grade_items kbi_gi, mdl_grade_grades kbi_g
    WHERE 
        kbi_gi.itemtype = 'course'
        AND kbi_g.itemid = kbi_gi.id
        AND kbi_g.finalgrade IS NOT NULL
    GROUP BY 
        kbi_gi.courseid
) g ON g.courseid = kbi_ctx.instanceid
WHERE kbi_ctx.contextlevel = 50
  AND kbi_ra.roleid        = 3
  AND kbi_u.deleted        = 0
  AND kbi_u.suspended      = 0
GROUP BY kbi_u.id, kbi_u.firstname, kbi_u.lastname
2. Activity participation and completion by course – Table

Table of visible courses, counting students with role ID 5 who accessed the course and have a recorded activity completion, those who accessed it without that record, and those with no last access to the course.

Cache: 30m. Refresh: 30m.

Full original SQL

SELECT kbi_c.id       AS c_id,
       kbi_c.fullname AS c_fullname,
       COUNT(DISTINCT kbi_ra.userid) AS num_learners,
       COUNT(DISTINCT CASE
           WHEN comp.userid IS NOT NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
           ELSE NULL 
       END) AS completed_learners,
       COUNT(DISTINCT CASE
           WHEN comp.userid IS NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
           ELSE NULL 
       END) AS not_completed_learners,
       COUNT(DISTINCT CASE 
           WHEN kbi_ula.id IS NULL THEN kbi_u.id 
           ELSE NULL 
       END) AS not_accessed_learners
FROM mdl_role_assignments kbi_ra
JOIN mdl_context kbi_ctx 
    ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
JOIN mdl_course kbi_c 
    ON kbi_c.id = kbi_ctx.instanceid
JOIN mdl_user kbi_u 
    ON kbi_u.id = kbi_ra.userid
LEFT JOIN (
    SELECT kbi_cm.course, kbi_cmc.userid
    FROM mdl_course_modules kbi_cm
    JOIN mdl_course_modules_completion kbi_cmc 
        ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.completionstate = 1
    WHERE kbi_cmc.id > 0
    GROUP BY kbi_cm.course, kbi_cmc.userid
) comp 
    ON comp.userid = kbi_u.id AND comp.course = kbi_c.id
LEFT JOIN mdl_user_lastaccess kbi_ula 
    ON kbi_ula.courseid = kbi_c.id AND kbi_ula.userid = kbi_ra.userid
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 5
GROUP BY kbi_c.id

Limitations and cautions

  • Despite being in the access/login category, this report does not query authentication logs.
  • The active student indicator in the first table counts valid, non-suspended accounts, not recent activity.
  • The first table calculates course completions using mdl_course_completions; the second counts completion of at least one activity. These metrics are not equivalent.
  • Sums and averages across joins between courses and teachers may give repeated records additional weight; verify counts before institutional comparisons.
  • Role IDs 3 and 5 are assumed by the SQL and may not match role structures on customized Moodle installations.
