REPORT 099

Students without course access

Identifies students with an assigned student role and a qualifying active enrolment in visible courses whose last course access is missing or zero, including days since enrolment.

Report purpose

Identifies students with an assigned student role and a qualifying active enrolment in visible courses whose last course access is missing or zero, including days since enrolment.

Why use this report?

Helps tutoring and student-retention teams identify learners who may not have accessed a course after enrolment and plan appropriate outreach or follow-up.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, student, date, a minimum number of days without access, or enrolment status.

Fixed criteria require shortname = 'student' in the course context, a visible course, and a user who is neither deleted nor suspended and is not guest. They also require kbi_enrol.enrolled_at IS NOT NULL and COALESCE(kbi_la.timeaccess, 0) = 0. The enrolment subquery requires active enrolment records and methods, with an end date of zero or in the future.

1. Students without course access · Table

The per-student, per-course table includes ID, name, email address, calculated enrolment date, last site-wide access, last course access, and the number of days from enrolment until the database's current date.

Full original MySQL SQL

SELECT CONCAT(kbi_students.userid, '-', kbi_students.courseid) AS id,
       kbi_students.userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_enrol.enrolled_at,
       kbi_u.lastaccess AS site_lastaccess,
       COALESCE(kbi_la.timeaccess, 0) AS course_lastaccess,
       CASE
         WHEN kbi_enrol.enrolled_at IS NULL THEN NULL
         ELSE DATEDIFF(NOW(), FROM_UNIXTIME(kbi_enrol.enrolled_at))
       END AS days_since_enrolment
FROM (SELECT DISTINCT kbi_ra.userid,
                kbi_ctx.instanceid AS courseid
FROM mdl_role_assignments kbi_ra
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
WHERE kbi_r.shortname = 'student') kbi_students
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_students.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_students.courseid
       LEFT JOIN (SELECT kbi_ue.userid,
       kbi_e.courseid,
       MIN(kbi_ue.id) AS enrolmentid,
       COALESCE(MIN(NULLIF(kbi_ue.timestart, 0)), MIN(kbi_ue.timecreated)) AS enrolled_at,
       MAX(kbi_ue.timeend) AS enrol_timeend
FROM mdl_enrol kbi_e
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.status = 0
  AND kbi_ue.status = 0
  AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP())
GROUP BY kbi_ue.userid, kbi_e.courseid) kbi_enrol ON kbi_enrol.userid = kbi_students.userid AND kbi_enrol.courseid = kbi_students.courseid
       LEFT JOIN mdl_user_lastaccess kbi_la ON kbi_la.userid = kbi_students.userid AND kbi_la.courseid = kbi_students.courseid
WHERE kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
  AND kbi_enrol.enrolled_at IS NOT NULL
  AND COALESCE(kbi_la.timeaccess, 0) = 0
ORDER BY days_since_enrolment DESC, kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Full original PostgreSQL SQL

SELECT CONCAT(kbi_students.userid, '-', kbi_students.courseid) AS id,
       kbi_students.userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_enrol.enrolled_at,
       kbi_u.lastaccess AS site_lastaccess,
       COALESCE(kbi_la.timeaccess, 0) AS course_lastaccess,
       CASE
         WHEN kbi_enrol.enrolled_at IS NULL THEN NULL
         ELSE ((CURRENT_TIMESTAMP)::date - (TO_TIMESTAMP(kbi_enrol.enrolled_at))::date)
       END AS days_since_enrolment
FROM(SELECT DISTINCT kbi_ra.userid,
                kbi_ctx.instanceid AS courseid
FROM mdl_role_assignments kbi_ra
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
WHERE kbi_r.shortname = 'student') kbi_students
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_students.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_students.courseid
       LEFT JOIN(SELECT kbi_ue.userid,
       kbi_e.courseid,
       MIN(kbi_ue.id) AS enrolmentid,
       COALESCE(MIN(NULLIF(kbi_ue.timestart, 0)), MIN(kbi_ue.timecreated)) AS enrolled_at,
       MAX(kbi_ue.timeend) AS enrol_timeend
FROM mdl_enrol kbi_e
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.status = 0
  AND kbi_ue.status = 0
  AND(kbi_ue.timeend = 0 OR kbi_ue.timeend > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint))
GROUP BY kbi_ue.userid, kbi_e.courseid) kbi_enrol ON kbi_enrol.userid = kbi_students.userid AND kbi_enrol.courseid = kbi_students.courseid
       LEFT JOIN mdl_user_lastaccess kbi_la ON kbi_la.userid = kbi_students.userid AND kbi_la.courseid = kbi_students.courseid
WHERE kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
  AND kbi_enrol.enrolled_at IS NOT NULL
  AND COALESCE(kbi_la.timeaccess, 0) = 0
ORDER BY days_since_enrolment DESC, kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The report identifies a missing mdl_user_lastaccess record for the course, not proven absence of every kind of access or event in historical logs.
  • An assigned student role is required. Learners using custom roles may be excluded even if they are enrolled, unless they also have that role short name.
  • The enrolment subquery accepts active records with no expired end date but does not explicitly check whether timestart is in the future. An enrolment that has not yet started may therefore appear.
  • The enrolled_at field comes from MIN(NULLIF(timestart, 0)) or the earliest enrolment creation time. With multiple enrolments, this value may not describe the enrolment currently granting access.
  • The site_lastaccess and course_lastaccess fields have different scopes: the former is the account's last site-wide access, while the latter records access to the specific course.
  • The days_since_enrolment calculation uses DATEDIFF(NOW(), FROM_UNIXTIME(...)) in MySQL and a difference between dates derived from CURRENT_TIMESTAMP and TO_TIMESTAMP in PostgreSQL. Results depend on the database's calendar and time zone.
  • There is no minimum-days threshold. Recently enrolled learners can appear, so the day count should be interpreted in its educational context.
  • Without a course filter, the report checks all visible courses meeting the criteria. Contact information and course-access status are personal information and must be protected.
