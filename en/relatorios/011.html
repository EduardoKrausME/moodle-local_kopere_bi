REPORT 011

Inactive users by course

Table of students with active enrolments in visible courses whose last course access was more than 30 days ago or was never recorded.

Report purpose

Table of students with active enrolments in visible courses whose last course access was more than 30 days ago or was never recorded.

Why use this report?

Helps tutors and course managers identify students who may need follow-up, relating last course access to completion records, cohorts, and the associated teacher.

Actual filters Visualizations and SQL Limitations

Available filters

There are no dynamic user, course, cohort, or date-range SQL parameters. The query considers all visible courses and active enrolments that meet its internal criteria.

The time threshold is fixed at 30 days: kbi_ul.timeaccess < (agora - 2592000 segundos) or kbi_ul.timeaccess IS NULL. Deleted or suspended users and the guest account are excluded; enrolment methods and enrolments must have status 0.

Visualizations and full SQL

This report provides one table visualization and two equivalent SQL queries, with cache and refresh settings. Full MySQL and PostgreSQL SQL statements are shown in separate panels within the same block, with Prism.js syntax highlighting.

1. Inactive users by course · Table

Table with student, course, cohort memberships, enrolment date, last login, first access recorded by Kopere BI, last course access, module count, and activity completions.

Cache: 1h · Refresh: none.

Full original MySQL SQL

SELECT DISTINCT kbi_u.id                                     AS userid,
                kbi_u.firstname,
                kbi_u.lastname,
                kbi_u.email,
                coo.cohortname                           AS cohorts,
                kbi_ue.timecreated,
                kbi_u.lastlogin,
                kbi_lit.firstaccess,
                kbi_ul.timeaccess                            AS lastaccess,
                m.modules,
                cmc.completed,
                kbi_cc1.timecompleted                        as course_completion,
                kbi_c.id                                     AS course_id,
                kbi_c.fullname                               AS course_name,
                (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
                 FROM mdl_role_assignments kbi_ra
                        JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
                        JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
                 WHERE kbi_ctx.instanceid = kbi_c.id
                   AND kbi_ctx.contextlevel = 50
                   AND kbi_ra.roleid = 3
                 LIMIT 1)                                AS teacher
FROM mdl_course kbi_c
       JOIN mdl_enrol kbi_e ON kbi_e.courseid = kbi_c.id
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ue.userid
       LEFT JOIN (SELECT kbi_ch.userid, GROUP_CONCAT(DISTINCT kbi_coh.name SEPARATOR ', ') as cohortname
                  FROM mdl_cohort kbi_coh
                         JOIN mdl_cohort_members kbi_ch ON kbi_ch.cohortid = kbi_coh.id
                  GROUP BY kbi_ch.userid) coo ON coo.userid = kbi_u.id
       LEFT JOIN mdl_course_completions kbi_cc1 ON kbi_cc1.userid = kbi_u.id AND kbi_cc1.course = kbi_c.id
       LEFT JOIN (SELECT kbi_cm.course, COUNT(kbi_cm.id) AS modules
                  FROM mdl_course_modules kbi_cm
                  WHERE kbi_cm.deletioninprogress = 0
                    AND kbi_cm.visible = 1
                  GROUP BY kbi_cm.course) m ON m.course = kbi_c.id
       LEFT JOIN (SELECT kbi_cm.course, kbi_cmc.userid, COUNT(kbi_cmc.id) AS completed
                  FROM mdl_course_modules kbi_cm, mdl_course_modules_completion kbi_cmc
                  WHERE kbi_cmc.coursemoduleid = kbi_cm.id
                    AND kbi_cm.visible = 1
                    AND kbi_cmc.completionstate IN (1, 2)
                  GROUP BY kbi_cm.course, kbi_cmc.userid) cmc ON cmc.course = kbi_c.id AND cmc.userid = kbi_u.id
       LEFT JOIN mdl_local_kopere_bi_tracking kbi_lit ON kbi_lit.page = 'course' AND kbi_lit.param = kbi_c.id AND kbi_lit.userid = kbi_u.id
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_u.id
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ue.status = 0
  AND kbi_e.status = 0
  AND (kbi_ul.timeaccess < (UNIX_TIMESTAMP() - 2592000) OR kbi_ul.timeaccess IS NULL)
GROUP BY kbi_u.id, kbi_c.id, kbi_u.firstname, kbi_u.lastname, kbi_u.email, cohorts, kbi_ue.timecreated,
         kbi_u.lastlogin, kbi_lit.firstaccess, kbi_ul.timeaccess, m.modules, cmc.completed, course_completion, course_id,
         course_name, teacher

Limitations and cautions

  • The report measures inactivity based on last course access recorded in mdl_user_lastaccess, not necessarily inactivity across the entire platform.
  • The 30-day threshold is fixed in SQL, not an adjustable selector. Enrolled students without recorded course access are also included.
  • The cohort field combines the names of the user's cohorts without restricting them to the course or to a selected cohort.
  • The teacher is selected using role ID 3 and LIMIT 1; if there are multiple teachers, only one may appear.
  • The module count does not necessarily equal the number of activities with completion tracking enabled. Profile and enrolment data must be protected.
