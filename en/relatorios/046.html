REPORT 046

Engaged and non-engaged participant details by course

Per-user and per-course table classifying users assigned the student role according to last-access and activity completion records.

Report purpose

Per-user and per-course table classifying users assigned the student role according to last-access and activity completion records.

Why use this report?

Provides an individual view of participants with evidence of access and activity completion, helping educational teams identify cases requiring review and follow-up.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters to select a course, user, or date range. The query covers visible courses with positive IDs and users assigned role ID 5 in course contexts (contextlevel = 50), excluding deleted, suspended, and guest accounts.

The classification checks for a row in mdl_user_lastaccess and a module completion with completionstate = 1 in the same course. The SQL does not filter enrolment status or enrolment method.

Visualization and full original SQL

One table visualization includes the complete original SQL, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL variant file is available in the catalog.

1. Engaged and non-engaged participant details by course · Table

One row per user and course, showing the course ID, participant name, identifier and email, and the binary indicators completed, not_completed and not_accessed. A value of 1 means the condition is met; 0 means it is not.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_c.id                                              courseid,
       kbi_c.fullname                                     AS course_name,
       kbi_u.id                                           AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       CASE
         WHEN MIN(comp.userid) IS NOT NULL AND MIN(kbi_ul.id) IS NOT NULL THEN 1
         ELSE 0 END                                   as completed,
       CASE
         WHEN MIN(comp.userid) IS NULL AND MIN(kbi_ul.id) IS NOT NULL THEN 1
         ELSE 0 END                                   as not_completed,
       CASE WHEN MIN(kbi_ul.id) IS NULL THEN 1 ELSE 0 END as not_accessed
FROM mdl_role_assignments kbi_ra
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_ctx.instanceid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_ra.userid
       LEFT JOIN (SELECT kbi_cm.course, kbi_cmc.userid
                  FROM mdl_course_modules kbi_cm
                         JOIN mdl_course_modules_completion kbi_cmc
                           ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.completionstate = 1
                  WHERE kbi_cmc.id > 0
                  GROUP BY kbi_cm.course, kbi_cmc.userid) comp ON comp.userid = kbi_u.id AND comp.course = kbi_c.id
       LEFT JOIN mdl_user_lastaccess kbi_ul ON kbi_ul.courseid = kbi_c.id AND kbi_ul.userid = kbi_ra.userid
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 5
GROUP BY kbi_c.id, kbi_u.id

Limitations and cautions

  • The term 'engaged' does not represent a measurement of educational participation or active time: classification depends only on last-access records and the existence of a completed activity.
  • The completed indicator does not mean formal course completion. At least one module with completionstate = 1 and a last course access record are required.
  • The completionstate = 2 state, which may represent successful completion, is excluded from the completed-activity query; students with only this state may appear as not completed.
  • The not_completed indicator applies to users with an access record but no module completion in state 1. This does not necessarily indicate dropout or failure.
  • The not_accessed indicator means there is no row in mdl_user_lastaccess; it does not prove that the person has never been active in other Moodle contexts.
  • The population includes users assigned role ID 5 but does not restrict results to active enrolments, so it may include students whose enrolments are no longer current.
  • Names and email addresses are personal data and must only be displayed to authorized users. There is no dedicated PostgreSQL file for this report.
