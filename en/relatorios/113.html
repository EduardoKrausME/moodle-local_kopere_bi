REPORT 113

Activity reach by course

Percentage of eligible actively enrolled students with at least one recorded visit to each activity.

Report purpose

A table for each visible module with course, module type, activity identifier, number of eligible students, number of students with recorded access, number without recorded access, and reach percentage. It prioritizes the lowest percentages, then course and module, and limits results to 500 rows.

Why use this report?

Identify activities and resources with the lowest reach among eligible students in each course, helping plan communications, reorganize materials, and investigate access barriers.

Available filters Visualization and SQL Calculation criteria Limitations

Available filters

There are no dynamic SQL filters for course, activity, student, cohort, or period. Modules are restricted to cm.deletioninprogress = 0, cm.visible = 1, and c.id > 1, without an explicit check of c.visible.

The denominator includes users with active enrolment records and methods, eligible validity dates, accounts that are neither deleted nor suspended, and a role with archetype student in the course context. The numerator requires t.page = 'module' and t.visits > 0. The SQL limits results to 500 modules.

Visualization and full original SQL

The report contains one table visualization with full original SQL and cache and refresh settings. Prism.js provides syntax highlighting. There is no separate PostgreSQL file in master for this definition, so none has been invented.

1. Activity reach by course · Table

A table for each visible module with course name, module type, activity identifier, number of eligible students, number with recorded visits, number without visits, and reach percentage. Results are ordered by lowest reach, then course and module, and limited to 500 rows.

Cache: 1h · Refresh: none.

Full original SQL

SELECT cm.id, c.id AS courseid, c.fullname AS course, m.name AS module,
       cm.instance AS activityid, COALESCE(en.enrolled, 0) AS enrolled,
       COALESCE(tr.accessed, 0) AS accessed,
       COALESCE(en.enrolled, 0) - COALESCE(tr.accessed, 0) AS neveraccessed,
       CASE WHEN COALESCE(en.enrolled, 0) > 0
            THEN ROUND(100.0 * COALESCE(tr.accessed, 0) / en.enrolled, 2)
            ELSE 0 END AS reach_percent
  FROM mdl_course_modules cm
  JOIN mdl_course c ON c.id = cm.course
  JOIN mdl_modules m ON m.id = cm.module
  LEFT JOIN (SELECT courseid, COUNT(DISTINCT userid) AS enrolled
               FROM (
    SELECT DISTINCT e.courseid, ue.userid
      FROM mdl_user_enrolments ue
      JOIN mdl_enrol e ON e.id = ue.enrolid
      JOIN mdl_context cx ON cx.contextlevel = 50 AND cx.instanceid = e.courseid
      JOIN mdl_role_assignments ra ON ra.contextid = cx.id AND ra.userid = ue.userid
      JOIN mdl_role r ON r.id = ra.roleid AND r.archetype = 'student'
      JOIN mdl_user u ON u.id = ue.userid AND u.deleted = 0 AND u.suspended = 0
     WHERE e.status = 0 AND ue.status = 0
       AND (ue.timestart = 0 OR ue.timestart <= UNIX_TIMESTAMP())
       AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP())
) learners GROUP BY courseid) en ON en.courseid = cm.course
  LEFT JOIN (SELECT t.courseid, t.param AS cmid, COUNT(DISTINCT t.userid) AS accessed
               FROM mdl_local_kopere_bi_tracking t
               JOIN (
    SELECT DISTINCT e.courseid, ue.userid
      FROM mdl_user_enrolments ue
      JOIN mdl_enrol e ON e.id = ue.enrolid
      JOIN mdl_context cx ON cx.contextlevel = 50 AND cx.instanceid = e.courseid
      JOIN mdl_role_assignments ra ON ra.contextid = cx.id AND ra.userid = ue.userid
      JOIN mdl_role r ON r.id = ra.roleid AND r.archetype = 'student'
      JOIN mdl_user u ON u.id = ue.userid AND u.deleted = 0 AND u.suspended = 0
     WHERE e.status = 0 AND ue.status = 0
       AND (ue.timestart = 0 OR ue.timestart <= UNIX_TIMESTAMP())
       AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP())
) learners ON learners.userid = t.userid AND learners.courseid = t.courseid
              WHERE t.page = 'module' AND t.visits > 0
              GROUP BY t.courseid, t.param) tr ON tr.courseid = cm.course AND tr.cmid = cm.id
 WHERE cm.deletioninprogress = 0 AND cm.visible = 1 AND c.id > 1
 ORDER BY reach_percent ASC, c.fullname, cm.id
 LIMIT 500

Calculation criteria and behavior

Reach is calculated as ROUND(100.0 * accessed / enrolled, 2) when eligible students exist; otherwise the SQL returns zero. enrolled is the number of distinct eligible enrolled students in the course, while accessed counts distinct users with tracked visits to the module.

The neveraccessed field is calculated as enrolled - accessed. Sorting by lowest reach makes this a list of modules that may warrant investigation, but does not establish that the content was mandatory.

Limitations and cautions

  • Reach is evidence of a visit recorded by the Kopere BI collector, not proof of activity completion, full viewing, learning, or actual material availability to every student.
  • The calculation treats all students with active enrolments in a course as eligible, even when an activity has group, date, or completion-based access restrictions.
  • Modules without eligible students receive a reach value of zero percent, which does not necessarily indicate a participation problem.
  • The query sorts by lowest reach and returns only 500 rows. Modules beyond that limit are not included.
  • The query checks module visibility but does not explicitly restrict course or section visibility.
  • Tracking history has no explicit date restriction. Visits may have occurred before the currently eligible enrolment or outside the period of interest.
  • The t.param expression must be compatible with cm.id. No dedicated PostgreSQL variant file is provided.

The original SQL from master is reproduced verbatim. It was not executed on Moodle during this documentation work. Before institutional use, verify database compatibility, data integrity, visibility, information protection, and educational interpretation.
