REPORT 015

Platform logins and logouts

Lists user logout events stored in the Kopere BI temporary log history, ordered by record ID.

Report purpose

Lists user logout events stored in the Kopere BI temporary log history, ordered by record ID.

Why use this report?

Helps technical support inspect Moodle logout events retained in the plugin's temporary log table to investigate session termination patterns.

Actual filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL filters for user, course, cohort, or date range.

The fixed criteria are kbi_l1.action = 'loggedout' and kbi_l1.contextid = 1. Records are ordered by kbi_l1.id ASC.

Visualization and full original SQL

One table visualization with the complete original SQL and its cache and refresh configuration. SQL syntax highlighting is provided by Prism.js.

1. Platform logins and logouts · Table

The table shows the log record ID, user ID, and logout event timestamp (loggedout) from mdl_local_kopere_bi_log_tmp, ordered by ascending ID.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_l1.id, kbi_l1.userid, kbi_l1.timecreated AS loggedout
FROM mdl_local_kopere_bi_log_tmp kbi_l1
WHERE kbi_l1.action = 'loggedout'
  AND kbi_l1.contextid = 1
ORDER BY kbi_l1.id ASC

Limitations and cautions

  • Although the title mentions logins and logouts, the query selects logout events only (loggedout); it does not list loggedin events.
  • The SQL uses the Kopere BI temporary log table, whose contents depend on how records are synchronized, collected, and retained in the installation.
  • There is no date-range, user, or course filter. On large databases, this query may return many events and requires performance and access review.
  • The timestamp comes from timecreated in the format stored by Moodle, generally a Unix timestamp, and needs to be displayed in the interface's time zone.
  • Not every browser exit necessarily produces an explicit logout event, so the list does not establish that all sessions have ended.
