REPORT 084

Competency evidence

Lists competency evidence associated with users across the Moodle installation, including the competency, source identifiers, reference URL, and creation date.

Report purpose

Lists competency evidence associated with users across the Moodle installation, including the competency, source identifiers, reference URL, and creation date.

Why use this report?

Helps administrators and competency managers locate existing evidence records and investigate their technical sources and associations with users and competencies.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for selecting a course, user, competency, status, or date. The query reads all evidence records from mdl_competency_evidence associated with a user found in mdl_user.

The fixed condition is kbi_u.id IS NOT NULL, excluding evidence with no valid user association. Records are sorted by surname, first name, and kbi_ce.timecreated DESC.

Visualization and full original SQL

One table visualization contains the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. There is no separate PostgreSQL definition file for this report.

1. Competency evidence · Table

The table lists each evidence record ID, user ID and name, competency short name, URL, description identifier, description component, description argument, and creation timestamp. It is sorted by surname, first name, and most recent evidence.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_ce.id,
       kbi_u.id AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.shortname,
       kbi_ce.url,
       kbi_ce.descidentifier,
       kbi_ce.desccomponent,
       kbi_ce.desca,
       kbi_ce.timecreated
FROM mdl_competency_evidence kbi_ce
       LEFT JOIN mdl_competency_usercomp kbi_cu ON kbi_ce.usercompetencyid = kbi_cu.id
       LEFT JOIN mdl_competency kbi_c ON kbi_c.id = kbi_cu.competencyid
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_cu.userid
WHERE kbi_u.id IS NOT NULL
ORDER BY kbi_u.lastname, kbi_u.firstname, kbi_ce.timecreated DESC

Limitations and cautions

  • The query does not restrict course, learning plan, competency type, framework, date, account status, or user role, so it may return extensive installation-wide data.
  • The joins to the competency and user competency records are optional. Evidence can be associated with a user while the competency short name is blank because the related record is missing.
  • The desca field is the description argument stored in the evidence, while descidentifier and desccomponent are technical keys that may require language-string resolution for a readable description.
  • The existence of an evidence record alone does not prove that a competency has been achieved or approved. The SQL does not examine final ratings, proficiency levels, or assessment criteria.
  • The url field is a reference stored with the evidence; the query does not verify whether the destination remains accessible or whether the report viewer is authorized to open it.
  • Records are ordered with the most recent evidence first for each user, but the query does not select only the latest evidence for each competency.
  • Because user names and academic evidence from the entire platform are displayed, access to the report and its exports must be controlled.
  • The catalog does not contain a separate PostgreSQL variant for this definition.
