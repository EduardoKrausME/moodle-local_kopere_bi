REPORT 090

Awarded badges

Lists visible issued course badges, including badge and recipient names, course, issue date, and recorded expiration date.

Report purpose

Lists visible issued course badges, including badge and recipient names, course, issue date, and recorded expiration date.

Why use this report?

Allows badge administrators and academic teams to review records of awarded course badges and check their issue and expiration dates.

Available filters Visualization and SQL Limitations

Available filters

There are no dynamic SQL parameters for course, user, badge, issue date, expiration, or award status.

Fixed filters require an existing mdl_badge_issued record (kbi_bi.id IS NOT NULL), an award marked as visible (kbi_bi.visible = 1), and a badge associated with a course (kbi_b.courseid IS NOT NULL). The query does not require an active user, a visible course, or a badge that has not expired.

Visualization and full original SQL

One table visualization contains the complete original SQL query, cache and refresh settings, and Prism.js syntax highlighting. No separate PostgreSQL SQL file is provided in the source.

1. Awarded badges · Table

The per-award table displays the issued badge record ID, recipient identification and email, course name and ID, badge name, issue date, and expiration date. Results are ordered from most to least recently issued.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_bi.id,
       kbi_u.id       AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.fullname as course,
       kbi_c.id       AS cid,
       kbi_b.name,
       kbi_bi.dateissued,
       kbi_bi.dateexpire
FROM mdl_badge kbi_b
       LEFT JOIN mdl_badge_issued kbi_bi ON kbi_bi.badgeid = kbi_b.id
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_bi.userid
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_b.courseid
WHERE kbi_bi.id IS NOT NULL
  AND kbi_bi.visible = 1
  AND (kbi_b.courseid IS NOT NULL)
ORDER BY kbi_bi.dateissued DESC, kbi_u.lastname, kbi_u.firstname

Limitations and cautions

  • The report lists visible awards but does not check whether dateexpire is in the past. Expired badges may therefore be listed among awarded badges.
  • The kbi_bi.visible = 1 condition applies to an issued award; it is not a comprehensive check of badge availability or course visibility.
  • The courseid IS NOT NULL condition limits the query to course-associated badges. Site-wide badges or awards without a course association are excluded.
  • User and course joins are optional. If an associated record cannot be found, the name, email, or course fields may be empty.
  • The SQL does not exclude deleted or suspended users or verify that their course enrolment is currently active.
  • An issue date alone does not confirm that a recipient still meets current recognition requirements or that the badge remains active.
  • The query spans the whole installation with no course, period, or user filter. Recipient email addresses must be protected through appropriate permissions.
  • No separate PostgreSQL file is available for this report.
