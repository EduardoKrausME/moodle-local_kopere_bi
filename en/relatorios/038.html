REPORT 038

Course content logs

Shows activity-component events for the selected course from Kopere BI's temporary log table, including user, module, origin, and forum details when available.

Report purpose

Shows activity-component events for the selected course from Kopere BI's temporary log table, including user, module, origin, and forum details when available.

Why use this report?

Helps support and administration teams examine records associated with visible course modules, identify the context and source of access, and investigate events retained by Kopere BI.

Available filters Visualization and SQL Limitations

Available filters

The actual dynamic filter is Course, represented once by :courseid.

Fixed criteria require kbi_l.component LIKE '%mod_%', a visible course and module, an account that is neither deleted nor suspended, and a user other than guest. There is no parameter for user, activity type, or date.

Visualization and full original SQL

One table visualization includes one SQL query, cache settings, and Prism.js syntax highlighting. There is no separate PostgreSQL variant for this report.

1. Course content logs · Table

Each log row includes the user, course, module identified by CMID, object table, origin, IP address, event date, and, for forum discussions or posts, a title or subject obtained through a subquery.

Cache: 1h · Refresh: none.

Full original SQL

SELECT kbi_l.id,
       kbi_l.courseid,
       kbi_l.userid,
       kbi_l.contextinstanceid          AS cmid,
       kbi_l.objecttable,
       kbi_l.origin,
       kbi_l.ip,
       kbi_c.fullname                   AS course,
       kbi_c.shortname,
       kbi_ca.name                      AS category,
       kbi_u.email,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_l.timecreated,
       (CASE
          WHEN kbi_l.objecttable = 'forum_discussions' THEN (SELECT name FROM mdl_forum_discussions WHERE id = kbi_l.objectid)
          ELSE (CASE
                  WHEN kbi_l.objecttable = 'forum_posts' THEN (SELECT subject FROM mdl_forum_posts WHERE id = kbi_l.objectid)
                  ELSE '' END) END) AS forumitem
FROM mdl_local_kopere_bi_log_tmp kbi_l
       LEFT JOIN mdl_course kbi_c ON kbi_c.id = kbi_l.courseid
       LEFT JOIN mdl_course_categories kbi_ca ON kbi_ca.id = kbi_c.category
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_l.userid
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = SUBSTRING(kbi_l.component, 5)
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.id = kbi_l.contextinstanceid
WHERE kbi_l.component LIKE '%mod_%'
  AND kbi_l.courseid = :courseid
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1
  AND kbi_cm.visible = 1

Limitations and cautions

  • Records come from mdl_local_kopere_bi_log_tmp, a plugin-maintained temporary table, rather than directly from mdl_logstore_standard_log. Historical coverage depends on collection and retention.
  • The LIKE '%mod_%' pattern treats _ as a SQL single-character wildcard, not a literal underscore. It may match components beyond the expected textual prefix.
  • The query optionally joins mdl_modules using SUBSTRING(kbi_l.component, 5), but does not use that association to restrict results. Component-name compatibility should be reviewed.
  • A visible CMID is effectively required because the WHERE clause requires kbi_cm.visible = 1, even though the join to the modules table is optional.
  • The forumitem field is populated only for forum_discussions and forum_posts when the referenced object is still available. Other events receive an empty string.
  • The table includes user email addresses and IP addresses, which are subject to privacy restrictions. No selectable time window is applied.
  • There is no separate PostgreSQL definition for this report; validate the query against the installation's database system.
