Dashboards and report pages

Arrange categories, pages, blocks and visual elements.

Content structure

Kopere BI groups reports into categories and pages. A page contains layout blocks, which in turn hold report elements and their data sources.

Category→Page→Blocks→Elements

For example, one course-health page may combine completion KPIs, participation charts and a detailed table without requiring separate destinations for each indicator.

Build a useful page

  1. Define a specific question, such as which courses need attention.
  2. Create or select a category and report page.
  3. Choose the block layout and add elements with suitable data sources.
  4. Configure filters, labeling, chart options and SQL caching.
  5. Check visibility using an account with viewing permissions only.

SQL and caching

Elements can use SQL queries and format table columns using Mustache. Choose cache durations according to the cost of each query and freshness requirements; rerunning expensive aggregation on every page view is usually unnecessary.

Always confirm both SQL compatibility with the Moodle database and the privacy implications of returned records.

Moving reports

Report definitions use JSON and the plugin supports dashboard import/export. Before reusing definitions, review refkey, database prerequisites, page capability, user filter behavior and SQL references.
