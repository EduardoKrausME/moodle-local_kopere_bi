Dashboards and organization

Structure reports using categories, pages, blocks, and elements.

Content structure

Kopere BI organizes content into categories and report pages. Each page contains visually arranged blocks, and each block holds elements populated by queries or other data sources available in the plugin.

Category→Page→Blocks→Elements

This makes it possible to combine a completion indicator, a student table, and a progress chart on the same page while keeping filters and access rules appropriate for the report.

Build a useful report page

  1. Define the question the report should answer, such as “Which courses need attention?”
  2. Create or select a category, register a page, and choose the block layout.
  3. Add visualizations to each block and configure the data source, labels, and cache lifetime.
  4. Attach course, date range, cohort, or user filters when they make sense for the SQL query.
  5. Test with an account that only has viewing permission, not just an administrator account.

SQL, formatting, and caching

Elements can use SQL and customize titles and columns; tables support Mustache formatting for displayed values. Set cache lifetimes according to query cost and required freshness: running a heavy aggregation every time someone reloads a page makes little sense.

When creating custom reports, verify the database engine and use bound parameters, correct escaping, and access checks. A technically valid query does not mean that every user should be allowed to see the records it returns.

Import and export

The code includes a JSON representation for reports, and the interface provides dashboard import and export features. Before publishing a definition moved between environments, review its refkey, database requirements, associated capability, and SQL fields.
