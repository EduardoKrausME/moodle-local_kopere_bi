Integração opcional via MCP

Consulte relatórios salvos como ferramentas de leitura, sem expor SQL arbitrário.

Dependência opcional

Quando o local_mcp está instalado e habilitado, o provedor classes/mcp/provider.php do Kopere BI é descoberto automaticamente. Sem ele, os dashboards e relatórios do Kopere BI continuam funcionando normalmente.

Isso é uma integração do Kopere BI, não uma documentação geral do servidor MCP.

Descoberta dinâmica dos relatórios

Com o local_mcp ativo, o provedor classes/mcp/provider.php é identificado automaticamente, sem configuração adicional ou alterações no servidor MCP. O comando de leitura kopere_bi_list_reports lista as páginas e os relatórios salvos que o usuário atual pode acessar, incluindo identificadores internos, títulos, categorias e nomes das ferramentas disponíveis.

Cada relatório acessível com refkey válido é publicado como uma ferramenta independente de leitura, com o padrão kopere_bi_report_<refkey>. Relatórios novos ficam disponíveis na solicitação MCP seguinte, sem registro estático; os nomes permanecem consistentes entre instalações Moodle que utilizam as mesmas chaves.

O refkey aceita letras, números, sublinhado (_), ponto (.) e hífen (-). Relatórios com chave vazia, inválida ou duplicada não são expostos até a correção. O ID do banco de dados é utilizado internamente na execução e não compõe o nome da ferramenta.

Exemplo de chamada

Primeiro execute kopere_bi_list_reports e escolha o nome efetivamente retornado. Depois invoque a ferramenta do relatório selecionado, por exemplo:

{
  "name": "kopere_bi_report_learning_analytics",
  "arguments": {
    "course_id": 2,
    "limit": 50,
    "offset": 0
  }
}

O refkey learning_analytics é apenas um exemplo: use sempre a chave publicada pela ferramenta de descoberta.

Filtros e paginação

As ferramentas de relatório aceitam os argumentos user_id, course_id, cohort_id, limit e offset. O limite padrão é de 50 linhas e o máximo é de 200 linhas por elemento. Cada elemento de visualização tem paginação independente, e has_more informa se há outra página de dados para consultar.

O retorno apresenta os valores brutos, sem HTML processado pelo Mustache e sem executar JavaScript dos gráficos no cliente MCP.

Estrutura da resposta e tratamento de erros

O resultado inclui metadados do relatório e da categoria, filtros aplicados e todos os blocos do relatório. Para cada elemento são apresentados o nome, o tipo de visualização, os títulos das colunas, as linhas originais retornadas pela consulta SQL, row_count, has_more e status.

Elementos de indicadores, como KPI e informações, também retornam value quando disponível. Elementos sem fonte de dados recebem o status no_data_source. Se um elemento falhar, o erro retornado é genérico, sem expor o texto SQL nem rastreamentos internos de execução.

Permissões e visibilidade

Todas as ferramentas são somente leitura e exigem o escopo MCP READ e a capacidade Moodle local/kopere_bi:view. A descoberta e a execução também respeitam a capacidade própria do relatório, sua visibilidade na página e as configurações de funcionalidades habilitadas no Kopere BI.

Um usuário não pode selecionar outro user_id sem a capacidade local/kopere_bi:manage. Alterar o filtro cohort_id também exige essa permissão. Para usuários que não são gestores, o filtro course_id respeita a matrícula no curso ou a permissão de visualização do curso.

Fontes de dados e limites de execução

A integração executa exclusivamente consultas salvas nos relatórios do Kopere BI; clientes MCP não podem fornecer SQL arbitrário. Fontes SQL são limitadas a uma única consulta do tipo SELECT ou WITH, com parâmetros de filtro vinculados e limite de linhas aplicado no banco de dados.

Fontes implementadas por classes devem cumprir o contrato external_report do Kopere BI. A integração não modifica as configurações de sessão de banco para forçar modo somente leitura, tampouco expõe o texto das consultas SQL.
