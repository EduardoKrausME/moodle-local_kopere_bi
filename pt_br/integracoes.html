DOCUMENTAÇÃO DO PLUGIN MOODLE

Integração opcional via MCP

Consulte relatórios salvos como ferramentas de leitura, sem expor SQL arbitrário.

Dependência opcional

Quando o local_mcp está instalado e habilitado, o provedor classes/mcp/provider.php do Kopere BI é descoberto automaticamente. Sem ele, os dashboards e relatórios do Kopere BI continuam funcionando normalmente.

Isso é uma integração do Kopere BI, não uma documentação geral do servidor MCP.

Descoberta e leitura

kopere_bi_list_reports apresenta os relatórios que o usuário atual pode descobrir, com seus títulos, categorias, IDs e nomes de ferramentas. Cada relatório salvo e com refkey válido pode publicar uma ferramenta kopere_bi_report_<refkey>; relatórios com chaves inválidas ou duplicadas não são expostos.

{
  "name": "kopere_bi_report_learning_analytics",
  "arguments": {"course_id": 2, "limit": 50, "offset": 0}
}

O nome acima é ilustrativo. Consulte sempre a lista retornada por kopere_bi_list_reports para usar um refkey existente.

Filtros e segurança

Argumentos aceitos: user_id, course_id, cohort_id, limit (padrão 50, máximo 200 por elemento) e offset. A resposta traz os dados tabulares brutos por elemento, metadados, contagem e indicador de mais páginas; não executa JavaScript de gráfico nem renderiza Mustache no cliente.

As operações são somente leitura. A integração aplica escopo MCP READ, permissões do Moodle, restrições de relatório e filtros. Consultas SQL devem ser consultas salvas do tipo SELECT/WITH, com parâmetros vinculados e limite de linhas no banco; um cliente não pode enviar seu próprio SQL para execução.

Fonte da especificação

Detalhes sobre o contrato de retorno e validação podem ser conferidos no guia de integração do próprio Kopere BI no repositório.
