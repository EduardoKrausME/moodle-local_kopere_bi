RELATÓRIO 098

Visão geral do progresso do aluno

Consolida por estudante com papel atribuído e curso visível o último acesso, quantidade de atividades monitoradas por conclusão, atividades concluídas, percentual calculado, notas e situação de conclusão do curso.

Finalidade do relatório

Consolida por estudante com papel atribuído e curso visível o último acesso, quantidade de atividades monitoradas por conclusão, atividades concluídas, percentual calculado, notas e situação de conclusão do curso.

Por que utilizar?

Auxilia docentes e gestores na identificação de estudantes sem atividade registrada, com atividades concluídas, com notas disponíveis ou com curso formalmente concluído, permitindo priorizar acompanhamento.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

Não há parâmetros SQL dinâmicos para curso, estudante, intervalo de datas, situação da matrícula ou status de progresso.

Os critérios fixos consideram atribuição de papel com shortname = 'student' no contexto de curso (contextlevel = 50), usuário não excluído e não suspenso, diferente de guest, e curso visível. Os totais de atividades incluem módulos com deletioninprogress = 0, visible = 1 e completion > 0. A contagem de concluídas considera completionstate IN (1, 2). A subconsulta de matrículas filtra inscrições e métodos com status ativo, sem encerramento registrado ou com timeend futuro.

SQL original integral MySQL

SELECT CONCAT(kbi_students.userid, '-', kbi_students.courseid) AS id,
       kbi_students.userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.email,
       kbi_c.id AS courseid,
       kbi_c.fullname AS course,
       kbi_enrol.enrolled_at,
       COALESCE(kbi_la.timeaccess, 0) AS course_lastaccess,
       COALESCE(kbi_total.total_activities, 0) AS total_activities,
       COALESCE(kbi_done.completed_activities, 0) AS completed_activities,
       CASE
         WHEN COALESCE(kbi_total.total_activities, 0) > 0 THEN ROUND((COALESCE(kbi_done.completed_activities, 0) / kbi_total.total_activities) * 100, 2)
         ELSE 0
       END AS progress_percent,
       ROUND(kbi_grade.finalgrade, 2) AS finalgrade,
       ROUND(kbi_grade.grade_percent, 2) AS grade_percent,
       kbi_cc.timecompleted,
       CASE
         WHEN kbi_cc.timecompleted IS NOT NULL THEN 'Completed'
         WHEN COALESCE(kbi_done.completed_activities, 0) > 0 THEN 'In progress'
         WHEN COALESCE(kbi_la.timeaccess, 0) > 0 THEN 'Accessed'
         ELSE 'Not started'
       END AS student_status
FROM (SELECT DISTINCT kbi_ra.userid,
                kbi_ctx.instanceid AS courseid
FROM mdl_role_assignments kbi_ra
       JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
       JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
WHERE kbi_r.shortname = 'student') kbi_students
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_students.userid
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_students.courseid
       LEFT JOIN (SELECT kbi_ue.userid,
       kbi_e.courseid,
       MIN(kbi_ue.id) AS enrolmentid,
       COALESCE(MIN(NULLIF(kbi_ue.timestart, 0)), MIN(kbi_ue.timecreated)) AS enrolled_at,
       MAX(kbi_ue.timeend) AS enrol_timeend
FROM mdl_enrol kbi_e
       JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
WHERE kbi_e.status = 0
  AND kbi_ue.status = 0
  AND (kbi_ue.timeend = 0 OR kbi_ue.timeend > UNIX_TIMESTAMP())
GROUP BY kbi_ue.userid, kbi_e.courseid) kbi_enrol ON kbi_enrol.userid = kbi_students.userid AND kbi_enrol.courseid = kbi_students.courseid
       LEFT JOIN mdl_user_lastaccess kbi_la ON kbi_la.userid = kbi_students.userid AND kbi_la.courseid = kbi_students.courseid
       LEFT JOIN (SELECT kbi_cm.course,
       COUNT(DISTINCT kbi_cm.id) AS total_activities
FROM mdl_course_modules kbi_cm
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
GROUP BY kbi_cm.course) kbi_total ON kbi_total.course = kbi_students.courseid
       LEFT JOIN (SELECT kbi_cm.course,
       kbi_cmc.userid,
       COUNT(DISTINCT kbi_cmc.coursemoduleid) AS completed_activities
FROM mdl_course_modules kbi_cm
       JOIN mdl_course_modules_completion kbi_cmc ON kbi_cmc.coursemoduleid = kbi_cm.id
WHERE kbi_cm.deletioninprogress = 0
  AND kbi_cm.visible = 1
  AND kbi_cm.completion > 0
  AND kbi_cmc.completionstate IN (1, 2)
GROUP BY kbi_cm.course, kbi_cmc.userid) kbi_done ON kbi_done.course = kbi_students.courseid AND kbi_done.userid = kbi_students.userid
       LEFT JOIN (SELECT kbi_gi.courseid,
       kbi_gg.userid,
       kbi_gi.gradepass,
       kbi_gi.grademax,
       kbi_gg.finalgrade,
       CASE
         WHEN kbi_gi.grademax > 0 AND kbi_gg.finalgrade IS NOT NULL THEN ROUND((kbi_gg.finalgrade / kbi_gi.grademax) * 100, 2)
         ELSE NULL
       END AS grade_percent
FROM mdl_grade_items kbi_gi
       JOIN mdl_grade_grades kbi_gg ON kbi_gg.itemid = kbi_gi.id
WHERE kbi_gi.itemtype = 'course') kbi_grade ON kbi_grade.courseid = kbi_students.courseid AND kbi_grade.userid = kbi_students.userid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_students.courseid AND kbi_cc.userid = kbi_students.userid
WHERE kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username <> 'guest'
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_u.lastname, kbi_u.firstname

Limitações e cuidados

  • O resultado parte das atribuições do papel student, não das matrículas. Como a subconsulta de matrícula é unida por LEFT JOIN, um estudante com papel atribuído pode aparecer mesmo sem matrícula ativa encontrada; nesse caso, enrolled_at pode ficar nulo.
  • A matrícula é considerada ativa pela subconsulta quando e.status = 0, ue.status = 0 e timeend é zero ou futuro. O SQL não verifica explicitamente se timestart já chegou.
  • O percentual progress_percent é a proporção de módulos visíveis com acompanhamento de conclusão e estado concluído. Ele não representa necessariamente a conclusão formal do curso, que vem separadamente de mdl_course_completions.timecompleted.
  • Na versão PostgreSQL, a divisão completed_activities / total_activities ocorre entre inteiros antes do cast para numeric. Ela pode truncar valores fracionários, resultando em 0% para progresso parcial inferior a 100%. O arredondamento posterior não corrige a perda.
  • No MySQL, o operador de divisão apresenta comportamento diferente, permitindo resultados fracionários. Assim, os percentuais de progresso podem divergir entre os dois bancos mesmo com os mesmos registros.
  • O SQL apresenta progress_percent = 0 quando não há atividades com conclusão configurada. Zero nesse caso não equivale a um curso iniciado e não concluído.
  • O campo student_status é uma classificação derivada de conclusão formal, atividade concluída ou último acesso, nessa ordem. Ele não utiliza diretamente o estado real de uma matrícula nem a situação de todas as atividades.
  • Os textos de status são retornados em inglês (Completed, In progress, Accessed e Not started), porque estão literais no SQL original.
  • A nota finalgrade vem do item de nota do curso, e grade_percent divide essa nota pelo máximo configurado quando este é positivo. Nota, percentual de atividades e conclusão formal são indicadores distintos.
  • O campo course_lastaccess utiliza mdl_user_lastaccess; ausência ou valor zero do registro não prova, isoladamente, que nunca houve qualquer evento relacionado ao curso. A consulta inclui dados pessoais e acadêmicos.
