RELATÓRIO 079

Ocorrências SCORM por curso

Apresenta a quantidade de pacotes SCORM cadastrados no curso selecionado e um nome de usuário associado ao papel de professor.

Finalidade do relatório

Apresenta a quantidade de pacotes SCORM cadastrados no curso selecionado e um nome de usuário associado ao papel de professor.

Por que utilizar?

Oferece uma visão simples da presença de atividades SCORM no curso e permite identificar rapidamente o total de pacotes para conferência administrativa.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

O filtro SQL dinâmico é Curso, através de :courseid, utilizado uma vez na condição kbi_c.id = :courseid.

Os filtros fixos exigem kbi_c.category > 0 e curso visível (kbi_c.visible = 1). A subconsulta de professor utiliza contextlevel = 50 e papel ID 3. Não há filtros por data, participante, tentativa ou visibilidade do módulo SCORM.

Visualização e SQL original integral

Uma visualização em tabela, com 1 consulta SQL integral, cache, atualização e destaque de sintaxe com Prism.js. A origem não possui arquivo separado de variante PostgreSQL.

1. Ocorrências SCORM por curso · Tabela

Uma linha com ID e nome do curso, número de registros de pacotes SCORM vinculados ao curso (scorms) e um nome de usuário encontrado com papel ID 3 (teacher).

Cache: 1h · Atualização: none.

SQL original integral

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_s.id) as scorms,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)   AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_scorm kbi_s ON kbi_s.course = kbi_c.id
WHERE kbi_c.category > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

Limitações e cuidados

  • A coluna scorms conta registros de mdl_scorm, não tentativas, participantes, pacotes concluídos ou recursos SCORM visualizados.
  • A consulta usa LEFT JOIN com a tabela SCORM, podendo apresentar o curso com valor zero quando não houver pacotes cadastrados.
  • O SQL não verifica a visibilidade específica do módulo SCORM; pacotes ocultos podem integrar o total.
  • O campo teacher retorna no máximo uma pessoa atribuída ao papel ID 3. O LIMIT 1 não possui ORDER BY, portanto não há critério determinístico de escolha nem garantia de que seja o responsável pelas atividades.
  • Papéis personalizados ou diferentes do ID 3 não são considerados para o campo de professor, e não há verificação de suspensão ou exclusão dessa pessoa.
  • O filtro category > 0 restringe a listagem a cursos com categoria positiva, sem representar um filtro selecionável de categoria na interface.
  • Não há métricas de nota, tempo de estudo, progresso SCORM ou conclusão. A origem não disponibiliza uma variante PostgreSQL separada.
