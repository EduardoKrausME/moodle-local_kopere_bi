RELATÓRIO 008

Painel geral

Dashboard com três indicadores e dois gráficos de linhas: usuários, acessos recentes, cursos, situação das inscrições por curso e cadastros mensais.

Finalidade do relatório

Dashboard com três indicadores e dois gráficos de linhas: usuários, acessos recentes, cursos, situação das inscrições por curso e cadastros mensais.

Por que utilizar?

Centraliza indicadores administrativos para uma leitura rápida da evolução dos cadastros e do uso do Moodle. Pode apoiar revisões de atividade da plataforma, desde que os critérios técnicos e eventuais limitações do SQL sejam considerados.

Filtros reaisVisualizações e SQLLimitações

Filtros disponíveis

Não existem parâmetros SQL dinâmicos de usuário, curso, coorte ou período nos dez SQLs deste painel. As condições temporais são fixas, como 5 minutos, 1 hora e 12 meses, e não filtros escolhidos no painel.

Os indicadores de cursos e usuários utilizam condições fixas de visibilidade, confirmação ou exclusão; a situação das matrículas é calculada no momento da execução da consulta.

Visualizações e SQL original integral

O relatório contém 5 visualizações e 10 consultas SQL. O código possui destaque de sintaxe, mantendo os caracteres originais. As variantes MySQL e PostgreSQL estão em caixas separadas dentro de cada visualização correspondente.

1. Usuários totais e usuários com acesso registrado — Indicador

Indicador numérico apresentado como total de usuários não excluídos / usuários não excluídos que têm lastaccess maior que zero, com exclusão do usuário ID 1.

Cache: 1h. Atualização: none.

SQL original integral MySQL

SELECT CONCAT(
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0),
    ' / ',
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0 AND lastaccess > 0)
)

SQL original integral PostgreSQL

SELECT CONCAT(
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0),
    ' / ',
    (SELECT count(*) AS num FROM mdl_user WHERE id > 1 AND deleted = 0 AND lastaccess > 0)
)
2. Usuários recentes: cinco minutos e uma hora — Indicador

Indicador com duas contagens a partir de lastaccess: acessos nos últimos 300 e nos últimos 3600 segundos. A implementação do MySQL contém agrupamentos ausentes na variante PostgreSQL.

Cache: 1h. Atualização: none.

SQL original integral MySQL

SELECT CONCAT(
    (
         SELECT count(id)
           FROM mdl_user
          WHERE lastaccess > UNIX_TIMESTAMP() - 300
       GROUP BY id
    ),
    ' / ',
    (
        SELECT count(id)
          FROM mdl_user
         WHERE lastaccess > UNIX_TIMESTAMP() - 3600
      GROUP BY id
    )
)

SQL original integral PostgreSQL

SELECT CONCAT(
    (
         SELECT count(id)
           FROM mdl_user
          WHERE lastaccess > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) - 300
    ),
    ' / ',
    (
        SELECT count(id)
          FROM mdl_user
         WHERE lastaccess > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) - 3600
    )
)

4. Inscrições por curso — Gráfico de linhas

Gráfico de linhas por curso com três medidas de matrículas: ativas, inativas e expiradas, classificadas por status e vencimento.

Cache: 1h. Atualização: none.

SQL original integral MySQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP()) THEN 1
               ELSE 0
           END) AS 'lang::active_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS 'lang::inactive_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < UNIX_TIMESTAMP() THEN 1
               ELSE 0
           END) AS 'lang::expired_enrolments::local_kopere_bi'
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname

SQL original integral PostgreSQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND(ue.timeend = 0 OR ue.timeend > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint)) THEN 1
               ELSE 0
           END) AS "lang::active_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS "lang::inactive_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) THEN 1
               ELSE 0
           END) AS "lang::expired_enrolments::local_kopere_bi"
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname
5. Novos usuários nos últimos 12 meses — Gráfico de linhas

Gráfico de linhas com quantidade de contas confirmadas e não excluídas criadas em cada mês dos últimos 12 meses.

Cache: none. Atualização: none.

SQL original integral MySQL

  SELECT FROM_UNIXTIME(timecreated, '%m/%Y') AS yearmonth,
         COUNT(id) AS 'lang::num_user::local_kopere_bi'
    FROM mdl_user
   WHERE deleted = 0
     AND confirmed = 1
     AND timecreated >= UNIX_TIMESTAMP(DATE_SUB(CURDATE(), INTERVAL 12 MONTH))
GROUP BY yearmonth
ORDER BY yearmonth DESC

SQL original integral PostgreSQL

  SELECT TO_CHAR(TO_TIMESTAMP(timecreated), 'MM/YYYY') AS yearmonth,
         COUNT(id) AS "lang::num_user::local_kopere_bi"
    FROM mdl_user
   WHERE deleted = 0
     AND confirmed = 1
     AND timecreated >= (EXTRACT(EPOCH FROM (CURRENT_DATE - INTERVAL '12 month'))::bigint)
GROUP BY yearmonth
ORDER BY yearmonth DESC

Limitações e cuidados

  • O indicador de acesso recente usa lastaccess no cadastro do usuário, não a presença online do Kopere BI, e não garante sessão aberta.
  • Na variante MySQL do indicador online, as subconsultas apresentam GROUP BY id apesar de serem usadas como expressões escalares; quando retornam várias linhas, podem causar erro de subconsulta com mais de um resultado. A variante PostgreSQL não tem esse agrupamento.
  • O gráfico de inscrições é uma comparação por curso, não uma série histórica por dia.
  • O gráfico de novos usuários ordena a etiqueta textual MM/AAAA; isso pode causar ordenação não cronológica na virada do ano.
  • Os indicadores com cache de uma hora podem ficar defasados em relação aos dados mais recentes. As versões MySQL/PostgreSQL estão documentadas em caixas separadas, mesmo quando o SQL é igual.
