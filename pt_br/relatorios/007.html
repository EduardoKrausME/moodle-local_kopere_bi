RELATÓRIO 007

Indicadores de engajamento

Duas tabelas resumem indicadores de professores e cursos: estudantes vinculados, conclusão registrada, notas e situação de acesso ou participação dos estudantes.

Finalidade do relatório

Duas tabelas resumem indicadores de professores e cursos: estudantes vinculados, conclusão registrada, notas e situação de acesso ou participação dos estudantes.

Por que utilizar?

É útil para coordenações e tutores que precisam localizar cursos com baixa participação, comparar o acompanhamento de diferentes turmas e verificar indicadores pedagógicos associados aos professores.

Filtros reaisVisualizações e SQLLimitações

Filtros disponíveis

Não há filtros SQL dinâmicos de usuário, curso, coorte ou período. As duas tabelas têm critérios fixos: contexto de curso de nível 50, papéis de IDs 3 e 5, cursos visíveis e usuários não excluídos ou suspensos, conforme cada consulta.

O SQL contém um filtro por data de lastaccess apenas como comentário, ou seja, não está sendo aplicado.

Visualizações e SQL original integral

O relatório contém 2 visualizações e 2 consultas SQL. O código possui destaque de sintaxe, mantendo os caracteres originais. As variantes MySQL e PostgreSQL estão em caixas separadas dentro de cada visualização correspondente.

1. Engajamento associado a professores — Tabela

Tabela por professor com o papel de ID 3 em contexto de curso, quantidade de cursos, alunos associados ao papel de ID 5, contas não suspensas, registros de conclusão formal de curso e média calculada das notas.

Cache: 30m. Atualização: 30m.

SQL original integral

SELECT 
    kbi_u.id        AS u_id,
    kbi_u.firstname,
    kbi_u.lastname,
    COUNT(DISTINCT kbi_ctx.instanceid)  AS num_courses,
    SUM(l.learners)                 AS num_learners,
    SUM(l1.activelearners)          AS num_activelearners,
    SUM(cc.completed)               AS num_completedlearners,
    AVG(g.grade)                    AS grade
FROM mdl_user kbi_u
LEFT JOIN mdl_role_assignments kbi_ra ON kbi_ra.userid = kbi_u.id
LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
JOIN mdl_course kbi_c ON kbi_ctx.instanceid = kbi_c.id AND kbi_c.visible = 1
LEFT JOIN (
    SELECT 
        kbi_ctx.instanceid, 
        COUNT(DISTINCT kbi_ra.userid) AS learners
    FROM mdl_role_assignments kbi_ra, mdl_context kbi_ctx
    WHERE 
        kbi_ctx.id = kbi_ra.contextid
        AND kbi_ctx.contextlevel = 50
        AND kbi_ra.roleid = 5
    GROUP BY 
        kbi_ctx.instanceid
) AS l ON l.instanceid = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        kbi_ctx.instanceid, 
        COUNT(DISTINCT kbi_ra.userid) AS activelearners
    FROM mdl_role_assignments kbi_ra, mdl_user kbi_u, mdl_context kbi_ctx
    WHERE 
        kbi_ctx.id = kbi_ra.contextid
        AND kbi_ctx.contextlevel = 50
        AND kbi_u.id = kbi_ra.userid
        -- AND kbi_u.lastaccess BETWEEN 1707755694 AND 1710347694
        AND kbi_u.deleted = 0
        AND kbi_u.suspended = 0
        AND kbi_ra.roleid = 5
    GROUP BY 
        kbi_ctx.instanceid
) AS l1 ON l1.instanceid = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        course, 
        COUNT(id) AS completed
    FROM 
        mdl_course_completions
    WHERE 
        timecompleted > 0
    GROUP BY 
        course
) cc ON cc.course = kbi_ctx.instanceid
LEFT JOIN (
    SELECT 
        kbi_gi.courseid,
        ROUND(AVG(CASE
            WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
            ELSE kbi_g.finalgrade 
        END), 0) AS grade
    FROM mdl_grade_items kbi_gi, mdl_grade_grades kbi_g
    WHERE 
        kbi_gi.itemtype = 'course'
        AND kbi_g.itemid = kbi_gi.id
        AND kbi_g.finalgrade IS NOT NULL
    GROUP BY 
        kbi_gi.courseid
) g ON g.courseid = kbi_ctx.instanceid
WHERE kbi_ctx.contextlevel = 50
  AND kbi_ra.roleid        = 3
  AND kbi_u.deleted        = 0
  AND kbi_u.suspended      = 0
GROUP BY kbi_u.id, kbi_u.firstname, kbi_u.lastname
2. Participação e conclusão de atividades por curso — Tabela

Tabela de cursos visíveis com total de estudantes de papel ID 5, estudantes que acessaram e possuem registro de conclusão de atividade, que acessaram e não possuem esse registro, e que não têm último acesso no curso.

Cache: 30m. Atualização: 30m.

SQL original integral

SELECT kbi_c.id       AS c_id,
       kbi_c.fullname AS c_fullname,
       COUNT(DISTINCT kbi_ra.userid) AS num_learners,
       COUNT(DISTINCT CASE
           WHEN comp.userid IS NOT NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
           ELSE NULL 
       END) AS completed_learners,
       COUNT(DISTINCT CASE
           WHEN comp.userid IS NULL AND kbi_ula.id IS NOT NULL THEN kbi_u.id
           ELSE NULL 
       END) AS not_completed_learners,
       COUNT(DISTINCT CASE 
           WHEN kbi_ula.id IS NULL THEN kbi_u.id 
           ELSE NULL 
       END) AS not_accessed_learners
FROM mdl_role_assignments kbi_ra
JOIN mdl_context kbi_ctx 
    ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
JOIN mdl_course kbi_c 
    ON kbi_c.id = kbi_ctx.instanceid
JOIN mdl_user kbi_u 
    ON kbi_u.id = kbi_ra.userid
LEFT JOIN (
    SELECT kbi_cm.course, kbi_cmc.userid
    FROM mdl_course_modules kbi_cm
    JOIN mdl_course_modules_completion kbi_cmc 
        ON kbi_cmc.coursemoduleid = kbi_cm.id AND kbi_cmc.completionstate = 1
    WHERE kbi_cmc.id > 0
    GROUP BY kbi_cm.course, kbi_cmc.userid
) comp 
    ON comp.userid = kbi_u.id AND comp.course = kbi_c.id
LEFT JOIN mdl_user_lastaccess kbi_ula 
    ON kbi_ula.courseid = kbi_c.id AND kbi_ula.userid = kbi_ra.userid
WHERE kbi_c.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_c.visible = 1
  AND kbi_ra.roleid = 5
GROUP BY kbi_c.id

Limitações e cuidados

  • O relatório não consulta logs de autenticação, embora esteja na categoria de acessos/login.
  • O indicador de estudantes ativos, na primeira tabela, considera contas válidas e não suspensas, não atividade recente.
  • A primeira tabela calcula conclusões de curso em mdl_course_completions; a segunda utiliza a conclusão de pelo menos uma atividade. Essas métricas não são equivalentes.
  • Somas e médias sobre junções entre cursos e professores podem pesar registros repetidos; confira os números antes de comparações institucionais.
  • Os IDs de papel 3 e 5 são assumidos pelo SQL e podem não corresponder à organização de papéis de uma instalação personalizada.

As consultas foram extraídas integralmente das definições JSON do plugin na master, sem execução em um Moodle nesta etapa. Antes de usar em produção, valide compatibilidade, permissões e resultados.
