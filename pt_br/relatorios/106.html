RELATÓRIO 106

Dashboard de analytics de aprendizagem

Visão geral da atividade, engajamento, progresso, conclusão e desempenho dos cursos.

Finalidade do relatório

O painel combina quatro indicadores numéricos, um gráfico de linhas de atividade diária, um gráfico de pizza de engajamento e uma tabela de desempenho por curso. Cada elemento consulta a versão mais recente dos dados analíticos armazenados pelo Kopere BI.

Por que utilizar?

Reunir, em um único painel, indicadores recentes de atividade, engajamento, conclusão e desempenho dos cursos para apoiar a triagem de prioridades administrativas e pedagógicas.

Filtros disponíveis

Não existem parâmetros SQL dinâmicos de curso, pessoa, coorte ou período nas sete consultas. Cada uma usa MAX(batchid) da respectiva tabela analítica para recuperar o lote mais recente disponível.

O gráfico diário tem o recorte fixo courseid = 0, correspondente ao agregado geral; o indicador de atividade considera actions7 > 0; o indicador de atenção considera risklevel IN ('high','medium') e timecompleted IS NULL. São condições internas do SQL, não filtros selecionáveis.

Visualizações e SQL integral

Este relatório reúne 7 visualizações, com o SQL original completo de cada elemento, acompanhado por descrição de apresentação, cache e atualização. O código recebe realce de sintaxe por Prism.js. A definição principal não tem variante PostgreSQL separada na master; por isso, não foi criada uma versão inexistente.

1. Alunos ativos nos últimos 7 dias · Indicador numérico

Indicador numérico: quantidade de usuários distintos com actions7 maior que zero no último lote de análise de engajamento. A métrica representa atividade registrada nos sete dias considerados pelo processamento, não usuários conectados neste instante.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(DISTINCT userid)
FROM mdl_local_kopere_bi_engage
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
  AND actions7 > 0
2. Alunos que precisam de atenção · Indicador numérico

Indicador numérico: quantidade de usuários distintos em risco alto ou médio, sem data de conclusão, no último lote de análise. Uma pessoa matriculada em vários cursos é contada uma vez nesta métrica.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(DISTINCT userid)
FROM mdl_local_kopere_bi_engage
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
  AND risklevel IN ('high', 'medium')
  AND timecompleted IS NULL
3. Progresso médio · Indicador numérico

Indicador numérico: média aritmética do campo progress dos registros do lote mais recente, com uma casa decimal. A média é dos registros analisados, não necessariamente uma média por pessoa distinta.

Cache: none · Atualização: none.

SQL original integral

SELECT ROUND(AVG(progress), 1)
FROM mdl_local_kopere_bi_engage
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
4. Matrículas concluídas · Indicador numérico

Indicador numérico: quantidade de registros de matrícula analisados com timecompleted preenchido. COUNT(id) conta registros, não estudantes distintos.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(id)
FROM mdl_local_kopere_bi_engage
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
  AND timecompleted IS NOT NULL
5. Alunos ativos por dia · Gráfico de linhas

Gráfico de linhas: usa daykey no eixo temporal e activeusers como quantidade de usuários ativos por dia. Seleciona somente courseid = 0 (agregado da instalação) no lote mais recente da tabela de agregação diária.

Cache: none · Atualização: none.

SQL original integral

SELECT daykey, activeusers AS active_learners
FROM mdl_local_kopere_bi_daily
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_daily)
  AND courseid = 0
ORDER BY daystart
6. Distribuição do engajamento · Gráfico de pizza

Gráfico de pizza: distribui as linhas analisadas conforme engagement high, medium, low ou outras situações ('At risk'). COUNT(id) mede registros, não necessariamente pessoas distintas.

Cache: none · Atualização: none.

SQL original integral

SELECT CASE engagement
         WHEN 'high' THEN 'High'
         WHEN 'medium' THEN 'Medium'
         WHEN 'low' THEN 'Low'
         ELSE 'At risk'
       END AS engagement_level,
       COUNT(id) AS learners
FROM mdl_local_kopere_bi_engage
WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_engage)
GROUP BY engagement
ORDER BY CASE engagement WHEN 'high' THEN 1 WHEN 'medium' THEN 2 WHEN 'low' THEN 3 ELSE 4 END
7. Resumo do desempenho dos cursos · Tabela

Tabela de cursos com matrícula, ativos em sete dias, médias de progresso/nota, conclusão, riscos alto/médio, tendência, escore e classificação de saúde. Ordena primeiro os escores menores e depois o risco alto.

Cache: none · Atualização: none.

SQL original integral

SELECT ca.id, c.id AS courseid, c.fullname AS course, ca.enrolments, ca.active7, ca.avgprogress, ca.avggrade, ca.completionrate, ca.highrisk, ca.mediumrisk, ca.trendpercent, ca.healthscore,
       CASE ca.healthlevel
         WHEN 'healthy' THEN 'lang::analytics_health_healthy::local_kopere_bi'
         WHEN 'attention' THEN 'lang::analytics_health_attention::local_kopere_bi'
         ELSE 'lang::analytics_health_critical::local_kopere_bi'
       END AS healthlevel
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, ca.highrisk DESC, c.fullname

Critérios e funcionamento

O painel depende das tabelas pré-processadas mdl_local_kopere_bi_engage, mdl_local_kopere_bi_daily e mdl_local_kopere_bi_courseag. As métricas como progress, risklevel, actions7, completionrate e healthscore já chegam calculadas a essas tabelas; os SQLs desta página as agregam ou apresentam, mas não definem seus algoritmos originais.

Como o último batchid é selecionado separadamente em cada fonte, a atualização das três tabelas precisa ser examinada para comparações consistentes.

Limitações e cuidados

  • “Ativos em sete dias” não significa presença online em tempo real e depende de actions7 produzido pelo processamento analítico.
  • Indicadores de pessoas distintas (COUNT DISTINCT userid) e indicadores de registros (COUNT id) têm denominadores diferentes e não devem ser comparados diretamente.
  • Os últimos lotes das tabelas engage, daily e courseag podem ter horários diferentes; não suponha atualização simultânea.
  • O nível de risco e o índice de saúde são classificações derivadas. O SQL desta página não explica a fórmula de cálculo nem justifica intervenções automáticas.
  • Não há filtro explícito de visibilidade do curso ou de exclusão/suspensão do usuário nos SQLs de origem analítica; a adequação depende do processamento que alimentou os lotes.
  • Todos os elementos declaram cache e recarga como none; isso não confirma que as tabelas analíticas estejam sendo atualizadas em tempo real.

Os SQLs são reproduzidos literalmente do arquivo JSON da master, sem execução em uma instalação Moodle nesta etapa. Verifique disponibilidade das tabelas analíticas, compatibilidade, resultados e permissões no ambiente de destino.
