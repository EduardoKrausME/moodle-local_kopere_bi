RELATÓRIO 116

Cursos ativos por dia

Quantidade diária de cursos com ações registradas nos módulos, segundo o snapshot mais recente.

Finalidade do relatório

Tabela com data de início do dia, número de cursos distintos com pelo menos uma ação e soma das ações dos cursos no dia, ordenada do dia mais recente para o mais antigo.

Por que utilizar?

Monitorar a quantidade de cursos que tiveram ações registradas em cada dia e o volume agregado de ações, usando os snapshots diários calculados pelo Kopere BI.

Filtros disponíveisVisualização e SQLCritérios de cálculoLimitações

Filtros disponíveis

Não existem parâmetros SQL dinâmicos de curso, usuário, coorte ou intervalo temporal. O relatório utiliza o último lote da tabela mdl_local_kopere_bi_daily, por meio de batchid = (SELECT MAX(batchid) ...), e considera apenas courseid > 1.

Na contagem de cursos ativos, a condição d.actions > 0 é aplicada dentro de COUNT(DISTINCT CASE ...). A consulta não possui limite explícito de linhas ou filtro para últimos N dias.

Visualização e SQL integral

O relatório contém uma visualização do tipo tabela, com SQL integral, cache e configuração de atualização. O código utiliza Prism.js para realce de sintaxe. Não existe arquivo PostgreSQL separado para esta definição na master; não foi criada uma variante inexistente.

1. Cursos ativos por dia · Tabela

Tabela com data de início do dia, número de cursos distintos com pelo menos uma ação e soma das ações dos cursos no dia, ordenada do dia mais recente para o mais antigo.

Cache: 1h · Atualização: none.

SQL original integral

SELECT d.daystart AS id, d.daystart,
       COUNT(DISTINCT CASE WHEN d.actions > 0 THEN d.courseid ELSE NULL END) AS active_courses,
       SUM(d.actions) AS actions
  FROM mdl_local_kopere_bi_daily d
 WHERE d.courseid > 1
   AND d.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_daily)
 GROUP BY d.daystart
 ORDER BY d.daystart DESC

Critérios e funcionamento

Para cada daystart, o SQL conta COUNT(DISTINCT CASE WHEN actions > 0 THEN courseid ELSE NULL END) e soma SUM(actions). Cursos sem ação naquele dia não entram em active_courses, mas suas linhas, se existirem, permanecem no agrupamento de ações.

O último batchid é recuperado na própria tabela de agregações diárias. Logo, a cobertura temporal, a periodicidade e o processamento do histórico dependem do lote existente, não da atualização da página HTML.

Limitações e cuidados

  • Curso ativo significa ter ao menos uma ação registrada naquele dia, não necessariamente ter estudantes conectados ou atividades concluídas.
  • As contagens são derivadas de agregações pré-processadas: o relatório não analisa os logs Moodle diretamente e pode refletir dados desatualizados.
  • O SQL não fixa número de dias nem intervalo calendário. A quantidade de períodos retornados depende das linhas contidas no último lote.
  • O relatório não restringe explicitamente a visibilidade dos cursos e não fornece filtros interativos de curso ou período.
  • SUM(actions) agrega ações dos cursos e não o número de pessoas. O conceito de ação depende das regras que alimentam a tabela diária.
  • O cache configurado é de uma hora, independentemente da cadência real de recomputação dos dados; não existe variante PostgreSQL separada no repositório.

O SQL está reproduzido integralmente do JSON original da master, sem execução em uma instalação Moodle nesta etapa. Verifique compatibilidade do SGBD, visibilidade dos dados, permissões e consistência de resultados.
