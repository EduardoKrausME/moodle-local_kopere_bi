RELATÓRIO 084

Evidências de competências

Relaciona evidências de competências associadas a usuários de toda a instalação, incluindo competência, identificadores de origem, referência e data de criação.

Finalidade do relatório

Relaciona evidências de competências associadas a usuários de toda a instalação, incluindo competência, identificadores de origem, referência e data de criação.

Por que utilizar?

Permite a administradores e responsáveis por competências localizar registros de evidências existentes e investigar suas origens técnicas e associações com usuários e competências.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

Não há parâmetros SQL dinâmicos para selecionar curso, usuário, competência, status ou data. A consulta lê todas as evidências da tabela mdl_competency_evidence associadas a um usuário encontrado em mdl_user.

A condição fixa é kbi_u.id IS NOT NULL, que exclui evidências sem uma associação válida a usuário. A ordem é por sobrenome, nome e kbi_ce.timecreated DESC.

Visualização e SQL original integral

Uma visualização em tabela com a consulta SQL original integral, configuração de cache, atualização e destaque de sintaxe por Prism.js. Não há arquivo de variante PostgreSQL separado para este relatório.

1. Evidências de competências · Tabela

Uma tabela por evidência com ID do registro, ID e nome do usuário, nome curto da competência, URL, identificador de descrição, componente de descrição, argumento de descrição e timestamp de criação, ordenada pelo sobrenome, nome e evidências mais recentes.

Cache: 1h · Atualização: none.

SQL original integral

SELECT kbi_ce.id,
       kbi_u.id AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_c.shortname,
       kbi_ce.url,
       kbi_ce.descidentifier,
       kbi_ce.desccomponent,
       kbi_ce.desca,
       kbi_ce.timecreated
FROM mdl_competency_evidence kbi_ce
       LEFT JOIN mdl_competency_usercomp kbi_cu ON kbi_ce.usercompetencyid = kbi_cu.id
       LEFT JOIN mdl_competency kbi_c ON kbi_c.id = kbi_cu.competencyid
       LEFT JOIN mdl_user kbi_u ON kbi_u.id = kbi_cu.userid
WHERE kbi_u.id IS NOT NULL
ORDER BY kbi_u.lastname, kbi_u.firstname, kbi_ce.timecreated DESC

Limitações e cuidados

  • A consulta não restringe curso, plano de aprendizagem, tipo de competência, framework, data, status da conta ou papel do usuário, abrangendo dados potencialmente extensos da instalação.
  • As junções com competência e competência de usuário são opcionais. É possível existir evidência com usuário vinculado, mas com nome curto da competência vazio por ausência de registro relacionado.
  • O campo desca representa o argumento de descrição gravado na evidência, e descidentifier e desccomponent são chaves técnicas que podem exigir resolução de idioma para uma descrição amigável.
  • Uma evidência registrada não comprova isoladamente que a competência foi alcançada ou aprovada. O SQL não consulta a classificação final, o nível de proficiência nem critérios de avaliação.
  • O campo url é uma referência armazenada na evidência; a consulta não verifica se o destino continua acessível ou autorizado ao usuário que visualiza o relatório.
  • A ordenação coloca as evidências mais recentes primeiro dentro de cada usuário, mas não seleciona apenas a última evidência de cada competência.
  • Como são apresentados nomes de usuários e evidências acadêmicas de toda a plataforma, o relatório exige controle de acesso e exportação.
  • O catálogo não contém uma variante PostgreSQL separada para esta definição.
