RELATÓRIO 062

Estrutura das questões dos questionários

Inventário das posições dos questionários em cursos visíveis, relacionando banco de questões, versão selecionada, características da questão e tags associadas.

Finalidade do relatório

Inventário das posições dos questionários em cursos visíveis, relacionando banco de questões, versão selecionada, características da questão e tags associadas.

Por que utilizar?

Facilita auditar a organização dos questionários, conferir posições e páginas, identificar tipos e versões de questões e localizar estruturas com referências incompletas para revisão.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

Não há filtro SQL dinâmico para curso, questionário, categoria de questão, tag, versão ou data. A consulta abrange questionários pertencentes a cursos e módulos visíveis (kbi_c.visible = 1 e kbi_cm.visible = 1).

Para cada posição, a referência a questão usa component = 'mod_quiz' e questionarea = 'slot'. A versão é a explicitamente referenciada ou, quando kbi_qr.version IS NULL, o maior número de versão da entrada correspondente.

Visualização e SQL original integral

O relatório apresenta uma visualização em tabela, com 2 consultas SQL, cache, atualização e realce de sintaxe usando Prism.js. As versões MySQL e PostgreSQL da mesma visualização estão em caixas separadas dentro de um único bloco.

1. Estrutura das questões dos questionários · Tabela

Uma tabela por posição de questão (quiz slot), com curso, questionário, CMID, número e página da posição, nota máxima, entrada do banco de questões, versão, ID e nome da questão, tipo, nota padrão, comprimento, situação da versão e tags.

Cache: 1h · Atualização: none.

SQL original integral MySQL

SELECT kbi_slot.id                AS id,
       kbi_c.id                   AS courseid,
       kbi_c.fullname             AS course,
       kbi_cm.id                  AS cmid,
       kbi_qz.id                  AS quizid,
       kbi_qz.name                AS quiz_name,
       kbi_slot.slot,
       kbi_slot.page              AS slot_page,
       kbi_slot.maxmark,
       kbi_qbe.id                 AS questionbankentryid,
       kbi_qv.version,
       kbi_q.id                   AS questionid,
       kbi_q.name                 AS question_name,
       kbi_q.qtype,
       kbi_q.defaultmark,
       kbi_q.length,
       kbi_qv.status              AS question_status,
       kbi_tags.tags              AS question_tags
FROM mdl_quiz kbi_qz
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_qz.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'quiz'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_qz.id
       JOIN mdl_quiz_slots kbi_slot ON kbi_slot.quizid = kbi_qz.id
       LEFT JOIN mdl_question_references kbi_qr ON kbi_qr.component = 'mod_quiz'
             AND kbi_qr.questionarea = 'slot'
             AND kbi_qr.itemid = kbi_slot.id
       LEFT JOIN mdl_question_bank_entries kbi_qbe ON kbi_qbe.id = kbi_qr.questionbankentryid
       LEFT JOIN mdl_question_versions kbi_qv ON kbi_qv.questionbankentryid = kbi_qbe.id
             AND (
                 kbi_qv.version = kbi_qr.version
                 OR (kbi_qr.version IS NULL AND kbi_qv.version = (
                     SELECT MAX(kbi_qv2.version)
                     FROM mdl_question_versions kbi_qv2
                     WHERE kbi_qv2.questionbankentryid = kbi_qbe.id
                 ))
             )
       LEFT JOIN mdl_question kbi_q ON kbi_q.id = kbi_qv.questionid
       LEFT JOIN (
             SELECT kbi_ti.itemid,
                    GROUP_CONCAT(DISTINCT kbi_t.rawname ORDER BY kbi_t.rawname SEPARATOR ', ') AS tags
             FROM mdl_tag_instance kbi_ti
                    JOIN mdl_tag kbi_t ON kbi_t.id = kbi_ti.tagid
             WHERE kbi_ti.itemtype = 'question'
             GROUP BY kbi_ti.itemid
       ) kbi_tags ON kbi_tags.itemid = kbi_q.id
WHERE kbi_c.visible = 1
  AND kbi_cm.visible = 1
ORDER BY kbi_c.fullname, kbi_qz.name, kbi_slot.slot

             AND kbi_qr.itemid = kbi_slot.id
       LEFT JOIN mdl_question_bank_entries kbi_qbe ON kbi_qbe.id = kbi_qr.questionbankentryid

                     SELECT MAX(kbi_qv2.version)
                     FROM mdl_question_versions kbi_qv2

  AND kbi_cm.visible = 1

Limitações e cuidados

  • A consulta usa junções opcionais com referências, entradas do banco, versões, questões e tags. Assim, posições sem referência resolvida podem aparecer com informações de questão vazias.
  • Quando a referência não fixa uma versão, o SQL seleciona a de maior número da entrada. Não verifica, nessa seleção, se a versão possui status ready ou é a versão pedagogicamente desejada.
  • O campo question_status apenas expõe o status da versão selecionada. Questões não prontas não são excluídas da consulta.
  • O inventário não informa respostas, alternativas, critérios de correção, tentativas, desempenho de estudantes nem qualidade da formulação das questões.
  • A lista de tags agrega nomes relacionados à questão e não garante que a organização por categorias do banco esteja completa ou atualizada.
  • O SQL só inclui módulos e cursos visíveis, mas não verifica restrições individuais de acesso, condições de disponibilidade ou permissões de visualização de cada estudante.
  • As variantes MySQL e PostgreSQL diferem no agregador de tags. Não há filtro temporal, de modo que o relatório apresenta a estrutura disponível no momento da consulta.
