RELATÓRIO 075

Visão geral das respostas nos fóruns

Apresenta a postagem inicial das discussões de fóruns do curso selecionado, as respostas e os dados da postagem pai quando a resposta se vincula a outra resposta.

Finalidade do relatório

Apresenta a postagem inicial das discussões de fóruns do curso selecionado, as respostas e os dados da postagem pai quando a resposta se vincula a outra resposta.

Por que utilizar?

Facilita a revisão das discussões e de suas cadeias de respostas, permitindo relacionar mensagens e autores, com as respectivas datas de publicação.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

O filtro SQL dinâmico é Curso, correspondente a :courseid, presente uma vez tanto no MySQL quanto no PostgreSQL.

O SQL exige curso com ID positivo, postagem inicial com parent = 0, respostas com parent <> 0 e, para preencher a resposta anterior, uma postagem pai que também tenha parent <> 0. Não há filtro temporal, de visibilidade ou de usuário.

Visualização e SQL original integral

Uma visualização em tabela, com 2 consultas SQL integrais, cache, atualização e realce de sintaxe com Prism.js. MySQL e PostgreSQL aparecem em caixas separadas dentro da mesma visualização.

1. Visão geral das respostas nos fóruns · Tabela

Tabela por resposta de discussão (ou discussão sem resposta), com nome do curso e fórum, assunto, nome do autor e data da postagem inicial, mensagem e autor da resposta, e mensagem, autor e data da postagem pai quando esta também for uma resposta.

Cache: 1h · Atualização: none.

SQL original integral MySQL

SELECT kbi_c.fullname            AS course,
       kbi_f.name                AS forum,
       kbi_fp.subject            AS discussion_post,
       kbi_u1.firstname          AS forum_started_by_first_name,
       kbi_u1.lastname           AS forum_started_by_last_name,
       kbi_fp.created            AS date_started,
       kbi_fp2.message           AS response,
       kbi_fp2.created           AS response_date,
       kbi_u2.firstname          AS response_first_name,
       kbi_u2.lastname           AS response_laste_name,
       kbi_fp3.message           AS response_immediatey_prior,
       kbi_fp3.created           AS response_immediatey_prior_date,
       kbi_u3.firstname          AS response_immediatey_prior_first_name,
       kbi_u3.lastname           AS response_immediatey_prior_last_name
FROM mdl_forum kbi_f
       JOIN mdl_course kbi_c ON kbi_c.id = kbi_f.course
       JOIN mdl_modules kbi_m ON kbi_m.name = 'forum'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.course = kbi_c.id AND kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_f.id
       JOIN mdl_forum_discussions kbi_fd ON kbi_fd.forum = kbi_f.id AND kbi_fd.course = kbi_c.id
       JOIN mdl_forum_posts kbi_fp ON kbi_fp.discussion = kbi_fd.id AND kbi_fp.parent = 0
       JOIN mdl_user kbi_u1 ON kbi_u1.id = kbi_fp.userid
       LEFT JOIN mdl_forum_posts kbi_fp2 ON kbi_fp2.discussion = kbi_fd.id AND kbi_fp2.parent <> 0
       LEFT JOIN mdl_user kbi_u2 ON kbi_u2.id = kbi_fp2.userid
       LEFT JOIN mdl_forum_posts kbi_fp3 ON kbi_fp3.discussion = kbi_fd.id AND kbi_fp3.id = kbi_fp2.parent AND kbi_fp3.parent <> 0
       LEFT JOIN mdl_user kbi_u3 ON kbi_u3.id = kbi_fp3.userid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid

Limitações e cuidados

  • O campo response_immediatey_prior identifica a postagem pai da resposta na árvore, quando ela própria é uma resposta, e não necessariamente a mensagem anterior na ordem temporal.
  • Para respostas diretas à publicação inicial, os campos de resposta anterior ficam nulos, pois o SQL exclui a postagem inicial dessa relação.
  • O uso de LEFT JOIN em postagens de resposta permite listar discussões sem respostas, com campos nulos.
  • A consulta não exige course.visible = 1 nem course_modules.visible = 1 e não verifica status dos autores. Dados de discussões ocultas podem ser retornados.
  • Mensagens são obtidas diretamente de mdl_forum_posts.message e podem incluir HTML e conteúdo privado; a exibição deve seguir as regras de segurança e de permissões.
  • Não são calculadas estatísticas de volume, desempenho, prazo de resposta ou participação: o resultado reproduz associações entre mensagens.
  • Há uma inconsistência entre os metadados e a consulta: a definição lista uma coluna id em info.column, mas o SQL não a retorna. A consulta original foi preservada.
  • MySQL e PostgreSQL apresentam a mesma lógica de vínculos entre postagens, cada qual com seu SQL integral.
