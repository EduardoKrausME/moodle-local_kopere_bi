RELATÓRIO 087

Detalhes do progresso nos planos de aprendizagem

Lista usuários que possuem pelo menos um plano de aprendizagem associado a um modelo com ID positivo, apresentando apenas identificação e contato.

Finalidade do relatório

Lista usuários que possuem pelo menos um plano de aprendizagem associado a um modelo com ID positivo, apresentando apenas identificação e contato.

Por que utilizar?

Permite localizar usuários associados a planos de aprendizagem baseados em modelos como ponto de partida para consultas administrativas mais detalhadas, sem presumir que os dados representem progresso.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

Não há parâmetros SQL dinâmicos de curso, usuário, plano, modelo, situação, data ou competência.

Os critérios fixos exigem kbi_cp.templateid > 0, usuário não excluído (deleted = 0), não suspenso (suspended = 0) e nome de usuário diferente de guest. A ordenação é por sobrenome e nome.

Visualização e SQL original integral

O relatório apresenta uma visualização em tabela com a consulta SQL original integral, configuração de cache e atualização e realce de sintaxe usando Prism.js. Não existe variante PostgreSQL separada no catálogo de definições.

1. Detalhes do progresso nos planos de aprendizagem · Tabela

Uma tabela com ID do usuário, nome, sobrenome e endereço de e-mail. A seleção é feita a partir de planos que referenciam um modelo de aprendizagem.

Cache: 1h · Atualização: none.

SQL original integral

SELECT kbi_u.id, kbi_u.firstname, kbi_u.lastname, kbi_u.email
FROM mdl_competency_plan kbi_cp
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_cp.userid
WHERE kbi_cp.templateid > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
ORDER BY kbi_u.lastname, kbi_u.firstname

Limitações e cuidados

  • Apesar do título, o SQL não apresenta progresso nem detalhes de proficiência. Nenhuma coluna de percentual, status do plano, evidências, competência avaliada ou data de conclusão é retornada.
  • Como o SQL não utiliza DISTINCT nem GROUP BY, uma pessoa com vários planos baseados em modelos pode aparecer repetida, uma vez por registro de plano correspondente.
  • A condição templateid > 0 não verifica se o modelo ainda existe ou se o plano está em um status específico.
  • O relatório não filtra por curso, modelo, responsável, papel ou intervalo de datas. Os registros vêm de planos de toda a instalação.
  • A coluna email contém dado pessoal e deve ser mostrada apenas a perfis autorizados.
  • A lista não identifica qual plano motivou cada linha, pois não retorna ID ou nome de plano, dificultando explicar duplicidades na interface.
  • Não existe variante PostgreSQL separada para esta definição.
