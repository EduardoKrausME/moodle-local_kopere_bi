RELATÓRIO 108

Saúde dos cursos

Compara a saúde dos cursos usando indicadores de engajamento, progresso, conclusão e risco dos alunos.

Finalidade do relatório

O painel reúne quatro indicadores de síntese, um gráfico de colunas dos 25 cursos com os menores índices de saúde e uma tabela detalhada com todos os registros do lote analítico mais recente.

Por que utilizar?

Comparar indicadores sintéticos de saúde dos cursos, identificar os cursos classificados como críticos ou necessitando de atenção e apoiar análises de tendência, risco e desempenho.

Filtros disponíveisVisualizações e SQLCritérios de cálculoLimitações

Filtros disponíveis

Não há parâmetros SQL dinâmicos de curso, estudante, coorte, período ou estado de saúde. Cada elemento consulta os registros de mdl_local_kopere_bi_courseag do MAX(batchid) disponível.

Os três primeiros indicadores têm os filtros fixos healthlevel = 'healthy', 'attention' ou 'critical'. O gráfico aplica LIMIT 25 e ordena por escore crescente. A tabela detalhada não limita a quantidade de cursos no SQL.

Visualizações e SQL integral

Este relatório reúne 6 visualizações, com o SQL original completo de cada elemento, acompanhado por descrição de apresentação, cache e atualização. O código recebe realce de sintaxe por Prism.js. A definição principal não tem variante PostgreSQL separada na master; por isso, não foi criada uma versão inexistente.

1. Cursos saudáveis · Indicador numérico

Indicador numérico: conta registros de cursos com healthlevel = 'healthy' no último lote da tabela de saúde dos cursos.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'healthy'
2. Cursos que precisam de atenção · Indicador numérico

Indicador numérico: conta registros com healthlevel = 'attention' no último lote.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'attention'
3. Cursos em situação crítica · Indicador numérico

Indicador numérico: conta registros com healthlevel = 'critical' no último lote.

Cache: none · Atualização: none.

SQL original integral

SELECT COUNT(id) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag) AND healthlevel = 'critical'
4. Índice médio de saúde · Indicador numérico

Indicador numérico: calcula a média do campo healthscore no último lote, arredondada para uma casa decimal. Pode ser NULL se não houver registros.

Cache: none · Atualização: none.

SQL original integral

SELECT ROUND(AVG(healthscore), 1) FROM mdl_local_kopere_bi_courseag WHERE batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
5. Índice de saúde dos cursos · Gráfico de colunas

Gráfico de colunas: exibe nome do curso e healthscore, ordenados de menor para maior escore, com LIMIT 25. Não são necessariamente os 25 cursos com melhor saúde; a consulta destaca os menores escores.

Cache: none · Atualização: none.

SQL original integral

SELECT c.fullname AS course, ca.healthscore AS health_score
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, c.fullname
LIMIT 25
6. Detalhes da saúde dos cursos · Tabela

Tabela de cursos com matrículas, usuários ativos em 7 e 30 dias, pessoas sem acesso, conclusões, riscos alto e médio, progresso/nota médios, taxas de conclusão/engajamento, tendência, índice e nível de saúde.

Cache: none · Atualização: none.

SQL original integral

SELECT ca.id, c.id AS courseid, c.fullname AS course, ca.enrolments, ca.active7, ca.active30, ca.neveraccessed, ca.completions, ca.highrisk, ca.mediumrisk, ca.avgprogress, ca.avggrade, ca.completionrate, ca.engagementrate, ca.trendpercent, ca.healthscore,
       CASE ca.healthlevel
         WHEN 'healthy' THEN 'lang::analytics_health_healthy::local_kopere_bi'
         WHEN 'attention' THEN 'lang::analytics_health_attention::local_kopere_bi'
         ELSE 'lang::analytics_health_critical::local_kopere_bi'
       END AS healthlevel
FROM mdl_local_kopere_bi_courseag ca
JOIN mdl_course c ON c.id = ca.courseid
WHERE ca.batchid = (SELECT MAX(batchid) FROM mdl_local_kopere_bi_courseag)
ORDER BY ca.healthscore ASC, ca.highrisk DESC, c.fullname

Critérios e funcionamento

Os dados de healthscore, healthlevel, engagementrate, completionrate e trendpercent são resultados de cálculos anteriores do Kopere BI. O SQL de cada elemento lê e resume esses campos; a definição do relatório não revela a ponderação usada para gerar a pontuação de saúde.

A tabela traduz o nível de saúde por chaves do plugin, e o gráfico apresenta no máximo 25 cursos com os menores escores, ordenados ascendentemente.

Limitações e cuidados

  • O escore de saúde não é uma avaliação definitiva da qualidade educacional do curso; depende de uma metodologia externa à definição SQL.
  • O gráfico mostra no máximo 25 cursos, selecionados pelos menores escores, enquanto a tabela pode apresentar todo o lote.
  • Os indicadores contam registros agregados, não verificam por conta própria a visibilidade dos cursos nem a situação dos usuários.
  • As métricas de engajamento, tendência e atividade recente dependem do processamento analítico. A configuração cache none não assegura atualização do lote em tempo real.
  • As quatro métricas de resumo podem retornar zero ou NULL conforme o tipo de agregação e a ausência de registros no lote atual.
  • Use a leitura combinada de riscos, matrículas e contexto institucional antes de comparar cursos com populações, cargas horárias e formatos diferentes.

Os SQLs são reproduzidos literalmente do arquivo JSON da master, sem execução em uma instalação Moodle nesta etapa. Verifique disponibilidade das tabelas analíticas, compatibilidade, resultados e permissões no ambiente de destino.
