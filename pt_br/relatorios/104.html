RELATÓRIO 104

Cadastros de alunos por mês

Apresenta a quantidade de contas identificadas como estudantes, agrupadas pelo mês de criação da conta e distribuídas entre situações ativa, suspensa e excluída.

Finalidade do relatório

Apresenta a quantidade de contas identificadas como estudantes, agrupadas pelo mês de criação da conta e distribuídas entre situações ativa, suspensa e excluída.

Por que utilizar?

Permite acompanhar a evolução da base de contas que receberam o papel de estudante e observar, mês a mês, a composição atual de situações administrativas dessas contas.

Filtros disponíveis Visualização e SQL Critérios de cálculo Limitações

Filtros disponíveis

Não há filtros SQL dinâmicos de curso, usuário, coorte ou período, nem intervalo de meses predefinido. A consulta agrupa todo o histórico de criação das contas encontradas.

O único recorte explícito no WHERE da consulta externa é username <> 'guest'. A subconsulta exige a atribuição do papel student em contexto de curso. Contas suspensas e excluídas não são excluídas do conjunto, pois são necessárias às contagens por situação.

Visualização e SQL original integral

Uma visualização em tabela e duas consultas SQL integrais equivalentes, MySQL e PostgreSQL, agrupadas no mesmo bloco. O realce de sintaxe é realizado por Prism.js e não modifica o SQL.

1. Cadastros de alunos por mês · Tabela

Tabela com uma linha por mês no formato AAAA-MM, total de estudantes distintos e três contagens de contas atualmente ativas, suspensas e excluídas; apresentada em ordem decrescente de mês.

Cache: 1h · Atualização: none.

SQL original integral MySQL

SELECT DATE_FORMAT(FROM_UNIXTIME(kbi_u.timecreated), '%Y-%m') AS id,
       DATE_FORMAT(FROM_UNIXTIME(kbi_u.timecreated), '%Y-%m') AS period_month,
       COUNT(DISTINCT kbi_u.id) AS student_count,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 0 THEN 1 ELSE 0 END) AS active_students,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 1 THEN 1 ELSE 0 END) AS suspended_students,
       SUM(CASE WHEN kbi_u.deleted = 1 THEN 1 ELSE 0 END) AS deleted_students
FROM mdl_user kbi_u
       JOIN (
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
             WHERE kbi_r.shortname = 'student'
       ) kbi_students ON kbi_students.userid = kbi_u.id
WHERE kbi_u.username <> 'guest'
GROUP BY period_month
ORDER BY period_month DESC

SQL original integral PostgreSQL

SELECT TO_CHAR(TO_TIMESTAMP(kbi_u.timecreated), 'YYYY-MM') AS id,
       TO_CHAR(TO_TIMESTAMP(kbi_u.timecreated), 'YYYY-MM') AS period_month,
       COUNT(DISTINCT kbi_u.id) AS student_count,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 0 THEN 1 ELSE 0 END) AS active_students,
       SUM(CASE WHEN kbi_u.deleted = 0 AND kbi_u.suspended = 1 THEN 1 ELSE 0 END) AS suspended_students,
       SUM(CASE WHEN kbi_u.deleted = 1 THEN 1 ELSE 0 END) AS deleted_students
FROM mdl_user kbi_u
       JOIN(
             SELECT DISTINCT kbi_ra.userid
             FROM mdl_role_assignments kbi_ra
                    JOIN mdl_role kbi_r ON kbi_r.id = kbi_ra.roleid
                    JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid AND kbi_ctx.contextlevel = 50
             WHERE kbi_r.shortname = 'student'
       ) kbi_students ON kbi_students.userid = kbi_u.id
WHERE kbi_u.username <> 'guest'
GROUP BY period_month
ORDER BY period_month DESC

Critérios e funcionamento

O relatório usa mdl_user.timecreated como referência temporal e seleciona usuários que possuem o papel de nome curto student em algum contexto de curso (contextlevel = 50). A subconsulta usa DISTINCT userid para evitar duplicação por múltiplos cursos.

A versão MySQL formata o período com DATE_FORMAT(FROM_UNIXTIME(...), '%Y-%m'); a versão PostgreSQL usa TO_CHAR(TO_TIMESTAMP(...), 'YYYY-MM'). Os campos active_students, suspended_students e deleted_students são calculados com condições sobre o estado atual da conta.

Limitações e cuidados

  • O mês representa a criação da conta no Moodle, não a data de inscrição em um curso nem a data em que o papel student foi atribuído.
  • As categorias ativa, suspensa e excluída consideram o estado atual das contas. O relatório não reconstrói historicamente qual era a situação de cada conta no mês informado.
  • A consulta só encontra usuários que ainda possuem uma atribuição do papel student no contexto de algum curso; cadastros que perderam esse papel podem não aparecer.
  • Não há segmentação dinâmica por curso, método de inscrição ou período. Uma mesma pessoa com mais de uma conta poderá ser contada como múltiplos cadastros.
  • A conversão de timestamps para meses pode variar com o fuso horário da conexão do banco; diferenças próximas da virada do mês devem ser verificadas.

O SQL está reproduzido literalmente das definições JSON da master, sem execução em uma instalação Moodle nesta etapa. Verifique compatibilidade, resultados, permissões e privacidade antes do uso institucional.
