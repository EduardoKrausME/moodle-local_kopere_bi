RELATÓRIO 004

Estatísticas de inscrições

Uma tabela relaciona matrícula, nota e conclusão por módulo no curso selecionado, enquanto um gráfico de área mostra as inscrições ativas, inativas e expiradas de cada curso.

Finalidade e conteúdo

Uma tabela relaciona matrícula, nota e conclusão por módulo no curso selecionado, enquanto um gráfico de área mostra as inscrições ativas, inativas e expiradas de cada curso.

Por que e quando utilizar?

Permite investigar a situação de estudantes e módulos de um curso, além de comparar a quantidade de inscrições entre cursos, distinguindo estado da matrícula de conclusão de atividades.

FiltrosSQL e visualizaçõesCuidados

Filtros disponíveis

A tabela utiliza o parâmetro :courseid, preenchido pelo filtro de curso, e restringe usuários não excluídos ou suspensos, cursos visíveis e módulos visíveis.

O gráfico de área não contém :courseid, logo não é afetado pelo curso escolhido na tabela; agrega todos os cursos da consulta. Não há parâmetros dinâmicos de usuário, coorte ou período. As datas de vencimento são comparadas com o instante atual.

Visualizações e SQL original integral

São 2 visualizações e 3 consultas SQL. Quando uma mesma visualização possui duas consultas para MySQL e PostgreSQL, elas são apresentadas em caixas separadas dentro do mesmo bloco.

1. Matrículas, notas e conclusão por módulo - Tabela

A tabela exibe usuário, curso, módulo visível, nota quando disponível, configuração de conclusão, resultado da conclusão e prazo da inscrição. Um estudante pode aparecer uma vez por módulo.

Cache: 30m · Atualização: 30m.

SQL original integral

SELECT
    u.id AS u_id,
    u.firstname,
    u.lastname,
    u.email,
    u.city,
    u.country,
    c.id       AS c_id,
    c.fullname AS c_fullname,
    cm.id      AS cm_cmid,
    m.name AS module_name,
    ROUND(
        CASE
            WHEN g.rawgrademax > 0 THEN (g.finalgrade / g.rawgrademax) * 100
            ELSE g.finalgrade
        END, 0
    ) AS grade,
    CASE
        WHEN cmc.completionstate = 0 THEN 'lang::report_4_completionstate_0::local_kopere_bi'
        WHEN cmc.completionstate = 1 THEN 'lang::report_4_completionstate_1::local_kopere_bi'
        WHEN cmc.completionstate = 2 THEN 'lang::report_4_completionstate_2::local_kopere_bi'
        WHEN cmc.completionstate = 3 THEN 'lang::report_4_completionstate_3::local_kopere_bi'
        WHEN cmc.completionstate = 4 THEN 'lang::report_4_completionstate_4::local_kopere_bi'
        ELSE 'lang::report_4_completionstate_none::local_kopere_bi'
    END AS completionstate_status,
    CASE
        WHEN cm.completion = 0 THEN 'lang::report_4_completion_0::local_kopere_bi'
        WHEN cm.completion = 1 THEN 'lang::report_4_completion_1::local_kopere_bi'
        WHEN cm.completion = 2 THEN 'lang::report_4_completion_2::local_kopere_bi'
        ELSE 'lang::report_4_completion_none::local_kopere_bi'
    END AS completion_status,
    ue.enrol_status AS enrol_status,
    ue.timeend       AS enrol_timeend
FROM (
    SELECT MIN(ue1.id) AS id, 
           ue1.userid, 
           e1.courseid, 
           MIN(ue1.status) AS enrol_status, 
           MIN(ue1.timeend) AS timeend
    FROM mdl_user_enrolments ue1
    JOIN mdl_enrol e1 ON e1.id = ue1.enrolid
    GROUP BY ue1.userid, e1.courseid
) ue
JOIN mdl_user u 
         ON u.id = ue.userid
JOIN mdl_course c 
         ON c.id = ue.courseid
JOIN mdl_course_modules cm 
         ON cm.course = c.id
        AND cm.instance > 0
JOIN mdl_modules m 
         ON m.id = cm.module
LEFT JOIN mdl_grade_items gi 
         ON gi.itemtype = 'mod'
        AND gi.iteminstance = cm.instance
        AND gi.itemmodule = m.name
        AND gi.gradetype = 1
LEFT JOIN mdl_grade_grades g 
         ON g.itemid = gi.id
        AND g.userid = u.id
LEFT JOIN mdl_course_modules_completion cmc 
         ON cmc.coursemoduleid = cm.id
        AND cmc.userid = u.id

WHERE c.id = :courseid
  AND u.deleted = 0
  AND u.suspended = 0
  AND c.visible = 1
  AND cm.visible = 1
2. Inscrições ativas, inativas e expiradas por curso - Gráfico de área

O gráfico de área compara três contagens agregadas por curso. As versões MySQL e PostgreSQL usam expressões distintas para o horário atual, mas compõem a mesma visualização.

Cache: 30m · Atualização: 30m.

SQL original integral MySQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP()) THEN 1
               ELSE 0
           END) AS 'lang::active_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS 'lang::inactive_enrolments::local_kopere_bi',
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < UNIX_TIMESTAMP() THEN 1
               ELSE 0
           END) AS 'lang::expired_enrolments::local_kopere_bi'
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname

SQL original integral PostgreSQL

SELECT c.fullname,
       SUM(CASE 
               WHEN ue.status = 0 AND(ue.timeend = 0 OR ue.timeend > (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint)) THEN 1
               ELSE 0
           END) AS "lang::active_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 1 THEN 1
               ELSE 0
           END) AS "lang::inactive_enrolments::local_kopere_bi",
       SUM(CASE 
               WHEN ue.status = 0 AND ue.timeend > 0 AND ue.timeend < (EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::bigint) THEN 1
               ELSE 0
           END) AS "lang::expired_enrolments::local_kopere_bi"
FROM mdl_course c
JOIN mdl_enrol e ON e.courseid = c.id
JOIN mdl_user_enrolments ue ON ue.enrolid = e.id
GROUP BY c.id
ORDER BY c.fullname

Limitações e interpretação

  • As linhas da tabela representam combinações de matrícula e módulo; não use a quantidade de linhas como contagem de estudantes distintos.
  • O filtro de curso afeta a tabela, mas não o gráfico.
  • O gráfico de área apresenta categorias de inscrição por curso, e não uma evolução diária.
  • A subconsulta agrupa matrículas por usuário e curso usando MIN(status) e MIN(timeend); em casos de múltiplos métodos, isso pode combinar dados de inscrições distintas.
  • Há dados pessoais e notas: conceda acesso somente a perfis autorizados.

SQLs transcritos sem alteração das definições JSON da master; não foram executados em um Moodle nesta etapa. Valide permissões, desempenho e resultados no ambiente de destino.
