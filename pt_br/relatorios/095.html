RELATÓRIO 095

Detalhes do uso de arquivos por professor

Lista arquivos associados a recursos do curso escolhido, com nome do arquivo, caminho técnico, data de criação e usuário registrado no próprio arquivo.

Finalidade do relatório

Lista arquivos associados a recursos do curso escolhido, com nome do arquivo, caminho técnico, data de criação e usuário registrado no próprio arquivo.

Por que utilizar?

Permite conferir os arquivos vinculados a atividades do tipo Arquivo, suas referências técnicas e a conta de usuário armazenada em cada registro, auxiliando auditorias administrativas e de manutenção.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

O filtro SQL dinâmico é Curso, por :courseid, presente uma vez na condição kbi_c.id = :courseid.

As condições fixas exigem curso visível, usuário do arquivo não excluído, não suspenso e diferente da conta guest, além de arquivos no contexto de módulo de recurso (contextlevel = 70, component = 'mod_resource', filearea = 'content', itemid = 0, filesize > 0). Não há filtro de papel ou de período.

Visualização e SQL original integral

Uma visualização em tabela com 1 consulta SQL original integral, configurações de cache e atualização e realce de sintaxe com Prism.js. Não existe arquivo PostgreSQL separado para esta definição.

1. Detalhes do uso de arquivos por professor · Tabela

Uma tabela por arquivo elegível, com ID do arquivo, ID e nome do curso, ID, nome e sobrenome e login do usuário associado ao arquivo, caminho técnico do recurso, nome do arquivo e timestamp de criação do registro.

Cache: 1h · Atualização: none.

SQL original integral

SELECT kbi_f.id,
       kbi_c.id                                                                              AS courseid,
       kbi_c.fullname,
       kbi_u.id                                                                              AS userid,
       kbi_u.firstname,
       kbi_u.lastname,
       kbi_u.username,
       CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath, kbi_f.filename) AS file_path,
       kbi_f.filename,
       kbi_f.timecreated
FROM mdl_course kbi_c
       JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
       JOIN mdl_user kbi_u ON kbi_u.id = kbi_f.userid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
ORDER BY kbi_c.fullname, kbi_f.filename

Limitações e cuidados

  • Apesar do título, a consulta não filtra professores. O usuário vem de mdl_files.userid; o SQL não o relaciona a mdl_role_assignments nem exige papel docente.
  • O identificador de usuário associado ao arquivo não comprova quem leu, fez download ou utilizou o recurso. Tampouco comprova necessariamente autoria pedagógica do material.
  • A consulta exige registro de usuário ativo e associado ao arquivo; arquivos sem usuário válido, excluído ou suspenso não entram no resultado.
  • Somente arquivos de conteúdo do componente mod_resource com tamanho positivo são retornados. Arquivos de outras atividades, diretórios e registros sem conteúdo não são abrangidos.
  • Os caminhos são construídos usando contexto do módulo e número de revisão; eles são referências técnicas e seu acesso deve ser validado pela aplicação.
  • A data timecreated é a criação do registro do arquivo no Moodle, não a última leitura, visualização ou modificação do conteúdo.
  • A consulta não filtra visibilidade do módulo, período de publicação, grupos ou matrícula. Não apresenta visitas nem tempo gasto em arquivos.
  • Não há arquivo PostgreSQL separado no catálogo original.
