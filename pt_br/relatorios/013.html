RELATÓRIO 013

Sucesso e progresso dos estudantes

Apresenta o acompanhamento de estudantes matriculados no curso selecionado, reunindo notas, referência de aprovação, conclusão, acesso registrado e medidas de participação.

Finalidade do relatório

Apresenta o acompanhamento de estudantes matriculados no curso selecionado, reunindo notas, referência de aprovação, conclusão, acesso registrado e medidas de participação.

Por que utilizar?

É útil para tutores e gestores acompanharem o progresso por estudante de um curso, identificarem possíveis dificuldades e compararem notas, critérios de aprovação, conclusão de módulos e registros de visitas.

Filtros reaisVisualização e SQLLimitações

Filtros disponíveis

O SQL utiliza exclusivamente o parâmetro dinâmico :courseid, presente quatro vezes: na seleção de matrículas, nos agregados de acompanhamento, na média de notas do curso e na contagem de atividades concluídas. Esse filtro restringe os resultados ao curso escolhido.

Há também condições fixas: inscrições e métodos de inscrição com status 0, papel de estudante com ID 5, contas não excluídas ou suspensas, cursos visíveis e exclusão do usuário guest. Não existem filtros dinâmicos de usuário, coorte ou período.

Visualização e SQL original integral

Uma visualização em tabela, com o SQL original completo e a configuração de cache e atualização. O código utiliza o destaque de sintaxe SQL do Prism.js.

1. Sucesso e progresso dos estudantes · Tabela

A tabela reúne por estudante e curso dados de matrícula, data de início, modalidade de inscrição, nota final e percentual, referência de aprovação, média das notas do curso, último acesso registrado, visitas, tempo acompanhado e conclusão formal do curso. A consulta combina informações de matrícula, notas, conclusão e acompanhamento do Kopere BI.

Cache: 1h · Atualização: none.

SQL original integral

SELECT CASE
         WHEN kbi_gi.grademax > 0 THEN (kbi_cri.gradepass / kbi_gi.grademax) * 100
         ELSE kbi_cri.gradepass END            AS gradepass,
       kbi_cri.gradepass                       AS gradepass_raw,
       kbi_u.email,
       ue.userid,
       ue.started,
       kbi_c.id                                AS cid,
       kbi_c.fullname,
       ue.enrolment,
       kbi_c.startdate,
       lit.lastaccess,
       git.average,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 2) AS grade,
       ROUND((CASE
                WHEN kbi_g.rawgrademax > 0 THEN (kbi_g.finalgrade / kbi_g.rawgrademax) * 100
                ELSE kbi_g.finalgrade END), 2) AS grade_raw,
       ROUND((CASE
                WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                        THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                ELSE kbi_g.finalgrade END), 2) AS grade_percent,
       cmc.completed,
       kbi_u.firstname,
       kbi_u.lastname,
       lit.timespend,
       lit.visits,
       kbi_c.enablecompletion,
       kbi_cc.timecompleted                    AS complete
FROM (SELECT DISTINCT kbi_e.courseid,
                      kbi_ue.userid,
                      (CASE
                         WHEN kbi_ue.timestart > 0
                                 THEN kbi_ue.timestart
                         ELSE kbi_ue.timecreated
                          END) AS started,
                      (CASE
                         WHEN kbi_e.name IS NULL
                                 THEN kbi_e.enrol
                         ELSE CONCAT(kbi_e.enrol, '(', kbi_e.name, ')')
                          END) AS enrolment
      FROM mdl_enrol kbi_e
             JOIN mdl_user_enrolments kbi_ue ON kbi_ue.enrolid = kbi_e.id
             JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 50 AND kbi_ctx.instanceid = kbi_e.courseid
             JOIN mdl_role_assignments kbi_ra
               ON kbi_ra.contextid = kbi_ctx.id AND kbi_ra.userid = kbi_ue.userid AND kbi_ra.roleid = 5
      WHERE kbi_ue.userid > 0
        AND kbi_e.status = 0
        AND kbi_ue.status = 0
        AND kbi_e.courseid = :courseid) ue
       JOIN mdl_user kbi_u ON kbi_u.id = ue.userid
       JOIN mdl_course kbi_c ON kbi_c.id = ue.courseid
       LEFT JOIN mdl_course_completions kbi_cc ON kbi_cc.course = kbi_c.id AND kbi_cc.userid = kbi_u.id
       LEFT JOIN mdl_course_completion_criteria kbi_cri ON kbi_cri.course = kbi_c.id AND kbi_cri.criteriatype = 6
       LEFT JOIN mdl_grade_items kbi_gi ON kbi_gi.courseid = kbi_c.id AND kbi_gi.itemtype = 'course'
       LEFT JOIN mdl_grade_grades kbi_g ON kbi_g.itemid = kbi_gi.id AND kbi_g.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_lit.userid,
                         kbi_lit.courseid,
                         SUM(kbi_lit.timespend)  as timespend,
                         SUM(kbi_lit.visits)     as visits,
                         MAX(kbi_lit.lastaccess) as lastaccess
                  FROM mdl_local_kopere_bi_tracking kbi_lit
                  WHERE kbi_lit.courseid > 0
                    AND kbi_lit.courseid = :courseid
                  GROUP BY kbi_lit.courseid, kbi_lit.userid) lit ON lit.courseid = kbi_c.id AND lit.userid = kbi_u.id
       LEFT JOIN (SELECT kbi_gi.courseid,
                         ROUND(AVG(CASE
                                     WHEN (kbi_g.rawgrademax - kbi_g.rawgrademin) > 0
                                             THEN ((kbi_g.finalgrade - kbi_g.rawgrademin) / (kbi_g.rawgrademax - kbi_g.rawgrademin)) * 100
                                     ELSE kbi_g.finalgrade END), 2) AS average
                  FROM mdl_grade_items kbi_gi, mdl_grade_grades kbi_g
                  WHERE kbi_gi.itemtype = 'course'
                    AND kbi_g.itemid = kbi_gi.id
                    AND kbi_g.finalgrade IS NOT NULL
                    AND kbi_gi.courseid = :courseid
                  GROUP BY kbi_gi.courseid) git ON git.courseid = kbi_c.id
       LEFT JOIN (SELECT kbi_cmc.userid, kbi_cm.course, COUNT(kbi_cmc.id) as completed
                  FROM mdl_course_modules_completion kbi_cmc, mdl_course_modules kbi_cm
                  WHERE kbi_cm.visible = 1
                    AND kbi_cmc.coursemoduleid = kbi_cm.id
                    AND kbi_cmc.completionstate IN (1, 2)
                    AND kbi_cm.course = :courseid
                  GROUP BY kbi_cm.course, kbi_cmc.userid) cmc ON cmc.course = kbi_c.id AND cmc.userid = kbi_u.id
WHERE kbi_u.id > 0
  AND kbi_u.deleted = 0
  AND kbi_u.suspended = 0
  AND kbi_u.username != 'guest'
  AND kbi_c.visible = 1

Limitações e cuidados

  • A consulta considera atribuições com papel de ID 5 em contexto de curso; instituições com papéis personalizados devem validar o critério.
  • O campo de nota é calculado a partir de escalas e notas registradas. Quando faltam dados de avaliação, alguns indicadores podem ficar vazios; não interprete ausência como nota zero.
  • Os dados de tempo, visitas e último acesso vêm de mdl_local_kopere_bi_tracking e dependem dos registros efetivamente coletados; tempo não equivale a aprendizagem.
  • O cálculo de conclusão de atividades conta estados 1 e 2 para módulos visíveis. Isso não deve ser confundido com a conclusão formal do curso, que é apresentada em outro campo.
  • A junção com itens de avaliação e critérios de conclusão pode multiplicar linhas em cursos com configurações específicas. Confira agregações antes de usar os resultados em decisões institucionais.
  • O SQL foi mantido como publicado; contém funções de arredondamento e outras expressões cuja compatibilidade depende do SGBD e da configuração. Não há variante PostgreSQL separada neste relatório.
