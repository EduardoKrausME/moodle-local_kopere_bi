RELATÓRIO 094

Uso de arquivos por professor

Reúne recursos de arquivo do curso selecionado, referências e nomes dos arquivos associados e um nome de professor encontrado nas atribuições de papel do curso.

Finalidade do relatório

Reúne recursos de arquivo do curso selecionado, referências e nomes dos arquivos associados e um nome de professor encontrado nas atribuições de papel do curso.

Por que utilizar?

Ajuda a localizar recursos do tipo Arquivo existentes em um curso, conferir os nomes e referências dos arquivos vinculados e identificar um usuário associado ao papel convencional de professor.

Filtros disponíveis Visualização e SQL Limitações

Filtros disponíveis

O filtro SQL dinâmico é Curso, vinculado a :courseid e presente uma vez em cada variante na condição kbi_c.id = :courseid.

As condições fixas exigem ID de curso positivo e curso visível (kbi_c.visible = 1). Para a lista de arquivos, a junção considera component = 'mod_resource', filearea = 'content', itemid = 0 e filesize > 0, associados ao contexto de módulo (contextlevel = 70). O professor é localizado pelo papel ID 3 no contexto de curso (contextlevel = 50).

Visualização e SQL original integral

Uma visualização em tabela com 2 consultas SQL originais integrais, configurações de cache e atualização e realce de sintaxe com Prism.js. As variantes MySQL e PostgreSQL equivalentes aparecem em caixas separadas no mesmo bloco de visualização.

1. Uso de arquivos por professor · Tabela

Uma tabela agregada por curso, com ID e nome do curso, campo de quantidade de recursos, caminhos técnicos e nomes dos arquivos separados em texto, e nome de um usuário atribuído ao papel ID 3. As duas versões usam o mesmo conjunto de colunas.

Cache: 1h · Atualização: none.

SQL original integral MySQL

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_r.id)                                     as resources,
       GROUP_CONCAT(CASE
                      WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath,
                                                        kbi_f.filename)
                      ELSE NULL END SEPARATOR '[[,]]') AS files,
       GROUP_CONCAT(kbi_f.filename)                        AS files_sorting,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)                                       AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       LEFT JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

SQL original integral PostgreSQL

SELECT kbi_c.id,
       kbi_c.fullname,
       count(kbi_r.id)                                     as resources,
       STRING_AGG((CASE
                      WHEN kbi_f.id IS NOT NULL THEN CONCAT('/', kbi_ctx.id, '/mod_resource/content/', kbi_r.revision, kbi_f.filepath,
                                                        kbi_f.filename)
                      ELSE NULL END)::text, '[[,]]') AS files,
       STRING_AGG((kbi_f.filename)::text, ',')                        AS files_sorting,
       (SELECT DISTINCT CONCAT(kbi_u.firstname, ' ', kbi_u.lastname)
        FROM mdl_role_assignments kbi_ra
               JOIN mdl_user kbi_u ON kbi_ra.userid = kbi_u.id
               JOIN mdl_context kbi_ctx ON kbi_ctx.id = kbi_ra.contextid
        WHERE kbi_ctx.instanceid = kbi_c.id
          AND kbi_ctx.contextlevel = 50
          AND kbi_ra.roleid = 3
        LIMIT 1)                                       AS teacher
FROM mdl_course kbi_c
       LEFT JOIN mdl_resource kbi_r ON kbi_r.course = kbi_c.id
       LEFT JOIN mdl_modules kbi_m ON kbi_m.name = 'resource'
       LEFT JOIN mdl_course_modules kbi_cm ON kbi_cm.module = kbi_m.id AND kbi_cm.instance = kbi_r.id
       LEFT JOIN mdl_context kbi_ctx ON kbi_ctx.contextlevel = 70 AND kbi_ctx.instanceid = kbi_cm.id
       LEFT JOIN mdl_files kbi_f
         ON kbi_f.component = 'mod_resource' AND kbi_f.filearea = 'content' AND kbi_f.itemid = 0 AND kbi_f.filesize > 0 AND
            kbi_ctx.id = kbi_f.contextid
WHERE kbi_c.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
GROUP BY kbi_c.id

Limitações e cuidados

  • A coluna resources é calculada por COUNT(kbi_r.id), sem DISTINCT. Um recurso com vários arquivos pode aparecer repetido após as junções; o total pode ultrapassar a quantidade real de recursos do curso.
  • O título sugere uso de arquivos por professor, mas o SQL não verifica quem enviou, criou ou acessou cada arquivo. O professor é escolhido independentemente da origem dos recursos e não há métricas de visitas, downloads ou tempo de uso.
  • A subconsulta teacher usa SELECT DISTINCT ... LIMIT 1 sem ORDER BY. Pode retornar arbitrariamente um professor quando vários usuários têm papel ID 3 no curso; papéis personalizados diferentes desse ID não são contemplados.
  • Os campos files e files_sorting reúnem textos de caminhos e nomes de arquivos, não representam arquivos lidos ou baixados. Valores duplicados podem aparecer pelas junções.
  • A versão MySQL utiliza GROUP_CONCAT e a PostgreSQL utiliza STRING_AGG. Nenhuma versão estabelece ordem interna para os arquivos agregados, e o texto [[,]] funciona como separador técnico da lista de caminhos.
  • Os caminhos de arquivo incluem contexto, revisão, caminho e nome do arquivo, mas não significam URLs públicas ou acesso autorizado ao conteúdo.
  • O SQL verifica a visibilidade do curso, mas não restringe módulos de arquivo visíveis. Recursos ocultos podem influenciar o resultado.
  • Uma linha pode existir mesmo que o curso não possua recursos de arquivo, devido às junções opcionais. A consulta não oferece filtro temporal ou por participante.
