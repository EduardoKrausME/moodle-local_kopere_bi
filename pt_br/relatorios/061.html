RELATÓRIO 061

Envios de arquivos

Resumo dos arquivos armazenados no Moodle, agrupados pelo componente responsável, com quantidade de registros de arquivos de tamanho positivo e soma dos tamanhos registrados.

Finalidade do relatório

Resumo dos arquivos armazenados no Moodle, agrupados pelo componente responsável, com quantidade de registros de arquivos de tamanho positivo e soma dos tamanhos registrados.

Por que utilizar?

Ajuda administradores a identificar quais componentes concentram arquivos e volume armazenado, oferecendo uma referência inicial para avaliar consumo de espaço e crescimento dos dados.

Filtros disponíveisVisualização e SQLLimitações

Filtros disponíveis

Não há parâmetros SQL dinâmicos de curso, componente, usuário, tipo de arquivo ou período.

A única condição é kbi_f.filesize > 0, aplicada a mdl_files. O SQL agrupa os registros por kbi_f.component e ordena os resultados pela soma dos tamanhos, em ordem decrescente.

Visualização e SQL original integral

O relatório apresenta uma visualização em tabela, com 1 consulta SQL, cache, atualização e realce de sintaxe usando Prism.js. O catálogo não disponibiliza arquivo de variante PostgreSQL para esta definição.

1. Envios de arquivos · Tabela

Uma tabela por componente com o código do componente, quantidade de arquivos, soma de bytes e maior ID de arquivo no grupo. O resultado é ordenado do maior volume de bytes para o menor.

Cache: 1h · Atualização: none.

SQL original integral

SELECT MAX(kbi_f.id)             AS id,
       kbi_f.component,
       COUNT(kbi_f.id)           AS files,
       COALESCE(SUM(kbi_f.filesize), 0) AS filesize
FROM mdl_files kbi_f
WHERE kbi_f.filesize > 0
GROUP BY kbi_f.component
ORDER BY filesize DESC, component

Limitações e cuidados

  • O título “Envios de arquivos” não corresponde necessariamente a uploads realizados por usuários: a tabela mdl_files inclui arquivos mantidos por diferentes componentes, inclusive arquivos gerados ou administrados pelo Moodle.
  • A contagem files representa registros da tabela com tamanho positivo, e não necessariamente arquivos físicos únicos: o armazenamento pode deduplicar conteúdos ou manter versões.
  • O volume filesize é uma soma dos tamanhos lógicos em bytes. Não equivale, obrigatoriamente, ao espaço real ocupado em disco, devido a conteúdos compartilhados, metadados e infraestrutura de armazenamento.
  • Arquivos vazios ou registros com tamanho zero são excluídos pelo filtro.
  • O campo id é MAX(kbi_f.id), ou seja, apenas o maior identificador no grupo. Não representa um identificador exclusivo do componente.
  • Não há recorte de curso, período, usuário ou origem do envio; não use o resultado como histórico auditável de uploads.
  • Não existe arquivo PostgreSQL separado para este relatório. O acesso a dados administrativos de armazenamento deve ser restrito.
