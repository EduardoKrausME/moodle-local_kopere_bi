RELATÓRIO 003

Cursos

Quatro tabelas de um curso selecionado: progresso da conclusão, notas, histórico de acessos a atividades e classificação de participação ou conclusão de atividades.

O que o relatório apresenta

Quatro tabelas de um curso selecionado: progresso da conclusão, notas, histórico de acessos a atividades e classificação de participação ou conclusão de atividades.

Por que e quando utilizar

É útil para coordenações e tutores que precisam cruzar participação, matrícula e desempenho de estudantes em um curso específico e investigar diferenças entre acesso, nota e conclusão.

Filtros disponíveisVisualizações e SQLLimitações

Filtros disponíveis

Filtro Curso, vinculado ao parâmetro SQL :courseid. O curso é escolhido no seletor correspondente, quando esse subplugin de filtro está habilitado, e aplicado a todas as consultas. Não foram encontrados filtros SQL de usuário, coorte ou período.

Como são as visualizações e o SQL

4 consultas SQL compõem este relatório. Em cada item estão o tipo de visualização, sua finalidade, a configuração de cache e o SQL integral. Abra cada item para consultar o código.

1. Progresso de conclusão por estudante · Tabela

Tabela com perfil, matrícula e percentual de módulos elegíveis com conclusão registrada.

Cache: 6h. Atualização: 30m.

SQL original integral

SELECT u.id AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       u.institution,
       u.department,
       u.phone1,
       u.phone2,
       u.address,
       u.city,
       u.country,
       u.timezone,
       u.firstaccess,
       u.lastaccess,
       ue.timecreated,
       MAX(cc.timecompleted) AS timecompleted,
       ROUND(((MAX(cmc.completed) / MAX(m.modules)) * 100), 0) AS course_completed
  FROM {user_enrolments} ue
  JOIN {user} u ON u.id = ue.userid
  JOIN {enrol} e ON e.id = ue.enrolid
  JOIN {course} c ON c.id = e.courseid
  LEFT JOIN {course_completions} cc ON cc.timecompleted > 0
                                   AND cc.course = e.courseid
                                   AND cc.userid = ue.userid
  LEFT JOIN (
        SELECT course,
               COUNT(id) AS modules
          FROM {course_modules}
         WHERE visible = 1
           AND completion > 0
           AND deletioninprogress = 0
      GROUP BY course
      ) AS m ON m.course = c.id
  LEFT JOIN (
        SELECT cm_i.course,
               cmc_i.userid,
               COUNT(DISTINCT cmc_i.id) AS completed
          FROM {course_modules} cm_i,
               {course_modules_completion} cmc_i
         WHERE cmc_i.coursemoduleid = cm_i.id
           AND cm_i.visible = 1
           AND cmc_i.completionstate IN (1, 2)
           AND cm_i.deletioninprogress = 0
      GROUP BY cm_i.course,
               cmc_i.userid
      ) AS cmc ON cmc.course = c.id
              AND cmc.userid = ue.userid
 WHERE ue.id > 0
   AND u.id > 1
   AND u.deleted = 0
   AND u.suspended = 0
   AND ue.status = 0
   AND e.status = 0
   AND c.id = :courseid
GROUP BY u.id, ue.timecreated
2. Indicadores de nota do curso · Tabela

Tabela nominal com nota do item de curso e dados do estudante.

Cache: none. Atualização: none.

SQL original integral

SELECT u.id AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       MIN(gc.grade) AS grade
  FROM mdl_user_enrolments ue
  LEFT JOIN mdl_user u ON u.id = ue.userid
  LEFT JOIN mdl_enrol e ON e.id = ue.enrolid
  LEFT JOIN mdl_course c ON c.id = e.courseid
  LEFT JOIN (
             SELECT course, COUNT(id) AS cmnums
               FROM mdl_course_modules
              WHERE visible = 1
           GROUP BY course
            ) AS cm ON cm.course = c.id
  LEFT JOIN (
             SELECT course, COUNT(id) AS cmnumx
               FROM mdl_course_modules
              WHERE visible = 1
                AND completion > 0
           GROUP BY course
            ) cmx ON cmx.course = c.id
  LEFT JOIN (
             SELECT cm.course, cmc.userid, COUNT(cmc.id) AS cmcnums
               FROM mdl_course_modules cm,
                    mdl_course_modules_completion cmc
              WHERE cmc.coursemoduleid = cm.id
                AND cm.visible = 1
                AND cmc.completionstate IN (1, 2)
           GROUP BY cm.course, cmc.userid
            ) cmc ON cmc.course = c.id
                AND cmc.userid = u.id
  LEFT JOIN (
             SELECT cm.course, cmc.userid, COUNT(cmc.id) AS cmcnuma
               FROM mdl_course_modules cm,
                    mdl_course_modules_completion cmc
              WHERE cmc.coursemoduleid = cm.id
                AND cm.module = 1
                AND cm.visible = 1
                AND cmc.completionstate IN (1, 2)
           GROUP BY cm.course, cmc.userid
            ) AS cmca ON cmca.course = c.id
                   AND cmca.userid = u.id
  LEFT JOIN (
             SELECT gi.courseid,
                    g.userid,
                    ROUND((CASE WHEN g.rawgrademax > 0 THEN (g.finalgrade / g.rawgrademax) * 100 ELSE g.finalgrade END), 0) AS grade
               FROM mdl_grade_items gi,
                    mdl_grade_grades g
              WHERE gi.itemtype = 'course'
                AND g.itemid = gi.id
                AND g.finalgrade IS NOT NULL
           GROUP BY gi.courseid, g.userid, g.finalgrade, g.rawgrademax
            ) AS gc ON gc.courseid = c.id
                AND gc.userid = u.id
 WHERE ue.id > 0
   AND e.courseid = :courseid
   AND u.deleted = 0
   AND u.suspended = 0
   AND c.visible = 1
GROUP BY u.id, c.id
3. Registros de acesso às atividades · Tabela

Tabela de eventos registrados, com módulo, origem, IP e data/hora de acesso.

Cache: 6h. Atualização: 30m.

SQL original integral

SELECT u.id                    AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       l.contextinstanceid     AS cm_cmid,
       CONCAT('lang::modulename::', l.objecttable) AS module_name,
       l.origin                AS l_origin,
       l.ip                    AS l_ip,
       l.timecreated           AS l_timecreated,
       l.objecttable
       
     FROM mdl_local_kopere_bi_log_tmp l
LEFT JOIN mdl_course       c  ON c.id = l.courseid
LEFT JOIN mdl_user         u  ON u.id = l.userid
LEFT JOIN mdl_modules      m  ON m.name = SUBSTRING(l.component, 5)
LEFT JOIN mdl_course_modules cm ON cm.id = l.contextinstanceid

WHERE u.id > 1
  AND l.component LIKE '%mod_%'
  AND l.courseid = :courseid
  AND u.deleted = 0
  AND u.suspended = 0
  AND c.visible = 1
  AND cm.visible = 1
4. Análise de participação e conclusão · Tabela

Tabela com situação calculada a partir do último acesso e da existência de conclusão de atividades.

Cache: 6h. Atualização: 30m.

SQL original integral

SELECT u.id        AS u_id,
       u.firstname,
       u.lastname,
       u.email,
       CASE 
           WHEN ul.id IS NULL THEN 'lang::case_never_accessed::local_kopere_bi'
           WHEN comp.userid IS NOT NULL THEN 'lang::case_complete::local_kopere_bi'
           ELSE 'lang::case_incomplete::local_kopere_bi'
       END AS status
       
FROM mdl_role_assignments ra
       JOIN mdl_context ctx                                   ON ctx.id = ra.contextid 
                                                            AND ctx.contextlevel = 50
       JOIN mdl_course c                                     ON c.id = ctx.instanceid
       JOIN mdl_user u                                      ON u.id = ra.userid
       
       LEFT JOIN (SELECT cm.course, cmc.userid
                  FROM   mdl_course_modules cm
                         JOIN mdl_course_modules_completion cmc ON cmc.coursemoduleid = cm.id 
                                                              AND cmc.completionstate = 1
                  WHERE  cmc.id > 0
                  GROUP BY cm.course, cmc.userid
                 ) comp ON comp.userid = u.id 
                         AND comp.course = c.id
       
       LEFT JOIN mdl_user_lastaccess ul                         ON ul.courseid = c.id 
                                                            AND ul.userid = ra.userid
       
WHERE  c.id = :courseid 
  AND  u.deleted = 0 
  AND  u.suspended = 0  
  AND  c.visible = 1 
  AND  ra.roleid = 5
GROUP BY u.id

Limitações e interpretação

  • O filtro :courseid é usado nas quatro consultas e limita as tabelas ao curso selecionado.
  • A classificação de 'Completo' na tabela de participação depende de registros de conclusão de atividade e não comprova conclusão formal do curso.
  • Há uma consulta com papel ID 5 fixo e expressões de agrupamento que precisam de validação de compatibilidade com o banco instalado.
  • Contém informações pessoais, IPs e notas; controle rigorosamente as permissões e a visibilidade da página.

O SQL é reproduzido sem alterações a partir da definição do plugin na master. As consultas não foram executadas em uma instalação Moodle nesta documentação; verifique compatibilidade, permissões e resultados no seu ambiente.
