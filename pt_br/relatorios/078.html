RELATÓRIO 078

Resumo das atividades SCORM por curso

Resume cada pacote SCORM pertencente ao curso selecionado, com número de registros de tentativa, visitas a seus módulos registradas pelo Kopere BI e duração acumulada declarada pelos pacotes.

Finalidade do relatório

Resume cada pacote SCORM pertencente ao curso selecionado, com número de registros de tentativa, visitas a seus módulos registradas pelo Kopere BI e duração acumulada declarada pelos pacotes.

Por que utilizar?

Oferece uma visão operacional do uso de objetos SCORM para verificar volume de tentativas, frequência registrada de visitas e tempo informado pelos próprios pacotes.

Filtros disponíveis Visualização e SQL Limitações

Filtros disponíveis

O único filtro dinâmico é Curso, representado por :courseid, que aparece uma vez em cada variante na condição kbi_c.id = :courseid.

Os filtros fixos exigem ID do pacote SCORM maior que zero e curso visível. As subconsultas agregam tentativas por pacote, tracking por módulo SCORM e duração por pacote. Não há restrições por usuário, papel, matrícula, data, status de conclusão ou visibilidade do módulo.

Visualização e SQL original integral

O relatório apresenta uma visualização em tabela com 2 consultas SQL integrais, configuração de cache e atualização e realce de sintaxe com Prism.js. MySQL e PostgreSQL aparecem em caixas separadas dentro do mesmo bloco de visualização.

1. Resumo das atividades SCORM por curso · Tabela

Uma tabela por pacote SCORM, incluindo identificador, nome do curso e do pacote, data da última modificação de configuração, quantidade de registros de tentativa, soma das visitas registradas pelo Kopere BI para o módulo e soma das durações SCORM em segundos.

Cache: 1h · Atualização: none.

SQL original integral MySQL

SELECT kbi_s.id,
       kbi_c.fullname,
       kbi_s.name,
       kbi_s.timemodified,
       COALESCE(kbi_attempts.attempts, 0) AS attempts,
       COALESCE(kbi_tracking.visits, 0) AS visits,
       COALESCE(kbi_duration.duration, 0) AS duration
FROM mdl_scorm kbi_s
JOIN mdl_course kbi_c ON kbi_c.id = kbi_s.course
LEFT JOIN (
    SELECT scormid, COUNT(DISTINCT id) AS attempts
      FROM mdl_scorm_attempt
     GROUP BY scormid
) kbi_attempts ON kbi_attempts.scormid = kbi_s.id
LEFT JOIN (
    SELECT kbi_cm.instance, SUM(kbi_t.visits) AS visits
      FROM mdl_course_modules kbi_cm
      JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module AND kbi_m.name = 'scorm'
      JOIN mdl_local_kopere_bi_tracking kbi_t ON kbi_t.page = 'module'
            AND kbi_t.param = kbi_cm.id
     GROUP BY kbi_cm.instance
) kbi_tracking ON kbi_tracking.instance = kbi_s.id
LEFT JOIN (
    SELECT a.scormid, SUM(CASE WHEN e.element = 'cmi.core.total_time'
                              THEN TIME_TO_SEC(v.value) ELSE NULL END) AS duration
      FROM mdl_scorm_attempt a
      JOIN mdl_scorm_scoes_value v ON v.attemptid = a.id
      JOIN mdl_scorm_element e ON e.id = v.elementid
     GROUP BY a.scormid
) kbi_duration ON kbi_duration.scormid = kbi_s.id
WHERE kbi_s.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_s.name

SQL original integral PostgreSQL

SELECT kbi_s.id,
       kbi_c.fullname,
       kbi_s.name,
       kbi_s.timemodified,
       COALESCE(kbi_attempts.attempts, 0) AS attempts,
       COALESCE(kbi_tracking.visits, 0) AS visits,
       COALESCE(kbi_duration.duration, 0) AS duration
FROM mdl_scorm kbi_s
JOIN mdl_course kbi_c ON kbi_c.id = kbi_s.course
LEFT JOIN(
    SELECT scormid, COUNT(DISTINCT id) AS attempts
      FROM mdl_scorm_attempt
     GROUP BY scormid
) kbi_attempts ON kbi_attempts.scormid = kbi_s.id
LEFT JOIN(
    SELECT kbi_cm.instance, SUM(kbi_t.visits) AS visits
      FROM mdl_course_modules kbi_cm
      JOIN mdl_modules kbi_m ON kbi_m.id = kbi_cm.module AND kbi_m.name = 'scorm'
      JOIN mdl_local_kopere_bi_tracking kbi_t ON kbi_t.page = 'module'
            AND kbi_t.param = kbi_cm.id
     GROUP BY kbi_cm.instance
) kbi_tracking ON kbi_tracking.instance = kbi_s.id
LEFT JOIN(
    SELECT a.scormid, SUM(CASE WHEN e.element = 'cmi.core.total_time'
                              THEN EXTRACT(EPOCH FROM NULLIF((v.value)::text, '')::interval) ELSE NULL END) AS duration
      FROM mdl_scorm_attempt a
      JOIN mdl_scorm_scoes_value v ON v.attemptid = a.id
      JOIN mdl_scorm_element e ON e.id = v.elementid
     GROUP BY a.scormid
) kbi_duration ON kbi_duration.scormid = kbi_s.id
WHERE kbi_s.id > 0
  AND kbi_c.id = :courseid
  AND kbi_c.visible = 1
ORDER BY kbi_c.fullname, kbi_s.name

Limitações e cuidados

  • O campo attempts conta registros distintos de mdl_scorm_attempt, não usuários distintos nem pacotes concluídos.
  • O campo visits soma os registros do Kopere BI com page = 'module' e param igual ao ID do módulo do curso. Ele depende da coleta e retenção do acompanhamento.
  • O campo duration soma os valores de cmi.core.total_time armazenados nos registros SCORM e convertidos em segundos. Esse tempo informado pelo pacote não é a mesma medida usada no acompanhamento de visitas do Kopere BI.
  • MySQL utiliza TIME_TO_SEC e PostgreSQL utiliza conversão de intervalo para segundos. Valores SCORM malformados ou ausentes podem prejudicar a apuração.
  • As três métricas usam COALESCE(..., 0) quando não há dados; portanto, zero pode significar ausência de registros, não necessariamente ausência de atividade real.
  • O SQL exige curso visível, mas não restringe course_modules.visible. Um pacote SCORM oculto no curso pode aparecer.
  • As contagens e durações englobam o histórico disponível, sem filtro por período, matrícula ativa ou estado de conclusão. Não representam diretamente desempenho ou aprendizagem.
  • A coluna timemodified vem de mdl_scorm, não da última tentativa de um usuário.
