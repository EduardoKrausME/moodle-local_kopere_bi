RELATÓRIO 113

Alcance das atividades por curso

Percentual de alunos matriculados ativos com pelo menos uma visita registrada à atividade.

Finalidade do relatório

Uma tabela por módulo visível com curso, tipo do módulo, identificador da atividade, número de estudantes elegíveis, número de estudantes com acesso registrado, total sem acesso e percentual de alcance. A lista prioriza menores percentuais, depois curso e módulo, e limita o resultado a 500 linhas.

Por que utilizar?

Identificar atividades e recursos com menor alcance entre os estudantes elegíveis de cada curso, auxiliando o planejamento de comunicação, reorganização dos materiais e investigação de dificuldades de acesso.

Filtros disponíveis

Não há filtros SQL dinâmicos de curso, atividade, estudante, coorte ou período. O conjunto de módulos é restringido por cm.deletioninprogress = 0, cm.visible = 1 e c.id > 1, sem verificação explícita de c.visible.

O denominador considera usuários com matrícula e método ativos, datas de validade elegíveis, conta não excluída ou suspensa e papel de arquétipo student em contexto de curso. O numerador exige t.page = 'module' e t.visits > 0. O SQL limita o resultado a 500 módulos.

Visualização e SQL integral

O relatório possui uma visualização em tabela, acompanhada por SQL integral e suas configurações de cache e atualização. O código é destacado com Prism.js. Não existe um arquivo PostgreSQL separado na master para esta definição; por isso, não foi adicionada uma variante inexistente.

1. Alcance das atividades por curso · Tabela

Uma tabela por módulo visível com curso, tipo do módulo, identificador da atividade, número de estudantes elegíveis, número de estudantes com acesso registrado, total sem acesso e percentual de alcance. A lista prioriza menores percentuais, depois curso e módulo, e limita o resultado a 500 linhas.

Cache: 1h · Atualização: none.

SQL original integral

SELECT cm.id, c.id AS courseid, c.fullname AS course, m.name AS module,
       cm.instance AS activityid, COALESCE(en.enrolled, 0) AS enrolled,
       COALESCE(tr.accessed, 0) AS accessed,
       COALESCE(en.enrolled, 0) - COALESCE(tr.accessed, 0) AS neveraccessed,
       CASE WHEN COALESCE(en.enrolled, 0) > 0
            THEN ROUND(100.0 * COALESCE(tr.accessed, 0) / en.enrolled, 2)
            ELSE 0 END AS reach_percent
  FROM mdl_course_modules cm
  JOIN mdl_course c ON c.id = cm.course
  JOIN mdl_modules m ON m.id = cm.module
  LEFT JOIN (SELECT courseid, COUNT(DISTINCT userid) AS enrolled
               FROM (
    SELECT DISTINCT e.courseid, ue.userid
      FROM mdl_user_enrolments ue
      JOIN mdl_enrol e ON e.id = ue.enrolid
      JOIN mdl_context cx ON cx.contextlevel = 50 AND cx.instanceid = e.courseid
      JOIN mdl_role_assignments ra ON ra.contextid = cx.id AND ra.userid = ue.userid
      JOIN mdl_role r ON r.id = ra.roleid AND r.archetype = 'student'
      JOIN mdl_user u ON u.id = ue.userid AND u.deleted = 0 AND u.suspended = 0
     WHERE e.status = 0 AND ue.status = 0
       AND (ue.timestart = 0 OR ue.timestart <= UNIX_TIMESTAMP())
       AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP())
) learners GROUP BY courseid) en ON en.courseid = cm.course
  LEFT JOIN (SELECT t.courseid, t.param AS cmid, COUNT(DISTINCT t.userid) AS accessed
               FROM mdl_local_kopere_bi_tracking t
               JOIN (
    SELECT DISTINCT e.courseid, ue.userid
      FROM mdl_user_enrolments ue
      JOIN mdl_enrol e ON e.id = ue.enrolid
      JOIN mdl_context cx ON cx.contextlevel = 50 AND cx.instanceid = e.courseid
      JOIN mdl_role_assignments ra ON ra.contextid = cx.id AND ra.userid = ue.userid
      JOIN mdl_role r ON r.id = ra.roleid AND r.archetype = 'student'
      JOIN mdl_user u ON u.id = ue.userid AND u.deleted = 0 AND u.suspended = 0
     WHERE e.status = 0 AND ue.status = 0
       AND (ue.timestart = 0 OR ue.timestart <= UNIX_TIMESTAMP())
       AND (ue.timeend = 0 OR ue.timeend > UNIX_TIMESTAMP())
) learners ON learners.userid = t.userid AND learners.courseid = t.courseid
              WHERE t.page = 'module' AND t.visits > 0
              GROUP BY t.courseid, t.param) tr ON tr.courseid = cm.course AND tr.cmid = cm.id
 WHERE cm.deletioninprogress = 0 AND cm.visible = 1 AND c.id > 1
 ORDER BY reach_percent ASC, c.fullname, cm.id
 LIMIT 500

Critérios e funcionamento

O alcance é calculado como ROUND(100.0 * accessed / enrolled, 2) quando existem estudantes elegíveis; caso contrário, o SQL retorna zero. enrolled corresponde à quantidade distinta de estudantes matriculados elegíveis no curso. accessed conta os usuários distintos com visitas registradas para o módulo.

O campo neveraccessed é calculado como enrolled - accessed. A lista é ordenada pelo menor alcance, funcionando como uma fila de módulos que podem merecer análise, mas não prova que o conteúdo era obrigatório.

Limitações e cuidados

  • O alcance é evidência de visita no coletor do Kopere BI, não de conclusão de atividade, visualização integral, aprendizagem ou disponibilidade real do material para cada estudante.
  • O cálculo assume como público elegível todos os estudantes com matrícula ativa no curso, mesmo quando uma atividade possua restrições de acesso por grupo, data ou condições de conclusão.
  • Módulos sem estudantes elegíveis recebem zero por cento, o que não significa necessariamente problema de participação.
  • O SQL ordena por menor alcance e devolve apenas 500 linhas; módulos além desse limite não são incluídos.
  • A consulta verifica módulos visíveis, mas não restringe explicitamente a visibilidade do curso nem da seção.
  • O histórico de rastreamento não tem recorte temporal explícito. As visitas podem ter ocorrido antes da matrícula atualmente elegível ou fora de uma janela de interesse.
  • A expressão t.param precisa ser compatível com cm.id. Não há arquivo de variante PostgreSQL dedicado.

O SQL original da master foi reproduzido literalmente. Ele não foi executado no Moodle nesta etapa. Antes do uso institucional, verifique compatibilidade do SGBD, integridade dos dados, visibilidade, proteção de informações e interpretação pedagógica.
