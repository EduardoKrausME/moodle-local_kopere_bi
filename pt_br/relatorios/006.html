RELATÓRIO 006

Registros de login

Duas tabelas usam campos de acesso do perfil para distinguir contas sem login ou último acesso registrados e contas com data de primeiro acesso.

Finalidade e conteúdo

Duas tabelas usam campos de acesso do perfil para distinguir contas sem login ou último acesso registrados e contas com data de primeiro acesso.

Por que e quando utilizar?

Útil para localizar cadastros ainda não utilizados e fazer acompanhamento de usuários que tiveram um primeiro acesso, sem consultar manualmente cada perfil.

FiltrosSQL e visualizaçõesCuidados

Filtros disponíveis

Não há parâmetros de curso, usuário, coorte ou período. As duas tabelas restringem usuários a u.deleted = 0 e u.id > 1.

A primeira usa lastlogin = 0 e lastaccess = 0; a segunda usa firstaccess > 0. Esses critérios fixos não equivalem a eventos históricos de autenticação.

Visualizações e SQL original integral

São 2 visualizações e 2 consultas SQL. Quando uma mesma visualização possui duas consultas para MySQL e PostgreSQL, elas são apresentadas em caixas separadas dentro do mesmo bloco.

1. Contas sem login nem último acesso - Tabela

Tabela de contatos, cidade, país e criação dos usuários com lastlogin = 0 e lastaccess = 0.

Cache: 30m · Atualização: 30m.

SQL original integral

SELECT u.id        AS u_id, 
       u.firstname, 
       u.lastname, 
       u.email,
       u.phone1, 
       u.phone2, 
       u.city, 
       u.country, 
       u.timecreated
  FROM mdl_user u
 WHERE u.deleted    = 0
   AND u.id         > 1
   AND u.lastlogin  = 0
   AND u.lastaccess = 0
2. Contas com primeiro acesso - Tabela

Tabela com dados de perfil, firstaccess, lastaccess, lastlogin e lastip de usuários cujo firstaccess é maior que zero.

Cache: none · Atualização: none.

SQL original integral

SELECT u.id        AS u_id, 
       u.firstname,
       u.lastname,
       u.email,
       u.phone1,
       u.phone2,
       u.city,
       u.country,
       u.firstaccess,
       u.lastaccess,
       u.lastlogin,
       u.lastip, 
       u.timecreated
  FROM mdl_user u
 WHERE u.deleted     = 0
   AND u.id          > 1
   AND u.firstaccess > 0

Limitações e interpretação

  • O SQL não consulta o log de eventos: o relatório apresenta informações armazenadas na conta do usuário, não um histórico de logins.
  • Os dois grupos não constituem necessariamente uma partição completa de todos os perfis.
  • A primeira tabela usa cache e atualização de 30 minutos, enquanto a segunda configura ambos como none.
  • Os resultados contêm dados pessoais, inclusive IP na segunda consulta. Verifique permissões e exportações.

SQLs transcritos sem alteração das definições JSON da master; não foram executados em um Moodle nesta etapa. Valide permissões, desempenho e resultados no ambiente de destino.
