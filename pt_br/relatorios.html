Relatórios e compatibilidade SQL

Catálogo incorporado, variantes MySQL/PostgreSQL e atualização segura.

Catálogo por banco de dados

O catálogo incorpora definições separadas quando a consulta depende de particularidades do MySQL ou PostgreSQL. As variantes têm referências próprias, e o instalador escolhe o conteúdo compatível com a família do banco Moodle; painéis compartilhados podem manter blocos específicos para cada motor.

A partir da versão de banco 2026102202, a atualização instala variantes ausentes sem substituir SQL e configurações personalizados. O comando manual opcional é:

php local/kopere_bi/cli/import_database_reports.php

Conforme o histórico e os dados disponíveis no Moodle, alguns relatórios podem permanecer vazios. Tempo rastreado é estimativa, e não medição de atenção contínua.

Revisão de SQL sem sobrescrever customizações

Há um comando separado para revisar e atualizar definições de relatórios analíticos. Primeiro execute a simulação; depois, caso faça sentido para seu ambiente, a execução efetiva:

php local/kopere_bi/cli/refresh_analytics_reports.php --dry-run
php local/kopere_bi/cli/refresh_analytics_reports.php

O processo atualiza SQL apenas quando o conteúdo armazenado ainda corresponde ao checksum de uma versão conhecida; SQL personalizado é mantido e metadados locais de colunas são conciliados.

Interpretação e limites

Agregações por dia e semana podem utilizar UTC. Relatórios baseados em tentativas de questionário consideram estados finalizados, e o histórico de notas depende da retenção nativa no Moodle. Alguns relatórios individuais limitam a consulta a 500 linhas; use filtros de curso e período para análises extensas.
